有璽氏の原則（2026-09-07・LIFE STAND UPサイト制作）：
「一つ前の件もそうですが、全ページで統一してください。特別な理由がなければ全ページで統一をしてください。」

**Why:** パンくずリスト周りの余白を、有璽氏は同日中に3回指摘している
（午前「窮屈」→午後「パンくずとバッジの間が狭い」→夕「ページによってヘッダーとの
間隔が違う」）。実装側は毎回1箇所・1ページを直して報告し、隣のページや隣接する
別要素が揃っていないまま残る、を繰り返した。個別修正の積み重ねは「直した」という
報告を生むが、サイト全体としては揃わない。

**How to apply:**
- CSS・レイアウトの調整依頼を受けたら、着手前に「同じ型が何ページ・何箇所あるか」を
  数える（grepやテンプレート一覧で機械的に）。1ページだけ直して終わりにしない。
- 報告には「◯ページ中◯ページ揃えた」の分母つき件数を書く。「直しました」だけで
  済ませない → [[feedback_never_write_an_unmeasured_number]]
- 「意匠上の特別な理由」がある場合だけ例外にしてよいが、その理由を報告に明記する。
- 関連の実例：[[project_lifestandup_website_wordpress]]
  「!importantで全ページへ実際に届かせた」節（22テンプレート中20本が詳細度の壁で
  共通ルールを受け取れていなかった実例）。**「共通化した」という申告は、対象ページを
  1つ実測しただけでは裏取りにならない。** 全ページ横断でcomputed styleを見ること。

**★2026-09-08・4回目の同型指摘（真因が判明）**：有璽氏「パンくずリストの位置は
全ページ統一してください。なんで位置がずれてるんだよね。ページによって異なるんだよね。
なんでそうなってんの？」。★真因は「1ページずつ実測してそのページ専用の補正値を入れる」
実装そのものだった（about-company .breadcrumb margin-top -6.1px/-14.1px/2px ★!important
つき、about-ilife は 11px/15px/-6px と別の値）。**測った幅・測ったページでしか
合わない値を、ページごとに個別で埋めていた＝統一しないことをコードに固定していた。**
- **教訓を一段深くする**：「全ページで統一する」だけでは再発する。**「1か所（共通CSS）で
  値を決め、ページ別CSSの個別上書きを消す」まで踏み込むこと。** 個別上書きが1つでも
  残っていれば、次にどこかのページだけ直したくなった瞬間に同じパターンが再発する。
- ページ別CSSに `!important` 付きの余白上書きを見つけたら、それ自体が「点で合わせた」
  痕跡だと疑う。まず共通CSS側の値を疑い、そちらを直してから個別上書きを消す。

**★2026-09-08・5回目（揃えた後にもう一段の確認が要ると判明）**：「再度伝えますが、
マージンが狭いです。」12ページとも既に統一済み（12.2〜15.4px）だったが、**統一した値
そのものが「窮屈」という指摘を満たしていなかった。** 17px→32pxへ実際に広げて解消。
「統一する」で終えず「統一した値が指摘の言葉（狭い・窮屈）を満たすか」まで確認すること。
→ [[reference_verify_outcome_not_mechanism]] の同日追記に詳細と数値。
**★2026-09-08・5回目（同日2件目・対象がCSSではなく「素材」）**：有璽氏
「素材写真の**明るさとかが異なっている**ように思います」（地域ポータル「かわちばなし」）。
★こちらは当初「写真が暗い」と診断していた。**本人の言葉は「暗い」ではなく「異なっている」。**

```
「暗い」と読むと    1枚ずつ明るくして終わる → 揃わないまま残る
「異なる」と読むと   ★基準値を1つ決めて全枠を合わせる → 揃う
```

- **★この原則はCSSだけの話ではない。写真・アイコン・図版など「素材」にも同じく効く。**
  実測：5枚の明るさが 10.9〜35.4（ひらき24.5・最明と最暗で3.2倍）。参考サイトは64.5。
- **★「揃っているか」は目で決めない。数字で決める。** 平均輝度・彩度・暗部率を1枚ずつ測り、
  **合否線（明るさ60〜70／彩度35〜45／暗部15%未満／ひらき±8以内）を先に置いてから作る。**
  後から見比べると「まあ揃っている」で通してしまう。
- 詳細と測り方 → [[project_kawachibanashi_portal]]

## ★2026-09-12 「揃える」の対象は同じ文字列ではなく、同じものを指している語（JFBI）

有璽氏「**この項目について「一般に働いている方」の表記を「一般企業にお勤めの方」に変更してください**」。

名指しはカード見出し1か所。だが同じ言い方が他にもあるので、先に実物を数えた。
**「一般」を含む箇所は5件あり、3件と2件にきれいに割れた。**

| # | 実物 | どこ | 揃えるか |
|---|---|---|---|
| 1 | 一般に働いている方 | §07 カード見出し ← **名指し** | **○ 変える** |
| 2 | 一般に働いておられる方にも | §06 本文 | **○ 同じ人を指している** |
| 3 | 一般に働いておられる方にも | §07 本文 | **○ 同じ** |
| 4 | 一般**就労**されている方・一般成人の3つのグループ | §06 研究1の説明 | **✕ 研究の比較群の定義** |
| 5 | 一般の就労支援に携わる方 | §06 研究2の説明 | **✕ 支援者側の話。働く人ではない** |

**★4と5を巻き込むと、研究デザインの記述が変わる。**
「一般就労」は福祉の制度用語で「福祉的就労」の対義語。言い換えると比較群の定義が崩れる。
5に至っては**主語が違う**（支援する側）。文字列が似ているだけ。

```
✕ 「一般」で全置換          ← 研究の定義まで書き換わる
✕ 名指しの1か所だけ直す      ← 同じ人を指す残り2件がずれたまま（5回指摘された型）
○ ★数える → 同じ"対象"を指すものだけ揃える → 性質が違うものは理由を添えて残す
```

**★カード本文は変えなかった件も、判断として残す。**
見出しを変えると本文「特性の有無にかかわらず、働いておられる方。」が見出しより広く読める。
だが本文の趣旨は「特性の有無を問わない」ことの強調で、書き換えると見出しの繰り返しになる。
**名指しされておらず、変えなくても通るので残し、その旨を報告した**（決めるのは有璽氏）。

## ★2026-09-24 写真も「統一」の対象（JFBI・同じ型で7回目）

有璽氏
> 「この掲載画像の**比率って全部同じものに統一できる**？　今見てる限り、多分この
>  のぼり、紫茶、緑茶、村麦緑茶とか団子のやつが**サイズ的に同じ**やと思うんだよね。
>  だから**そのサイズに合わせる**とか、**全部をね、する**とかにしてもらえる？」

**★こちらは「中身が切られないこと」を最適化して、比率をバラバラにしていた。**
写真ごとに元の比へ近い枠を当てた（3:2・3:4・1:1・contain の4種類が混在）。
一枚ずつ見れば最適でも、**並べると凸凹して揃っていない。**

```
こちらの基準   1枚ずつ、中身が切られない枠を選ぶ      → ★比率が4種類に散った
有璽氏の基準   並べたときに同じ形に見えること          → ★枠は1種類
```

**★「揃える」は1枚ずつの最適化より優先する。** 切られるのが嫌なら
`object-fit:contain`（枠内に収める）で両立できる ── **枠を揃えたまま中身も切らない。**
→ [[reference_grid_collapses_when_only_one]]

**★有璽氏は基準になる1枚を先に名指しする。**今回は「のぼり（縦長のパッケージ）」。
**「そのサイズに合わせる」か「全部を（何かひとつに）する」か**という言い方＝
**揃っていればどちらでもよい**。基準の候補が示されたら、まずそれで作って見せる。

**★並べるものは、作る前に「何を揃えるか」を1つ決める。**
写真・カード・図版など複数を並べる場面はすべて同じ。
迷ったら**枠は1種類・中身は contain**から始める。
