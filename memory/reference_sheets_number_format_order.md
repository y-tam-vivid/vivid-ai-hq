Apps Scriptでシートを書くときに踏んだ地雷。**どれもエラーにならず、静かに間違った結果を出す。実行が通ったことを成功の根拠にしてはいけない。必ず実物の値と位置を読んで確認する。**

**① 書式指定は書き込みより前でないと無意味。** 書式が標準のまま数字だけの文字列を `setValues` すると数値化され先頭0が消える。後から `setNumberFormat('@')` を当てても復元されない。

```javascript
range.setNumberFormat('@'); range.setValues(rows);   // 正
```
復旧可能性は非対称：固定電話(10桁→9桁)は先頭0を補って復元できるが、**携帯(11桁→10桁)は桁数から判別できず復元不能**。

**② `getLastRow()` は「値がある最終行」ではなく「セルが空でない最終行」。** 数式の結果が `""` でも数式セルは非空と判定される。数式を1000行目まで敷いた列があると、データ0件でも1000を返し、追記が1001行目に飛ぶ。**実データ末尾は数式でない値列で判定する。**

```javascript
function lastDataRow_(sh, col) {
  const vals = sh.getRange(3, col, sh.getMaxRows() - 2, 1).getValues();
  for (let i = vals.length - 1; i >= 0; i--) if (String(vals[i][0] || '')) return i + 3;
  return 2;
}
```

**③ 冪等なはずのバッチに「既存はスキップ」を入れると冪等性が壊れる。** 判定ロジックを直しても既存データに反映されない。スキップではなく**検証を通す**（正しければ据え置き／直せるなら補正／無効なら破棄して再処理）。集計の分母も「全行」に統一しないと実態を誤認する。

**④ 入力規則(`setAllowInvalid(false)`)のある列へ統制外の値を含む `setValues` を投げると、範囲全体が例外で落ちる。ただし部分的には書き込まれている。** 365行のうち224行が入った状態で停止した実例あり。**再実行で続きから、はやってはいけない**（重複判定をすり抜けて二重登録になる）。書き込む前に統制値へ寄せ、寄せられない値は空欄にして生値を備考へ退避する。

さらに**例外は `setValues` の行ではなく、次に読み取りを行った行で投げられる**（書き込みが遅延実行され、次の読み取りでflushされるため）。**スタックトレースの行番号が原因箇所を指さない。**

**⑤ 指数表記は「表示だけの問題」とは限らない。実体が壊れていることがあり、復元してはいけない。** エクスポートCSVをスプレッドシートに変換すると、法人番号は `4.1201E+12` という**有効数字5桁の値そのもの**になる。`getValues()` で数値を取って `toFixed(0)` すれば戻る、というのは誤り（13桁は2^53に収まるので一見正しそうに見えるが、丸めは変換時点で既に起きている）。

戻すと `4120100000000` のような**13桁で検査数字も通るが別法人を指す値**ができる。実測で、壊れた4件のうち1件が検査数字を素通りした。**検査数字では止められない。**

```plain text
正 4120102013090 検査OK   壊 4120100000000 検査OK ← 素通り
正 6120101064356 検査OK   壊 6120100000000 検査NG
```

対策は変換しないこと。**エクスポートは `.csv` のままDriveに置き、`Utilities.parseCsv` で読む**（型推定が働かない）。

**法人番号の先頭1桁は検査数字で、国税庁の仕様上 1〜9 にしかならない。先頭0の法人番号は存在しない**（12桁の会社法人等番号がゼロ詰めされた壊れた値）。検査数字は復元できる：`9 - (Σ Pn×Qn) mod 9`（Pn=基礎番号12桁の下位n桁目 / Qn= nが奇数なら1・偶数なら2）。**誤った法人番号は空欄より有害**（kintoneの結合キーなので別法人に紐づく）。

**⑥ フォーム連携シートでは列を削除してはいけない。** 手で足した列であっても、削除するとフォーム側が自分の管理範囲を復元しようとし、次にフォームへ質問を追加したタイミングで `Column 13` `Column 14` のような**空のプレースホルダ列が生成される**。2026-08-08に受付シートで実測（当方用4列を一時退避しようとして3本発生）。消すとまた生えるので**非表示にして残す**。

同じ理由で、フォーム連携シートの列は**位置で参照しない**。フォームに質問を1つ足すだけで、手で足した列は右へずれる。**必ず見出し名で引く**。

**⑦ 末尾に新しい列を足すと、左側のチェックボックスの入力規則を引き継ぐことがある。** 空のはずの新列に `false` が入る。`getValues()` は文字列 `""` ではなく boolean `false` を返すので、「既に値が入っていれば上書きしない」という安全弁が全行で発火し、**1件も書き込まれずに正常終了する**。2026-08-10に `00_企業マスタ`（23〜25列がチェックボックス）へ28列目を足して実測。

列を作った直後に `clearDataValidations()` を当てる。既存値の判定は `String(v).trim() !== ''` ではなく **boolean を除いてから**行う。

```javascript
if (v === true || v === false) { /* 未入力とみなす */ }
```

**⑧ 「値が無い」と「行が無い」は別物。`getLastRow()` で書き込み先を決めてはいけない。** `getLastRow()` は値がある最後の行、`getMaxRows()` は**シートが物理的に持っている行数**。両者が一致しているシートでは、その次の行は存在しない。2026-08-18に `00_企業マスタ`（getLastRow=779 / getMaxRows=779）へ780行目から17行を書こうとして
`対象の範囲の座標がシートのサイズから外れています` で落ちた（`08_関係フォロー` は getMaxRows=1000 で余裕があり、こちらは通っていた）。

```javascript
var need = 書き出し開始行 + 件数 - 1;
if (sh.getMaxRows() < need) { sh.insertRowsAfter(sh.getMaxRows(), need - sh.getMaxRows()); }
```

**★このとき `copyTo()` は範囲外でも例外を投げず、何もしない。** 数式の複製を先に走らせていたが、無言で失敗し、次の `setValue` で初めて落ちた。**「例外が出ていない＝実行された」ではない。**

**そしてこれは、ドライランでは絶対に検出できない。** 読むだけのドライランは「書けるかどうか」を検証していない。
**ドライランに「書き込み先の行数が足りているか」を数えさせる**まで、それは本実行の予行演習になっていない。

## ⑨ ★器を増やしても、守りは付いてこない（2026-08-20 実測）

`00_企業マスタ` は器807行ちょうどでデータが満杯だった。新規行を足すため `add_rows` が要る。
だが**保護も条件付き書式も 807行で止まっている**。

```
範囲保護 4本        A列ID・G列電話番号_正規化・U列作成日・V列更新日
                    いずれも endRowIndex:807 固定 ＝ **808行目には及ばない**
条件付き書式        D列（法人番号）の指数表記検知も807行で止まる
                    ＝ **新規行では指数表記の検査が働かない**
```

`08_関係フォロー` には「保護の自動延長」を組み込んだが、**`00_企業マスタ` には無い**。

- **行を足す作業は、値を書く作業と守りを伸ばす作業の2つ。** 片方だけやると穴が開く
- **穴は新しい行にだけ開く。** 既存行を見ている限り気づけない
- 足したあとに「保護が器の行数に届いているか」を突合する（08で作った形をここへも入れる）
