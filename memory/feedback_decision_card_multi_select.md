判断カードで、複数の軸が混ざった答えを1つのボタンに束ねない（「確定して全社へ共有」「相手は新規（受付へ）」「社内・個人だった」が横に並ぶ形）。
軸ごとに問いを分け、それぞれ選んでから［送信］で読み込む形にする。AIの見立ては最初から選んだ状態で出してよい。違っていれば有璽氏が押し直す。

**Why:** 有璽氏「1個押したらもう完了してしまう」「全部押した方が早い。ポチポチ押して、それを読み込んで反映する」（10/30 #91b725 を見て）。1つのボタンに複数の判断が入ると、どれか1つ違うだけで押せるボタンが無くなる。

**How to apply:**
- 議事録の仕分けカードは3問＋送信：①区分（個人／社内／社外）②相手が社外のとき 新規か既存か（相手の候補もここ）③機微 あり／なし。共有するかは別の問いにするか①に含めるかを設計で決める。
- ask_hub に選択の部品（ラジオ・セレクト）と、送信のときに選んだ値をまとめて受け取る道が要る。10/30 時点の ask_hub.py・slack_socket.py には無い（grep で radio/select/state.values 0件）。どちらもバックオフィス担当の持ち物。
- 他のカードでも、答えが2軸以上なら同じ型にする。
- ★罠（10/30 バックオフィス担当が実物で指摘）：slack_socket.py の handle_interactive は actions[0].value を json.loads し、読めなければ「ボタンの中身が読めませんでした」と返す。ラジオ・セレクトには value が無い（selected_option だけ）＝選び直すたびにエラー返事が出る。action_id を `askhubq_` で始め、json.loads の前で return する。
- 送信ボタンは value `{'hub':'ask','id':…,'opt':'__submit__'}` にすれば既存の分岐に乗る。選んだ値は payload['state']['values']（block_id を `askq_<key>`）。answer['label'] には要約を入れて待ち役・台帳の読み手を壊さない。回答済みで閉じるときはラジオのブロックも消す。
- 10/30 バックオフィス担当の返事：持ち主の根拠は無い・差分はこちらで入れてよい（WORKING の該当行に1行添えて控えを取ってから）。
