**2026-09-13 有璽氏の依頼**：「PCサイズから幅を狭めていって、最終的にスマホになっても
表示が崩れないようにするための設定を、視覚的に確認しながら進めたい」。
★有璽氏はこれを**「レスポンシブ」「オートレイアウト」**と呼ぶ。この語をそのまま使う。
言い換えない（例：「幅を測る」等の実装寄りの言い換えで報告しない）。

**背景**：既存の★C（lsu-editor）は 375/390/414/768/820/1366/1920 の7点しか見ない。
★端は通るが中間で崩れる型を既に踏んでいる → [[reference_endpoints_pass_middle_breaks]]。
そこで「幅を連続で掃いて、崩れる幅を機械に名指しさせる」方式（sweep_widths.py）を
リリスへ発注した。

**有璽氏が決めた条件（2026-09-13）**
```
A 崩れの定義 = 横あふれ ＋ 重なり の2つだけ。★恒久ルール①〜⑥違反は含めない
B 対象      = ★代表5ページだけ（/ ・/stand-up/ ・/recruit/ ・/stand-up/programs/ ・/news/）
C 刻み      = ★粗く20px → 崩れた帯だけ2px の2段階
```

**Why**: 全22ページ・1px刻みは過剰な作り込み（探索領域の初期段階＝完璧を求めない）。
代表5ページ・粗刻みで手順そのものが成立するかを先に確認する方針。

**How to apply**: 次にこの検証手順を他ページ・他サイトへ広げる判断が出たら、
このメモリと `~/lifestandup-wp/review/sweep/` の結果を見てから着手する。
「レスポンシブ」「オートレイアウト」という有璽氏の語を、報告・UIのラベルでも
維持すること（過去に実装名で報告して「使い方がわからん」と差し戻された前例あり
→ [[feedback_ui_must_be_self_explanatory]]）。

**実装は自分（メインセッション）で書けなかった**：`hook_role_guard.py` が
agent_id欠落によりメインセッション（ビビ）扱いし、`.py`のWriteを拒否した。
Bashでの回避はせず（[[reference_hooks_enforce_what_discipline_cannot]]の
「③Bashで書いて通すのは回避。やらない」に従う）、Agent tool経由でweb-developer
サブエージェントへ実装・実行・報告を委譲した。

**★2026-09-13 走行中に判明した2点（サブエージェントの中間報告より）**
1. **print()のバッファリングでログが0行のまま**：`python3 sweep_widths.py`を
   バックグラウンド実行したところ、標準出力がブロックバッファリングされ
   `flush=True`を付けていなかったため、完了かバッファが溜まるまで途中経過が
   ログファイルへ出てこなかった。★長時間走る検証スクリプトをバックグラウンドで
   動かすときは、`print(..., flush=True)`か`python3 -u`を使うこと。
   How to apply: 次に長時間バックグラウンドで走らせるPythonスクリプトを書くときは、
   最初から`-u`オプション（または各printにflush=True）を付ける。
2. **ローカル検証サーバのポート8750に、無関係な別セッションが相乗りしていた**：
   `sweep_widths.py`が`E.serve()`で127.0.0.1:8750にPHPサーバを立てている最中、
   `pgrep -fl "Google Chrome"`で392プロセス・うち21件が`lsu-tape-dock.html`
   （sweep_widths.pyには存在しない文字列）を呼んでいるのを発見。`lsof -i :8750`
   ではLISTENは自分のプロセスのみだったので、別セッションが同じポートへ
   リクエストを送っているだけ（サーバ乗っ取りではない）と見られる。
   これは既知の型 → [[reference_two_sessions_built_the_same_thing]]
   「★8750はredeployも検証も同じものを使う」の新しい実例。
   How to apply: 8750で検証中に見慣れないChromeプロセスや文字列を見つけたら、
   まず自分のコードに無い文字列かを確認し、別セッションの並行使用を疑う。
   撮影の遅延・失敗が起きたら、この競合を最初に見る。
