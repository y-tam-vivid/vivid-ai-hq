**2026-09-13 有璽氏の依頼**：「PCサイズから幅を狭めていって、最終的にスマホになっても
表示が崩れないようにするための設定を、視覚的に確認しながら進めたい」。
★有璽氏はこれを**「レスポンシブ」「オートレイアウト」**と呼ぶ。この語をそのまま使う。
言い換えない（例：「幅を測る」等の実装寄りの言い換えで報告しない）。

**背景**：既存の★C（lsu-editor）は 375/390/414/768/820/1366/1920 の7点しか見ない。
★端は通るが中間で崩れる型を既に踏んでいる → [[reference_endpoints_pass_middle_breaks]]。
そこで「幅を連続で掃いて、崩れる幅を機械に名指しさせる」方式（sweep_widths.py）を
リリスへ発注した。

**有璽氏が決めた条件（2026-09-13）**
```
A 崩れの定義 = 横あふれ ＋ 重なり の2つだけ。★恒久ルール①〜⑥違反は含めない
B 対象      = ★代表5ページだけ（/ ・/stand-up/ ・/recruit/ ・/stand-up/programs/ ・/news/）
C 刻み      = ★粗く20px → 崩れた帯だけ2px の2段階
```

**Why**: 全22ページ・1px刻みは過剰な作り込み（探索領域の初期段階＝完璧を求めない）。
代表5ページ・粗刻みで手順そのものが成立するかを先に確認する方針。

**How to apply**: 次にこの検証手順を他ページ・他サイトへ広げる判断が出たら、
このメモリと `~/lifestandup-wp/review/sweep/` の結果を見てから着手する。
「レスポンシブ」「オートレイアウト」という有璽氏の語を、報告・UIのラベルでも
維持すること（過去に実装名で報告して「使い方がわからん」と差し戻された前例あり
→ [[feedback_ui_must_be_self_explanatory]]）。
