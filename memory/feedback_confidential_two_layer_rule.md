ふくち。グループの**機微情報の二層管理ルール（全社標準・2026-07-20確定）**。Drive/ナレッジ全般に適用。

**原則＝部署・PJフォルダは共有ドライブ**（チームで協働）。**例外＝各フォルダ内に固定名「_機微」サブフォルダを置き、そこだけ閲覧メンバーを限定**（Google共有ドライブはフォルダ単位で権限を絞れる。先頭`_`で一覧最上部固定・機械判定容易）。

**Why**: 顧客の製本ワンシステム統一より「日常業務は共有して協働、機微だけ隠す」が実務に合う。機微を部署ごと丸ごと隠すと協働が死に、全部共有すると給与/契約/個人情報が漏れる。二層で両立。

**How to apply**:
- **_機微の基準メンバー**＝本人(担当者)＋代表＋当該部門の管理責任者(管理部門長)、必要に応じ担当役員。フォルダ単位で微調整可。
- **判定**＝「外部流出・他部署閲覧で具体的損害/プライバシー侵害が生じるか」でYES→`_機微`。入れる例＝給与明細・個人報酬/応募者・従業員の個人情報/契約原本・法的機密/口座・決済/健康・マイナンバー/未公開M&A・重大人事。通常(共有)＝マニュアル・企画書・提案資料・議事録(機微部分除く)・制作物・進捗・公開予定コンテンツ。
- **2つの隠し方**：①部署まるごと本人限定(部署フォルダ自体を個人マイドライブ or 部署単位で権限限定＝経理部14-200)／②部署は共有・中の`_機微`だけ限定(労務14-100/法務14-300/採用14-400)。総務14-500=共有。
- **sort_downloads.py**は機微キーワード(給与/契約書/マイナンバー/応募 等)検知ファイルを該当部署フォルダの`_機微`直下へ自動隔離する仕様にする([[project_downloads_archive_system]])。
- 権限設定は一度人が実施、以後は場所固定で運用が軽い。

設計ドキュメント=ナレッジホーム設計§9([[reference_notion_knowledge_design]])に記録。Drive部門軸再設計の一部([[reference_org_master_4db]])。

## ★「機微そうに見えるもの」を機微と決めるのはAIではない（2026-08-22 実地・2回目）

イベント写真4件（「第36回こどもまつり」羽曳野市）に**子どもの顔が写っていた**ため、
当方の判断で `_要確認_肖像許諾` に隔離し、有璽氏へ「tane. の資産として置いてよいか、
`_機微` 扱いにするか」と判断を仰いだ。**回答は「問題ない」。**

**これは2回目の同じ型。** 2026-08-19、法務（センゴク）が「福祉利用者の情報は
自動共有から除外」と出したが、有璽氏の「それは業務ナレッジで社内に残すべきもの」で覆った
（→ fukuchi-core「★AIの所見はドメイン知識で覆る」）。

```
AIがやること     ★止めて聞く。勝手に共有領域へ広げない
AIがやらないこと  ★「これは機微だ」と自分で確定して隔離を既成事実にする
                 隔離した先を忘れると、資産が静かに死蔵される
```

- **上の判定表（給与・契約原本・個人情報…）に無いものを、雰囲気で足さない。**
  表にあるのは「外部流出で具体的損害が生じるもの」。
  **公開イベントの記録写真は、団体が広報のために撮っているもの**であって、
  その場で判断すべき機微ではない。許諾は撮影時の運用側にある
- **聞き方は「隔離しました」ではなく「置いてよいか、隔離するか」。**
  先に隔離して報告すると、有璽氏は「戻す」という余計な指示を出す羽目になる
- 迷ったら**移動せずに場所を保ったまま聞く**（fukuchi-core「ファイルを動かすか → 動かさない」）

→ [[feedback_dont_call_it_a_typo]]（実測を根拠に断定しない）と同じ構え。

## ★Notionでは「誰が見られるか」を機械で確認できない（2026-09-03 実測）

**機微をNotionへ置いてよいかを、AIが自力で確かめる手段が無い。**
個人の家計を予実の器へ入れる前に確かめようとして判明した（[[project_cfo_agent]]）。

```
経路1  notion-get-users          ワークスペースの人間メンバーは3名
                                 ★これは「見られる可能性の上限」であって招待者一覧ではない
経路2  list-private-pages/shared  対象ページは Private 側に実在・Shared は0件
                                 ★これは「サイドバーの表示分類」であって共有者一覧ではない
結論   ★どちらも「本人限定」を証明しない。共有者一覧を返すAPIが存在しない
```

- **★空配列がエラーではなく正常応答だったので、「ok:false を0件と誤読」の型には当たらない。**
  読み違いではなく、**そもそも読む手段が無い**。両者を混同しない
  → [[feedback_one_route_is_not_verification]]。
- **★間接証拠が「非公開寄り」でも足さない。**「たぶん本人限定」で機微を置くのは、
  規範上いちばんやってはいけない判断。**止まるのが正しい。**
- **★確認できるのは人だけ。** だから聞き方は「見てください」ではなく
  **押す場所まで特定して渡す**（fukuchi-core）── 対象ページを開く → 右上「共有」→ 招待者の一覧。
- ★Drive は違う。`get_file_permissions` で共有者を実測できる（同日、月次明細フォルダで
  「所有者1件のみ」を2経路で確認済み）。**同じ「非公開の確認」でも、道具によってできる/できないが割れる。**

## ★「検知した」は「隔離した」ではない（2026-10-15 実測・自分で踏んだ）

`drive_sort.py` は機微語リスト（`SENSITIVE`＝マイナンバー・診断・給与・個人情報…）に
**当たったことを判定の理由文に書いていただけで、行き先を変えていなかった。**
行き先を強制していたのは `契約原本 / 労務 / 採用` の3つだけ。

```
実測 ── _要判断_20261014 の138件を名前で数え直した
  規則で _機微 へ寄るもの      13件  勤務表・勤怠・標準報酬決定通知書・誓約書・応募者
  ★機微語に当たるのに素通り      3件  マイナンバー(表)_田村佑司.pdf
                                      鈴川聖子さん診断結果.pdf ほか
  → ★人が開ける素の箱に、マイナンバーと診断結果が置かれていた
```

```
★型： 条件を「検知する」コードと「行き先を変える」コードは別物。
      ログや理由文に機微語が出ていると、隔離できている気になる。
      ★確かめ方は1つだけ ── ★置き場を実物で数える（何件が _機微 の下に在るか）
```

- **直し**：`forced = 契約原本 or 労務 or 採用 or bool(機微)`。
  **部門が決まらない機微は `_要判断/_機微` へ**（素の `_要判断` に置かない）。
  判定表の語に当たったら、Haiku が「確信：低」でも機微側へ倒す。
- ★`_要判断` のような**人が開く箱そのものにも `_機微` を持たせる。**
  「決まらないもの」の箱は、決まるまで開かれる前提の場所＝いちばん無防備になる。
- → [[feedback_one_route_is_not_verification]]（理由文は実測ではない）
  ／[[reference_drive_placement_rules]]（置き場の規則）

## ★機微語に当たっても「機微」とは限らない（2026-10-15 有璽氏の判断 #03479b・回答3）

`_機微` に入れた中で、**公的機関の案内・様式・自社の商材は `_機微` から出す**と決まった。
語（給与・契約・診断…）に当たるだけでは機微と判定しない。区分は3つ：
1＝公的機関の案内・様式・要項・書類リスト ／ 2＝ふくち。グループ自身の商材・会社案内（相手の事情が無いもの）
／ 3＝上以外（個人・取引先の内情・従業員・利用者・児童・ログイン情報）。**迷ったら3。**
- 例：厚労省の助成金案内・自社の商材一覧 → 1/2 → `_機微` から出す ／ 従業員の雇用契約・顧客の資産状況 → 3 → 残す
- 判定の正本は上の型。区分の結果を行き先に反映するのは、人が1件ずつ確かめてから（一括で動かさない）
  ／[[reference_drive_placement_rules]]（置き場の規則）

## ★機微の線は「個人情報か」ではなく「外へ出たら不利益があるか」（2026-10-16 有璽氏の判定・境界6件）

規則では当たらず、こちらが「残す」に倒した6件を有璽氏が1件ずつ裁いた。**★当方の線引きは逆に倒れていた。**

```
機微でなくて良い（出す）
  ① 田村有璽の経歴         ★発達障害の診断の記述を含む  ＝本人が公開している物語。出て困らない
  ② ゼロイチの挑戦vol.3    ★申込者一覧が同梱            ＝書籍の掲載・申込＝公開前提のもの
  ⑤ 実地指導で求められる書類（行政書士事務所が作成）      ＝ただの業務資料
機微のまま（残す）
  ③ 事業変遷年表           ★行政処分・指定取り消しの記述 ＝★会社の処分歴は外に出ると不利益
  ④ 社労士・税理士の顧問報酬の計算表 2件                  ＝★自社の値付けのロジック
```

**★当方は「診断名・個人情報がいちばん重い」と見て、本人の経歴を機微に倒していた。**
有璽氏の軸は違う ── **自分のことは自分が決めて出している。重いのは「会社が不利益を受けるもの」。**

```
★語でも人でもなく、こう問う ──「これが外へ出たとき、誰がどんな不利益を受けるか」
   有璽氏本人の病歴・経歴      → ★本人が公開済み＝機微でない（本人の判断が先に在る）
   会社の処分歴・指定取り消し  → ★機微（取引・指定に効く）
   自社の値付け・報酬の計算式  → ★機微（商売の中身）
   公開前提の書籍の申込者一覧  → 機微でない
   専門家が作った一般の業務資料 → 機微でない
```

★`_個人(本人限定)` に在るものを、さらに `_機微` へ入れる必要は無い（本人限定で既に閉じている）。
関連 [[reference_drive_placement_rules]]（置き場）／[[feedback_never_write_an_unmeasured_number]]
