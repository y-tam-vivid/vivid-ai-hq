## ★同じ事故が別の入口で再発しかけた ── 突合ロジックを2箇所で書かない（2026-08-20）

## ★照合が「該当なし」を出した2件は、台帳に居た（2026-08-26 有璽氏の指摘・実測）


### 真因は3つ。どれも「見ていなかった」ではない

```
① 人名が完全一致でしか照合されない
   norm_person('上妻') = '上妻' ／ norm_person('上妻央育') = '上妻央育' → 一致=False
   ★02_個人マスタは読んでいる。索引にも入っている。
     **見たうえで、完全一致しないので落としていた**
   ＝ 苗字だけで入力されたら、どれだけ珍しい名字でも絶対に当たらない
② 想定している商材（toB／toC）を照合に使っていない（grep 該当0行）
   ★「保険・資産形成（toC）」と書いてあるなら、C- 側を優先して見ればよい
③ 今回の接触の種類を使っていない（grep 該当0行）
   ★「継続関係（再訪・フォロー）」と書いてあるものが新規のはずがない。
     有璽氏の言葉 ── 「継続関係ってなってるのに、新規なわけない」
```

**②③は入力欄に存在していて、照合に一度も渡されていなかった。**
人が書いた手がかりを、機械が使っていない。

- **★「該当なし」を出すときは、使わなかった手がかりを添える。**
  「氏名の完全一致では見つからず。★商材=toC・接触=継続関係 は照合に使っていません」
  と出ていれば、人はすぐ気づけた
- **★完全一致で落とすなら、部分一致の候補も別枠で出す。**
  「一致はしないが、苗字が同じ人が台帳に1人います」で足りる

## ★設計の欠陥 ── 「同じ人」と答えても、どの人かを伝えられない（2026-08-26）

確認欄の選択肢は `○ 同じ人` ／ `× 別人（新規でよい）` ／ `保留` の3つ。
**「○ 同じ人」を選んでも、どのIDと同じかを書く欄が無い。**

```
有璽氏がやったこと   社内メモへ「C-0049 上妻央育　と同じ」と手で書いた
                     ★仕組みが受け取れないので、人が別の欄へ書くしかなかった
```

- **★答えを1つに畳めない質問を、二択三択で聞かない。**
  「同じ人ですか」に「はい」と答えられても、**誰と同じかが残らなければ処理できない**
- 直し方は2つ ── ①候補が1件のときだけ「○ 同じ人」を出す（誰と同じかが自明）
  ②候補が複数なら **候補ごとにボタンを分ける**（「○ C-0049 と同じ」「○ C-0026 と同じ」）
  ★Slack投稿側は既に②の形を実装済み。**受付シート側の選択肢が追いついていない**
