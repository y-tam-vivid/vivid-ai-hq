**カレンダー**: `y_tam@vivid-global.com`「[01]ビビッド_田村有璽」（Asia/Tokyo）。
有璽氏は**予定を入れるときに色で種別を分けている**（2026-08-25 有璽氏）。
申告された分類は7つ ── 会食・個人／事務作業・クリエイティブ／社内ミーティング／
社外・商談面談／交流会／研修／移動。

### ★トマト(11)だけ軸が違う ── 種別ではなく「緊急」（2026-08-25 有璽氏）

> 「緊急度の高いものを赤に設定していました。**終了後は関係するラベルに修正**していますが、
> 中には異なるものがあります。」

```
色 1〜10   種別の軸   その予定が「何であるか」
色 11      緊急の軸   その予定が「急ぎであるか」   ★同じ色空間に2つの意味体系が同居
```

- **★トマトを1つの種別として数えない。**中身を見て正しい種別へ寄せる。
- **★寄せ方は「提案して確認」（2026-08-25 有璽氏）**
  > 「**今回のように想定される種別を提案し確認してください。**」

  実測1件は「【事務作業】国保連請求処理」→ タイトルから事務作業と提案 → 有璽氏が承認、の順。
  **黙って寄せない。読めても提案の形で出す。**件数が増えたら一覧で出して1回で確認を取る
  （[[feedback_batch_the_checks]]）。
- **終了後に関係するラベルへ直す運用なので、残っているトマト＝直し忘れ。**
  緊急度は「いま急ぎか」を表すので、**過ぎた予定にトマトが残っていても異常ではない。**

## ★出欠で「実際に出た会議」を切り分けられる（2026-08-25 有璽氏）

> 「私が**出席ボタンになっているものは参加**です。それ以外は不参加。」

`attendees[]` の中で `self:true` の要素の `responseStatus` を見る。

**★算入ルール（2026-08-25 有璽氏が確定）**

> 「基本的に**出席と回答したものだけ算定**してください。そこを触れていない可能性があります。
> **出席するものは、出席ボタンを基本的には押しています。**」

```
accepted           算入する    出席ボタンを押した＝参加した
tentative          除外する    12件 週5.5h  ★触っていないだけ＝出ていない
needsAction        除外する     2件 週0.7h
declined           除外する     3件 週1.0h
attendees が無い    算入する    出欠の概念が無い自分の枠（事務作業・生活・交流会はここ）
```

- **★除外の21.5h（週7.2h）は、うち20.5hが社外商談。**全部 松本氏が入れた予定で、
  有璽氏は出席ボタンを押していない ＝ **出ていない**。
- **★「色が付かないから商談が見えない」ではなく「出ていない予定が入っていた」が正しい。**
  ビビは当初これを「週6時間ぶん商談が消える」と誤読した。**色の欠落より出欠の方が強い情報。**
- 「単独」（attendees なし）を不参加と混同しない。出欠の対象外であって、参加している。

## ★集計に使うときの穴（3つ。ここを知らずに数えると必ず誤る）

```
① 他人が作った予定には色が付かない
     色なし24件のうち14件が他人の作成（12件が松本氏）。分類は色から取れない
     ★ただし出欠を見れば片づく ── その14件はほぼ全部 未回答＝出ていない予定だった
② タイトルの【】タグは55%が未記入        86件/165件がタグなし
     色とタグは穴の位置が違う（色=他人作成が漏れる／タグ=自分でも付け忘れる）
③ カレンダーは「予定」であって「実績」ではない
     睡眠の記録は21日中8日しかない＝記録が断続的。実働時間の根拠に単独で使わない
     ★所要時間を本当に測るなら、完了ログ側に「＊タスク名 20分」と書き足す方が確実
```

**★情報の強さの順**: 出欠 ＞ 色 ＞ タグ。**色が無いことを「分類の穴」と即断しない。**
出欠を先に見れば、色の無い予定の多くはそもそも算入対象外だと分かる。

## 実測値（2026-08-04〜08-24・3週間・165件・全件処理）

色なし24件は「作成者が他人＝打合せ」「タイトルが睡眠/食事＝生活」で補正して振り分けた。

```
★仕事の時間                      週 39.0h（出席と回答したもの＋自分の枠。生活は除く）
    事務作業         週 8.8h  23%  ★単独では最大
    社外/商談・面談   週 7.8h  20%
    社内/ミーティング  週 7.0h  18%
    交流会           週 5.8h  15%
    移動            週 3.7h   9%
    研修・学習会      週 2.3h   6%
    クリエイティブ     週 2.2h   6%
    懇親会・会食      週 1.0h   3%
  個人                          週24.8h  ★睡眠の記録は21日中8日のみ＝実態ではない

  人と会う（商談＋社内MTG＋交流会＋懇親会） 週21.6h  55%
  手を動かす（事務作業＋クリエイティブ）      週11.1h  28%
  移動・研修                              週 6.3h  16%
```

**★出欠で除外する前は週46.0hだった。**除外して週39.0h。分母が減った結果、
**事務作業が単独項目で最大（23%）になる。**移譲の効果は 10%→**23%** に上がる。

**★示唆①**: 出た会議だけを数えると **週21.6h（55%）**。依然として最大の塊だが、
**単独項目では事務作業（週8.8h・23%）が最大**。移譲の対象としてまず現実的なのはここ。

**★示唆②**: カレンダー上の事務作業は週8.8h、[[project_personal_task_system]] の
ルーティン表「実施中×自分で実行」は週4.4h。**ちょうど半分しか表に載っていない。**
棚卸しは完了していない ── 表に無い事務が同量ある。**両方渡せば仕事時間の23%が空く。**

**★示唆③【解決済み・異常ではない】**: 松本氏が入れた社外商談 週5.2h に出席ボタンが
付いていないのは**設計どおり**（2026-08-25 有璽氏）。

> 「これは私が出なくていいものです。**松本側が組んだものは、必要な場合は別途彼から
> 出席の打診がある**ので、そこには出ている。それ以外は彼単独で行っている商談なので、
> **私は同席しない**という前提です。」

**★これは取りこぼしではなく、既に移譲できている証拠。**カレンダーに予定が入っているのに
出欠が空いている状態を「抜け」と読まない。**招待は共有であって出席要請ではない。**
出席が要るときは別経路（松本氏からの打診）で来る ＝ カレンダー外に判断の経路がある。

## 取り方（再現手順）

MCP `list_events` は3週間分で15万字を超えてツール結果に収まらず、
`~/.claude/projects/.../tool-results/*.txt` へ落ちる。**そのJSONをPythonで全件集計する**。
`colorId` はイベント直下。所要時間は `start.dateTime` と `end.dateTime` の差
（終日予定は `date` のみなので別枠にする）。
