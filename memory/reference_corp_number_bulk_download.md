**法人番号の取得経路は2つある。片方は申請が要らない。**

```
経路A  Web-API          1社ずつ即時に引ける
                        ★アプリケーションIDの発行に 2週間〜1か月かかる
                        申込 https://www.invoice-kohyo.nta.go.jp/web-api/index.html#cmsprereg
                        入力は 氏名／メールアドレス のみ（3分）

経路B  全件ダウンロード  ★申請が要らない。今日から使える
                        https://www.houjin-bangou.nta.go.jp/download/
                        前月末時点の全件（CSV／XML）＋日別の差分
                        全国分・都道府県別のどちらでも落とせる
```

**2026-08-20 実測** ── 経路Bのダウンロードページはログイン無しで200を返し、
フォームのCSRFトークンも取れた。アプリケーションIDの入力欄は無い。
選択肢（`selDlFileNo`）はJSで動的に入るため、HTMLの静的解析だけでは出てこない。

## なぜこれが要るか

「法人番号の自動取得」を経路Aだけで設計していたため、**アプリケーションIDの申請が
有璽氏の操作待ちとなり、⑤のステップが止まっていた。** 申請は1か月かかるので、
待つ設計にした時点で1か月の停止が確定していた。

**片方の経路しか見ずに「人の操作待ち」と判定していた。**
→ [[feedback_one_route_is_not_verification]] と同じ形。

## 使い分け

| | どちらを使うか |
|---|---|
| 台帳の既存行を埋める（一括） | **経路B**。月1回まとめて落として突合すれば足りる |
| 受付フォームから入った瞬間に埋める | 経路A。即時性が要る |

## ★注意

- 利用規約に**取得元の明示義務**がある。ただし**社外へ公開する画面を作る場合のみ**。
  台帳の中で使う分には関係ない
- 突合して1社に絞れたときだけ確定してよい。
  → [[reference_recover_exponential_corp_number]]（計算で復元してはいけない）
- 法人番号が違えば別法人。統合してはいけない
  → [[project_sales_workbook_read_first]]
