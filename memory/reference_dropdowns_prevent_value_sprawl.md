# 選択肢の列は、プルダウンを付けるまで「決めた」ことにならない

**2026-10-07 実測で分かった型。** 営業案件管理ワークブック 02_個人マスタの「総合ステータス」が
81件に対して★10種の値に増えていた。語を統一する話だと思って3回ほど触っていたが、真因は別だった。

```
🔴真因（実測）
  ① 90_選択肢マスタに★「総合ステータス」の列が存在しない（案件／対応／申請ステータスはある）
  ② 02_個人マスタの総合ステータス列に★データ検証が1行も付いていない（先頭40行で0件）
  → ★自由入力。だから時期ごとに違う語が足されていった
     （「見込み／フォロー」の時期と「①今すぐ検討したい／②数ヶ月以内には」の時期が同居した）
```

- **★値を畳んでも、入口が自由入力のままなら必ず再発する。** 畳む作業と同じ回で検証を付ける
- **★「選択肢マスタに列がある」と「その列を参照する検証が付いている」は別。** 両方を実物で見る
- ★検証の有無は Sheets API の `includeGridData=True` ＋ `fields=...dataValidation...` で数えられる。
  **画面を見た印象で判断しない**（人が見ても、値が入っているセルでは矢印が出ていないと気づきにくい）

## 付けるときの作法

```
範囲      見出しの次の行から器の最終行まで（02は1000行）
参照      90_選択肢マスタの該当列を ONE_OF_RANGE で参照（値をベタ書きしない）
rejectInput  ★false（警告だけ出す）
  true にすると、まだ畳んでいない値や★外部スクリプトの書き込みが弾かれて処理が止まる
showCustomUi true（矢印を出す）
列の追加   ★末尾へ足す。間に挿入すると列番号で参照しているスクリプトが壊れる
```

- ★`update_channel_master` `merge_channel_detail` `applySchemaV3()` は選択肢マスタ・流入経路を
  **旧値へ巻き戻す力がある**ので実行しない → [[reference_hardcoded_option_lists]]
