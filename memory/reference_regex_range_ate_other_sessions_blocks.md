# 正規表現の範囲指定が、他セッションのブロックまで食った

**2026-10-11・WORKING.md を 15,168B → 6,770B にした（進行中10本のうち9本が消えた）。**

かわちばなしの1ブロックだけを差し替えようとして、こう書いた。

```python
m = re.search(r"- \*\*【ビビ / 10/05〜】かわちばなし\*\*.*?(?=\n- \*\*)", s, re.S)
s = s[:m.start()] + new + s[m.end():]
```

**★`- **【ビビ / 10/05〜】` は実物に無かった**（実物は `- **【ビビ / 2026-10-05〜】`）。
`re.search` は None を返すはずだが、`assert m` を書いていたのに**別のブロックに当たって**
`.*?` が次の `\n- **` まで伸び、**他セッションの行を含む8,398Bを飲み込んだ**。

```
★気づけた理由   書いた直後に os.path.getsize() を出していた（6,770B と見えた）
★戻せた理由     直前に commit していた（git show <sha>:WORKING.md で復元）
```

## やること

```
★毎ターン届くMD（WORKING.md・MEMORY.md・Current_Focus）の一部を
  「ここから次の見出しまで」の範囲指定で置換しない
  → 行を特定して Edit で1行ずつ置き換える（old_string が一意でなければ失敗してくれる）

★置換の前後でサイズと「数えられるもの」を必ず出す
  WORKING.md なら進行中の行数（grep -c "^- \*\*【"）。減っていたら事故

★大きく書き換える前に commit する（戻せる状態を先に作る）
```

★`.*?` と `(?=...)` の組み合わせは、**目印が1文字違うだけで範囲が暴走する**。
範囲で消すのではなく、**置き換える対象を一意に特定してから**触る。

## ★2026-10-13 ── 同じ型を、HTMLで、同じ日に2回やった

2日前に上のルールを書いたのに、**対象が WORKING.md ではなく HTML だったので使わなかった。**
JFBI 協力団体の詳細ページ（`~/jfbi-research-site/partners/plusone/index.html`）で：

```
1回目  「ギャラリーを差し替える」つもり → 節ひとつ（APPROACH）ごと消えた
       開始位置から `</div>\n  </div>\n</section>` を探し、別の節の閉じタグに当たった
2回目  「写真1枚を差し替える」つもり → 写真が8枚から2枚になった
       `<figure>…(?:.*\n)*?…closeup…(?:.*\n)*?</figure>` が最初の figure から食い始めた
```

**★このルールは「毎ターン届くMD」に限らない。本文を持つテキスト全部に効く。**
HTML は同じ閉じタグが何度も出るので、開始と終了を別々に探せば必ずどこかで橋が架かる。

```
★差し替えは完全一致の文字列で行う。範囲を正規表現で取らない
★置く前に count == 1 を確かめる。0なら字下げ違い・2以上なら絞れていない
  → count が合わなければ、その場の実物（前後400字）を出して目で見る。推測で広げない
★置いた後に「数」を出す  写真の数／節の見出しの一覧／<div> と </div> の数
```

**★戻せた経路（jfbi-research-site は git リポジトリではない）**

```
curl -s https://<本番URL>/<ページ> -o /tmp/復元.html   # ★本番の配信物が唯一の控え
数えて同じことを確かめてから cp で戻す → 完全一致で1か所だけ置き換え直す
```

★git が無い置き場では、**本番に出ているものが控えである**。だから順序は
「壊してから出す」ではなく、**出す前に数えて、数が合ってから出す**。
