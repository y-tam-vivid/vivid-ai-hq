**Notion に「バックアップから戻す」機能は無い。だが復元経路は作れる。**

```
やり方   書く前に、これから上書きするページの現在値を GET して保存しておく
戻し方   保存した生プロパティを **そのまま** PATCH の body に送る
実測     id / type / annotations などの余剰フィールドが入ったままでも
         Notion API は正しく処理する。★余剰フィールドは無害だった
```

**2026-08-20 実測** ── 検証専用ページを新規に作り、`社内顧客ID` `法人番号` `ホームページ`
`流入経路` `同期メモ` の5項目をわざと壊してから復元。fetch し直して
**5項目とも1文字ずつ完全一致**で戻った。既存の486件には一切触れていない。

## ★「取った」と「戻せる」は別物

この検証をする前、`notion_upsert_snapshot.json` というファイルは**存在していた**。
中身は**台帳の社内顧客ID集合だけ**で、Notion側のプロパティ値を1つも持っていなかった。
＝ **バックアップの顔をした、戻せないファイル。**

```
保存している    ✓ ファイルは在る    → 「バックアップ済み」に見える
戻せる          ✗ 中身が足りない    → 事故が起きて初めて分かる
```

**復元を1度も実行していないバックアップは、バックアップではない。**
規範の「取れているかを確認するまでが復帰経路」はこの形で破れる。

## 検証のやり方（本番を1件も触らずに済む）

```
① 検証専用ページを新規作成      名前に【検証用・削除可】と日付を入れる
② 機械が触る列だけ値を入れる    ★人の列（メモ・協業メモ・強み・課題）は触らない
③ スナップショットを取る
④ わざと壊す
⑤ --restore を実行
⑥ fetch して1文字ずつ突合      ★日本語は化けるので目視でなく機械で突合
⑦ 検証ページをアーカイブ
```
