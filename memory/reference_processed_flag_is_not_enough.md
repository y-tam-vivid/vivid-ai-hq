**取りこぼしを戻すとき、印を消すだけでは足りない。元データがスキャン対象の中にあるかを見る。**

2026-08-18実測（議事録GAS）。承認管理シートから15行を削除したが、処理されたのは11件。
残り4件は `APPROVED`＝**承認時に取得元フォルダから移動済み**で、`checkNewFiles` は
取得元しか見ないため二度と拾われなかった。手で取得元へ戻して初めて処理された。

```
行を消す        「未処理」に戻る
だが            取得元フォルダにいない
結果            行も無い・Notionにも無い・ファイルだけ別の場所にある＝完全な迷子
```

**これは4〜6月の128件にも当てはまる**（全部APPROVED＝移動済み）。行を消しても1件も拾われない。
戻すなら「移動先フォルダを一時的に取得元として登録する」か「GASを介さず直接登録する」。

## 突合の穴（同じ日に3つ踏んだ）

| 踏んだもの | 中身 |
|---|---|
| 却下だけ見ていた | Notionに入らない原因は却下だけではない。**登録エラーでも同じ結果になる**。条件は原因ではなく「結果として入っているか」にする |
| 隔離を知らなかった | 意図的にNotionから消したもの（重複退避・空・機微）は、監査から見ると常に「入っていない」。**隔離フォルダ配下は対象外にする**。でないと隔離するそばから戻す |
| ファイルIDで突合した | 「このファイルは入っていない」は「この会議は入っていない」ではない。同じ会議がnottaとMeetで別ファイルとして存在する |

## 承認カードと退避が競合する

`PENDING` のカードが残ったまま「重複→退避」を押すと、退避でファイルを 02_重複 へ移した後に
**カードを承認すると元の場所へ移し戻され、退避が無かったことになる**（2026-08-18実測）。
退避したら対応するカードも閉じる必要がある。未修正。
