## ★営業ルールの正本は Notion の公開ページへ寄せる（2026-08-23 有璽氏）

有璽氏の方針 ── 「営業にはNotionで共有するのが望ましい。公開ページの形にして、
等しくルールが溜まっている状態を作る。間違っている場合は定例ミーティング等で指摘できるように。
NotionもしくはClaude側で生成した営業ルールのURLを作り、そこを更新していく」。

```
正本      Notion の公開ページ（1本・URLで配る）
ミラー    94_営業の使い方 ／ 受付シート「使い方」タブ
          → ★本文を持たせない。「ルールはこちら → URL」の1行だけにする
指摘の口  定例ミーティング＋ページ内コメント（＝誤りが人から戻ってくる経路）
```

- **★これは「手順書が2つある」問題への回答**（上の節）。どちらを正本にするかが決まった＝
  **シート側は2つとも降格**。片方を選ぶのではなく、両方を入口に落とす形
- **★正本をシートの外へ出せるのは、更新の頻度が違うから。** ルールは月に数回変わる。
  シートは毎日触る。同じ器に置くと、毎日触る側の都合で書き換えられて腐る
- **★URLを配った時点で消せなくなる**（→ [[reference_notion_archive_line]]）。
  公開ページは作り直さず、同じURLを更新し続ける
- **★公開ページは「誰でも閲覧」の共有設定が配下に効く。** 内部数値・顧客名を
  そのページ配下へ置かない（→ [[reference_link_sharing_inherits_everywhere]]）
- 開いた瞬間の着地点の問題（上の節）はこれで解決しない。**シートのどこにURLを置くか**を
  決めるまでは、営業はページに辿り着かない
- **★3枚目を足す形にしない。** Notionを作って94をそのまま残すと二重管理が三重になる。
  **新設と同時に旧2枚を1行へ縮めるまでが1作業**
- **「公開ページ」は Web公開とワークスペース内共有のどちらかを先に決める。**
  営業に届けるだけなら後者で足りる。Web公開が要る理由を確かめる
  （手順書には顧客名・社内顧客IDの実例・シートURL・チャンネル名が入りやすい）
- **鮮度ヘッダー（種別／最終更新／次回棚卸／責任AI）を付ける**（参照層）。
  手順書が実態から腐るのは既に2回実測済み。**更新責任者が空のままなら必ず腐る**
- **「定例で指摘できるように」は、指摘の出口を先に決めないと死ぬ。**
  コメント欄か③決定ログか ── ★指摘 → 反映 → 反映したことの通知 まで1本にする
  （→ [[reference_log_needs_an_exit]]／[[reference_delivered_but_unread]]）

## ★★営業へ渡せない本当の理由 ── 「該当なし」は永久に止まる（2026-08-31 つる発見）

```
実測（ビビも2経路で確認）
  ★該当なし かつ 確認欄が空   6行（34・36・38・39・40・41）── 永久に停止
  候補ありの行                 2行（35・37）── 人が押して進んでいる
  コードの実物                 intake_notify.py:203 が「該当なし」を通知対象から除外
                               intake_register.py は確認欄が空なら一切触らない

★結果 ── 新規のお客さまは、いま台帳に入っていない
   しかも新規は「該当なし」に落ちるので、★件数がいちばん多いケースがこれ
```

**★こちらは手順書に「Slackに何も来ない → そのまま進んでいます」と書いた。事実は逆。**
営業がこれを信じて放置すれば、そのお客さまは一生台帳に入らない。

### 対処の2案（★8/26の経緯を読んでから決めること）

```
案A 実装側   「該当なし」もSlackへ通知する
             ★2026-08-26 に一度この設計だったが「催促の蒸し返し」問題で撤去された経緯がある
               （intake_notify.py の docstring ④⑤）。単純に戻すと同じ事故を再現する
案B 手順書側 「候補がない場合もSlackには来ません。受付シートの確認欄を自分で開いて
             『× 別人（新規でよい）』を選んでください」と書く
             ★だが営業の手数が増える。fukuchi-sales「営業の手数を増やす変更はしない」に触れる
```

**★案Aの再設計が筋。** ただし撤去された経緯を読まずに戻さない。

### ★ここから引く型

**「聞かれない」には2種類ある。** 混ぜて説明すると、片方が永久に止まる。
```
迷わなかったから聞かれない   → そのまま進む
候補が無いから聞かれない     → ★止まる。人が動かないと進まない
```
**手順書に「何も来ない＝進んでいる」と書く前に、「来ない理由」が何通りあるかを数える。**

## ★「統一したらいい」── 有璽氏の指摘（2026-08-27）
