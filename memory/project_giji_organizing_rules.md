議事録の「溜める」自動化は動いている（650件・2025-07-06〜。毎日入る）。
**弱いのは「引き出す」側**＝商談前に相手の過去が出てこない。そのためのルール設計。
経緯は [[project_giji_automation_gas]]、着手は2026-07-14に「現行作業の完了後」として保留され、
2026-08-13に条件が満たされて再開。

## 決まったこと（2026-08-13 有璽氏承認）

### 1. 区分は議事録に持たせない。台帳が持つ

**🏢顧客DB の `種別` は multi-select**（顧客／見込み客／パートナー／仕入先／人材／その他）で、
`取引ステージ`（リード→商談中→受注済→継続取引→停止）も既にある。
**「顧客かつパートナー」は台帳側で既に表現できる。**

→ 議事録側に `相手区分` を新設する案は**却下**。作れば台帳の写しになり必ずズレる
（正本層の事実を手で写さない）。当初この案を出しかけたのは設計の誤り。

### 2. 突合先は区分で絞らない

```
社外の相手  → 🏢顧客DB       顧客もパートナーも仕入先も人材も研究も、全員ここへ当てる
社内の人    → 👤担当者マスター  ★議事録側にrelationを新設する
```

**「顧客の行だけ突合する」は誤り**（有璽氏指摘）。パートナーも研究も突合する。

### 3. 行政・警察・研究者も台帳に入れる（案A採用）

kintone 側にも種別を足して、**相手を1か所に揃える**。相手を2か所に分けると、
結局どちらを見ればよいか分からなくなる。藤井寺市障害福祉担当・羽曳野警察署刑事課は
福祉事業では継続的な相手で、まさに「過去を引き出したい」対象。

> ※ 有璽氏は一度「行政は台帳に入れず議事録だけで管理」と述べた直後に「じゃあAにしましょう」と
> 転換。**最終決定はA（両方とも台帳に入れる）**。

### 4. `相手・会社` は「台帳と同じ表記」にする

**「正式名称」ではない。** 顧客DB 382件は 法人89 / 個人事業主・屋号51 / 区分なし242 で、
**法人は少数派**。「法人の正式名称だけ」にすると、個人名や屋号で登録されている層
（根本小百合・中村真・諸橋薫・`rosée design（冨田まどか）` 等）が構造的に書けなくなる。

```
✗ 敬称をつける            大城様 / 榎本忠彦さん
✗ 相手と自社を併記        エオン(小林)・ビビッド      ← 実際に誤紐付けを生んだ
✗ 複数の相手を1欄に詰める  江辺野・高川・吉良
✗ 法人名と担当者名を混ぜる 株式会社アイライフ（田村有璽）
○ 顧客DBのNameと同一表記   株式会社ノースオブジェクト / 諸橋薫 / rosée design（冨田まどか）
○ 台帳に無ければ空欄       → 登録候補として自動で拾える
```

**「正式名称」は人によって割れるが、「台帳と同じ表記」は機械が判定できる。**

### 5. 指標を変える

**「未紐付を減らす」は指標として誤り。** 未紐付464件の中身は
「社内」333 /「未登録」40 / 有璽氏本人13 / 社内スタッフ10 / 行政4 で、
**議事録の大半はそもそも社外の相手がいない会議**。分母が違う。

→ 正しい指標は **「社外の相手がいる会議のうち、台帳に当たっている割合」**。
