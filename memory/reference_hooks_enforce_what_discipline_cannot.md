**繰り返す理由は「知らないから」ではない。知っているのに適用しないから。**

2026-08-20 の実例 ── `reference_sheets_number_format_order.md` に
「A列がキーとは限らない」と**自分で書いた2時間後**、40_活動ログをA列で数えて
「2行」と誤報告した（実際は25行）。

```
memory     毎ターン届くのは索引1行だけ。本文は関連しそうなときだけ引かれる
           → 作業中に該当する本文が引かれない
規範       毎ターン全文届く。だが量が多く、適用点で気づかない
```

**書くだけでも読むだけでも足りない。** 有璽氏の言葉：
「作業の時に記録してても、作業の時見てなかったら全く意味ないから」（2026-08-20）

## 3つの穴と、それぞれの機械（`~/.claude/settings.json` の hooks）

| 穴 | 機械 | 実体 |
|---|---|---|
| ① 作業の瞬間に思い出さない | **PreToolUse** | `~/.vivid-relay/hook_inject_memory.py` |
| ② 指摘されるまで記録しない | **UserPromptSubmit** | `~/.vivid-relay/hook_catch_correction.py` |
| ③ 誰も棚卸ししない | 毎朝ロビンが前日を読む | `~/.vivid-relay/memory_sweep.py` |
| （付） 承認待ちが本人に見えない | **PermissionRequest** | `~/.vivid-relay/hook_permission_slack.py` |

**①が本体。** Sheets／Notion／cron／削除／Slack を触ろうとした瞬間に、
**その作業で実際に踏んだ地雷だけ**を `additionalContext` で文脈へ割り込ませる。
★一般論は書かない。実際に踏んだものだけ。書くと読まれなくなる。

**②は作り直した。** 最初の版は「怒り」を検出する作りで、
> 「怒った時だけやりますってなっとるやろうが、それが一番おかしいねん」
と指摘された。いまは「新しい事実・制約・やり方が示された合図」を拾う。
**怒っているかどうかは関係ない。**

## ★配布されないことに注意

```
~/.vivid-relay/     git管理外。フックの実体はここ
~/.claude/settings.json  git管理外・機械ローカル（絶対パスを含むため）
```

**他機（MacBook等）には自動で配られない。** 新しい機械では `bin/setup_hooks.sh` を
**1回だけ**実行する（冪等・既にあれば0件登録）。フックを増やしたらここへ追記すること。

### ★「入っている」の判定は4点そろって初めて言える（2026-08-20 実測）

ファイルが置いてあることは、効いていることの証拠にならない。

```
① ~/.vivid-relay/ に *.py が5本      置いただけ
② settings.json に3フックが登録      ここで初めて呼ばれる
③ landmines.json が生成済み          無いと①のPreToolUseが空を撃つ
④ cron 2行（08:20 selfcheck / 08:25 index再生成）  無いと静かに腐る
```

確認は `python3 ~/.vivid-relay/hook_selfcheck.py`（**2026-08-29 以降は「4本とも正常」**）。

| 機械 | 状態（2026-08-20） |
|---|---|
| Mac mini | **①〜④すべて導入済み・selfcheck 正常** |

## ★Stop フックを入れた ── ターンの終わりで捕まえる（2026-08-25）

有璽氏「**途中で止まったりするんだよね、このオペレーションが。確実に回るようにしてほしい**」。
「離席宣言」「区切りで書き戻す」は**どちらもAIの規律に依存**していて、実際に落ちていた。

```
実体    bin/hooks/hook_session_writeback.py（repo）／ ~/.vivid-relay/ へ複製して settings.json の Stop へ登録
条件    memory/ ・WORKING.md ・.claude/ ・bin/ の未コミットのうち
        ★最終更新から10分以上たっているものがあれば exit 2 で差し戻す
        （＝いま書いている最中・他セッションが書いた直後では鳴らない）
無限ループ  stop_hook_active が true なら黙って通す。★差し戻しは1ターンに1回まで
失敗時   フック自身が例外を出しても exit 0。★フックの不具合でセッションを止めない
```

- **実測（2026-08-25）**: ①未コミット2件がある状態 → exit 2 で一覧と手順を返した
  ②`stop_hook_active=true` → exit 0 で黙った。**両方向を確かめてから登録した。**
- **★settings.json は機械ローカル（git外）。** → [[reference_fix_where_git_reaches]]（届かない側は偽陽性を出す）。
  ~~Mac mini には未登録~~ → **✅2026-08-28 実測。両機とも登録済み**（mini は 8/26 に入っていた）。
  実体も正本 `bin/hooks/` とバイト一致。**この記述は10日近く古いまま流通していた。**
- 手順の正本 → [[feedback_write_back_before_you_go]]

## ★「鳴っているか」を人が確かめられないと、鳴っていても消えたと思われる（2026-08-28 実地）

有璽氏 ──「**またなんか10分ぐらいなかったら発火みたいなルールが消えてる気がする**」。

**実測したら、消えていなかった。** 両機に登録あり・実体はバイト一致・20分前のmtimeの未コミットを
置いたら exit 2 で差し戻された。**ルールは完全に生きていた。**

では、なぜ「消えてる気がする」が起きるのか。**観測手段が1つも無かったから。**

```
鳴っても見えない   exit 2 の stderr は Claude にしか返らない。有璽氏の画面には出ない
ログが無い         いつ鳴ったか・何回通したかがどこにも残らない
心拍が無い         ⚙️自動処理レジスタに行が無い＝止まっても🔴が立たない
```

**★これは fukuchi-core「稼働確認は最後にいつ動いたかと次はいつ動くはずかをセットで持つ」の
違反だった。** cron やバッチには心拍を付けていたのに、**フックだけ例外になっていた**。
「常に走っているもの」は在庫が見えないぶん、cron より観測が要る。

- **★対処（2026-08-28 実装・両機へ配布し md5 一致を確認）**：
  `hook_session_writeback.py` に `log()` を足し、**全分岐で1行残す**ようにした。
  出力先 `~/.vivid-relay/hook_writeback.log`（tab区切り・時刻／判定／内訳）。
  判定は「★差し戻した」「通した」の2値。3分岐すべて実測でログ着弾を確認済み。
  **★例外は握りつぶす。ログの失敗でセッションを止めない。**
- **確かめ方（次に同じ質問が来たらこれを出す）** ── `tail ~/.vivid-relay/hook_writeback.log`
- **★残**：⚙️自動処理レジスタへの行と稼働盤への表示は未着手。
  ログは「見に行かないと分からない場所」＝ [[reference_delivered_but_unread]] の型に当たる。
  **ログを足しただけでは、有璽氏側の観測手段としてはまだ弱い。**

**★一般化 ── 「消えてる気がする」は仕様の指摘ではなく、観測の欠落の指摘。**
まず実測で在否を確定させる。そのうえで、**在ったなら「なぜ見えなかったか」を直す**。
「ちゃんと動いてます」と答えて終わらせない ── 次も同じ質問が来る。

## ★検査する側の対象リストがベタ書きだと、増えた分は永久に検査されない（2026-08-29 つる実測）

`hook_selfcheck.py` は毎朝「**3本とも正常**」と出し、心拍も🟢を打っていた。
実測すると `settings.json` に登録されていたフックは **4本**。

```
点検されていた3本   hook_inject_memory ／ hook_catch_correction ／ hook_permission_slack
点検されていなかった1本   ★hook_session_writeback（Stop）
                          ＝規範を機械で止める唯一のゲート（[[reference_norms_outnumber_their_enforcement]]）
```

**いちばん重いものが、いちばん見られていなかった。** settings.json から Stop の行が
消えても、点検は毎朝「3本とも正常」と言い続ける。**監視が壊れているのではなく、
監視の視野の外に置かれていた**（＝ [[feedback_one_route_is_not_verification]] の変種）。

- **直した（実測2ケース）**：`PLAIN_CASES` を新設して Stop フックを実行して応答文字列を見る／
  settings.json の必須イベントに `Stop` を追加／**「3本」のベタ書きをやめ数えた値を出す**。
  ①正常系＝「4本とも正常」exit 0 ②Stop を消した settings.json を隔離して再現＝「異常 2件」。
  `~/.vivid-relay/` と正本 `bin/hooks/` の両方へ入れバイト一致を確認。
- **★型として持ち帰るもの**：**点検スクリプトの対象は、点検される側から数えて突き合わせる。**
  手で並べたリストは、増えた日から静かに古くなる。**本数をベタ書きした出力は必ず嘘になる**
  → [[feedback_never_write_an_unmeasured_number]]・`bin/hooks/hook_output_guard.py` が
  検出しようとしている型そのもの。

## ★配ったが配線していない検問は、一度も鳴らない（2026-08-29 実測）

有璽氏の3度目の指摘（「そもそもビビ自身が実装するのがおかしい」）を受けて
ピタゴラスが `hook_role_guard.py`（役割違反を止める PreToolUse）と `hook_output_guard.py` を新設。

```
実体      ✅ bin/hooks/ にある（git管理下＝両機へ届く）
実体      ✅ ~/.vivid-relay/ にも配られている（MacBook 実測）
配線      ❌ MacBook の ~/.claude/settings.json に登録が無い
結果      ★一度も鳴っていない。ビビの実装コード編集は現に止まっていない
```

- **★「作った」「配った」は「効いている」ではない。** 3段ある ──
  **①実体を書く ②相手機へ配る ③settings.json へ登録する。**
  ③だけが git で配れない（機械ローカル）ので、**必ず最後に取り残される。**
  → [[reference_fix_where_git_reaches]]
- **★検問を新設したら、その場で「鳴ること」を実測する。** 止めたい操作を実際にやってみて
  止まるか見る。**止まらなければ、それは存在しないのと同じ。**
- **★作った本人が検証できない検問がある。** 今回、判定は
  「`agent_id` が無ければメインセッション（ビビ）」だが、**ピタゴラスは自分がメインセッションに
  なれないので実測できない**とコード内に明記していた。
  **この種の宿題は、実測できる側（ビビ／有璽氏）が引き取らないと永久に未検証で残る。**
  → **2026-08-29 ビビが引き取り、実 payload を捕まえて検証した（下記）。**

### ★宿題を引き取って検証した ── 判定は正しい（2026-08-29 ビビ実測）

**副作用ゼロの検証（フックへ直接 payload を流す）**

```
① agent_id 無し ＋ .py 編集    → exit 2 で差し戻し。文面も正しい
② agent_id あり ＋ .py 編集    → exit 0（担当は通る）
③ agent_id 無し ＋ memory 編集 → exit 0（ビビの許可範囲は通る）
```

**実 payload の検証（settings.json へ一時プローブを登録 → 実際に Edit を1回起こす）**

```
メインセッションの PreToolUse payload の実キー
  cwd / effort / hook_event_name / permission_mode / prompt_id /
  session_id / tool_input / tool_name / tool_use_id / transcript_path
★agent_id は存在しない（'agent_id' in payload → False）
```

→ **`agent_id` の有無でメイン／担当を分ける判定は成立する。** 設計は正しかった。

- **★検証の作法**：`settings.json` を**先にバックアップしてから**一時登録し、
  読み終えたら**復元して残数0を確認**する。プローブは `print(json.dumps({}))` ＋ exit 0 で
  何も止めない。**検証のために本番の通り道へ物を置くときは、戻す手順まで含めて1回で書く。**
- **★「作った本人が検証できない」で止めない。** 実測できる側が引き取れば1ターンで終わる。
