# シェルで変数の直後に全角文字を置くと落ちる（`set -u` と組むと実行時に止まる）

**2026-10-07 実測。** 有璽氏が Mac mini の画面で実行したら、2行目で止まった。

```
🔴 出たエラー
   crm_key_check.sh: line 29: SV_SEND?: unbound variable
🔴 書いていたコード
   show "送る用（$SV_SEND）" "$K1"
★真因
   全角の「）」が★変数名の一部として読まれ、`SV_SEND）` という変数を探した
   （macOS標準の bash 3.2 のマルチバイトの扱い）。`set -u` があるのでそこで停止
   ★エラー表示では全角が `?` に落ちて `SV_SEND?` と出る ── これが手がかり
```

## 直し方

```
✗ "送る用（$SV_SEND）"        変数の直後に全角「）」
✅ "送る用（${SV_SEND}）"      ★波括弧で変数名の範囲を閉じる
✅ "送る用 $SV_SEND"          ★全角括弧を使わない
```

- **★日本語のメッセージに変数を埋めるときは必ず `${VAR}`。** 読点「、」中黒「・」全角括弧「（）」
  いずれも同じ型で踏む
- **🔴`bash -n` では検出できない。** `bash -n` は★文法だけを見る。
  `unbound variable` は★実行時に出るので、**「文法OK」は動く証拠にならない**
- ★機械で探せる（恒久の検査）：
  ```
  grep -nE '\$[A-Za-z_][A-Za-z0-9_]*[^A-Za-z0-9_ "'"'"'/:=,.;}$)\[]' <file>
  ```
  ★変数参照の直後が「英数字・アンダースコア・空白・一般的な区切り」以外の行を出す
- ★今回は**SSH越しでは早い段階で `exit` する作りだったため、29行目に到達せず検出できなかった**。
  → **★人に渡すスクリプトは、人の環境で通る行まで自分で通せるか考える。
    通せないなら★静的に検査する**（上の grep を渡す前に必ず走らせる）
