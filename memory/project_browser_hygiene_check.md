ブラウザ（実体はほぼChrome）を軽い状態に保つためのルールと、それを毎週自動で確かめる仕組み。
2026-08-17〜18 に設計・稼働開始。経緯 →
[⑥ディスカッションログ](https://app.notion.com/p/3bf7b1568b57812a9ed2d9399c896bd6)

## 拡張機能は「数」でなく「型」で見る（2026-08-17 実測）

```
[A] 開いた全ページにコードを注入する    タブを開くたび、そのタブに乗る
                                        ★タブ数との掛け算＝唯一の大物
[B] 裏で待機するだけ（注入なし）        ブラウザ全体で1回。MV3は暇なら寝る
[C] アイコンを押した時だけ動く          押すまで何も動かない。実質ゼロ
```

**タブ16枚 × 注入13個 = 208回の注入**が「タブ16枚しかないのに5GB」の正体だった。
[C]型は何個あっても重くならない。**32個あることは問題ではない。13個が[A]なのが問題。**

直し方は削除でも無効化でもなく、拡張ごとの「サイトへのアクセス」を
**すべてのサイト → クリック時のみ／特定サイトのみ**へ変える。機能は残り完全に可逆。
結果 13個→2個（AdBlockは広告をページ読込前に止める必要があるので変えない）。

## ルールを置く場所は3層。上ほど強い

```
① 構造で持つ    プロファイルの数と役割・拡張の配置   守らなくても勝手に守られる
② 既定値で持つ  メモリセーバー・起動時の挙動         判断が発生しない
③ 文章で持つ    ①②で表現できなかったものだけ        増やした瞬間に読まれなくなる
```

規範2-2と同じ構造 ──「読む規律に依存する対策は、規律が切れた回にだけ効かない」。
③に残ったのは3行だけ（同じページを2枚開かない／動画タブは閉じる＝自動解放が効かない唯一の型／
Notion・スプレッドシートを開きっぱなしにしない）。

## 週次チェック

`~/vivid-ai-hq/bin/browser_hygiene.py` ／ 毎週月曜09:30 ／ MacBook の launchd
（`com.vivid.browser-hygiene`）／ ⚙️自動処理レジスタへ心拍。**読むだけ・設定は書き換えない。
起動していないブラウザを起動しない**（AppleScriptは`tell application`した時点で起動するので
先にpgrepで確認する）。

**慢性的な黄色を出さないことが設計の要。** 初版は毎週同じ🟡が7件出る作りで、それは出し続けた
時点で読まれなくなる（信号が死ぬ）。判定を2本立てにした。

```
🔴 閾値を超えた            🟡 先週から変わった
🟢 先週と同じで閾値内       ⚪ 報告のみ（判定しない）
```

- **「常にアクティブにするサイト」を悪と決めつけない。** 業務上わざと入れることがある
  （実際 vivid-global.com に care-all.jp が1件）。増減したときだけ知らせる
- Chromeが自分で入れる部品拡張（ウェブストア決済）は人が消せないので数えない
- **ルールの正本はスクリプトの判定条件そのもの。** 文章側に同じルールを書かない（二重管理）。
  Notion側は結果だけで、器も新設せず⚙️レジスタのメッセージ欄1本に収めた

## 注意

- **cronを使わない。** MacBookの週次cronは寝ていた回を捨てる（Downloads整理が7回中2回・
  29%欠落を実測）。launchdは復帰後に取り戻す
- **ただしTCCに触れる仕事はlaunchdへ移せない** → [[reference_launchd_loses_file_access]]。
  このスクリプトは`~/Library`配下しか読まないので該当しない
- メモリセーバーは有璽氏が既に「最大」にしていた。設定変更の提案は不要だった
