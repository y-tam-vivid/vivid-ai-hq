**有璽氏の問い（2026-08-20）** ── 「営業案件管理を進めることと、それ以外の自動化を分けるべきか。
1つのセッションで両方行えるならそれで問題ない」

## 答え ── 1セッションでよい。分けるのは担当

```
営業案件管理    ★ビビ（窓口）が持つ
                有璽氏の判断が要る場面が多く、往復が発生する
                （どの法人番号を書くか／2行に分けるか／消すか）

自動化の修理    ★担当へ投げる
                ナミ・ロビン・ステラが自分の routine を自分で直す
                ビビは受け取って束ねるだけ
```

**セッションを分けると、かえって悪くなる。** 2026-08-20 に実測した。

- MacBook 側のセッションと**同じ作業を二重に実装**した（実害ゼロだったのは冪等に作ってあったから。
  設計で防いだのではない）→ [[reference_two_sessions_built_the_same_thing]]
- `WORKING.md` の着手宣言を**読み落として**、法人番号の突合を重複して投げた
  → [[reference_delivered_but_unread]]

**1つの窓口が全体を見ているほうが、二重作業を止められる。**
セッションを増やすと、止める役がいなくなる。

## 並列の作り方

```
ビビ（1つ）
  ├→ ナミ      自分の定期処理2本を確かめて直す
  ├→ ロビン    自分の定期処理2本を確かめて直す
  ├→ ステラ    自分の定期処理1本を確かめて直す
  └→ ピタゴラス システム側1本
        ↓ 返ってきたものを つる が検査する（作る役と検査役を分ける）
        ↓ ビビが束ねて、有璽氏には1本で出す
```

- **同時に4体まで投げても回る**（2026-08-20 実測）
- **★同じ git 作業ツリーを複数体が触ると混ざる。**
  `git add -A` を使わず、触ったファイルを明示する → [[reference_git_add_all_swallows_others]]
- **有璽氏へ出すのは1本にまとめる。** 担当ごとにバラバラに報告しない

## ★セッションには「担当する案件」がある。拾ったものは引き継ぐ（2026-09-05 有璽氏）

> 「**ここのセッションでは、スタンドアップのホームページ制作がメイン**なので、
> それは**また別のところに引き継いで**くれたらいいよ。ありがとうございます。助かりますけどね。」

```
起きたこと  サイト制作の会話中に、営業台帳の未回答（8日連続）を見つけた
            → そのまま引き継ぎ書を作り、さらに整合の検査まで走らせた
★有璽氏の線 「助かる」＝成果物は要る。「別のところへ」＝★このセッションでは扱わない
```

- **★見つけたものを、見つけたセッションで最後まで持たない。**
  拾うのは正しい。**抱え込むと、本来の案件（サイト制作）の集中が薄まる。**
- **★引き継ぎの形は3つそろえる** ── ①成果物（PDF等の実物）②置き場
  ③**`WORKING.md` の該当セッションのブロックへ1行**。
  ★会話の中だけに置くと、次のセッションからは存在しないのと同じ
  → [[reference_two_sessions_built_the_same_thing]]。
- **★走行中のものは止めなくてよい。** 出口が Slack になっていれば、
  どのセッションが受けても届く。**止めるより、行き先を書いておく方が安い。**
