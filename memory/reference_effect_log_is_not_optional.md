**2026-10-03 有璽氏の決定**が正本（Core_Brain `00_System/03_作成物の効果記録ルール.md`）。
ここには置き場と、**2026-10-07 に実際に漏れた経緯と対処**だけを書く。

```
ルールの要点（本文は Core_Brain が正本）
  Skill・GAS・スクリプト・アプリ・サイト・Notion DB 等の「仕組み」を★新規作成または★大きく改修したら完了時に記録
    → Notion「AI活用ログ」へ1件    collection://16936917-fd98-42e7-962b-f13820600d22
    → Notion「AI資産台帳」へ登録    https://app.notion.com/p/50f4165ff69345e79a5b9a040764fa1b
  削減時間は有璽氏へ★1問だけ（「以前は1回何分かかっていて、月に何回ありましたか？」）
  答えが得られない → ★「未計測」。0や推測値を入れない
```

## 🔴2026-10-07 漏らした（有璽氏の指摘で気づいた）

営業台帳 02_個人マスタの構造を変え（段階6種へ畳む・検討時期列の新設・プルダウン998セル×2）、
intake_register.py も改修したのに、**効果記録をしなかった。**

- **★真因はトリガーが人（AI）の判定に依存していたこと。** ルールは MOC §1 の35行目で
  **毎ターン届いていた**。届かなかったのではなく、**「台帳の構造を変えた」を「仕組みの改修」と
  判定しなかった**。判定に任せる限り再発する
- **★スプレッドシートの台帳も、プルダウン（データ検証）も「仕組み」である。** コードだけが対象ではない
- 対処：`run_agent.sh` が担当を起動するとき、指示文に「改修／新規／列を足す／構造／プルダウン」等が
  あれば `effect_log_pending.jsonl` へ積み、`hook_session_writeback.py` の★検査5で
  ターン終了時に鳴らす（ピタゴラスが実装・2026-10-07）

## 🔴Notionへの書き込みは経路で可否が違う（2026-10-07 実測）

```
claude.ai の Notion コネクタ（MCP）  AI活用ログ・AI資産台帳とも★読める・ページも作れる
mini の NOTION_TOKEN（Chatworkリレー） ★この2つが見えない（search で22件・どちらも含まれない）
                                      API直叩きは404 object_not_found
                                      （DB-ID／DS-ID／API版 2022-06-28・2025-09-03 の3通りとも）
→ ★自動処理（cron・担当エージェント）からは書けない。★接続を足すのは有璽氏の手
   Notion のDBページ → 右上「…」→「接続」→「Chatworkリレー」を追加
```

- **★MCP の `notion-update-data-source` は、`schema_updates` 形式では効かない。**
  「Updated」と返るが★反映されない（fetch で5つのまま・ページ作成も選択肢エラーで弾かれた＝3経路で確認）。
  **★正しいのは `statements` に SQL DDL**：
  `ALTER COLUMN "種別" SET SELECT('既存1':blue, …, '新しい値':green)`
  ★既存の選択肢を全部書く（options は置換されるため、落とすと既存行の値が壊れる）。
  ★書く前に現在の options を控えへ（`_backups/notion_ai_asset_kind_before_YYYYMMDD.json`）
