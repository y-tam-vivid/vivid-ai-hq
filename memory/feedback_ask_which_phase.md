# 相手の資料に書かれた「完成形」を、いまの要件として扱わない ── フェーズを確かめる

**2026-10-07 実測で分かった型。** 家計台帳連携で、送る手前まで組み立てたあとに前提が崩れた。

```
✗ こちらが置いた前提
   相手の資料「家計台帳はFP・顧客の双方（特に顧客側）が現状を確認し合える状況を作るもの」
   → ★顧客がログインする ＝ ★メールアドレスが必要 ＝ ★連絡先が無いと送れない
   → 「FP側24件はメール0件・電話0件なので送れません」と報告した

✅ 実際（有璽氏 2026-10-07）
   家計台帳は★3段階で広げていく。いまは★第1弾。
     第1弾（いま）★社内で管理する。社内の営業担当等が使う。★テスト運用。顧客へは共有しない
                  → ★先方のメールアドレスは入れない（テスト用のメール等で社内が動く状態を作る）
     第2弾         既存顧客・見込み客へ利用を促す。★担当と顧客を招待して一緒に見る
     第3弾         より広く一般の方が使えるよう公開する
   → ★「顧客がログインする」は★第2弾の話だった。第1弾では★先方のメールを入れてはいけない
   → ★連絡先が無いことは★問題ではなかった。むしろ入れない方が正しい
```

## 何を変えるか

- **★相手の資料にある仕様は「完成形」で書かれていることがある。** いま作るものの要件とは別。
  **★着手の前に「これはどの段階の話か」を確かめる。**「いつからそうするのか」を1問で聞く
- **★「できない理由」を見つけたら、それがどのフェーズの条件かを確かめてから報告する。**
  今回は★止める理由として報告したが、★そもそも条件ではなかった
- ★有璽氏も「それ確かに自分の中でも抜け落ちてました」と言っている＝**双方が気づいていなかった**。
  ★だからこそ**段階を言葉にして置く**（資料の冒頭にフェーズ表を書く）
