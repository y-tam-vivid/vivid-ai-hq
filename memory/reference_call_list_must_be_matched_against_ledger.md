**2026-09-05 有璽氏 ──「そうね、テレアポリストとの整合性も見ないといけないですね。」**

## 何が問題か

```
① 営業台帳 00_企業マスタ      既に接点のある相手（紹介・受付フォーム・SalesBreaker）
② テレアポリスト（外部データ） これから架ける相手（大阪府の指定事業所を機械的に抽出）

★①と②は別々のソースから別々に育っており、突き合わせた記録が無かった
```

**いちばん重い事故は「既存のお客さまへ、新規のつもりで電話してしまう」こと。**
架電は外へ出る操作＝取り返せない。データの汚れと違い、あとから直せない。

## 型として

- **★外部から作ったリストは、架電・送信の前に必ず自社の台帳と突き合わせる。**
  リストを作った時点では「正しいリスト」でも、自社との関係は入っていない。
- **★突合キーは法人番号を第一に。会社名だけで突き合わせない。**
  「株式会社Lily」は国税庁の全件データに全国77件ある。市区町村まで要る。
  → [[reference_fuzzy_match_design]] ／ [[reference_ledger_name_blocks_corp_match]]
- **★「台帳の掃除」の価値は、用途で変わる。**
  眺めるだけなら後回しでよい（2026-08-31 有璽氏の決定）。
  **突合に使うなら、法人番号の空欄は「見逃し」に直結する。**
  同じ汚れでも、掃除する理由が変わったら判断をやり直す。
  → [[reference_ledger_cleanup_triage]]
- **★「架けてはいけない」の判定材料が台帳にあるかを先に確かめる。**
  取引中・断られた・担当が付いている、を区別できる列が無ければ、
  突合しても「重なっている」までしか言えない。
- **★除外は毎回やり直す形にする。**リストへ「済」を書き込む形にすると、
  次のリストで同じ判断をもう一度することになる → [[reference_new_list_splits_judgment]]

## 実測（2026-09-05 つる・読むだけ）

```
台帳 00_企業マスタ 467社 × テレアポリスト 法人単位 3,495行
   重なり 19社  ★法人番号で確実 10社 ／ 判定不能 4社 ／ ★別法人だった 3社（誤検出）
   ★社名だけで当てた9社のうち3社が別法人＝番号が無い行では3分の1が外れる

★重なりの本体は台帳ではなかった
   テレアポリスト × 05_問い合わせ営業リスト(8,046社) = ★3,041社(38%)
   うち SUCCESS 484社＝7月に既にフォームでメッセージが届いている
   ★05はテレアポリストと同じ元データから作られている（list_tags で確認）

🔴 自社が2行載っていた（株式会社ＩＬＩＦＥ／ＬＩＦＥ STAND UP・放デイ）
🔴 「断られた」の記録が台帳4シートで 0件。備考欄は 8,046行中4行しか使われていない
🔴 00_企業マスタ「電話番号_正規化」列は190件中169件で先頭0が落ちている
   ＝★名前が正規化なのに正規化されていない。この列で突合すると電話一致がほぼ全部すり抜ける
```

**★掃除の優先順位が用途で変わった。**法人番号の空欄196件は「眺めるための汚れ」から
「架電を止められない穴」になった。重複21組は突合には効かない（どちらのIDでも既存と判定できる）。

**★人が架ける前に見るべきは21行だけ**（重なり19社＋自社2行）。1本目は手で足りる。
**2本目のリストを作るなら仕組みへ移す** ── 手作業は2回目から破綻する。
