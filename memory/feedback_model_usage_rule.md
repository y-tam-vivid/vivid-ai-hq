Claude/エージェントのモデル使い分けの標準ルール。

- **既定=Sonnet 5**（速い・安い、$3/$15）。日常業務・要約・下書き・調整・定例処理・アプリ量産はSonnetで完遂。
- **難所=Opus 4.8 へ昇格を"提案"**（$5/$25）。契約・複雑な設計/実装・精度が結果を左右する分析など。勝手に切り替えず「Opus 4.8を推奨（理由）」と述べて承認を仰ぐ。
- **Fable 5 は封印、明示指名時のみ**（$10/$50＝Opusの約2倍）。極めて難しい一発勝負・大規模移行・長時間自律のみ提案。
- **過剰も進言**：Opus/Fableで受けた依頼でも「Sonnetで十分」と判断したらダウングレードを提案。

**Why:** Fableは高コストゆえ封印が合理的。Opus 4.8で実力的にも十分。地力はモデル固有で指示では変わらないため、"能動的な推奨"という形で最適配分する。

**How to apply:** 全エージェント(~/.claude/agents/*.md)は `model: sonnet` を既定に持ち、本ルールを本文に明記済み。Fable Style([[feedback_language_japanese]]と同じ~/.claude/output-styles/fable-mode.md)にも「モデル使い分け(能動的推奨)」節あり。正はNotion「🤖 Claude運用ルール（モデル使い分け）」。関連：[[project_agent_naming]]

## ★API 529（過負荷）で落ち続けるなら、モデルを下げる（2026-09-04 実地）

担当2体が **claude-opus-5 で API 529 Overloaded を計6回**受けて落ちた（サーバー側の一時的な混雑）。

```
落ちた回数   リリス 3回 ／ ピタゴラス 3回。★いずれも Opus
判断         残っていた工程＝★スクリーンショットを撮って分割するだけ
             → ★Opus の地力を要さない ＝ Sonnet で足りる
対処         ★Sonnet で新しく起こし、引き継ぎを明示して渡した
```

- **★「同じモデルで再開する」を繰り返さない。** 529 は待てば直るが、
  **待つ間ずっと止まる。** 残り工程が軽いなら**モデルを下げて通す方が早い。**
- **★引き継ぎが書けるかで判断する。** 文脈を失っても指示できる工程なら、新しい担当へ渡せる。
  詰まっている調査・設計の途中なら、渡すと最初からやり直しになる。
- ★このとき**残り工程を1つに絞って渡す**のが要点。
  「続きをやって」では引き継げない。**何を作れば終わりかを書く。**
- ★停止の原因は3種類ある → ①担当の設計 ②窓口の渡し損ね ③**外的要因**。
  ③は直せないので、**落ちても再開できる形**と**モデルを下げる手**が対策になる。
  → [[reference_hooks_enforce_what_discipline_cannot]]（停止を拾う経路は3本）

**★結果（2026-09-04）── Sonnet で通った。**
```
残り工程を1つに絞って渡した   「スクリーンショットを撮って6,500px以下に分割する」
Sonnet が守ったこと           ★既存の部品（lsu_env.py・make_sp_images.py・make_review.py）を
                              流用し、撮影とiframeのロジックを新しく書かなかった
                              ★2経路の確認（配置のsha256／撮影幅21枚をPILで実測突合）
                              ★サーバ停止を2経路で確認
結果                          21枚・6,500px超え0件・幅は21枚とも期待値と一致
```
**★引き継ぎに「守るべき制約」を書いたから、モデルを下げても品質が落ちなかった。**
（既存を探してから書く／2経路で確かめる／サーバを止める、を全部明記した）
**モデルの地力ではなく、渡し方で決まる部分が大きい。**
