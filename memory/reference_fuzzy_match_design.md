**「同じ人・同じ会社かもしれない」を機械に出させる実装は、全部この型で作る。**

営業台帳（受付シート⇄00/01）で 2026-08-27 に実測した内容を、**領域を問わない形**にしたもの。
実例と数字の正本は [[project_sales_workbook_read_first]]（「人名に役職が混ざる」以降の節）。
議事録⇄顧客・kintone⇄Notion・名刺の突合でも同じ穴が開くのでここに置く。

## 1. 「1文字違い」は距離であって、似ているかどうかではない

```
誤結合の実例   「小林直樹」 ⇄ 「小林正樹」   ★別人。無関係の2社
               1文字違いという理由だけで繋がった
正しい範囲     祐/佑・裕/祐 ── ★同じ読みで、人が実際に書き間違えるペアだけ
               直/正 は読みも意味も違う。人は間違えない
```

- **編集距離をそのまま「似ている」に使わない。** 人名は**確認済みの紛らわしいペアの表**で持つ
- 法人名は語が長く、1文字違いの発火自体が稀（台帳466キーで3件）＝制限しなくてよい。
  **★同じ緩さでも、キーの長さで危険度が変わる。** 一律に決めない

## 2. 候補を出す実装ほど、誤りの実例で試す

**正しく繋がる例だけ見ても穴は出ない。** 「繋がってほしい2件」で通しても、
「繋がってはいけない2件」を入れなければ、緩すぎることは永久に分からない。

- 検証セットには **①繋がるべき組 ②繋がってはいけない組（他人の空似）** を必ず両方入れる
- **緩めた直後に雑音を数える。** 受付40行に対して新規発火0件＝緩めすぎていないことの実測。
  「候補が増えていないこと」を数字で言えないなら、その緩和は載せない

## 3. 正規化は「両側」に同じものを通す。元の値は消さない

```
入力側だけ整える   → 台帳側に残った表記と一致しない。直したつもりで何も直っていない
両側に通す         → 一致する
```

- **比較のときだけ外し、元の値は保存する。** 役職・敬称・空白・記号は表示にも証跡にも要る
- 正規化の実装を入口ごとに書き直さない（過去に同じ事故 →
  [[project_sales_workbook_read_first]]「突合ロジックを2箇所で書かない」）
- **外しすぎの実例を数える。** 役職27種を除去したとき、台帳側で誤って削れた行は462件中0件だった

## 4. 台帳側にも人が作った型のゆれが積もっている

**入力の型は1つではない。** 入口を疑う前に、突合先の索引そのものを見る。

```
実例   01_顧客詳細に「藤原 康祐 / Kosuke Fujiwara」形式の和文＋ローマ字併記が 636件中33件
       → 人名索引にこの文字列のまま入り、和文単独の入力と永久に一致しなかった
```

索引を作る側で分解する（併記は両方をキーに入れる）。**入力側の書き方を責めても直らない。**

## 5. キーは複数持つ。1本では必ず落ちる

```
実例   受付37行 「藤原康佑」 ／ 台帳 B-0218 「藤原 康祐」
       人名 ── 一致しない（祐/佑）
       会社名 ── ★一致した。だから候補に出た
```

- 人名・会社名・電話・メールの**どれか1本で拾えれば十分**という設計にする
- **1本のキーを精緻にするより、キーを増やすほうが効く。** 精緻化には上限があるが、
  別のキーは別の理由で落ちるので、重なりにくい

## 6. 出すのは候補まで。確定は人

- 一意でなければ確定しない。**先頭を採らない。機械が「新規」と判定して書かない**
  （fukuchi-core／営業層の既決事項）
- 候補には**どの行と繋がったか（ID）と、何のキーで一致したか**を必ず添える。
  「同じ人かもしれません」だけでは人が判断できない

## 7. ★候補に添えた警告は、次の工程へ渡さないと消える（2026-09-06 実地）

**候補タブに「別法人の可能性がある」と書いてあった。その同じファイルの中で、
次の工程がその警告を無視して確定の印を書いた。**

```
何が起きたか（テレアポリスト・つる検査で発覚）
  1  突合で21法人が当たり、候補タブへ出した
     ★備考に明記されていた ──「法人格が違う（合同会社⇔株式会社）＝別法人の可能性」
                             「当たったキーは会社名だけ。法人番号・電話は一致していない」
  2  有璽氏が「印を付けて残す」と決めた
  3  ★実装は21法人ぜんぶに機械的に印を付けた。備考の警告は読まれなかった
  4  実測：76行中★20行（4法人）が別法人。台帳のB-IDと法人番号が一致しない
     株式会社Lien ⇔ 株式会社Ｌｉｅｎ ⇔ Lien が★3法人で同一視されていた
```

- **★「候補」と書いた紙は、次の人には「一覧」に見える。** 件数（21法人）だけが指示に乗り、
  「うち9件は会社名だけの一致」という但し書きは乗らなかった。
  **★件数で指示を出すと、確度の違いが消える。**
- **★依頼する側の落ち度でもある。** ビビは前の工程の報告で
  「★『会社名だけ』で当たった9件は別法人のことがあります」を**読んでいながら**、
  次の指示文に書かなかった。**読んだことと、渡したことは別。**
- **直し方は、確度をデータに持たせること。** 候補の行に
  **「当たったキー」と「確度」の列**を必ず置き、**次の工程はその列で分岐する**。
  備考の文章にだけ書くと、次の工程は読まない。
- **★警告つきの候補を人へ出すときは、警告のない候補と混ぜて数えない。**
  「21法人」ではなく「確定12法人＋要確認9法人」と数える。
