**2026-10-13 起きたこと**：ふくち。側のさくら（初期ドメイン vivid.sakura.ne.jp・210.224.185.82）に cms.ko-station.org を足すつもりだった。
途中で ko-station.org の DNS を触るため有璽氏が★別の会員IDでドメインコントロールパネルにログイン → そのあと開いたサーバーのコントロールパネルは★その会員のサーバー（初期ドメイン 5en.sakura.ne.jp＝219.94.129.104＝団体のメールの www1094 と同じ）に切り替わっていた。
気づかずに「ドメイン新規追加」を実行し、★団体のサーバーに cms.ko-station.org の項目を作ってしまった（有璽氏が選ばなかった案2の場所）。中身・ファイル・DNS は無し（DNS の cms はふくち。側 210.224.185.82 のまま・apex/MX/www・サイト200 は不変を確認）。
削除は自動操作の裏タブで確実に押せず、隣の行が団体のメールを持つ ko-station.org のため★押し違えの危険が大きい＝止めて有璽氏の手に渡した。

**Why:** 同じブラウザ・同じ URL（secure.sakura.ad.jp/rs/cp/）でも、最後にログインした会員でサーバーが変わる。画面の見た目はほぼ同じ。

**How to apply:**
- さくらのサーバーのコントロールパネルで★書く操作の直前に、ホームの「FTP情報（FTPサーバー・アカウント）」かドメイン一覧の「初期」ドメインを読み、目的のサーバーか確かめる（vivid＝ふくち。側／5en＝団体）。
- 会員IDのログインを挟んだら、サーバー側のセッションは別物になったと扱う。
- 本番のドメイン一覧で削除するときは、隣の行（特にメールを持つドメイン）を押し違えない手段（人の手か、行を特定した確実な操作）で。
