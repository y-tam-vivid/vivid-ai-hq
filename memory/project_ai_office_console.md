## How to apply ── 部品は全部ある。1から作らない

```
見る側（稼働済み）
  https://fukuchi-kadoban.vercel.app  Basic認証・middleware.js
  web/kadoban/api/data.js             Vercel Function（λ api/data・★拡張子なしでマッピング）
  dashboard_{data,projects,build}.py  mini の cron :03/:33 で出し直し
  dashboard_realtime_push.py          Vercel Blob へ数字を push → 画面が30秒ポーリング

★指示側（既に1本通っている＝ここを流用する）
  lsu-editor（2026-09-10・実測8項目合格）
  ブラウザ → Vercel Function → ★Vercel Blob へキュー保存
            → ★mini の editor_apply.py が cron */5 で読む → 実行 → 出し直し
  体感1〜6分で反映。★この形を「CSSを書き換える」から「担当を起動する」に差し替えるだけ

起動側（稼働済み）
  ~/.vivid-relay/run_agent.sh <担当名> <指示文ファイル> [作業ディレクトリ]
  AskUserQuestion封じ／認証確認／切り離し（ssh切断でも死なない）／通信系のみ再試行3回／
  ログ統一／run_agent_launch.log へ1行台帳

判断側（稼働済み）  ask_hub.ask() ── Slackのボタン・台帳・answer_of() で回収
見張り（稼働済み）  stall_watch.py（*/5・無言20分で鳴る）／心拍→⚙️自動処理レジスタ
```

### ★Blob 経路の既知の穴（2026-09-10 実測・そのまま効く）

- **書き込みが `@vercel/blob` SDK の非公開ヘッダーに依存**（`x-vercel-blob-access` 等）。
  公式ドキュメントに無い＝**SDK更新で壊れる可能性**。壊れたら指示が黙って届かなくなる
- **put 直後の get で古い内容が返ることがある**（1秒待って再送する対策済み）
- → **指示コンソールに流用するなら「投げた指示が届いたか」を画面へ返す経路が要る**
  （投げっぱなしにしない。ask_hub と同じ「出した側が台帳を閉じる」型）

## ★未決は1点だけ ── 指示の自由度

技術の不明点はほぼ無い。作るものが根本から変わるのはここ。

| | 何ができる | 代償 |
|---|---|---|
| A ボタンだけ | 決まった処理を起動（台帳を数え直す・稼働盤を出し直す・担当の定型タスク） | 新しい仕事は投げられない |
| B 定型＋入力欄 | 担当を選び、対象を入れて投げる | 入力の検査が要る |
| C 自由文 | 画面に書いた文がそのまま `claude -p` へ | **ブラウザから任意の処理が走る。合言葉1本の内側で** |

**★Cは「ブラウザ＝実行権限」になる。** Basic認証1本しか挟まっていない現状では、
稼働盤のURLと合言葉を知る者が mini 上で何でも動かせる状態と同義。
段階導入（A→B→C）が既定の推奨。

## こちらで既定を決めてよい4点（有璽氏に聞かない）

1. **反応速度** ── まず5分ポーリング（既存 cron を流用）。数秒が要るなら後から常時接続へ
2. **承認の置き場** ── 判断は Slack のボタンのまま（[[project_ask_hub_push_decisions]]）。
   画面にも置くと二重管理になる。画面は「投げる」だけ、「決める」は Slack に寄せる
3. **誰が開くか** ── まず有璽氏のみ（現行の Basic 認証のまま）
4. **失敗の戻り先** ── run_agent.sh のログ ＋ stall_watch ＋ Slack。新しい見張りは作らない
