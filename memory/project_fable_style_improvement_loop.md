Fable Style・各エージェント規範・モデル運用ルールを、実務の学びから継続的に磨く**自己改善ループ**。地力(モデルの賢さ)は上がらないが、作法・指示の質を高めて実務精度・失敗率・手戻りを改善する。自律度=**ハイブリッド**、頻度=**毎週**。関連: [[feedback_model_usage_rule]] / [[project_cxo_build_playbook]] / [[reference_ai_org_chart]]

# なぜ二段構えか（クラウド/ローカルの制約）
- クラウドの定期実行(routine)は**ローカルの `~/.claude` ファイルを編集できない**(Notion等の公式コネクタのみ)。
- ローカルのファイル書き換えは**ローカルのClaude Codeセッションからのみ**。
- → **クラウドが毎週"提案を溜め"、ローカルで"適用"** する二段構え。

# 構成部品
1. **改善ログDB(Notion)**: 収集＋提案＋ステータス管理の一元DB。
   - ページ: https://app.notion.com/p/9f1182e0cef44b00ab48cd1aad318064
   - data source: `collection://92193db0-627f-49ec-8a8e-a22ed3d7bf84`
   - 親: 🤖 Claude運用ルール（モデル使い分け）`3977b156-8b57-8119-99b8-f5aeaa4f7f4f`
   - プロパティ: 改善タイトル/種別(文言調整・構造変更・モデル運用・その他)/対象(Fable Style・共通・各エージェント)/自律区分(自動適用可(軽微)・要承認(構造))/ステータス(未対応・提案済・適用済・却下)/根拠・事例/改善案/適用日/起票
2. **週次レビューroutine(ロビン/CKO・クラウド)**: `trig_01EA44rtTw94gTDFjxM4rC2T`、cron `0 12 * * 0`(日曜21:00 JST)。未対応→提案済に磨き＋自律区分付与、Notion探索で新規の種を最大3件起票。ローカルは触らない。
3. **ローカル適用フロー**: 下記「適用手順」。
4. **changelog**: `~/.claude/output-styles/CHANGELOG.md`(ロールバックの根拠)。

# 収集ルール(種の残し方)
- **ローカルセッションでユーザーが訂正・"こうして"・やり直しを求めたら、その学びを改善ログDBに1行残す**(ステータス=未対応、根拠・事例に具体事例)。これが最高信号の入力。
- クラウド各routineも、繰り返す摩擦に気づいたら同DBへ種を残してよい。

# 適用手順(ローカル・トリガー: 「改善ログを適用して」)
1. 改善ログDBの**ステータス=提案済**を取得。
2. **自律区分=自動適用可(軽微)** → 該当ローカルファイル(fable-mode.md / agents/*.md 等)へ即適用し、CHANGELOGに1行記録、DBのステータスを適用済＋適用日に更新。**事後報告**する(結論先行)。
3. **自律区分=要承認(構造)** → 変更前→変更後の差分を提示して承認を仰ぐ。承認→適用+CHANGELOG+適用済、却下→ステータス=却下。
4. Notionが正。ローカルとの版ズレはClaude側が検知・報告。

# ハイブリッドの線引き
- 自動適用可(軽微): 既存文の言い回し・トーンの微修正、一文の追記程度。
- 要承認(構造): 原則の新設/削除、境界・スコープの定義変更、モデル使い分け基準の変更など**挙動を変えるもの**。迷えば要承認。

# 別トラック(将来): 新モデル採用
- 地力の飛躍は新モデル採用で得る。Anthropicが新Opus/Sonnetを出したら移行提案する(移行の型は claude-api スキルにあり)。必要なら新モデル検知routineを追加。

# ★種の入口が汚れている ── corrections.log の28%は有璽氏の発言ではない（2026-08-25 実測・つる）

`~/.vivid-relay/hook_catch_correction.py` が拾った `corrections.log` は **157行中44行（28%）が
エージェント起動プロンプトそのもの**だった。「あなたは『ビビ』です…」「あなたは『つる』です…」
という**こちらが書いた依頼文**が、「事実が示された／恒久のルール／繰り返しの指摘」として記録されている。

```
狙い    有璽氏が訂正・制約・やり方を足した瞬間を拾う
実際    起動プロンプトに「守ること」「してはいけない」が並ぶので毎回ヒットする
結果    最高信号のはずの入口に、自分の書いた文が3割混ざる
```

- **★フックの判定はキーワードで、話者を見ていない。** 誰が書いたかを条件に入れない限り、
  自作自演を拾い続ける。日別では 08-20 に77行、08-23 に45行 ── 多い日ほどエージェントを
  多く起動した日で、有璽氏の指摘が多かった日ではない。
- **★「種が集まっている」を件数で判断しない。** 中身を数えるまで、集まっているのはノイズかもしれない。
  → [[reference_log_needs_an_exit]]（器を作ったら出口を数える）と対になる話 ── **入口も数える**。
- 直すのは `hook_catch_correction.py` のコード＝ステラ／ピタゴラス領域。つるは指摘まで。
  案：起動プロンプト（`あなたは「◯◯」` を含む・agents/*.md を名指しする）を除外する。

## ★汚染源は2つあった。合計38%（2026-08-29 実測・ロビン）

**8/25 の28%は過小だった。** つるは起動プロンプトだけを数えており、
**もう1つの混入源を見ていない。** 4日後に数え直した結果：

```
corrections.log 全 231行
  54行 (23%)  エージェント起動プロンプト     「あなたは〜です」＝こちらが書いた依頼文
  33行 (14%)  ★自己点検のテスト文字列        「何回も言ってるやろ」
  ────────────────────────
  87行 (38%)  有璽氏の発言ではない
```

**★テスト文字列の出どころは `bin/hooks/hook_selfcheck.py:9`。**
毎朝のフック生存点検が `hook_catch_correction.py` へ
`{"prompt":"何回も言ってるやろ"}` を**実際に流し込んでいる**。フックは正しく反応し、
正しくログへ書く。**検査そのものが、検査対象の器を汚している。**
日別で毎日2回（8/20 の導入日だけ13回）── 規則正しいので本物に見える。

### ★これが実害を出した日 ── 2026-08-28

毎朝のロビン棚卸しへ渡る材料には「**有璽氏の発言（フックが拾ったもの）**」という
見出しが付く。8/28 のその欄は4件。**4件とも有璽氏の発言ではなかった。**

```
08:20:00  何回も言ってるやろ          ← hook_selfcheck.py のテスト文字列
08:30:05  あなたはロビン（CKO）…       ← ロビン自身の起動プロンプト
08:40:01  何回も言ってるやろ          ← 同上（つる起動前の点検）
08:40:06  あなたは「つる」…            ← つるの起動プロンプト
```

**★有璽氏の実発言はゼロ。** それでも欄は埋まっており、しかも
「してはいけないこと／恒久のルール／繰り返しの指摘」という**最も重い分類**が付いている。
拾う側（ロビン）が中身を読まずに件数で判断すれば、**テスト文字列や自分の起動文から
"有璽氏の指示"を捏造した記憶が生まれる**。→ [[feedback_never_write_an_unmeasured_number]]

- **★検査の入力は、検査対象のログへ入れてはいけない。** 入れるなら話者か経路で印を付ける
  （例：`source=selfcheck` を1列足す／テスト時だけ書き込み先を差し替える）。
- **★「フックが拾った」を「有璽氏が言った」と書かない。** 見出しが話者を保証していない。
  拾う側は**必ず本文を読んでから**記録の対象にする。
- **★4日経っても直っていない。** 8/25 に「ステラ／ピタゴラス領域」と投げたまま、
  8/29 も同じ状態（むしろ10行増えた）。指摘に持ち主と期限が無い典型
  → [[reference_a_warning_nobody_owns]]。**次に触る人はこれを直してから種を数えること。**
