## 台帳と実体の突合（2026-08-19 新設）

**心拍とは見る角度が違う。心拍は「載っている処理が動いているか」、これは「そもそも載っているか」。**

```
① 実体にあるが台帳に無い   登録漏れ。誰も見ていない自動処理が動いている
② 台帳にあるが実体に無い   「稼働中」と書いてあるが cron も launchd も持っていない
                        ＝「自動と言っているのに自動になっていない」の正体
```

**②は心拍では絶対に見つからない** ―― 行が無ければ、心拍が来ないことすら分からない。
実際 2026-08-19 に部門名寄せ・重複検知を作ったとき、心拍を打つコードは書いたのに
レジスタの行を作り忘れ、心拍が空振りしていた。**作る側の規律に依存する限り再発する。**

**実体 = `crontab -l` と `~/Library/LaunchAgents/*.plist`。** 自前のもの
（`/.vivid-relay/` `/vivid-ai-hq/` `/bin/`）だけを数え、第三者製（Google更新等）は無視する。
台帳側は「実体」欄からスクリプト名を拾って突合する。

**★自分のマシンの分だけを見る。** 相手機へ ssh すると、閉じている日に検査が働かない
＝**「調べられなかった」が「異常なし」に見える**のが一番危ない。各機が自分を見る。

```
実体      ~/.vivid-relay/automation_inventory_check.py（両機・md5一致）
予定      毎週月曜 09:20（両機の cron）
通知      ズレがある日だけ Slack。読むだけで cron も Notion も変更しない
レジスタ   「台帳と実体の突合（Mac mini）」「同（MacBook）」の2行
初回実測   mini 実体7本⇄台帳7行 ／ MacBook 実体3本⇄台帳3行 ＝ どちらもズレ0
```

**この仕組みは自分自身を検知した。** レジスタに登録した直後、cronに載せる前の状態で
「申告倒れ1件」と出た。載せたら0に戻った。

**検知できないもの**: GAS（トリガー列挙APIが外から無い／GAS内に関数を置けば可能）、
クラウドroutine（列挙APIが存在しない＝外形監視の代理心拍でしか見られない）。

## ★逆向きの食い違い ── 実体は動いているのにレジスタが「無効」（2026-08-20 実測）

これまで見ていたのは「申告倒れ」だった。**逆がある。**

```
申告倒れ    レジスタ「有効✓・成功」  実体が無い     → 動いていないのに気づけない
★逆向き    レジスタ「有効=False」    実体は動いている → **監視されていない**
                                                      止まっても🔴が立たない
```

実測（2026-08-20）

  ★逆向き → **レジスタを実体に合わせる**（実行行は正しい。止めてはいけない）

- **心拍を打つコードを書いたら、レジスタで最終実行が動くところまでを1作業にする。**
  ★実行して、レジスタの値が変わったことを目で確かめる
- **★検査の正規表現は、呼び出しの書き方が変わると静かに外れる。**
  `import as` / ラッパー関数 / 動的呼び出し ── 書き方を1つ増やしたら検査も足す
  → [[reference_reference_audit_false_negative]]

## ★Mac mini の launchd 経路は空だった（2026-08-25 実測・つる）
