**症状**：Zoom・Google・Notion は開くのに、GitHub など多くが開かない。Wi-Fiでも有線でも同じ。
スマホもWi-Fiを切る（＝モバイル回線へ逃がす）と動く。

**実測（2026-10-01・MacBook／ルーター 192.168.0.1）**
- ルーターまで：ping・TCP80 とも通る（LAN内は正常）
- IPv4で外へ：8.8.8.8/1.1.1.1 への ping 0%・`curl -4` 全滅・traceroute は1ホップ目から無応答
- IPv6で外へ：`curl -6 google` 200・IPv6のDNS(ルーター/Google)は正常応答
- → **IPv6を持つサイトだけ開き、IPv4しか無いサイト(github.com 等)が落ちる**
- Wi-Fi(en0)・有線(en5) 両方で同じ ＝ MacBook の問題ではなく**ルーター/回線のIPv4側**
- Tailscale を切っても変化なし（無実を確認済み）。SYNC_STATUS の github 22番タイムアウトも同じ原因

**切り分けコマンド**：`curl -4 -m 8 https://www.google.com` と `curl -6 ...` を並べる。
v6だけ通ればルーター側。

**直し方（人の手）**：ONU→ルーターの順に電源を抜き、1分置いてONU→ルーターの順に入れる。
直らなければ回線事業者のIPv4（IPv4 over IPv6/PPPoE）障害を確認。

**経過（2026-10-01）**：ONU→ルーター再起動では直らず（再起動直後もIPv4全滅・IPv6は200）。
★ルーターの時計が 2024-08-14 のまま（HTTPのDate）＝外の時刻サーバーへIPv4で届いていない傍証。

**機器構成（2026-10-01 写真で確認）**：ONU → NTT ホームゲートウェイ RX-600MI（LAN 192.168.1.1・管理画面あり）
→ TP-Link Archer BE3600（ルーター動作・192.168.0.1）→ 端末。二重ルーター。
★MacBook から IPv4 で 192.168.1.1 まで届く（管理画面 401）＝TP-Link は無実。
**IPv4 が止まっているのは RX-600MI から外（PPPoE 等のプロバイダ接続）**。
見る場所＝ http://192.168.1.1 （ユーザー名 user）→ 状態表示 → 接続状態。

**⛔真因（2026-10-01 13:5x 解決）── 回線ではなかった。上の「ルーター/回線のIPv4断」は誤診**
- 有線(en5)は TP-Link でなく **NTT RX-600MI に直結**していたのに、TP-Link 時代の古い住所
  192.168.0.190（GW 192.168.0.1）を持ち続けていた → IPv4 だけ迷子。IPv6 は NTT の RA で取れていた
- Wi-Fi(en0)側の TP-Link は WAN 未接続（管理画面に「インターネット接続なし」）＝別の理由で IPv4 不可
- 直し：システム設定→ネットワーク→USB LAN→詳細→TCP/IP→**DHCPリースを更新**（管理者権限要・AIからは不可）
  → 192.168.1.8／GW 192.168.1.1 に変わり、IPv4・github・git ssh すべて復旧（実測）
- ★見分け方：`ndp -rn` の IPv6 ルーターのMACと、`ipconfig getpacket en5` の router が**別の機械**なら住所の取り違え
- ★NTT の PPPoE「接続中」を見た時点で回線説を捨てるべきだった。ONU 再起動は不要だった
- ✅Wi-Fi側も復旧（14:1x 実測：en0経由で 8.8.8.8 ping 応答・google 200・NTT管理画面401）。
  TP-Link の青(WAN)ポートには白い平型ケーブルが正しく挿さっていた（写真で確認）。
  ケーブルを挿し直した後、TP-Link が約2分無応答（再起動）→その後つながった＝接触不良か起動待ちだったと推定（原因は1経路のみ）

**注意**：`ssh mini` は Tailscale 経由（mini は同じLANに居ない）。mini が動く＝この網は無関係。

**再発するか（2026-10-01 有璽氏「たまにこういう事象がある」）**
- 最初の故障は TP-Link が外(WAN)を失ったこと（当初 en5 は TP-Link 側=ARPで確認）。有線がNTT直結に
  なっていたのは切り分け中の配線変化。★スマホがWi-Fiを切らないと動かない、の長年の不調と同じ型＝再発しうる
- 構造：NTT RX-600MI(192.168.1.x) と TP-Link(192.168.0.x) の二重ルーター。TP-Link 側が落ちると
  IPv6 だけ残って「一部だけ開く」紛らわしい壊れ方になる
- 再発防止の案：①TP-Link をアクセスポイントモードへ（NTTを唯一のルーターに・網を1つに）
  ②WANの白い平型ケーブルを丸型Cat6へ交換 ③症状が出たら `curl -4`/`-6` で切り分け→DHCPリース更新
- 有璽氏の判断待ち（①②をやるか）
