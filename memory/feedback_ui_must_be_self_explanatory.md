**2026-09-10、同じ日に2回。** 昼：可視化ツール（lsu-inspect.html）で「見方がよくわからない」。
夜：ブラウザ編集ツール（lsu-editor）で「①この1、2、3の使い方がよくわからん」。

```
こちらの対応（昼）   出口ファイルへ説明を書き足した
結果（夜）           ★別のツールで同じ種類の指摘が再発した
```

**Why**：文書（`feedback_write_for_the_reader`）と同じ型が、**触る画面**でも起きている。
文書は「実装名を出さない」で直るが、**画面は文字の説明を足しても直らない**。
画面自体が「何を押せばいいか」を語っていなければ、使う人は説明文を読みに行かない
（読ませる時点で、ツール本体の設計が負けている）。

**How to apply**：

```
✕ 説明を足す     README・出口ファイルに「①こうしてください②ああしてください」と書く
○ 画面を直す     ★開いた瞬間に「次に何をするか」が1つだけ大きく出ている状態にする
```

- **1度に1つだけ指示を出す（ウィザード型）。** 選択肢や入力欄を全部並べない。
  「①ページを選ぶ→②要素を選ぶ→③動かす」のように、**前の手順が終わるまで次が出ない**形にする
- **ラベルは実装の言葉を使わない。** 「セレクタ」「プロパティ」「diff」等の内部用語ではなく、
  日常の言葉に置き換える（例：「要素を選ぶ」→「直したいものをクリック」）
- **ボタン名は出口ファイルの説明文と1文字も違えないこと。** 説明文だけ先に書いて実装と
  ズレると、「読んでもボタンが見当たらない」という新しい迷子を作る
- **判定は自分で画面を撮って見る。** 「初めて開いた人が、次に何をすればいいか3秒で分かるか」
  を自問し、分からなければ画面を直す。説明を足して終わらせない

**同じ型で起きること** ── 社内向けの検証ツール・営業向けの入力フォーム・有璽氏が直接触る
編集画面。**渡す相手が実装を知らない画面すべて**が対象。

## ★2026-09-13 ── 説明文は書いてあった。それでも伝わらなかった

かわちばなしのイベント一覧。「今週末」で絞ると0件なので、
**条件をひとつ外した結果を下に出す**設計になっていた。画面にはこう書いてある。

```
今週末の全4市には、まだイベントの登録がありません
条件をひとつ外した結果を、下にご紹介します。
全4市のイベント（今週末以外もふくむ）  2件
```

**それでも有璽氏には「今週末で絞ったのに10/31が出ている」と見えた。**

**Why:** 説明文は**上にある**が、目は**下のカードへ行く**。
カードには `10.31 SAT` と**他と同じ赤い日付**で出ており、
見た目が「今週末のイベント」とまったく同じだった。
**説明が足りないのではなく、★見た目が説明と食い違っていた。**

**How to apply:** 「例外です」と**文で断る**のでなく、**見た目を変える**。
```
✕ 上に注意文を置く（既にあった）
○ ★カード自体の見た目を変える  日付の色を落とす／「今週末ではありません」を
                              カードの中に置く／背景を薄くする
○ ★そもそも出さない            0件は0件と出し、代わりに「次は◯月◯日です」と案内する
```
**★注意文を足す方向で直さない。**足すほど読まれなくなる。

**★2026-09-14 有璽氏が★Cを実機で触って出した指摘 ── 3つとも「画面が伝えていない」型**

```
①「ためた変更がどんどん積み重なる仕様になっている」
   ★実物：1回ドラッグすると left / right / width / top の★4件が別々に積まれる
   ★有璽氏の言葉「マスキングテープを動かしたやつのログはあくまで一つ」
   ＝★人は「何を動かしたか」で数える。機械は「どのプロパティを書いたか」で数えていた
   → 表示と取消は★ファイル＋セレクタ単位で束ねる。内部の持ち方は変えない

②「サイズ変更とかもこっちではできない」
   ★実物：★できる。ハンドル8個も resize も実装済みで、実際に width:10.41% が積まれていた
   ＝★動く機能が「無い」と思われている。★これは機能の不足でなく★画面の不足
   → 説明文を足すのでなく、つまむ場所と効果が画面で分かる形にする

③「選択のボックスと本体がずれてる。どっちが正しいのって思う」
   ★枠は getBoundingClientRect（外接矩形）で描いている＝★回転した要素では見た目とずれる
   → ★人は「ずれている方が壊れている」と読む。数値が正しくても信用を失う
```

**★「できない」という報告が来たら、まず実装を数える。** 無いのか、在るのに見えないのかで
直す場所がまったく違う。②は★在るのに見えなかった。
