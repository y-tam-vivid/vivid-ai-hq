**記録を溜める器を作ったら、そこから何が出ていくかを数える。出口が無ければ、その記録は形骸化する。**

> 「ログは欲しいよ。あった方がいいと思うけど、これを活用されてなかったらマジで意味がないで。
> 何かには活用しないと。単なる記録やん。記録のための記録やん。……形骸化する」（2026-08-19 有璽氏）

**Why**: ⑥ディスカッションログは全AIが都度書く規範があり毎日増えていた。だが出口を数えたら
**1本しか無かった**（モルガンズ週次→発信ネタ）。しかもそれは対外向けで、書いた本人の実務に戻らない。
「決定の取りこぼしを③へ回収する」経路は実際に1度壊れており、2026-06-21〜07-13 に③への登録が
**1ヶ月半止まって誰も気づかず**、後から手で46件を拾い直した。**止まっても何も壊れないから気づかない。**

**How to apply**:

```
入口を作るとき、同時に出口を書き出す。1本も書けないならその器は作らない
  ⑥ディスカッションログ
    出口1  モルガンズ週次 → AI活用 発信ネタDB      対外発信
    出口2  ロビン週次     → ③決定・論点ログ        決定の取りこぼし回収（2026-08-19新設）
    出口3  ロビン週次     → 規範/memory への昇格候補（★提案のみ。規範変更は要承認）
    検知   ビビ朝ブリーフィング「⑥の最終更新が③より3日以上新しい」
```

- **出口は「人の目に入る場所」へ着地させる。** 見に行かないと分からない場所は届いていないのと同じ
  → [[reference_silent_sync_failure]] と同じ話
- **出口を足すときも器と確認先は増やさない。** 既存DBへ書き、既存の朝ブリーフィングに乗せる
- **溜める側の器が「追記型」なら、拾う側は追記の単位で拾う。**
  ⑥は1ページに `📅 YYYY-MM-DD セッション` を積む構造。ページ単位で重複排除すると
  **1度拾ったページは永久に対象外**になり、中身の濃い長期スレッドほど拾えなくなる（実測13件中1件）
- 出口が動いているかも心拍で見る。**0件でも心拍を打ち、0件の理由を1行書かせる**。
  理由が書けないなら読み込みが足りていない → [[project_automation_register]]

## ★「最終追記日」プロパティは腐る。機械が持つ値を見る（2026-08-20 実測）

⑥の棚卸しで、**プロパティ経由の一覧が「0件」と嘘をつくところだった。**

```
営業案件管理スレッド
  プロパティ「最終追記日」   2026-07-30 のまま止まっていた（人が手で更新する欄）
  登録更新 last_edited_time  2026-08-19 23:33（★機械が持つ値）
```

「最終追記日 >= 直近7日」で絞ると、**このスレッドは一覧に出てこない。**
実際には確定済み未回収の決定を3件も抱えていた。

- **人が手で書くプロパティを、機械の判定条件に使わない。** 書き忘れた瞬間に対象から消える
- **★「0件でした」は、条件が壊れている可能性を先に疑う。**
  棚卸しが空振りしても、エラーは出ない。**静かに何も拾わないだけ**
- Notion なら `last_edited_time`、Drive なら `modifiedTime` ── **機械が必ず更新する値**で絞る
- → [[reference_ran_is_not_succeeded]]（動いたと成功したは別）と同じ family。
  **動いた・条件も通った・だが対象がゼロだった** という3つ目の失敗の形

## ★「こちらでやる」と書いた側が、実際にはやっていない（2026-08-23 実測）

`memory_sweep.py` は毎朝ロビンを呼び、拾った事実を `memory/` へ書かせる。
そのプロンプトの最後にこう書いてあった ── **「commit はしない（こちらで行う）」**。
だが呼び出し側のスクリプトに **`git commit` は1行も無かった**（`git log` を読むだけ）。

```
ロビンが memory を書く   →  未コミットのまま残る
                            vivid-sync.sh の送信対象は「コミット済み」だけ
                            →  MacBook へ永久に届かない ＝ 出口が塞がっている
```

2026-08-22・08-23 と**2日連続で、朝の自己監査が人の手で確定させていた**。
毎朝直しても翌朝また開く ―― **手で直したのは症状で、真因は「出口が実装されていない」こと**。

- **★「◯◯はこちらで行う」と他所へ書いたら、その場でこちら側を grep して実在を確かめる。**
  責任の移譲を文章で書くのはタダなので、書いただけで済ませてしまう。
- **書く処理を作ったら「書いた先が誰に届くか」を最後まで追う。**
  ファイルに書けた＝届いた、ではない。git 配下なら **commit されるまでは届いていない**
  → [[reference_fix_where_git_reaches]] [[reference_silent_sync_failure]]
- **同じ穴が翌日また開いたら、直した場所が間違っている。** 症状の後始末を毎日やっていないか疑う
- 直し方は commit まで自動化し、**失敗しても黙らせない**（黙ると未コミットが静かに積み上がる）。
  `git add` は触った領域だけに絞る → [[reference_git_add_all_swallows_others]]
