**記録を溜める器を作ったら、そこから何が出ていくかを数える。出口が無ければ、その記録は形骸化する。**

> 「ログは欲しいよ。あった方がいいと思うけど、これを活用されてなかったらマジで意味がないで。
> 何かには活用しないと。単なる記録やん。記録のための記録やん。……形骸化する」（2026-08-19 有璽氏）

**Why**: ⑥ディスカッションログは全AIが都度書く規範があり毎日増えていた。だが出口を数えたら
**1本しか無かった**（モルガンズ週次→発信ネタ）。しかもそれは対外向けで、書いた本人の実務に戻らない。
「決定の取りこぼしを③へ回収する」経路は実際に1度壊れており、2026-06-21〜07-13 に③への登録が
**1ヶ月半止まって誰も気づかず**、後から手で46件を拾い直した。**止まっても何も壊れないから気づかない。**

**How to apply**:

```
入口を作るとき、同時に出口を書き出す。1本も書けないならその器は作らない
  ⑥ディスカッションログ
    出口1  モルガンズ週次 → AI活用 発信ネタDB      対外発信
    出口2  ロビン週次     → ③決定・論点ログ        決定の取りこぼし回収（2026-08-19新設）
    出口3  ロビン週次     → 規範/memory への昇格候補（★提案のみ。規範変更は要承認）
    検知   ビビ朝ブリーフィング「⑥の最終更新が③より3日以上新しい」
```

- **出口は「人の目に入る場所」へ着地させる。** 見に行かないと分からない場所は届いていないのと同じ
  → [[reference_silent_sync_failure]] と同じ話
- **出口を足すときも器と確認先は増やさない。** 既存DBへ書き、既存の朝ブリーフィングに乗せる
- **溜める側の器が「追記型」なら、拾う側は追記の単位で拾う。**
  ⑥は1ページに `📅 YYYY-MM-DD セッション` を積む構造。ページ単位で重複排除すると
  **1度拾ったページは永久に対象外**になり、中身の濃い長期スレッドほど拾えなくなる（実測13件中1件）
- 出口が動いているかも心拍で見る。**0件でも心拍を打ち、0件の理由を1行書かせる**。
  理由が書けないなら読み込みが足りていない → [[project_automation_register]]
