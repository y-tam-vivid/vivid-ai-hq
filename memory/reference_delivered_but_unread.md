**★届いていることと、読まれていることは別。**

2026-08-20、`WORKING.md` に「【ビビ着手中】法人番号の一括補完」と書いてあり、
`corp_number_fill.py` が581万件を引き直して**確定4件／要判断79件**まで出ていた。
それでも同じ作業を担当へ投げた。

```
届く仕組み    WORKING.md は CLAUDE.md が @import している ＝ 毎ターン必ず届く
実際          500行を超えていた。着手宣言は52行目にあった
結果          読み落とし、二重に投げた
```

**これは規律の問題ではない。長さの問題。**
memory の「1プロジェクトにつき5〜7項目まで。全部書けば全部届かない」と同じ形が、
WORKING.md でも起きていた。→ [[feedback_reading_list_is_not_a_map]]

## 直し方 ── 届けるのをやめて、その瞬間に必要な行だけ出す

```
これまで   毎ターン全文を届ける          → 長くなるほど読まれない
これから   担当を起動する直前に、
           その作業に関係する行だけ出す  → 4行なら読む
```

`~/.vivid-relay/hook_inject_memory.py` の `already_in_progress()`。
PreToolUse で `Agent` を対象に、依頼文の特徴語で `WORKING.md` を検索し、
**着手宣言・進行中の印がある行**を優先して最大4行を突きつける。

2026-08-20 に**今日の失敗そのものを再現して実測**した。
「法人番号の突合を担当へ投げる」を流すと、着手中の行が先頭に出る。

## 一般化

- **文書を長くして解決しない。** 長い文書は、届いていても読まれない
- **「必ず読む」という対策を採らない。** 読む規律に依存する対策は、規律が切れた回にだけ効かない
- **その瞬間に必要な数行へ絞って、行動の直前に出す。**
  → [[reference_hooks_enforce_what_discipline_cannot]]
- **WORKING.md に履歴を溜めない。** 溜めた瞬間に読まれなくなる（もともとファイル冒頭に
  そう書いてあった。書いてあっても起きた）

**どちらか早い方がボタンを押す。** `slack_socket.py` は実装・接続実測まで完了していた。

**それを翌朝「誰が○を付けるか、案を3つ」と聞き直した。**
WORKING.md の20行上に全部書いてあった。

```
フックの動作   ★正しく鳴っていた
               「【★WORKING.md に同じ話が載っています】」を先頭に出していた（実測で再現）
読んだか       ★読まずに担当へ投げた
```

- **仕組みの穴ではない。出力を無視したのがこちら。**
  ここを「フックを強くする」方向で直そうとすると、また別の出力が増えるだけ
- **★担当へ投げる前に、フックが出した WORKING.md の行を声に出して確認する。**
  出ているのに読まないなら、出す量を増やしても同じ

  有璽氏が最も繰り返し指摘していること（「同じこと何回も繰り返してんねや」）
- 依頼を受けたら、まず **「これは前に決めたか」** を WORKING.md と ③決定ログで確かめる。
  ★担当へ投げるときは「決着済みの部分」を前提として渡し、**そこは調べさせない**
## ★★「記録します」と書いておきながら、その記録を読んでいない（2026-08-31 有璽氏）

> 「**記録しますと書いとんのに、見とらんやんけ、お前、ひどくない？それ。**」

```
実測（同じ日の中で起きた）
  memory に書いてあったこと   「営業手順書の正本は Notion。公開設定で配る」
                             ★2箇所に記録済み（feedback_write_for_the_reader /
                               feedback_one_route_is_not_verification）
  こちらがやったこと          ★読まずに「受付シートの使い方タブを正本に」と提案した

  Notion に既にあったもの     📋 営業へ渡す手順書 ── 書き換え案（2026-08-23）
                             🔧 Slack設定の手順（2026-08-23）
  こちらがやったこと          ★探さずに「新しく作ります」と言った
```

**★記録する行為はしている。記録を読む行為をしていない。**
書けば書くほど「書いた」で満足し、**読む手間だけが増えて、誰も読まなくなる。**

- **★何かを提案する前・新しく作る前に、必ず memory を grep する。**
  「無いから作る」ではなく「**在るかを数えてから**」。
  → 探し方は [[feedback_use_the_team_not_alone]] の「①スキル ②bin/ ③pip ④過去実績 ⑤公式ドキュメント」
    に **⑥memory ⑦Notion** を足す。**7箇所を数えてから「無い」と言う。**
- **★「記録しました」は成果ではない。** 次に読まれて初めて意味がある。
  読まれない記録は、書いていないのと同じ（[[reference_log_needs_an_exit]] の記憶版）。
- ★これで**3回目**。1回目＝決着済みの議論を蒸し返した（8/24）。
  2回目＝正本の場所を決め直そうとした（8/31）。3回目＝既存ページを探さず新規作成を提案（8/31）。
