**Webサイトの制作に入る前に、この1枚を通す。**（2026-10-06 有璽氏「スタンドアップを制作する際に
出戻りが相当あったので、そうならないような形になっているのであれば問題ない」）

**★ここは共通の正本。案件フォルダへ書き写さない**（→ [[reference_design_assets_home]]）。
案件側に書くのは「この案件でどう決めたか」と、下を**通した日付**だけ。

---

## なぜ要るか ── 出戻りの原因は実測で分かっている

```
LIFE STAND UP（2026-09）
  崩れ106件が★3つの型に集約      親は%で縮むのに★子は固定px＝幅が変わると取り残される
  HTMLへ座標の直書き ★88箇所     position:absolute ★402箇所
                                 → ★インラインstyleはCSSから上書きできない（!important以外）
                                 → 幅ごとに打ち消すCSSが「幅の数」だけ増える（7幅）
  ★同型の指摘が5回               9/7「特別な理由がなければ全ページで統一」＝1件ずつ直していた結果
  ★機械の検査0件でも崩れは残った  恒久ルール①②⑥とも0/56件のときに有璽氏が重なりを発見
  ★9/13 決定「作る側に先に渡す」  → ★渡し状は10/6時点で未着手だった（この1枚がそれ）

こどもステーション／かわちばなし（2026-10）
  情報欄のURLがリンクにならない   テンプレの展開のしかた（テキスト展開）を先に見ていなかった
                                 → 公開後にデザイン側へ修正依頼＝丸ごと1往復
  計測が公開後に0だと分かった      かわちばなし（Clarity/GA4/GTMとも0）
  日本語ファイル名で404            Vercel・macOSの濁点分解（NFC化でも解消せず）
```

**★上流で防げば、下流の直し作業そのものが消える。** 以下はすべて「作る前に言う」ための項目。

---

## A デザインを作らせる前に渡す（★崩れを作らせない）

1. **子の位置を固定pxで置かない。** 親に規則を持たせる ── 方向／Gap（すき間）／Padding（内側の余白）／
   Fixed・Hug・Fill（伸び縮み）／Wrap（折り返し）。★子の座標を1つずつ決める作りにしない。
2. **HTMLに座標を直接書かない**（`style="top:80px;left:46%"` を作らせない）。位置はCSSへ。
3. **検査する幅は 375 / 390 / 414 / 768 / 820 / 1366 / 1920**（StatCounter 2026-08 日本の実データ）。
   ★**1440は日本・世界とも上位に1件も無い**＝制作者の慣習値。ここに合わせても実機では効かない。
4. **「特別な理由がなければ全ページで統一」**（2026-09-07 有璽氏・同型5回目）。
   1ページだけ直す依頼が来ても、同じ作りの他ページを数えて一緒に出す。
5. 詳細・来歴 → [[project_web_build_rules_asset]]（恒久ルール①〜⑥と適用範囲）。
   担当は**チョッパー**（`responsive-engineer`）＝業務①がこの渡し状。

## E 案件ごとの「崩さないルール」をどう作るか（★①〜⑥から取り出した原則・2026-10-06）

LIFE STAND UP の恒久ルール①〜⑥は、**中身が全部あの案件の意匠に紐づいた値**だった
（見学ボタン・パンくず・マスキングテープ・60px・40/35/24px）。**★名前だけ持ち出しても効かない。**
持ち出せるのは作り方だけ。**新しい案件では、この5つの形でその案件のルールを作る。**

```
E1 ★はみ出しの基準は「ページの固定物」で決める   LSU＝[見学ボタン]と[パンくず]
                                                 → ★案件ごとに基準物を先に1つ決める
E2 ★対象外の装飾を先に列挙する                   ★「判断がつかない」分類を作らない
                                                 （LSUで作って廃止した。曖昧な分類は判断を増やす）
E3 ★帯ごとの数値は比率で再計算する               1帯で決めて他帯へ★同じ数値を置かない
E4 ★ルールに「適用範囲」の欄を必ず持たせる        全帯か・1帯だけか。
                                                 ★前回の扱いを横展開すると指示違反になる（実際に危うく踏んだ）
E5 ★これらは「位置」しか見ていない                重なり・読めるかは別に見る（→ C・D16）
```

## B 相手が受け取れる形を先に数える（★作ってから制約に気づくのを止める）

6. **Claude Design はクラウドが正本。** ローカルの `.dc.html` を直しても反映されない
   → [[reference_claude_design_local_edit_not_reflected]]。**公開HTMLを直接直すと次の書き出しで消える。**
7. **テンプレの展開のしかたを先に見る。** 例：情報欄が `<sc-for>` ＋ `{{ i.v }}` の★テキスト展開だと、
   URLを入れても**リンクにならない**。ボタンの `href` が固定のこともある（こどもS 10/6 の実例）。
   ★「あとで直せる」と思って設計すると、デザイン側への修正依頼1往復になる。
8. **書き出し形式は3つある。** どれで来るかで取り込み方が変わる。先に確かめる。

## C 公開の前に入れる（★あとからでは取り返せない）

9. **計測は公開前に入れる。** 手順の正本は Skill `web-tracking-setup`。
   台帳 `bin/web_tracking/sites.json` へ**公開前に載せる**（検問が公開直前に止める）。
   ★検索に載り始めた最初の数週間は、あとから測れない。
10. **作業印（【要差替】・黄色い付箋）を公開面から消す仕組みを先に入れる。**
    印だけ消すと「項目名はあるのに値が空」が残るので、★項目ごと落とす処理まで含める。
11. **日本語ファイル名を使わない**（Vercelで404・macOSの濁点分解NFD）。
12. **公開は必ず最新の版番号から。** 古い番号から出すと、後から入れた直し（計測・リンク・告知）が消える。

## D 回し方（★手戻りの量を決めるのはここ）

13. **まず1本・1ページで型を確認してから量産する。** 型が決まる前に複数作ると、作り直しが本数倍になる
    （119番の第1便は5本とも作り直し → [[project_f119_post_standard]]）。
14. **骨組みを先に見せる。** 20本仕上げてから見せると、直しが要れば20本ぶんの手戻り
    → [[feedback_show_the_skeleton_first]]。
15. **「合わせて」「揃えて」は作り直しの許可に読まれる。** 触らない対象を列挙して渡す
    → [[feedback_check_the_archive_first]]。
16. **検査0件は「崩れていない」ではない。** 測っているのが位置なら、重なりは見えていない
    → [[reference_verify_outcome_not_mechanism]]。★人の目で1幅は必ず見る。

---

**How to apply:** Webサイトの制作に入る前（★デザイン側へ最初の指示を出す前）にA〜Dを読み、
A・Bを**指示文に書いて渡す**。案件フォルダの `00_はじめに読む_案件の地図.md` へ
「着手前チェック：通した日（YYYY-MM-DD）」の1行だけ残す（★中身は写さない）。
