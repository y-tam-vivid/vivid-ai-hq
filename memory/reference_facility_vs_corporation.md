**福祉施設の営業では、営業先（施設）と法人番号の持ち主（運営法人）がずれる。**

2026-08-20 の実例 ── `B-0415 体験型 児童発達支援・放課後等デイサービス MIKKE HOUSE`

```
営業先   MIKKE HOUSE（大阪市淀川区東三国4丁目）── 実際に訪ねる相手
法人     株式会社wakoku（東京都渋谷区恵比寿2-28-10）── 法人番号 2011001119280 の持ち主
```

## どちらを台帳に置くか ── 営業が何で探すかで決める

**営業台帳は営業のためのもの。** 営業は施設名で探す。
「MIKKE HOUSE」で引けない台帳は使われない。

```
会社名     施設名のまま
法人番号   運営法人のものを入れる
備考       運営法人名を書く（★これが無いと、法人番号だけ見て別法人と誤認する）
```

## ★ただし「法人番号の重複を許すか」は別の判断

同じ法人が複数施設を運営していれば、**法人番号が複数行に出る**。福祉ではこれが普通。

```
2026-08-20 の実測   00_企業マスタ ── 法人番号269行・ユニーク268・重複1件
                    （その1件も SWELL SOCITY / SOCIETY のタイポ由来）
                    ＝ いまの台帳は「法人番号は一意」という前提で運用されている
```

| 影響する先 | 重複したらどうなるか |
|---|---|
| Notion同期 | **問題なし。** 突合は 社内顧客ID → 法人番号 → 会社名 の順でIDが第一キー（実測済み） |
| kintone | **★未確認。** 記憶では結合キー＝法人番号。重複するとどちらの行に紐づくか決まらない |

- **当面は重複しない**（wakoku の他の施設は台帳に無い）。
  だから **いまの形で進め、同じ法人番号が2行に出た瞬間に検知する**のが実務的
- **恒久の設計は kintone の結合キーを実測してから決める。**
  法人番号のままなら、施設ごとの行は kintone 側と1対1にならない
- → [[reference_kintone_customer_master]] ／ [[project_sales_pipeline_workbook]]

## 一般化

- **「どちらが正しいか」ではなく「誰が何で探すか」で決める。**
  台帳の層ごとに答えが変わる（営業＝施設／請求＝法人）
- **ずれを消そうとしない。ずれを書いておく。**
  施設名の行に運営法人名を併記すれば、両方から辿れる
