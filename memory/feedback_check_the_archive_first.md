**型・フォーマットを「新しく作る」前に、過去の実物を数える。**

## 何が起きたか（2026-08-20）

Manus の発信ラインを個人IGから他アカウントへ広げる作業で、Drive の
`Instagram_Manus MDファイル` に**デザイン正本（MD）があるのは個人IGだけ**と分かった。
そこで「他3アカウントには型が無い」と判断し、Manus に**ゼロから4案を提案させた**。

有璽氏の指摘 ── **「Vividの投稿は過去のアーカイブを確認し、そのデザインフォーマットで作成してください」**

ビビッド法人IGには過去の投稿が積まれていた。
- Notion **「法人Instagram 投稿アーカイブ」DB**（`collection://d28b812e-0b3a-4f2f-8916-cf3c471250c2`）
- Drive **「ビビッドInstagram投稿」**（`1m6Ezw15h7LOBBNWe10xJo8z4H42j_Qp6`）に
  `Instagram投稿031`〜`050`＋`修正版` の番号フォルダ群

**しかも当方は、その Drive フォルダを検索結果で見ていた。** 見たうえで使わなかった。

## なぜ間違えたか

**「正本ファイルが無い」＝「フォーマットが無い」だと読んだ。** これが誤り。

```
正本（MD・ガイドライン）が無い    ＝ 明文化されていないだけ
過去の投稿が積まれている          ＝ ★事実上の正本がある
```

実績が1本でもあれば、それが型。明文化されていないなら**アーカイブから型を起こす**のが順序で、
ゼロから提案させるのは、既にあるブランドを捨てて作り直すのと同じ。

## どうするか

**新しい型を作らせる前に、必ず2つ数える。**

| 数えるもの | 場所 |
|---|---|
| ① その媒体のアーカイブ件数 | Notion「情報発信 コンテンツ管理DB」配下の各投稿アーカイブDB |
| ② 実ファイル（画像・動画）の置き場と件数 | Drive（アカウントごとにフォルダがある） |

```
0件            → 新規に型を作ってよい
1件でもある    → ★まずアーカイブから型を起こす。ゼロから提案させない
                  そのうえで「変える点」だけを提案させる
```

- 提案させるときも「ゼロから4案」ではなく「**現行フォーマットを基準に、変える点の案**」と書く
- 個人IGのように正本MDがあるものは、正本 + アーカイブの両方を見る

## 資料を Manus に渡すときの型（2026-08-20）

```

             完成形の見本（承認済みのものだけ）／禁則／サービス資料（公開可の範囲）
```

## ★案は「どれか1つを選ぶ」ではなく「使い分ける」ことがある（2026-08-20 有璽氏）

複数案を出させたとき、当方は暗黙に「1案を選んで残りは捨てる」前提で進めていた。
有璽氏の判断は違った。

```
福祉施設の119番   「A・B・D 3つとも良い。方向によって使い分け、
                   ルーティンで使っていく等の判断をしてください」
                   → C だけ不採用。3つを併用
tane.             「投稿内容によって提案いただいた4種類を使い分けていけたら」
                   → 4つとも採用
```

**★このとき決定的に重要なこと ── ブランドは1つ、型は複数。**

```
ブランド（ロゴ・配色・書体）   ★全型で共通。ガイド／営業資料が正
型（構成・レイアウト・写真）   ★投稿内容によって選ぶ
```

案を「別々のデザイン提案」のまま採用すると、**同じアカウントが4つの見た目を持つ**ことになり、
読者からは別アカウントに見える。案を採用するときは、
**必ず「1つのブランドの中の型」へ整理し直す。**

そして型を複数持つなら、**「どの型を使うか」の選び方の基準**が要る。
基準が無ければ運用する人が毎回迷い、結局1つしか使われなくなる。
（目標：投稿ネタを前にして5秒で型を選べること）

**運用の設計も、判断を委ねられたら自分で決めて出す。**
119番では「A を主軸に週2・B を週1・D は不定期（ケースがある月だけ）」と決め、
個人IGが月水金なので**曜日をずらして火木土**にした。
★Dのように「素材が無いと嘘になる型」はルーティンに入れない。無理に埋めさせない。

## ★「揃えろ」は危険な指示 ── 何を揃えて何を揃えないかを分けて言う（2026-08-20）

有璽氏個人IGの画像量産で、当方は Manus にこう指示した。

> 「AI-131 の3枚と、**色味・構図・文字の入れ方を揃えてください**（あれが基準です）」

結果、**全部が同じフォーマットの投稿になった。** 有璽氏の指摘 ──
「ガイドラインに入れていたと思うけど、**全く同じフォーマットでなく、動きのある何パターンかの型に
寄せて**作成してください」

**正本には複数の型が定義されていた。当方の「揃えろ」がそれを潰した。**

```
★揃えるもの      ブランド ── 配色・ロゴ・書体・余白・トーン・禁則
                  ここがブレると別アカウントに見える

★揃えないもの    レイアウトの型 ── 構成・図解の形・情報の並べ方・リズム
                  ここが同じだと、並べたとき単調でスクロールが止まらない
```

同じ日（2026-08-20）に 119番・tane. では「ブランドは1つ、型は複数」と正しく指示できていたのに、
個人IGでは「揃えろ」の一言で全部を同じにした。**同じ原則を、指示の言葉が裏切った。**

**指示を書くときのチェック**
- 「揃えて」「合わせて」「同じように」と書いたら、**何をか**を必ず添える
- 量産を頼むときは「**全部を同じ型にしないこと**」を明示する。書かないと同じ型で埋まる
- 正本に型が複数あるなら、**型の一覧を指示文に書き出して「使い分けよ」と言う**
- 出させた後、**並べて見る**（1枚ずつ見ていると単調さに気づけない）

## ★実績を他へ横滑りさせない ── 頻度・リズムはアカウントごとに決める（2026-08-20）

119番の運用を設計するとき、当方はこう決めた。

> 「週3回にしたのは、有璽氏個人IGが月水金で回っているため曜日をずらして分散させる意図です」

有璽氏の訂正 ──
> 「**私個人のアカウントが週3投稿にしているだけで、それ以外のアカウントは投稿頻度はまだ定めていません。**
> 逆にその辺り提案ください」

**個人IGの週3は「個人IGの事情」であって、全アカウントの基準ではなかった。**
当方は唯一observableだった実績を、そのまま他アカウントの前提として横滑りさせた。

```
×  既に回っているアカウントの頻度 → 他もそれに合わせる（曜日だけずらす）
○  ★アカウントごとに、目的・書き手の負荷・読者の接触リズムから決める
    結果として同じ頻度になるのは構わない。理由が「他がそうだから」なのが誤り
```

**頻度を提案するときに要る材料**
- そのアカウントの目的（認知を広げる／信頼を積む／問い合わせにつなげる）
- ネタの供給量（素材が尽きない頻度か。尽きると質が落ちるか休止する）
- 読者の接触リズム（BtoBの経営者は平日、保護者は夜・週末 など）
- **止めても崩れない下限**から始める。増やすのは後からできる

★「他がそうだから」は理由ではない。**理由を書けない頻度は提案しない。**

## ★外部サービスの成果物は「自分が指示した分」だけではない（2026-08-22）

有璽氏の依頼 ──
> 「ここに今、**Claude Codeとやり取りした以外の、以前に作成した投稿画像やリール動画**なども
>   格納しておいてもらえますか？ **マヌス側しかわからないと思うので、マヌス側に聞いてください。**」

当方は Manus の `task.list` で30件を見て「これが全部」と扱っていた。だが実際には、
**Claude Code から接続する前に作られた成果物**が Manus 側に蓄積されている。
API で一覧が取れることと、その中身を全部把握していることは別。

```
自分が指示した分   会話の中に記録がある。回収済み
★それ以前の分     相手のサービス内にある。こちらの記録には無い
                   → 一覧が取れても、添付を回収していなければ「知らない」のと同じ
```

**外部サービス（Manus・claude.ai Project・GAS・Notion）へ作業を出しているとき、
そこには自分の知らない資産がある前提で扱う。**

- 新しい置き場（Drive の正本フォルダなど）を作ったら、
  **「これまでに作ったものを全部そこへ集めてください」と相手へ棚卸しを依頼する**
- 依頼するときは **「全プロジェクト・全期間」** と範囲を明示する。
  「最近の分」では取りこぼす
- 相手の申告は **こちら側で数えられるもの（task.list の件数など）と突合**する。
  申告だけを信じない

## ★「◯◯に合わせて」は作り直しの許可になる（2026-08-23・「揃えろ」型の2回目）

有璽氏
> 「Manus側の画面を見てるけど、**イラストの仕上がりが依頼と全然違う**んだけど、
>   一度確認してくれるかな？」

**当方の指示** ── 「見本は I-03/01 と I-04/05。**全30枚をこれに合わせてください**」
**起きたこと** ── 13本65枚が**全部おなじ人物・おなじポーズ・おなじ背景**になった。

```
直前に釘を刺していたこと   「構図まで2枚に似せないでください。揃えるのは画風だけです」
それでも起きたこと         ★構図が全点で1つに潰れた
                          ★見本にした I-03/01・I-04/05 自体まで作り直された
                          ★レイアウトが組み直され、画像パーツが版面からはみ出した
                          ★前版のサブコピーの残骸「える。」が全枚に残った
                          ★人物なしだった I-06 に人物が入った
                          ★肝心の顔立ちは参照写真に寄っていない
```

**「合わせて」は「作り直してよい」と読まれる。** 禁止を1行添えても効かない。

- **★触ってよい対象を列挙し、触ってはいけない対象も列挙する。**
  「画風だけ」では足りない。**「レイアウト・文字・配置・構図・既存の見本には触らない」**まで書く
- **★いちばん確実なのは差分の言い方。**
  「合わせて」ではなく「**元の版のレイアウトをそのまま使い、人物イラストだけ差し替える**」
- **★見本は「作り直し対象の外」だと明示する。**
  見本を対象に含めると、基準そのものが消える。合格したものは母集団から外す
  → [[feedback_dont_remake_what_was_approved]]
- **1回目は 2026-08-22、「AI-131と色味・構図・文字の入れ方を揃えろ」で正本の4型が全部同じになった。**
  **今回が2回目。**「揃える／合わせる」という語を使うときは、必ず対象を限定する

**★申告と実物は別。** Manus の報告は「2枚見本を共通基準にした」「構図は回ごとに使い分けた」
と満点だった。**比較シートを1枚見れば全点同一だと分かる状態だった。**
