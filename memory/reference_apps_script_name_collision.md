**Apps Script はプロジェクト内の全ファイルが同じグローバルスコープを共有する。**
同名の関数・`var` は「後に読まれたファイル」の定義が勝つ。

```
新版を貼っても、旧版がどこかに残っていれば旧版が勝つ
旧版に無い名前（新版で新設した定数）だけは新版の定義が生き残る
        ↓
   混  在  す  る（エディタの画面では絶対に分からない）
```

2026-08-14〜15 実地。v2を貼って実行したのにv1が動き、切り分けに3往復かかった。
実測すると混在していた ── 共通名は全部v1が勝ち、v2にしかない定数だけv2が生きていた。

## 暴き方 ── `toString()` はランタイムの実体を返す

`関数名.toString()` は、**実行時にその名前へ結び付いている関数の中身そのもの**を返す。
エディタの表示ではなくランタイムを見るので、「見えているコード」と「動くコード」の
ズレが1回の実行で出る。

```javascript
var src = String(addRelationViews_.toString());
src.indexOf('（v2）') >= 0     // 新版にしか無い目印を含むか
src.indexOf('renames') >= 0    // 新版でしか足していない処理を含むか
src.length                     // 関数の長さ
```

**新版には必ず「自分が新版だと名乗る目印」を入れておく。** バージョン定数をログの
冒頭に出すだけでよい。これが無いと実測しようがない。

## 直し方 ── 犯人を探さず、衝突を断つ

旧版の在り処を数往復探して見つからないなら、探索をやめて**識別子を全部改名する**。

```
addRelationViewsDryRun  →  relationFinishDryRun
addRelationViews_       →  relationFinish_
○○_RV（定数・小道具）   →  ○○_RW
```

旧版がどこに残っていても1つもぶつからない。名前空間を分離するコストのほうが、
探し続けるより安い。

**ただし旧版は地雷として残る。** 新版は実行のたびに `typeof 旧関数名 === 'function'` で
生存を検査し、ログ冒頭で警告する。消えるまで気づける状態にしておく。

## 一般化

- **エディタに見えているコードと、実行時に動くコードは別物。** 同名定義を許すプラットフォームでは常に
- **「別ファイルに旧版がある」と推測で断定しない。** 2回断定して2回とも外れた。
