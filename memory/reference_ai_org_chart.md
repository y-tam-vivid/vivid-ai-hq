## ★名鑑は台帳。実体（定義ファイル）との突合が要る（2026-08-20）

```
台帳   🚤 AIエージェント名鑑  collection://ce19f944-22fb-4647-987b-7f93715809df
実体   ~/vivid-ai-hq/.claude/agents/*.md
```

**両者がずれても、エラーは出ない。静かにずれるだけ。**
⚙️自動処理レジスタで「台帳と実体の突合」を作ったのと同じ構造が、名鑑にもある。
→ [[project_automation_register]]

### 見るのは6つ

```
① 名鑑にあるが実体が無い       消えた／改名された／別名で作り直された
② 実体があるが名鑑に無い       ★登録漏れ。次に誰かが「担当がいない」と同じ役を作る
③ 役割の説明が実体とずれている 定義を直したのに名鑑を直していない
④ 参照先が古い                 ファイルパス・Notionのハブ・DB
⑤ 「稼働中」なのに routine / cron が存在しない
⑥ 統括・上下関係が、いまの体制と食い違っている
```

**★②がいちばん高くつく。** 登録されていない役は「無い」ものとして扱われ、
同じ役が二重に作られる。**エージェントを作ったら、名鑑へ登録するまでが1作業。**

### 登録と検査は別の主体で

```
登録   ロビン（CKO・ナレッジ統括）
検査   つる（data-auditor）── 台帳と実体の突合
```

★同じ主体が登録して検査すると、書いたとおりに読むだけになる。

### ★実例 ── 「作ったら名鑑へ登録するまでが1作業」を書いた数分後に、その漏れが出た

2026-08-20、当方（ビビ）がこの原則を memory へ書いた**直後**につるが突合し、
**つる自身（`data-auditor.md`・同日午前に新設）が名鑑に1行も無い**ことが分かった。

```
名鑑 21名（うち予約枠10・実働11） ／ 実体 14本
本物のずれ 3件
  ★つる          名鑑に無い（同日午前に新設した役）
  モルガンズ      ステータスが「定義のみ」。実体は完成定義＋実案件を持つ ── 後退した記述
  開発ライン4名   定義ファイル列が「別タブ管理」のまま。他10名は実パスが入っている
参照先の腐り
  モルガンズの自動化先が「📣発信ネタボード」── 2026-08-19に⛔廃止・統合済み
  ⏰定期自動化一覧ページ（最終更新 2026-07-12）も同じ古い記載のまま
```

**原則を書いても、書いた時点の漏れは自動では埋まらない。** 書いたら**その場で棚卸しを1回**回す。

### ★検査役が「異常なし」と「未確認」を分けた（良い形）

つるは crontab とクラウドroutine の実体を今回見ていないため、
**「異常なし」ではなく「未確認」**と明示して返した。

**「探した範囲では見つからなかった」と「無い」は別物。**
読んでいない範囲を書かない報告は、読んだと誤解される。
