**有璽氏の確認は溜めて1回にする。** 一手ごとに「これでよいですか」を出さない。

2026-08-19、1日で GAS を⑩⑪⑫⑬⑭と5回貼らせ、そのたびに確認を求めた。
**「なるべくこちらのチェックのタイミングをまとめてください。もうめんどくさいから。
自動で基本やるようにやってよ」**（有璽氏）

## やり方

```
可逆なものは全部やり切る   バックアップ → 実行 → 実物で照合 を自分で回す
まとめて1度だけ出す        「ここを見てください」の形で、確認点を並べて渡す
承認が要るのは6項目だけ    外へ出る／お金／正本の削除／規範の変更／人に配る／大きな分岐
```

**「念のため確認」で止めるのは、判断を人に押し返しているだけ。** 戻せる状態を先に作れば、
確認は事後でよい。→ [[feedback_verify_before_declining]]

## ★溜めるのは「確認」であって「報告」ではない（2026-09-03）

**この2つを混同すると、まとめたつもりで有璽氏を暗闇に置く。**

```
確認（承認を求める）  ★溜めて1回。可逆なものは全部やり切ってから並べて出す
報告（進捗を伝える）  ★溜めない。進んだ時点で出す。完了だけ待たない
```

2026-09-03、有璽氏「**また完了、進捗が進んだら教えてください**」。
担当を並列で走らせているときは、**1体が返るたびに出す**（全員の完了を待って1本にしない）。
ただし出し先は1本にまとめる → [[feedback_one_session_split_by_owner]]

**判断の目安**：その一言が有璽氏の手を止めるなら確認（溜める）。止めないなら報告（すぐ出す）。

## 環境は必ず両機に入れる

**ローカルで動くものを入れたら、その場でMac miniにも入れる。** MacBookだけで済ませない。
2026-08-19、clasp をMacBookにだけ入れて有璽氏に指摘された。
mini は**非対話sshで `/usr/local/bin` がPATHに入らない**ので、呼ぶときは毎回通すか絶対パスで書く。

## 人の手が要る作業は、押す場所まで特定してから渡す

「@gijiroku-bot を招待してください」と書いたが、Slackでの表示名は「議事録整理Bot」だった。
**APIのhandleと画面の表示名は違う。** 調べずに渡すと往復が増える。

> 「**現状進捗は随時共有して。**」

**★これは「確認は溜めて1回」と衝突しない。**溜めるのは**確認（判断依頼）**であって、報告ではない。

```
溜める      ★判断を求めるもの ── ボタン1通にまとめて、押せば終わる形で出す
溜めない    ★進捗の報告 ── 走行中でも、区切りが来る前でも出す
```

- **★毎回の応答の冒頭に、いま走っているものの状態を置く。**
  「走行中◯本／終わったもの／待っているもの」を3行で。**聞かれてから出さない。**
- **★「終わってから報告」にしない。**長い作業ほど、途中が見えないと待たされている感覚になる
  → [[reference_offload_long_work_to_mini]]（miniとのやり取りもMacBook側へ出す・ただし整理して）。
- **★生ログを貼らない。**整理して出す（有璽氏の明示・2026-09-05）。

## ★2026-09-07 「遅いね」── 投げるときに、いつ画面に出るかを必ず添える

> 「遅いね。**それぞれの業務がどれぐらいでできるか、どれぐらいで修正版が上がってくるかなど、
> 都度それをこちらに確認で投げてくれ。**」

★有璽氏が「遅い」と感じるのは、**待ち時間の長さではなく、いつ終わるか分からないこと。**
こちらは「投げました」「走行中です」しか言っておらず、**目安を1度も出していなかった。**

**How to apply:** 担当へ投げたら、その場で次の3つを添える。**聞かれてからでは遅い。**
```
① 何をしているか（1行）
② ★いつ終わる見込みか（時刻で。「◯分ほど」ではなく「17:30ごろ」）
③ ★どこを見れば分かるか（URL）
```

**★見込みの根拠＝実測（2026-09-07 のログから・開始→最終更新）**
```
全ページに及ぶもの     50〜65分   全ページの余白統一64分／ヘッダー52分
複数ページの修正       20〜30分   保護者の声5件＋フォーム＋法定開示 25分
1ページ・小さい修正     7〜20分   法定開示PDF差し込み7分／稼働盤18分
出し直し（静的書き出し＋デプロイ）  ＋5〜10分  ★これを足し忘れると必ずずれる
```
★**この表は実測から更新し続ける。**次に投げるときはここを見て時刻を出す。
★★**「出し直し」を必ず足す。** 実装が終わっても、書き出してデプロイするまで画面は変わらない
→ [[feedback_write_for_the_reader]]（有璽氏が開くURLで数えてから「直した」と言う）

### ★同日 追記 ── 見込みを出したのに、その時刻に自分から戻らなかった

有璽氏「**今動いてるんですかね。もう報告の時間は過ぎておりますがね。**」

```
17:08  こちらが「17:25〜17:35に反映」と見込みを出した
17:09  ★担当は完了していた（1分後）。こちらは気づいていない
17:41  有璽氏に指摘されて初めてログを見た  ← ★32分、誰も何も見ていない
```
**★見込みを出すことと、その時刻に戻ることは別。** 出しっぱなしにすると、
かえって「言った時刻に来ない」という不信を作る。

**How to apply:** 見込み時刻を出したら、**その時刻に自分から実物を取得して報告する。**
担当の完了報告を待たない（★ログにしか出ないので、見に行かない限り気づかない）。
```
◎ 見込み時刻に ①走行中か ②人に渡すURLを取得して数える ③結果を出す
✕ 「終わったら報告します」で放置する（★誰も鳴らしてくれない）
```
★★**担当の「反映を確認済み」を根拠にしない。** 2026-09-07、担当は
「crawl_static→deploy→alias まで実施し反映を確認」と報告したが、
**実物の /news/ は4枚のままだった**（担当が見たのは /legal-disclosure/ だけ）。
→ [[feedback_check_the_archive_first]]（消す対象が何か所あるかを先に数える）
