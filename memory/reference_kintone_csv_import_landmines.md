kintoneへCSVを取り込むときの地雷。**5件で試して通ったものが300件で落ちる**を3回繰り返した。原因は毎回「サンプルが全体を代表していない」。**送る前に全項目の形を型ごとに全件数える。**

**① 更新キーは「3. 読み込み時の処理の指定」で指定する。**「4. データの対応付け」だけでは更新にならず、全件が新規追加される。

**② 更新キーにできるのは重複禁止フィールドかレコード番号。** 自動採番のカスタマーIDは重複禁止が効いていないことがあり、**静かに新規レコードが作られる**（同じカスタマーIDのレコードが2件共存する）。アプリ設定は変更後に「アプリを更新」を押すまで反映されない。**レコード番号なら設定に依存せず一意が保証される。**

**③ CSVに列が無い項目は触らないが、列があって値が空だと空で上書きする。** 更新CSVは「キー＋更新したい項目だけ」にする。全項目を並べるとkintone側にしか無い値を潰す。

**④ フィールド型ごとの送り方**（型は取り込むまで分からない。5件で試す）

```plain text
ユーザー選択   ログイン名で送る。氏名の文字列では入らず空になる
日付          yyyy-MM-dd。文字列のままだと GAIA_IL17 で行ごと落ちる
数値          整数。文字列を送るとその値だけ空になる（行は落ちない）
チェックボックス 1 または空。Sheetsの FALSE は空に変換する
選択肢        初期値が設定されていることがある（空で送っても値が入る）
```

**⑤ エクスポートの文字コードは UTF-8 を選ぶ。** 既定の Shift_JIS では `髙` `﨑` `É` `〜` `−` が `?` に化ける。**kintone内のデータは無傷で、書き出しで落ちるだけ。**化けた状態で突合すると大量の偽の「食い違い」が出る。

**⑥ 「エラー行のみスキップ」を選ばない。** 一部だけ入った状態になり、次の実行で重複エラーになる。

**⑦ サブテーブルがあると列名が重複する。** 顧客管理では 部署/支店・郵便番号・住所・電話番号・FAX番号 が本体とサブテーブルの両方にある。列名で引く設計と両立しないので、**取込CSVにはサブテーブル列を出さず、取り込み画面でも割り当てない。**

**⑧ 入力欄の説明文が値として保存されていることがある。**「フリガナ」「法人名または屋号を入力」「同業他社に負けない事など」「自社の売上ベスト5」。プレースホルダではなく実値なので、突合や比較に紛れ込む。

**⑨ 取り込んだら必ず突合をやり直す。** 前回の反映を手元に教えないまま次の新規CSVを流すと、同じ会社をもう一度作る。
