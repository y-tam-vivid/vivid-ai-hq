## 決まったこと

### 入口 ── 名刺も受付フォームと同じ形にする

```
受付フォーム   ──▶ 受付シート ──▶ 照合 ──▶ ★人が○× ──▶ 台帳
名刺（Drive）  ──▶ ★同じ形へ揃える  照合 ──▶ ★人が○× ──▶ 台帳
```

**★入口が違っても、照合と人の確認は同じ形を通す。** 名刺だけ別の道を作らない。

### 議事録の昇格 ── 有璽氏と社員で分ける

```
有璽氏の🔒個人議事録   本人が「全社へ共有」にチェック → 🌐全社議事録DBへ自動昇格
                       ★いまも手動のまま。仕組みが固まるまで保留しているだけ
                       ★昇格ルールをAIが理解して自動判定できるなら、それが最大限望ましい
社員の議事録           ★AI側で重複・機微をチェックしたうえで自動で全社DBへ格納し、
                       タスクも振り分ける
```

### ★逆向きを辿れるようにする（設計する）

**営業が「この会社と過去に何を話したか」を1クリックで見る経路が要る。**
いまは顧客DBの「関連議事録」が🌐全社議事録DBを指しており、🔒個人議事録DBとは非連動。

**論点①の決定 ── 「全社へ昇格したものだけ営業に見せる」。**

## ★2026-08-22 追加で決まったこと

### 架電のフローは使う ── ただしリストを増やさない方向で設計中

有璽氏の指摘 ── **「問い合わせフォームとテレアポリストは同じものになる可能性が高い」**

```
実測でわかっている性質の違い
   05_問い合わせ営業リスト  ★SalesBreakerが持つ事実のミラー（送信・クリック追跡）
                            毎朝上書きされる ＝ 人が書いても消える
                            → これは「リスト」ではなく機械が持つ記録
   06_テレアポリスト        人が使う作業リスト。★実データ0件・運用に載っていない
```

**★対象の会社は重なるが、役割が違う。** 05は機械のもの、06は人のもの。

**★決まった形（2026-08-22 検証を経て確定）── 既存2枚で完結。リストを増やさない**
```
今日どこへ電話するか   ★08_関係フォロー ／ 09_進捗MTG⑤（反応スコア順が既に出ている）
架電の結果             ★40_活動ログ へ TEL種別で書く（種別は既にある）
06_テレアポリスト       ★⛔にする（消さない。A1へ降格注記）
★08へ電話番号列（00参照の数式）を1本足せば 5手 → 4手
理由                   ★リストを増やすと「どっちに書くんだっけ」が必ず起きる
                       2026-08-22 に 40 へ書く経路が2本あって重複記入の危険が出たばかり
```

**★有璽氏の案「別リストを設け、一定ステータスになったものを反映」は、
既に一度実行されて死んでいた**（それが 06_テレアポリスト・実データ0件）。
型 → [[reference_new_list_splits_judgment]]（「反映」を挟むと判断が2箇所に増える）
