**2026-08-22、有璽氏が全論点へ回答した。** ここは決まったことだけを置く。
経緯と図は Notion 🔗議事録DB×顧客DB連携フロー `3b27b1568b578184902ffd4324882ed5` の0章。

## 決まったこと

### 入口 ── 名刺も受付フォームと同じ形にする

```
受付フォーム   ──▶ 受付シート ──▶ 照合 ──▶ ★人が○× ──▶ 台帳
名刺（Drive）  ──▶ ★同じ形へ揃える  照合 ──▶ ★人が○× ──▶ 台帳
```

**★入口が違っても、照合と人の確認は同じ形を通す。** 名刺だけ別の道を作らない。

### 議事録の昇格 ── 有璽氏と社員で分ける

```
有璽氏の🔒個人議事録   本人が「全社へ共有」にチェック → 🌐全社議事録DBへ自動昇格
                       ★いまも手動のまま。仕組みが固まるまで保留しているだけ
                       ★昇格ルールをAIが理解して自動判定できるなら、それが最大限望ましい
社員の議事録           ★AI側で重複・機微をチェックしたうえで自動で全社DBへ格納し、
                       タスクも振り分ける
```

### ★逆向きを辿れるようにする（設計する）

**営業が「この会社と過去に何を話したか」を1クリックで見る経路が要る。**
いまは顧客DBの「関連議事録」が🌐全社議事録DBを指しており、🔒個人議事録DBとは非連動。

**論点①の決定 ── 「全社へ昇格したものだけ営業に見せる」。**

### 「対象外」は人が判断する

```
いま   AIが自動で対象外に振り分けている（445件）。★見込み客が混ざっていた
決定   ★対象外の判別は人間側が確認する。**対象外とする根拠・理由が要る**
希望   有璽氏がNotionで判断したい。★議事録の格納をSlackへ通知しているので、
       そこへ足せないか（★実現できるか未確認）
```

### 受付の○×は各営業担当が日次で確認する

```
決定   各営業担当が日次で確認し、○×を付ける
       ★早いタイミング（翌日・翌々日）なら記憶が鮮明なうちに入力できる
       理由 ── 有璽氏には全てを判断する材料が無い
未定   ★営業側へ○×を共有するやり方が定まっていない。ここを決める必要がある
```

### 論点②の決定 ── 結合キーは社内顧客IDへ寄せる

```
決定   kintone の結合キーは ★社内顧客ID へ寄せる
★注意 法人番号が不要という意味ではない。
       **スプレッドシートの顧客管理に登録するタイミングで、法人番号は自動で収集する**
```

### 論点④ ── 案件化のルールを設ける

```
決定   案件化するルールが要る
★懸念 案件にならなくても、関わりのある企業が案件シートに載る可能性がある
       そのとき **後追いできない・登録しづらい状況になるのは望ましくない**
```

### 論点⑤ ── 鈴木・柴田は営業ではない

```
実態   2人は営業側の人間ではない。いまフォームを使うことはない
今後   顧客との接点が発生する可能性はある（営業ではなくフォローアップで）
```
