**★`git add -A` は、いま自分が変えたものだけを拾わない。作業ツリー全部を拾う。**

2026-08-20、mini 上で **ビビ本体＋サブエージェント3〜4体が同時に `~/vivid-ai-hq/` を編集**していた。
その状態で `git add -A && git commit` を繰り返した結果、
**他のエージェントが書きかけのファイルが、無関係なコミットメッセージで入った**（実測2回）。

```
起きたこと   内容そのものは壊れていない
             だが「どのコミットが何をしたか」が混線する
なぜ困るか   あとで戻すとき、1コミットに複数の作業が混ざっていると切り離せない
             ★不具合の原因を git log から追えなくなる
```

## どうするか

```
書くとき     git add <触ったファイルを明示>    ★-A を既定にしない
             複数体が走っている間はとくに
確かめる     git status --short で、自分が触っていないものが混じっていないかを見る
それでも     完全な分離はできない（同じ作業ツリーを共有しているため）
             ＝ **混ざる前提で、コミットメッセージに何をしたかを具体的に書く**
```

**★サブエージェントに commit させない。** 束ねる側（ビビ）が、
何をしたかを把握したうえで、触ったファイルを明示して commit する。

## 併発しやすい状況

- 1つのセッションから `Agent` を3体以上、並列で起動しているとき
- そのうち複数が `~/vivid-ai-hq/` 配下（memory・bin・.claude）を書くとき
- ★`~/.vivid-relay/` は git 管理外なので、この問題は起きない
  （代わりに他機へ配られないという別の問題がある → [[reference_hooks_enforce_what_discipline_cannot]]）

## 🔴2026-09-24 再発 ── ★SYNC_STATUS.md が「宣言なしで触られている」と名指ししていたのに巻き込んだ

JFBI の記録を commit するとき、手癖で `git add -A` を打った。

```
巻き込んだ   .claude/skills/synced/  254ファイル（★他の誰かが置いた未追跡ファイル）
自分の変更    6ファイル
commit        275ファイル入り ── ★1つのコミットの97%が他人のもの
```

**★このセッションは、その存在を毎ターン知らされていた。**
`~/.claude/SYNC_STATUS.md` は @import されて毎ターン届いており、そこに

```
## いま手がついているもの（機械が git から書き出した実態）
  ?? .claude/skills/synced/
```

と**名指しで出ていた**。「着手宣言の無いものがここにあれば誰かが宣言せずに触っている」という
説明つきで。**読んでいたのに、コミットの瞬間にそれと結びつかなかった。**
→ [[reference_delivered_but_unread]]（届いていても、使う瞬間に引けなければ届いていない）

**戻した**（未pushだったので間に合った）：

```
git reset --soft HEAD~1     コミットだけ取り消す。作業ツリーは無傷
git reset                   ステージを全部外す（★syncedは ?? へ戻る）
git add <自分の6本を名指し>
git diff --cached --name-status   ★A（新規）と件数を目で見る
```

**★`git add -A` を打つ前ではなく、打てないようにする。**
このリポジトリでは **常に名指し add** にする。ディレクトリ指定すら危ない
（2026-09-14 チョッパーは `git add <ディレクトリ>` でテーマ本体95KBの複製を巻き込みかけた）。

**★コミットの前に必ず1行**：`git diff --cached --name-only | wc -l` で件数を見る。
自分が触った数と合わなければ、そこで止まる。今回は 6 のはずが 275 だった。

## ★2026-09-24 後日談 ── 巻き込んだコミットが★別系統で push され、同期を1日止めた

同じ日の夕方、`SYNC_STATUS.md` が **🔴「未取込1件・自動マージが衝突して中止」** を出した。
中身を開いたら、**こちらが `git reset` で外したはずの 254件が付いたまま、
同じコミットメッセージで origin に載っていた。**

```
origin ffa59ec  「JFBI 協力団体をメンバーと同じ並びへ…」＋ .claude/skills/synced/ 254件
local  c7c3e35  「同じメッセージ」            ★JFBI の5ファイルだけ
実測            5ファイルとも★中身がハッシュ一致 ＝ 同じ変更が2系統に入っていた
```

**★`git reset` は手元を戻すだけ。別の面（cron の自動確定・別セッション）が
同じ作業ツリーを見ていれば、外したものがそちらから出ていく。**
巻き込みは「消したから終わり」にならない。

**解き方（実測で通した手順）**

```
① git merge-tree --write-tree origin/main HEAD    ★先に衝突の有無だけ測る（何も変えない）
② 両方の中身をハッシュで突合 → 同じなら情報は落ちないと確定してから解く
③ ローカルの未追跡ファイルは rm でなく ★mv で控えへ（消さない）
④ git merge → 衝突は ours（先へ進んでいる側）→ git add → commit
⑤ ★実測 ── 行数・追跡件数・控えとのハッシュ一致・behind 0 の4つ
```

**★「衝突したから人を待つ」の前に、2つの中身が同じかを測る。**
同じなら衝突は見かけだけで、失うものは無い。測らずに待つと、その間ずっと
全セッションが古い WORKING.md / MEMORY.md を最新だと思って答え続ける。

## 🔴2026-09-26 棚卸し（ロビン）── 巻き込んだものが★追跡されたまま残り、毎日「変更あり」を出し続けている

9/24 に解いたあとも `.claude/skills/synced/` は★git の追跡下に残った。
中身は claude.ai のスキル同期が置くもので、**`manifest.json` を毎朝08:30に書き換える**。

```
実測  lastUpdated  09-25 08:30:05 → 09-26 08:30:05（★ちょうど24時間おき・date -r で換算）
      変わるのは lastUpdated と source(custom→plugin) 等 ＝ 人の作業ではない
影響  自動確定が 9/25 だけで★3回拾った（47f7691 / 8a72074 / 8896867）
      書き戻しの検問が 9/25 に★4回「差し戻した」（hook_writeback.log）
      9/26 朝も M のまま ＝ 毎日1件、誰の作業でもない未コミットが出続ける
```

**★害は「うるさい」だけではない。** 検問と自動確定が毎日これを拾うと、
本物の書き忘れが同じ行に埋もれる（[[reference_delivered_but_unread]] と同型）。

**★直し方は判断が要る（ロビンは触っていない）**：
①`.gitignore` へ入れて `git rm --cached`（両機から追跡を外す）
②残して検問・自動確定の対象から除外
どちらもリポジトリの構成を変えるので、ステラ／ビビ経由で決める。
