## 未対応の持ち越しリマインド=継承方式＋週次点検(2026-07-06 設計確定)
毎日7日全スキャンは重いので**継承方式**を採用(ユーザー提案)。「### 未対応・持ち越し」セクションで運用。
- **持ち越しの記憶=親ページ自体**: 毎朝②で親ページを上書きする前にfetchすると、それが前日ブリーフィング。その「### 未対応・持ち越し」と未完了「### 今日の要対応事項」を持ち越し候補として取得(新DB不要)。
- **毎朝**: (A)継承=前日候補の各件を狙い撃ちで解決確認(該当メール/Slackに自分が返信したか・該当Chatworkタスク完了か)→解決済みは落とし、未解決は経過日数+1で持ち越し。(B)新規=直近24hの新着から未対応追加。
- **月曜のみ**: (C)過去7日の深掘り棚卸しで漏れを拾う(抜け漏れ防止)。
- 各件に「○日未対応(初回検知 M/D)」。各媒体10件上限。**完了は自然に外れ、未対応は毎朝再掲=再リマインド**。
- より厳密な"意図的保留案件"管理は Phase 1 タスクDB(Notion構造確定後)で。解決判定は近似(未読/スレッド最新が相手)に留意。検証は 7/7 朝(継承の初回)、週次点検は次の月曜。
