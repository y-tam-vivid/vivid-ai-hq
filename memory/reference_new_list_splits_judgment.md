**★「反映」を挟むと、同じ判断が2箇所に増える。繋いでいるように見えて、分岐を作る。**

2026-08-22、有璽氏から案が出た ──
> 「別でリストを設け、**一定ステータスになったものをどちらに反映させる**方が
>   ファイルとしてはうまくないかと思うが、どうだろう。」

**★それが `06_テレアポリスト` だった。** 既に一度作られ、一度も使われずに死んでいた。

## 実測（2026-08-22）

```
06_テレアポリスト   器1000行×12列。列構成は 電話番号・架電担当・架電日・ステータス
                    ＝★架電管理そのもの。まさに今ほしいと言われた形
                    ★実データ0件。1回も使われていない
                    A1に旧称（05_テレアポリスト）の説明文が残ったまま
                    94_営業の使い方 にも 95_運用ルール にも記述が無い
```

**箱があること・列が正しいことは、運用に載っている証拠にならない。**

## なぜ死んだか（同じ形で必ず死ぬ）

```
05 → 08 は既に自動で反映されている（毎朝・反応スコア付き）
08 の「段階」列が既に「誰に架電すべきか」の判定軸を持っている
      ↓
08 → 06 の反映を新設すると
      ↓
★「架電すべき相手」が2箇所にできる
      ↓
どちらを見ればよいか分からなくなり、★両方とも使われなくなる
```

「反映」は同期に見えて、**判断の置き場を増やす操作**。器が2つになった時点で
「どっちに書くんだっけ」が必ず起きる（2026-08-22 に `40_活動ログ` へ書く経路が
2本あって重複記入の危険が出たのと同じ形）。

## 決めた形 ── 既存2枚で完結させた

```
誰に架電すべきか   08_関係フォロー ／ 09_進捗MTG⑤（反応スコア順が既に出ている）
架電した記録       40_活動ログ へ TEL種別で（★活動種別に TEL は既にある）
06_テレアポリスト   ★⛔にする（消さない。A1へ降格注記）
★08へ電話番号列（00参照の数式）を1本足せば 5手 → 4手
```

**★リストを増やさずに列を1本足す。** これで「見る場所」は増えない。

## 型として

- **★新しいリストを作る前に、同じ役割のものが墓場に無いか探す。**
  過去に同じ案が実行され、使われずに残骸になっていることがある
- 「別に器を設けて反映」と言われたら、**まず既存の器で完結できないかを数える**。
  器を足すのではなく **列を足す／既存ビューを使う** で済むことが多い
- 死んだ器は**消さずに⛔で状態を書く**（次に同じ案が出たとき、これが証拠になる）
  → [[reference_notion_archive_line]]
- 判断軸は fukuchi-core「★新しい仕組みの採否は二重管理が増えないかで決める」と同じ

## 🔴 2026-09-05 続報 ── 器を1つにしたのに、**指した先が空**だったので誰も従えなかった

**上で「既存2枚で完結させた」と決めた先を、2週間後に実測した（ロビン・読むだけ）。**

```
決定（2026-08-23 有璽氏承認）      実測（2026-09-05）
架電先＝09_進捗MTG⑤（反応スコア順） → ★実データ0件（165行のうち値があるのは見出し4行だけ）
      ／08_関係フォロー             → 76行。テレアポ対象3,495社は1社も入っていない
記録先＝40_活動ログ 活動種別＝TEL   → ★TELは0件。37行すべて「その他」・最終は8/18
                                      （担当は松本31・有璽6）
人が実際に書いていた場所            → ★見本ファイル(1x_KgLfPbre…)の事業所単位タブに15行
                                      松本秋紀が9/1・9/4に更新（revision 232/251 が本人名義）
```

**★「器を1つにした」だけでは足りない。残した1つに中身が無ければ、決定は実行不可能になる。**
現場は空の器の前で止まらない。**別の場所（元の見本ファイル）へ書く。**
その結果、⛔にした器を含めて **「テレアポリスト」という名前の器が3つ**になった
（見本／今日できた新リスト／06_テレアポリスト）。**死体を1つ増やした形。**

### 型として足すこと

- **★「使わない」を決めたら、使う側に中身が入るところまでを1つの作業にする。**
  ⛔注記を書いた時点では終わっていない。**移行先が空のまま⛔を付けると、規範だけが残る。**
- **★決定が守られているかは、宣言ではなく行数で見る。**
  「40_活動ログへTELで書く」なら `活動種別=TEL` の件数を数える。**0件なら守られていない。**
- **★人がどこに書いているかは、ファイルのリビジョン名義で分かる。**
  「聞く」前に、更新者名と値が入っている行を数える方が速くて確か。
- 判定は「決めたか」ではなく「**決めた先に1行でも入ったか**」に置く
  → [[reference_verify_outcome_not_mechanism]]（部品でなく目的の側で測る）
