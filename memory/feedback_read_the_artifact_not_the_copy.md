**シート・DB・ファイルの存在や中身を述べる前に、その場で実物を読む。写しで代用しない。**

**Why**：2026-08-12の1セッションで3回、既に決まっていた・既に存在していたことを「無い」「未実施」と報告した。田村さんから「前に実施したことを覚えていない状態なのはすごく困る」と指摘を受けた。記録は存在していた。読まなかった、または写しを読んだのが原因。

失敗の型は3つとも同じで、**実物ではなく派生物を信じた**。

```
打ち切られた書き出し   Driveの read_file_content は1シート約86行で切れる
                      → 後半のシートが欠けたのを「存在しない」と誤認
ソースのコメント       .gs のコメントは書かれた時点のスナップショット
                      → 「未照合」と書いてあったが、同じ日に照合済みだった
自分の過去の記録       ⑥ログにもメモリにも書いてある決定に矛盾する提案をした
                      → 読んだうえで矛盾させた。注意不足
```

**How to apply**：

- 存在確認は必ず実物で。GASで `getSheets()` を回す、ファイルを直接開く。**書き出しの欠落を「無い」の証拠にしない**
- 「未実施」「無い」「されていない」と書く前に、一度立ち止まって根拠が実物かを確かめる。派生物ならそう明示する（「〜の記録では」と書く）
- 着手前に読む正本の一覧を持つ（この案件では [[project_sales_workbook_read_first]]）
- **同じルールが複数箇所にあると必ずずれる。** データで繰り返し学んだことは、ルール文書にも当てはまる。正本を1つ決め、他はリンクと差分だけにする
- 決定は経緯の文章に埋めず、1決定1行で引けるようにする
