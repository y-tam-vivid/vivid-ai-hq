**空行に値が入る経路は1つではない。** 書式を潰しても、走査範囲が広いままなら別の経路から同じ事故が起きる。

```
書式  チェックボックス等の入力規則が空行まで敷かれている → 未チェック＝false が値になる
走査  実データが離れた行にある                          → その手前の空行まで書き込まれる
```

2026-08-12の実例（`00_企業マスタ`）：実データは3〜387行だが、`合同会社NOLLEY` だけが778行にあった（別作業で空行の途中に追加された）。スクリプトの多くは「会社名が入っている最後の行」まで走るので走査範囲が776行になり、`matchKintoneRun()` が `stV.push([curSt || '未登録'])` で**空行390行の `kintone登録状況` に「未登録」を書いた**。

- **「空行に値が入っている」を見つけたら、書式だけでなく走査範囲も疑う。** 離れた行に実データが1行でもあれば、その手前は全部巻き込まれる
- 直し方は**実データを詰める**（離れた行の値を実データ直後へ写し、元の行を空にする。行削除はしない）。走査範囲が縮めば以後は書かれない
- 既に入ったゴミを消すときは**連続する区間ごとに**消す。「最初のゴミ行〜最後のゴミ行」を1範囲でまとめると、間に挟まった実データを巻き込む
- 移動の前に**移動先が完全に空か**を確かめる。2026-08-12はこの安全弁が実際に止めた（移動先に前段のゴミが残っていた）

診断の入口：`matchKintoneRun()` の「企業マスタ NNN件」が実データの件数と食い違っていたら、この状態。
