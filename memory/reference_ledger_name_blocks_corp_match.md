**「法人番号が取れない」の真因は、取得経路ではなく台帳の会社名欄にある。**

2026-08-20 実測 ── `00_企業マスタ` の法人番号の空欄151件を国税庁の全件データ
（581万件）と突合したところ、**機械で確定できたのは8件**だった。
残りを分解すると、**国税庁側に無いのではなく、台帳の会社名が突合できない形**だった。

```
151件（法人番号が空）
 ├ 64  個人（事業主）        ★そもそも法人番号が存在しない。対象外
 ├ 53  国税庁に候補ゼロ       ← ここが問題の本体
 │      ├ 士業の個人事務所（法律／税理士／行政書士／社労士／FP）＝個人事業
 │      ├ 個人名・屋号（樋口勇人／Luca食堂／吉村靴下）
 │      └ ★法人なのに出ないもの ＝ 下の3つの型
 └ 34  候補が複数 or 所在地が食い違う → 人が決める
```

## 突合を殺す3つの型（全部この日に実測）

| 型 | 実例 | 何が起きるか |
|---|---|---|
| **法人名＋施設名を1セルに入れている** | `医療法人幸人会 田島クリニック` | 国税庁の商号は `医療法人幸人会`（6120005011438・大阪市生野区）。**法人は実在するのに候補ゼロになる** |
| **社名の誤記** | `ジブラルタル生命保険株式会社` | 正しくは **`ジブラルタ生命保険株式会社`**（"ル"が1つ多い）。全件データに「ル」付きは**0件**、無しは**1件**。誤記は誰も気づかない |
| **2社をスラッシュで連結** | `株式会社セールスコムズ/スマートリクルーティング株式会社`<br>`株式会社REN/LEAPS Community` | 1行に2社。どちらの法人番号を入れるかが決まらない |

## だからどうするか

- **法人番号が埋まらない行を見たら、まず台帳の会社名を疑う。** 「国税庁に無い会社」だと
  判定する前に、法人名だけを切り出して引き直す
- **会社名欄は法人の商号だけを入れる。** 施設名・店舗名は別の列（サービス種別・備考）へ。
  1行1社。連結しない
- **社名の修正は正本の値の変更なので、機械では直さない。** 候補を出して有璽氏へ返す
- 士業事務所・屋号・個人名は **`顧客種別=個人（事業主）` を入れる**。
  入れておけば以後の突合対象から自動で外れる（＝毎回「取れなかった」と報告されない）

## 突合そのものの注意（同じ日に自分で踏んだ）

- **社名が完全一致しても、都道府県が食い違えば別法人。** 一致した項目だけを見て
  「一意に決まった」と判定すると、東京都の会社に神奈川県の法人番号を当てる。
  2026-08-20 に G-Blossom／コンクス／スモールM&A の3件でこれを出しかけた（書く前に検出）
- **絞り込みは「候補が減ったか」ではなく「矛盾が無いか」で見る。**
  1件に絞れたことは、それが正しいことを意味しない

## ★候補が1件になった瞬間、後ろの検査が全部飛ぶ（2026-08-20 つるが検出）

絞り込みを `if len(候補) > 1:` で連ねて書くと、**先の条件で1件になった時点で
以降の検査が1つも実行されない。** 順番の最後に置いた検査ほど効かない。

```
① 社名完全一致で絞る      ← ここで1件になると
② 都道府県で絞る               ↓
③ 市区町村で絞る          ② ③ ④ は一度も動かない
④ 閉鎖済みを除外          ★これが飛んだ
```

実例 ── `日本アクセス株式会社` に `6120001072698` を当てようとした。
この法人番号は **2025-10-16 に合併で解散し、登記記録が閉鎖されている**
（処理区分 21・摘要「株式会社ＫＥＬ ＣＲＥＳＴＩＡ に合併し解散」）。
社名が完全一致したので1件に絞られ、閉鎖の検査に到達しなかった。

- **絞り込み（候補を減らす）と 適格性の検査（そもそも使ってよい値か）を混ぜない。**
  適格性は候補数に関係なく、最後に必ず1回通す
- **消滅した法人番号は空欄より有害。** 存在しない相手を指したまま二度と疑われない

## ★欠損には2種類ある。分けないと永遠に終わらない（2026-08-20 実測）

`corp_number_fill.py` の **要判断79件**の内訳（実測）。

```
候補ゼロ            50件   ← ここが問題の本体
候補複数で絞れず    16件
都道府県の食い違い   3件
所在地の情報が無い   3件
市区町村の食い違い   2件
登記記録が閉鎖       2件
番地の食い違い       1件
```

**候補ゼロ50件を見ると、20件前後が個人事務所・屋号・個人名だった。**
法律事務所／税理士／会計士／社労士／行政書士／FP／特許事務所など。
**法人番号がそもそも存在しない。** 顧客種別を「個人（事業主）」にすれば、
最初から対象外になる。

```
候補ゼロ50件を1件ずつ見た結果（2026-08-20 実測）
  Ａ 個人事業主      22件  法人番号がそもそも存在しない。★埋めようとしてはいけない
  Ｂ 社名欄の汚れ     6件  直せば埋まる。国税庁側に実在することまで確認済み
  Ｃ 分からない      22件  ★無理に振り分けない
```

**★当初「約30件が汚れ」と見積もったが、実測は6件だった。**
キーワードでの概観を確定数として扱ってしまった。→ [[feedback_one_route_is_not_verification]]
**いちばん多いのは「分からない」22件。** 汚れとして追える分はもともと少ない。

**「埋まらない」を全部「汚れ」と見なすと、存在しないものを永遠に追い続ける。**
未達の数字が下がらない理由が「作業が足りない」に見えてしまう。

★汚れ側の3型は**サンプル5件すべてで実在を確認**した。
医療法人幸人会／医療法人昌栄会（施設名の同居）、ジブラルタ生命保険（台帳は「ル」が1つ多い）、
株式会社ＲＥＮ／株式会社セールスコムズ／スマートリクルーティング株式会社（スラッシュ連結）。
**国税庁側には在る。台帳側の書き方で見つからないだけ。**

★`if len(候補)>1` の欠陥は修正済み。適格性検査（閉鎖済み除外・都道府県の食い違い）は
絞り込みの外で、候補数に関係なく実行される作りをコードで確認した。

## ★同じ判断を2経路でやると、片方だけ基準が緩くなる（2026-08-20 実測）

法人番号を確定する判断が、いつのまにか2つの経路で行われていた。

```
経路①  corp_number_fill.py の decide()     機械。適格性検査が候補数に関係なく必ず通る
          ・登記記録が閉鎖 → 弾く
          ・都道府県／市区町村／番地の食い違い → 弾く
          ・★所在地が台帳に無ければ確定しない → 弾く
経路②  社名欄の汚れを人が分類して引いた   ★decide() を通していない
          ・「国税庁側に実在するか」しか見ていない
          ・★所在地の裏付けが無くても「実在＝書いてよい」に見える
```

**経路②が2件を誤って通しかけた。**
ジブラルタ生命保険（5010001034776・実在）とセールスコムズ／スマートリクルーティング。
どちらも**台帳側の都道府県・市区町村・住所が全て空欄**で、
**社名の1経路しか根拠が無い**。経路①なら弾かれていた。

- **「実在する」と「その行が指している法人だ」は別。**
  国税庁側に実在することは、台帳のその行と結びつく根拠にならない
- **判断の基準はコードの中にある。** 手で分類した結果を同じ土俵に載せるなら、
  **同じ検査を通してから**でないと基準が下がる
- → [[feedback_one_route_is_not_verification]]

## ★4つ目の型 ── core一致（法人種別を落とした比較）は法人格の違いを見逃す（2026-09-07 実測）

`corp_lookup.py` の `core()` は「合同会社」「株式会社」等の種別語を全部落として比較する
（前株・後株のゆれを吸収するため）。**この設計のまま候補を出すと、法人格そのものが違う
別法人が「候補」として出てくる。**

```
台帳    合同会社クレアメゾン（大阪府大阪市東住吉区）
候補    クレアメゾン株式会社（愛知県岡崎市）
        ★「クレアメゾン」の部分だけ一致。法人格（合同会社⇔株式会社）も都道府県も違う
```

`decide()` はこのケースを「候補なし」と正しく返す（都道府県一致が無く1件に絞れないため）
が、**候補の一覧だけを別途取り出す（○×シートを作るために scan_candidates() を直接使う等）
と、この低信頼な候補も他と同じ見た目で並んでしまう。**

- **候補を人に見せるときは、法人格が一致しているかを別途明記する。** 「候補が見つかった」
  だけでは、有璽氏が中身を読まずに○を押すリスクがある
- 型としては1〜3個目（施設名同居・誤記・2社連結）と同じ根：**「一致した」の中身が
  弱い（部分一致・種別無視）ほど、有力候補に見えて実は違う法人という事故が起きる**
- 対処：候補提示の理由欄に「社名の一部一致のみ」「法人格が異なる」等、一致の根拠の
  強さを必ず添える → `~/.vivid-relay/corpno_sheet_result.md`（2026-09-07）で実装した形

## ★5つ目の型 ── 有璽氏の○は「候補が正しい」の意味であって「書いてよい」の意味ではない（2026-09-08 実測）

確認シートで有璽氏が○を付けた13件のうち3件（B-0187 C-TAKE／B-0377 日本アクセス／
B-0443 T&Pコンサルティング）に、備考「閉鎖しているなら削除」が付いていた。国税庁全件データ
（08-31版）を実測すると3件とも**処理区分=21（登記記録の閉鎖等）**で、実際に閉鎖済みだった。

```
有璽氏の○の意味   「この法人番号の候補は、この行が指す法人として正しい」
★書いてよいの意味ではない  法人が既に消滅していれば、番号を書くこと自体が
                          [[reference_ledger_name_blocks_corp_match]] 冒頭の
                          「消滅した法人番号は空欄より有害」に抵触する
```

- **★候補提示の時点で処理区分（閉鎖・解散の有無）を理由欄へ明記しておくべきだった。**
  今回は「登記記録が閉鎖」と理由欄に書かれていたので有璽氏も認識した上で○＋「閉鎖しているなら
  削除」を選んだと読めるが、この備考は「法人番号を書け」ではなく**「台帳のこの行をどうするか
  判断してほしい」という別の依頼**。○×だけを見て機械的に反映すると、閉鎖済み番号を書いてしまう。
- **★対処**：○が付いていても、対象法人が閉鎖済みなら法人番号は書かず、削除要否を人へ返す
  （正本の削除は承認が要る操作＝自分の役割外）。

## ★候補シートの「詳細住所は台帳に情報なし」は、国税庁データが省略された表記であって
候補自体に詳細住所が無いという意味ではない（2026-09-08 実測）

法人番号確認シートの「候補の住所（国税庁表記）」欄が都道府県・市区町村までしか書かれて
いない行（B-0427/B-0441/B-0445/B-0120）があった。**これは台帳（既存の住所欄）に詳細住所が
無いことの注記であって、国税庁の元データに詳細住所が無いという意味ではなかった。**

```
確認シート表記          「東京都品川区」（都道府県+市区町村のみ）
国税庁CSV実物（grep）   "東京都","品川区","上大崎２丁目１３番３０号"（丁目番地までフルにある）
```

- **★候補シートは人が読みやすいよう省略されていることがある。書き込み時は必ず元データ
  （国税庁全件CSV）を再度開いて、省略されていない全項目を確認する。** シートの表記を
  そのまま「情報が無い」と読んで住所欄を都道府県・市区町村止まりで書くと、書ける情報を
  書き逃す。
- 台帳の住所欄が元々空欄なら、国税庁の詳細住所（丁目番地）まで書いてよい
  （既存の値と衝突しないため）。台帳に既存の詳細住所がある行は、番地まで一致確認済みでも
  上書きせず触らない（表記ゆれで無用な差分を作らないため）。
