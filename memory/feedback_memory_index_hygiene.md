**`memory/MEMORY.md` には読み込み上限（約24.4KB）がある。超えた分は黙って落ちる。**
2026-08-21 実測 ── **61,671バイト・132行**まで肥大し、システムから
「Only part of it was loaded」の警告が出ていた。**索引が全部は届いていない状態が続いていた。**

**Why:** 索引行は追記で育つ。1件の学びを足すたびに既存行へ「／★…」を継ぎ足していくと、
1行が1,000バイトを超える。**索引は「どこに何があるか」を運ぶもので、内容を運ぶものではない。**
索引が届かなくなると、**そのメモリは存在しないのと同じ**になる（本文がどれだけ充実していても、
索引に載っていなければ誰も引きに行かない）。届く経路が壊れる＝いちばん高くつく壊れ方。

**How to apply:**

```
1行の上限     180バイト（日本語で約55字＋リンク部）。全体で 24.4KB を超えない
              ★130行なら1行あたり平均188バイトしか使えない。行を増やすほど各行は短くなる
書き方        - [名前](file.md) — 現在地を1文
              「Xプロジェクト — 概要」ではなく「Xプロジェクト — いまYの状態。Zは未実装」
足すとき      既存行へ継ぎ足さない。詳細は**そのファイルの本文**へ書き、索引は現在地だけ差し替える
重複          同じファイルを指す索引行を2本作らない（2026-08-21 時点で3組の重複を統合した）
数え方        `wc -c ~/vivid-ai-hq/memory/MEMORY.md` で見る。20KBを超えたら棚卸しの合図
```

- **削るときは必ず全文を残す。** 2026-08-21 の棚卸しでは、圧縮前の132行を
  `memory/_archive/MEMORY_full_20260821.md` へ保存してから置き換えた（git管理下）。
  **索引にしか書かれていなかった記述は、順次それぞれのファイル本文へ戻す。**
- 実体は1つ。`~/.claude/projects/-Users-yujimac/memory` は `~/vivid-ai-hq/memory` への symlink
  （2026-08-21 実測）。**索引が2か所にあるように見えても二重管理ではない。**
- 関連 → [[reference_delivered_but_unread]]（長い文書は届いていても読まれない・同じ型）

## ★このルールを書いた当日に、自分で744バイトの行を足していた（2026-08-22 実測）

2026-08-21、「1行180バイトまで」と書いて索引を61,671→23,247バイトへ圧縮した。
**その同じ日のコミット群（a2b08c0→64d1605）で、`feedback_type_is_not_layout` の索引行が
744バイト＝上限の4倍**になっていた。本文へ書いた内容を、索引にも継ぎ足していた。

```
1行744バイト      索引全体（23,447）の3.2%を1行で占有
残り              上限24.4KB まで約1,500バイト＝索引行にして約9本ぶんしかない
本文の重複        744バイトの内容は feedback_type_is_not_layout.md 本文51〜87行に全部ある
                  ＝索引側は消しても何も失われなかった（実物を読んで確認してから短縮）
```

- **★索引に1行足したら、その場で測る。** 書いた直後が唯一測るタイミング。
  `awk 'length($0)>180 && /^- \[/ {print length($0)": "$0}' memory/MEMORY.md`
- **★`./check.sh` はこれを見ていない。** 項目4が見るのは「孤児が無いか」だけで、
  **1行の長さも合計バイト数も検査していない。**＝規範違反がそのまま通る
  → [[reference_hooks_enforce_what_discipline_cannot]]（規律に依存する対策は、規律が切れた回に効かない）
- 短縮するときは **必ず本文に同じ内容が在るかを実物で確かめてから**削る
  → [[feedback_read_the_artifact_not_the_copy]]

### ★180バイトは宣言されただけで、守られていない（2026-08-22 実測）

744バイトの1本を直したあと全件を数えたら、**134本中38本（28%）が180超**だった。
合計は 22,856 バイトで上限（24.4KB）の内側なので**いまは全部届いている**が、
**残りは約1,500バイト＝索引行にして9本ぶんしかない。**

```
いま     134本 / 22,856バイト / 38本が180超 / 最長236バイト
上限     24.4KB。到達したら超過分は黙って落ちる（警告は出るが行は消える）
余力     約1,500バイト。新規メモリを9本足したら再び溢れる
```

- **★「上限を決めた」と「上限が守られている」は別。** 決めた日に自分で4倍の行を足していた
- 38本の短縮は**残件**（今日は744バイトの1本と新規1本だけ直した）。
  溢れてから一斉に削ると、削る判断を急いですることになる
- 新規メモリを足す前に `wc -c` を見る。22KB を超えていたら、**足す前に1本削る**
