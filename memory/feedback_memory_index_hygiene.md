**`memory/MEMORY.md` には読み込み上限がある。超えた分は黙って落ちる。**

★2026-08-29 公式仕様で確認 ── 上限は **200行 または 25KB、先に来た方**。
これまで byte しか見ていなかった。**行数の上限があることを知らずに運用していた**
（実測 75行 / 13.0KB ＝ 行数側にはまだ余裕がある）→ [[reference_what_actually_reaches_the_next_turn]]
2026-08-21 実測 ── **61,671バイト・132行**まで肥大し、システムから
「Only part of it was loaded」の警告が出ていた。**索引が全部は届いていない状態が続いていた。**

**Why:** 索引行は追記で育つ。1件の学びを足すたびに既存行へ「／★…」を継ぎ足していくと、
1行が1,000バイトを超える。**索引は「どこに何があるか」を運ぶもので、内容を運ぶものではない。**
索引が届かなくなると、**そのメモリは存在しないのと同じ**になる（本文がどれだけ充実していても、
索引に載っていなければ誰も引きに行かない）。届く経路が壊れる＝いちばん高くつく壊れ方。

**How to apply:**

```
1行の上限     180バイト（日本語で約55字＋リンク部）。全体で 24.4KB を超えない
              ★130行なら1行あたり平均188バイトしか使えない。行を増やすほど各行は短くなる
書き方        - [名前](file.md) — 現在地を1文
              「Xプロジェクト — 概要」ではなく「Xプロジェクト — いまYの状態。Zは未実装」
足すとき      既存行へ継ぎ足さない。詳細は**そのファイルの本文**へ書き、索引は現在地だけ差し替える
重複          同じファイルを指す索引行を2本作らない（2026-08-21 時点で3組の重複を統合した）
数え方        `wc -c ~/vivid-ai-hq/memory/MEMORY.md` で見る。20KBを超えたら棚卸しの合図
```

- **削るときは必ず全文を残す。** 2026-08-21 の棚卸しでは、圧縮前の132行を
  `memory/_archive/MEMORY_full_20260821.md` へ保存してから置き換えた（git管理下）。
  **索引にしか書かれていなかった記述は、順次それぞれのファイル本文へ戻す。**
- 実体は1つ。`~/.claude/projects/-Users-yujimac/memory` は `~/vivid-ai-hq/memory` への symlink
  （2026-08-21 実測）。**索引が2か所にあるように見えても二重管理ではない。**
- 関連 → [[reference_delivered_but_unread]]（長い文書は届いていても読まれない・同じ型）

## ★このルールを書いた当日に、自分で744バイトの行を足していた（2026-08-22 実測）

2026-08-21、「1行180バイトまで」と書いて索引を61,671→23,247バイトへ圧縮した。
**その同じ日のコミット群（a2b08c0→64d1605）で、`feedback_type_is_not_layout` の索引行が
744バイト＝上限の4倍**になっていた。本文へ書いた内容を、索引にも継ぎ足していた。

```
1行744バイト      索引全体（23,447）の3.2%を1行で占有
残り              上限24.4KB まで約1,500バイト＝索引行にして約9本ぶんしかない
本文の重複        744バイトの内容は feedback_type_is_not_layout.md 本文51〜87行に全部ある
                  ＝索引側は消しても何も失われなかった（実物を読んで確認してから短縮）
```

- **★索引に1行足したら、その場で測る。** 書いた直後が唯一測るタイミング。
  `awk 'length($0)>180 && /^- \[/ {print length($0)": "$0}' memory/MEMORY.md`
- **★`./check.sh` はこれを見ていない。** 項目4が見るのは「孤児が無いか」だけで、
  **1行の長さも合計バイト数も検査していない。**＝規範違反がそのまま通る
  → [[reference_hooks_enforce_what_discipline_cannot]]（規律に依存する対策は、規律が切れた回に効かない）
- 短縮するときは **必ず本文に同じ内容が在るかを実物で確かめてから**削る
  → [[feedback_read_the_artifact_not_the_copy]]

### ★180バイトは宣言されただけで、守られていない（2026-08-22 実測）

744バイトの1本を直したあと全件を数えたら、**134本中38本（28%）が180超**だった。
合計は 22,856 バイトで上限（24.4KB）の内側なので**いまは全部届いている**が、
**残りは約1,500バイト＝索引行にして9本ぶんしかない。**

```
いま     134本 / 22,856バイト / 38本が180超 / 最長236バイト
上限     24.4KB。到達したら超過分は黙って落ちる（警告は出るが行は消える）
余力     約1,500バイト。新規メモリを9本足したら再び溢れる
```

- **★「上限を決めた」と「上限が守られている」は別。** 決めた日に自分で4倍の行を足していた
- 38本の短縮は**残件**（今日は744バイトの1本と新規1本だけ直した）。
  溢れてから一斉に削ると、削る判断を急いですることになる
- 新規メモリを足す前に `wc -c` を見る。22KB を超えていたら、**足す前に1本削る**

### ★翌日には上限を超えていた（2026-08-23 実測）

前日「余力は約1,500バイト＝9本ぶん」と書いた。**翌朝には 24,518バイト／139行／41本が180超**。
＝**上限（24.4KB）を既に超えており、索引の末尾は落ちている状態だった。**

```
2026-08-22  22,856バイト / 134本 / 38本が180超
2026-08-23  24,518バイト / 139本 / 41本が180超  ★超過
```

**★1日で1,662バイト増える。** 「9本ぶんの余力」は、この速度なら1日で使い切る。
残件として置いた38本の短縮は、**残件にした時点で間に合わない量だった。**

- **★新規メモリを足す日は、必ず同時に1本以上を短縮する。** 足すだけの日を作らない
  （この日は 500バイト・480バイトの2本を本文と突合してから短縮した）
- 削る前に本文へ同じ記述が在ることを実物で確認する。索引にしか無い記述は先に本文へ戻す
- **★超過は警告なしで起きる。** `wc -c` を見ない限り、超えたことに誰も気づかない

### ★「足す日に1本削る」では追いつかない（2026-08-23 実測・同日2度目）

同じ日のうちに再測したら **24,209バイト／140行／42本が180超**。
規範どおり1本（266→146バイト）短縮して 24,117バイト。**残り約283バイト。**

```
削った量   120バイト     ＝ 索引行 0.7本ぶん
増える量   1日 1,662バイト（前日実測）＝ 1本削っても14倍の速さで埋まる
```

**★「足す日は1本削る」は、増加速度に対して桁が足りない。**
41本の一括短縮を残件にしている限り、**毎日この帳尻合わせが発生し、毎日負ける。**

- **★残件にしてよい量かどうかを、速度で判断する。** 「38本の短縮は残件」と書いた翌日に
  上限を超えた。件数ではなく **1日あたりの増分で割って**、間に合うかを見る
- 41本 × 平均40バイト削減 ＝ 約1,600バイト ＝ **ちょうど1日ぶん**。
  一括でやっても1日しか稼げない → **★本当の対策は「索引行を増やさない」ほうにある**
  （新規メモリを作る前に、既存ファイルへの追記で済まないかを先に見る）

### ★3日で上限に戻った ── 行を短くしても解けない（2026-08-24 実測）

8/21 に 61,671→23,247 へ圧縮した。**8/24 に測ったら 25,063 バイト。上限（24,986）を超えていた。**
有璽氏の側にも「MDファイルがいっぱい」という警告が出ていた。

```
8/21 圧縮直後   23,247 バイト / 132行 / 180超 38本
8/24 実測       25,063 バイト / 142行 / 180超 40本   ← 3日で +1,816。上限超過
8/24 棚卸し後   23,224 バイト / 144行 / 180超 12本   ← 24本を短縮＋新規2本
```

- **★真因は「1行が長い」ではなく「本数が多い」。** メモリ実体は **146ファイル**。
  1本の索引行はリンクだけで約60バイト使う。**146本 × 170バイト ≒ 24,800 ＝ それだけで上限。**
  行を短くする対策は毎回効くが、**新規メモリ10本で必ず戻ってくる。**
- **したがって棚卸しの単位は「行の長さ」ではなく「索引に載せる本数」。**
  終わったプロジェクト・後継に置き換わった規範は、**ファイルは残して索引行だけ落とす**
  （→ [[reference_notion_archive_line]] と同じ線引き。消すのではなく載せるのをやめる）。
  ★ただし索引から落ちた瞬間、そのメモリは事実上存在しなくなる。**落とす判断は有璽氏に出す。**
- 実測コマンド（両方を1度に見る）
  ```
  cd ~/vivid-ai-hq/memory && wc -c MEMORY.md && \
    echo "180超: $(awk 'length($0)>180' MEMORY.md | wc -l) / 全 $(wc -l < MEMORY.md)" && ls *.md | wc -l
  ```
- 圧縮前の控え: `/private/tmp/.../scratchpad/MEMORY_before_20260824.md`（セッション限り）と
  git 履歴（commit 前の版が残る）。**8/21 の全文は `memory/_archive/MEMORY_full_20260821.md`。**

## ★誰に届いているのか（2026-08-22 実測）

有璽氏の問い「このMEMORY.mdは全AI・全エージェントが見るものか」に対して調べた結果。

```
届く    ターミナル／デスクトップのメインセッション（両機）
          ~/.claude/CLAUDE.md が @import（機械ローカル・絶対パス）
        リポジトリ内が cwd のセッション
          vivid-ai-hq/CLAUDE.md が @memory/MEMORY.md（相対パス）
        Web／スマホ／クラウド（vivid-ai-hq を clone している場合）

★届かない   .claude/agents/*.md（14体）── MEMORY.md をどれも参照していない（grep で0件）
             各体が読むのは frontmatter の skills: fukuchi-core / cross-check だけ
           vivid-ai-hq 以外のリポジトリで開いたクラウドセッション
```

- **エージェントは「規範（fukuchi-core）」は読むが「記憶（MEMORY.md）」は読まない。**
  サブエージェントに親セッションの CLAUDE.md が渡るかは Claude Code の実装依存で、**未実測**。
  確かめるなら1体起動して**肯定形で**聞く（→ [[reference_mac_mini_execution_env]]）。
- **つまり「全AIが見る」ではない。** エージェントに前提を渡したいなら、
  呼ぶときのプロンプトに書くか、agents 定義側へ持たせるしかない。

## 棚卸しの進め方（2026-08-26 有璽氏「どのような形で棚卸しをしていけばいいか」）

```
① 候補を出す   python3 bin/memory_audit.py --retire      ★機械は候補を出すだけ
② 一覧を渡す   有璽氏が ○（降ろす）／×（残す）を決める   ★AIは降ろす判断をしない
③ 索引から外す MEMORY.md か INDEX_*.md の1行を消す        ★ファイルは消さない
④ 履歴を残す   memory/_archive/INDEX_過去.md へ
               「日付｜名前｜降ろした理由」を1行
⑤ 検査        ./check.sh（どの索引にも無い＝孤児として赤になる）
```

**★降ろしてよい線**（[[reference_notion_archive_line]] と同じ）── 終わった案件／後継に
置き換わった規範／一度きりで再発しない事故。**配った・リンクされた・他から参照されている
ものは降ろさない。**

### ★実測してみたら、降ろせるものは実質ゼロだった（2026-08-26）

```
1回目の判定    候補7本。★全部いま動いている案件だった
               真因＝「完了。」を終わりの印にしていた。進行中でも「〜まで完了。」と書く
               （昨日作ったばかりの project_ops_dashboard_artifact が上位に来た）
締めたあと     候補1本。それも project_notion_operating_rules（現役の正本）の誤検出
```

- **★「棚卸しをしよう」と決めた時点では、まだ棚卸しすべきものが無いことがある。**
  MEMORY.md は 11KB・上限まで約14,000バイト＝**新規メモリ約80本ぶんの余力**。
  **急いで降ろす理由が無い。**上限に近づいてから使う道具として置いておく。
- **★判定の語を「本文にありそうな言葉」で選ばない。**進行中の文書にも同じ語が出る。
  終わったものだけが持つ語（【廃止】【降格】後継＝）に絞る。
