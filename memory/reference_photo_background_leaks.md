# 写真は被写体でなく「背景」で事故る

**2026-09-03 実地。** LIFE STAND UP サイトの掲載写真266枚を検分中に発見。

```
見ていたもの   誰が写っているか（顔・後ろ姿・手元）＝掲載同意の話
見落とすもの   ★その人の後ろに何が書いてあるか
実物          ホワイトボードに児童の名前が書かれており、拡大すると読める
              （Photo-211・212・222・236 ほか。板書が写るカットは他に40枚以上ある）
```

**★掲載同意を取っても、これは解決しない。** 同意は「あなたを写してよいか」であって、
**背景に写り込んだ別の児童の名前**は同意の範囲外。福祉施設では個人情報の漏えいそのもの。

## ★縮小版では見えない。原寸で読む

```
400px の縮小版   文字がつぶれて読めない → 「問題なし」に見える
原寸             読める
```
**縮小版で一覧して選び、そのまま公開すると必ず抜ける。**
選定は縮小版でよいが、**採用が決まった枚は必ず原寸で1枚ずつ読む。**
→ [[feedback_one_route_is_not_verification]]（縮小版だけは1経路）

## 背景で見るもの（チェックの順）

```
1  文字が書かれた面    ホワイトボード・黒板・模造紙・掲示物
2  紙                 名簿・記録用紙・個別支援計画・出席表・机上の書類
3  画面               PC・タブレットに個人情報が表示されていないか
4  持ち物             名前が書かれた道具・靴・カバン・ロッカーの名札
5  ★内容の正しさ       書いてある中身が間違っていないか（下記）
```

## ★5番目 ── 書いてある内容が間違っていることがある

同じ回に見つかった2件目。英語療育の証拠として使う板書のカットに**英文の誤りがあった**。

```
Photo-100  板書 "Question: Do you going to school?"（正しくは Are you going to）
★英語療育を売りにするページに載せると、証拠のつもりが逆効果になる
```
**専門性を示すために撮った写真ほど、写っている中身の正しさを見る。**
判定できるのはその領域の人（この件なら英語スタッフ）。**こちらで直さない。差し替えるか外す。**

## 誰が決めるか

```
背景の写り込み     施設。★原寸での洗い出しは施設と一緒にやる（AIの縮小版検分では足りない）
顔の掲載可否       本人・保護者・施設
写っている中身     その領域の担当（英語なら英語スタッフ）
```
**AIは判断材料を作る役。可否は決めない。** → [[feedback_write_for_the_reader]]

関連 → [[project_lifestandup_website_wordpress]] ／ [[project_event_skills_suite]]（顔ぼかしは
被写体しか見ない。★背景の文字は素通りする）

## ★服にも写る ── 体操服の背中の学校名（2026-09-03 追記）

板書・掲示物・書類を見ていて見落とした。**子どもの体操服の背中に学校名が大きくプリントされている。**

```
実物   「KAWARAJYO OSAKA」。Photo-182・193・194 の3枚。いずれも第1候補か次点に入っていた
★板書の下の名前より重い。名前が読めなくても★通学先の学校が特定される
★同じ体操服の子は他の写真にも多数写っている。原寸で読んだのは52枚だけなので、
  実際の該当枚数はもっと多い可能性が高い
```
→ 背景で見るものの「4 持ち物」に**服のプリント（学校名・園名・チーム名）**を必ず含める。

## ★縮小版では「掲載に適さない絵」も見えない（2026-09-03）

写り込みだけの話ではなかった。**縮小版で「活動風景」に見えていたカットが、大きく見ると
掲載に適さない絵だった。**

```
Photo-89   ★床に横たわる子ども   → 一度 about-staff FV の第1候補に置いてしまっていた
Photo-166  ★スタッフが子どもの身体を抱えている場面 → 次点に入っていた
```
**福祉施設のサイトで、この2枚は出せない。** 縮小版のコンタクトシートでは判別できなかった。
**★「原寸で読む」は文字のためだけではない。絵が何をしているかを見るためでもある。**

## 🔴 検分は2軸ある ── 「出せるか」と「その枠に合うか」（2026-09-05）

**このファイルはずっと「出せるか（安全か）」だけを書いてきた。もう1軸あった。**

```
2026-09-04  fv-hand（トップ「手元のクローズアップ」）に Photo-218 を入れたと報告
2026-09-05  ★実物は「英語授業で挙手する子どもたち」＝#10「プログラム小学生一覧」の写真
            ★「手元のクローズアップ」とは構図がまったく違う
            → 正しい Photo-29（算数プリントに取り組む手元）へ訂正
```

- **★原寸で検分したのに気づかなかった。** 見ていたのは
  「板書の児童名・服の学校名・掲載に適さない絵」＝**安全の軸だけ。**
  **「この枠にこの構図でよいか」を見ていなかった。**
- **★検分は2回いる。**
  ```
  ① 出せるか（安全）   背景の文字・服のプリント・写っている行為
  ② ★その枠に合うか    枠の名前が言っている構図か（手元／後ろ姿／笑顔／全景）
  ```
  ①だけ通すと、**安全だが場違いな写真**が載る。
- **★枠の名前が仕様書。**「手元のクローズアップ」という枠名に、
  挙手している集合写真は入らない。**枠名と実物を並べて読む。**

## 🔴 候補として挙がっていても、載せられない写真がある（2026-09-05）

```
Photo-140（採用トップ「メインビジュアル（丸）」）  ★載せられない
理由  ★「LABUBU」というキャラクター名・ぬいぐるみ・グッズが明確に写り込んでいる
      写っているのも大人で、子どもの活動風景ではない
```
- **★確認シートの候補そのものに問題があることがある。** 32枚は
  「掲載してよいか施設に聞く」ために選んだもので、**こちらの検分を通った保証はない。**
- **★他社の商標・キャラクターの写り込みは、施設の○×とは別の問題。**
  施設が○を出しても載せられない。**判断の軸が違う。**
- ★同じ担当が**2回とも同じ理由で見送っている**（前回コミット `1b98da7`）。
  **見送りの理由を記録に残さないと、次の担当がまた開いて同じ結論に達する。**

**★あわせて判明**：`recruit-top.php:57` は写真の仕組みに繋がっていない `image-slot` のまま。
**★写真を差し替えても表示されない実装状態。** 枠が「ある」ことと「出る」ことは別。

## ★機械で読めないことがある（OCRの実測・2026-09-03）

全点の文字を機械で読もうとして3経路とも失敗した。
```
tesseract   未導入
Swift(Vision) SDKとコンパイラのバージョン不整合
pyobjc      ビルド失敗
```
**→ 目視に落ちる。目視なら枚数に限りが出る。** だから「全点確認した」と書けない回がある。
**★読んだ枚数と数え方を必ず添える**（この回は採用候補52枚・各980px幅／残り214枚は400px幅のみ）。
