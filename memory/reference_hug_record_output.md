2026-10-20 MacBook の Claude in Chrome で実測（Slack `#sf7f2a3`・有璽氏ログイン済み・読むだけ）。

- **★「利用者の様子」は実績記録票には無い。** `service_record.php?mode=select`（サービス提供実績記録票一括印刷）は日付・時間・加算・保護者確認欄の国保連用の帳票。
- **★様子の入口は「本日の様子一括印刷」** `https://www.hug-ilife.link/hug/wm/contact_book.php?mode=selectComment`
  （サービス提供記録・ケア記録・生活記録の一覧 `contact_book.php` の上のボタン）。
  - 絞り込み：日付の範囲・施設・利用サービス・下書き含む/含まない・保護者コメント表示 → 児童を選んで「印刷」
  - 出る欄：日付／施設／本日の様子／記録者名。期間の絞り込みは効く（9月で出したら9月の行だけ）
  - 2026年9月・STAND UP で 38人
- 「ケア記録・生活記録一括印刷」（`?mode=select`）は別物。1年半の範囲でも6人しか出ない＝STAND UP ではほぼ使っていない。
- **★出力はPDFではない。** 「印刷」は POST で HTML を返し、読み込むと `window.print()` でブラウザの印刷ダイアログが開く。
  ★Chrome 拡張は印刷ダイアログで止まる＝★画面で「印刷」を押さない。同じ POST を `fetch` で送れば HTML を受け取れる（同じログインのまま）。
- PDF にするには、受け取った HTML を手元のヘッドレス Chrome（`--print-to-pdf`）で変換する案。★ダウンロードは有璽氏の許可が要る・置き場は機微。

関連：[[project_gov_filings_drive_structure]]（10/16 に HUG のメニュー名を読んだ記録）

- **★2026-10-20 自動保存は止められた。** HUG の HTML を `fetch` で受けて Blob でダウンロードさせる JS を、Claude Code の自動許可の判定が「個人情報の扱い」で拒否した。
  ★回り道はしない。有璽氏の手で HUG の「印刷」→「PDFに保存」が正規の経路。自動化するなら有璽氏が許可の設定を判断してから。
  ★JS でチェックを入れても「出力人数」は0人のままで「印刷」が押せない＝★チェックは画面上のクリックで入れる。

- **★2026-10-20 有璽氏の決定**：HUG「本日の様子一括印刷」→「PDFに保存」の中身で問題ない。★月単位で保存していきたい。
  ★ファイル名は「何月の・どなたの分か」が分かる形（★氏名を入れる。こちらが出した「利用者IDだけ」案は採られなかった）。
  ★置き場（仮）：MacBook `~/Documents/_機微_HUG本日の様子/`（★Downloads は毎週月曜の自動整理でドライブへ運ばれるので使わない）。最終の置き場は有璽氏の判断待ち。
  ★名前の案：`2026-09_本日の様子_STANDUP_氏名.pdf`（年月を先頭＝並べると月順）。

- **★2026-10-20 印刷画面は「表示件数 25」でページ送りがある＝1回の保存で25人まで。** 38人選んでも保存したPDFは25人分だった（2経路で確認：PDF内の「利用者名（」の見出し25個・印刷画面の表示件数25とページ送り）。
  ★残りは印刷画面で2ページ目に送って保存するか、表示件数を増やす。分ける道具は件数を数えて HUG の出力人数と合わなければ知らせる。
- 印刷画面には HUG の「**PDFを出力する**」ボタンがある（mpdf で HUG 側が作る `mpdf.pdf`）。注意書き：絵文字・環境依存文字は化けることがある＝そのときはブラウザの「PDFに保存」。
- PDF の見出しは「本日の様子／利用サービス：…／利用者名（ 氏 名 ）」。1人が複数ページにまたがる。分ける道具 `bin/hug_split_yosu.py`。
- ★期間を広げた1本は、1人の分の中で月が替わるページに2か月が混ざる＝ページ単位では月で切れない。★1か月ずつ出す（月の数だけ保存）のが確実。
- **★訂正（同日 08:4x）：有璽氏は1本で38人全員を出せた**（`mpdf (2)26.09.pdf`・66ページ）。25人止まりは有璽氏の1回目の出し方によるもので、★1本で全員出せる。道具は人数を出すので HUG の出力人数と照らす（「25人」の警告は外した）。
- 2026-09 の38本を書き出し済み（合計66ページ＝元と一致・人数＝HUGの選択38人と一致）。最初の25本は `_旧/2026-09_25人版_20261020/` へよけた（消していない）。

- **★2026-10-20 有璽氏の決定：原本は利用者別、月別はショートカット。** 理由＝日々の様子をもとに個別支援計画等を作る（利用者ごとに読む）。
  形：`利用者別/<氏名>/<YYYY-MM>_本日の様子_<施設>_<氏名>.pdf`（原本）／`月別/<YYYY-MM>/` に同じ名前のショートカット（MacBook 上は相対の symlink）。
  ★Google ドライブへ移すときは symlink は運ばれない＝ドライブのショートカットで作り直す。

- **★2026-10-20 有璽氏の決定（続き）**
  - 元PDFも名前を付ける：`<YYYY-MM>_本日の様子_<施設>.pdf`（氏名なし）。
  - ★ショートカットは Google ドライブに移す前提（＝ドライブのショートカットで作る。symlink は仮）。
  - ★最終の置き場＝**STAND UP の共有ドライブにある STAND UP のフォルダ**（STAND UP のものだから）。
  - ★置き場の答え（#17160b・08:50）：共有ドライブ「15-000_施設運営部門」›「**LIFE STAND UP**」› 本日の様子（HUG）/{利用者別,月別,元PDF}
  - ★手順（10/20 初回）：①`hug_split_yosu.py` で手元に分ける ②`利用者別/` と `元PDF/` を Mac の Google ドライブ同期フォルダ（共有ドライブ/15-000_施設運営部門/LIFE STAND UP/本日の様子（HUG）/）へコピー
    ③同期が終わってから mini で `bin/hug_drive_shortcuts.py`（月別にドライブのショートカット・何度流してもよい）。★コピー直後は同期途中＝ドライブ側の本数を数えてから作る（初回は22/38で一度止まった）。
  - ★有璽氏がHUGのPDFを置く所＝MacBook `~/Documents/_機微_HUG本日の様子/受け取り（HUGから保存）/`（10/20 有璽氏「格納するフォルダはどこか・開いて」）。
    道具はここに置かれたPDFを受け、結果は1つ上（利用者別・月別・元PDF）へ出す。
