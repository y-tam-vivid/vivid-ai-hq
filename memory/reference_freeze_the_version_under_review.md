# 検査に出す版を固定する ── 検査中に成果物が動いた

**2026-09-03 実地。ビビの段取りミス。** cross-check（作る役と検査役を分ける型）を回していて、
**検査役が読んでいる最中に、作る役が同じファイルを書き換えた。**

```
15:45  ビビ「対応完了。2周目をお願いします」→ 検査役（ステラ）へ渡す
15:52〜 ステラが検査を開始
15:53  ★front-page.php / functions.php / audit_tweaks.py が書き換わる
15:53  ★図案の削除・バナー挿入がテーマへ反映され、WordPressへ再配置される
15:54  ★スクリーンショットが撮り直される
15:58  ★README が書き換わる
```

**なぜ起きたか。** ビビが**1周目の検査完了を受けて「もう当ててよい」と作る役へ伝えた**あとに、
**2周目の検査を出した。** どちらの指示も単体では正しく、**重なる可能性を見ていなかった。**

## 何が壊れるか

- **検査結果がどの版に対するものか分からなくなる。** 「載せてよい」がどの中身への判定か特定できない。
- 検査役は**同じ測定が違う値を返す**という矛盾を踏む。今回は 1,207px → 0px。
  ステラが mtime を取り直して初めて原因が分かった。
  **片方だけ採っていれば、誤った検査結果がそのまま流通していた**
  → fukuchi-core「出力に矛盾があったら都合のいい方を採らない」がそのまま当たった実例。

## 型（次からこうする）

```
検査へ出すとき   ★対象ファイルの sha256 を添えて渡す。「この版を見てください」と明示する
検査の間         ★作る役は対象を触らない。手が空くなら別の対象へ回す
                 （今回なら「20本の分解の下ごしらえ」など、検査対象の外）
検査が返ったら   その版に対する判定として受け取り、そこから当てる
判定の書き方     検査役も「検査した版」のハッシュを判定に添える
```

**★「検査待ちも停止である」（有璽氏）と矛盾しない。** 止めるのは**その対象への書き込みだけ**で、
人を遊ばせろという意味ではない。**窓口（ビビ）が、触ってよい別の対象を同時に渡す。**

**★窓口の責任。** 作る役は指示どおり動いただけ。**重なる指示を出したのは束ねる側。**
