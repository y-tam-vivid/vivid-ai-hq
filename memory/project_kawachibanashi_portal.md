## ★写真のトーンが本体と合っていない（2026-09-08 実測）

**有璽氏「今入っている写真も最適なものでないと理解している」。実測すると原因は1つに絞れた。**

サイト本体が約束しているトーンと、写真のトーンが**逆**。3経路で一致した。

| 見た場所 | 出ている色・雰囲気 |
|---|---|
| ロゴ（uploads/C87337A4…png） | 水彩イラスト・青空・新緑・ぶどう紫・菜の花黄・桜ピンク・虹の縁＝**ハイキー** |
| CSSの配色（v4.dc.html） | `#FBF3DC` クリーム／`#FFFFFF`／丸ゴシック Kiwi Maru／破線の丸・波線＝**やわらかい** |
| 参考サイト まつもトコトコ | 順光・高彩度・主題ドアップ（トマト・松本城・おやき）＝**明るいカタログ写真** |
| ★いまの写真5枚 | 逆光・低彩度・黒/茶に沈む・引きの構図＝**大人のフォトエッセイ** |

**＝「良い写真か」ではなく「役割が違う」。** いまの5枚は *読ませる写真*。必要なのは *探させる写真*。

### ★有璽氏の言葉は「暗い」でなく「**異なっている**」（2026-09-08・本人が承認）

> 「素材写真の**明るさとかが異なっている**ように思います」

**★私は「暗い」と診断したが、本人の見え方は「揃っていない」だった。こちらが本質。**
「暗い」だと1枚ずつ明るくして終わる。「揃っていない」なら**基準値を1つ決めて全枠を合わせる**
話になり、対処がまったく違う。→ [[feedback_uniform_unless_reason]] と同型（明るさ版）。

**実測（平均輝度0-100／彩度0-100／明るさ25未満の画素の割合）**

```
                      明るさ   彩度   暗部
いちじく                35.4   38.3   47.4%   ← 5枚で最も明るい
イベント特集(夜の縁日)    33.7   47.9   53.8%
hero 川辺マルシェ        24.1   46.2   65.4%
喫茶店                  18.9   58.2   77.7%
古墳                    10.9   59.6   87.3%   ← 最も暗い
                      ★ひらき 24.5（最明と最暗で 3.2倍）

参考 まつもトコトコ hero   64.5   40.3    7.7%
     かわちばなし ロゴ     81.8   24.6    0.5%
     サイト地色 #FBF3DC   95.2 ／ #FFFFFF 100.0
```

**問題は2つ重なっている。**
① 写真の平均 **24.6** に対し**地色は 95**。落差70＝**写真の場所だけ穴が開いて見える**
② **5枚どうしも揃っていない**（10.9 と 35.4 が同じ画面に並ぶ）

**★目標値（これが選定・生成の合否線）**

```
明るさ  60〜70        ★1枚ごとに測る。ひらきは ±8 以内に収める
彩度    35〜45        ★60超は「濃い」。ロゴ(24.6)より少し高い程度でよい
暗部    15% 未満      ★これを超えたら順光で撮り直し／生成し直し
```
**目視で決めない。ただし数値だけでも決めない（下記）。**

### ★補正では直らない ── 数値は合格したが目視で不合格（2026-09-08 実測）

明るさ65・彩度40へ寄せる補正（ガンマ＋彩度復元）を5枚に当てた結果：

```
数値   L65 / S40 / 暗部0〜4%     ★5枚とも合格
目視   暗部から緑と青のノイズが浮く／古墳は全体が青緑に転ぶ／
       夜の縁日は「夜のまま明るい」で不自然   ★4枚が不合格
例外   いちじく のみ破綻しない（元が L35.4 と最も明るかった）
必要だった補正量  γ0.15〜0.30・彩度×2.5〜3.3 ＝ ★無理な持ち上げ
```

**★元の写真に光の情報が無ければ、後処理では作れない。**
**★そして「合否線を数値で置く」だけでは足りない。数値の合格は目視の合格を意味しない。**
判定は必ず **数値 → 目視** の2経路。→ [[feedback_one_route_is_not_verification]]
比較シートは scratchpad `compare2.jpg`（左=いま／右=補正後）。

## ★実写を拾ってくる道は塞がっている（実測・6枚を1枚ずつ見た）

Wikimedia Commons に南河内の実在の場所の写真は**在る**（古市古墳群・津堂城山古墳・葛井寺・
道明寺天満宮・道の駅しらとりの郷・河内音頭）。**だがトップページには使えない。**

```
古市古墳群（高尾山から）  冬の霞んだ市街地。★古墳がどこか分からない
津堂城山古墳             冬枯れ＋工事の緑の柵が主役
誉田御廟山古墳の空撮      ★飛行機の翼が写り込み・曇天
道の駅しらとりの郷        冬の駐車場・人が1人もいない
河内音頭                 夜・★日付が焼き込まれている・★顔が特定できる（肖像権）
```

**Commonsは記録写真の器。観光写真の器ではない。** 探し方の問題ではなく、在るものが違う。
→ **イメージ画像は生成でよい。直すのはソースではなくトーン指定。**

## イメージ写真の選定・生成の基準（この6つを外さない）

```
① 順光・日中・晴れ           逆光と夜を使わない（hero は上に暗いグラデーションが重なる）
② 主題が画面の6割以上         引かない。「何の写真か」を1秒で言えること
③ 空か白い壁が入る            画面のどこかに明るい抜けを作る
④ 顔を写さない                手・後ろ姿・引きの群衆まで（肖像とリアル過ぎを同時に避ける）
⑤ 彩度は高め                  ★緑・黄・水色が出ること。茶と黒に寄せない
⑥ 文言と絵を一致させる        「ぶどうマルシェ・昼・河川敷」に夜祭りの写真を当てない
```

## ★一括生成の道具（2026-09-08 新設・実測済み）

```
bin/image_tone.py                        トーンを測って合否を返す（★読むだけ・汎用）
bin/gen_images_openai.py                 OpenAIの画像APIで全枠を一括生成→測定→不合格は作り直し
scratchpad/kawachibanashi_prompts.json   共通指定1本＋枠ごとの差分18件
```

- **★既定はドライラン。`--run` を付けたときだけ課金される。** 概算は 18枚 × gpt-image-1.5 high
  ＝ **$2.39**（作り直しが最大まで走ると $7.18）。**★1経路（第三者のまとめ）でしか確かめて
  いない。公式ページはトークン単価のみで1枚換算を載せていない。**
- 鍵は `~/.vivid-relay/config.env` の `OPENAI_API_KEY`（既存4件と同じ形）。★両機に入れる。
- **★ChatGPT Plus の課金とAPIの課金は別。** Plus を払っていてもAPIのクレジットは0から。
