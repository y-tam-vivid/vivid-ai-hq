## ★デザイン側への依頼文は「案件フォルダ直下の `0X_デザイン側への指示文/`」へ番号順に置く（2026-10-06 有璽氏）

```
「今回格納したやつも、このデザインの修正依頼文みたいなものも、
  何かフォルダを作ってそこに格納していってください。今後も発生すると思うので。」
```

**★置き方（かわちばなしの形を全案件の標準にする）**

```
<案件フォルダ>/0X_デザイン側への指示文/
  01_YYYYMMDD_修正依頼_内容_★これを渡す.txt     ← いま渡すもの。★印は1本だけ
  02_YYYYMMDD_修正依頼_内容_旧版.txt            ← 渡し終えたら _旧版 に改名（消さない）
```

- **★連番は渡した順。** 中身でなく「いつ渡したか」で並べる。
- **★`★これを渡す` は常に1本だけ。** 新しいものを置いたら、前のを `_旧版` へ改名する
  （かわちばなしで v1・v2 を旧版にした実績。**どれを渡すか迷わせない**）。
- **★消さない。** 旧版は残す。何を依頼したかが案件の履歴になる。

**🔴 2026-10-06 実測 ── 捨ててはいないが、置き方がバラバラで二重になっていた**

```

こどもステーション ★3か所に散在。しかも★同じ指示文が2か所に（sha256 一致 2bbbf6c73859）

チラシ系        制作物フォルダの奥（クライアントから届いた修正依頼。これは別物＝受け取ったもの）
```

★**「こちらが出す依頼文」と「先方から届いた修正依頼」は分けて置く。**混ぜると、どちらが指示か分からなくなる。

## ★Webサイトを作るときの案件フォルダは、この番号で作る（2026-10-06 有璽氏・型）

```
「今後ウェブサイトを制作する際も同じような形、形式で行えたらと思います。
  子どもステーションとか、かわちばなしとかがそこの参考になるモデルかなと個人的に思っています。」
```

**★正は「かわちばなし」の形。** 実際に 00〜06 で回っていて、人が開いて迷わない状態になっている。
こどもステーションは同じ中身を別の番号で持っており（下の対応表）、★番号の意味が案件ごとに違うのが唯一の不便だった。

**★新しくWebサイトの案件フォルダを作るときは、これをそのまま使う。**

```
<案件フォルダ>/
├─ 00_はじめに読む_案件の地図.md   ★必須。30秒で「いま何ができているか」が分かる1枚
│                                  公開URL・合言葉・ページ一覧・中身の更新経路・次の本筋
├─ 01_コンセプトと読者像           誰に何を届けるか・収益の柱・★参考サイト（真似たい画面）
├─ 02_デザインの版                 デザイン側の書き出し（版番号順・★最新が正）
│                                  └ 00_デザインシステム/  色・字・部品（★作る前に決める）
├─ 03_デザイン側への指示文         連番・★これを渡すは常に1本（上の節の置き方）
├─ 04_画像素材                     用途別に小分類（見出し／アイコン／全体／記事／図）
├─ 05_公開と計測                   公開URL・ドメインとDNSの手順・Clarity/GA4/Search Console
├─ 06_検査と報告                   担当への指示と担当の報告を★交互に（01指示→02報告→03指示…）
├─ 07_先方とのやり取り             ★要るときだけ。確認リストと回答・団体から受け取った素材
└─ 08_集客と広告                   ★要るときだけ。Google広告・Ad Grants・SNS告知
```

- **★空フォルダを先回りで作らない。** 07・08 は必要になってから作る（上の節と同じ理由）。
- **★番号は中身でなく「制作の流れの順」。** 決める→作る→渡す→素材→出す→検査、の順に並んでいる。
- **★名前はツールに依存させない。** 「ClaudeDesign書き出し」ではなく **02_デザインの版**、
  「写真・イラスト素材」ではなく **04_画像素材**。★デザインを作る道具が変わっても名前が生き残る。
- **★デザインシステムは 02 の中**（`02_デザインの版/00_デザインシステム/`）。デザイン側が版と一緒に食うもので、
  指示文（03）とは別物。★案件直下に zip を置きっぱなしにしない（こどもSでそうなっていた）。
- 雛形：`03_デザイン制作プロジェクト/_雛形_Webサイト案件/`（00の地図の空欄入り＋この表）。

**★実測した2案件（2026-10-06・Drive を直接数えた）**

```
かわちばなし 06_…/   00_地図.md ／ 01_コンセプトと読者像(2) ／ 02_デザインの版(17) ／
                     03_デザイン側への指示文(22) ／ 04_画像素材(7) ／ 05_公開と計測(7) ／ 06_検査と報告(6)
こどもS 04_…/05_こどもステーションWEBサイト/
                     01_団体への確認リスト ／ 02_Google広告 ／ 03_ClaudeDesign書き出し ／
                     04_写真・イラスト素材 ／ 05_デザインシステム ／ 06_デザイン側への指示文
                     ＋★案件直下に デザインシステムの実体と .zip ／ 参考サイト_… が裸で置かれている
                     ★00の地図が無い ＝ 開いた人が「いまどこまで出来ているか」を掴めない
```

**★番号の読み替え（こどもSを開くとき）**

| 型 | こどもS の実際 |
|---|---|
| 01_コンセプトと読者像 | （無し）／参考サイト_子どもは未来WEBサイト が案件直下 |
| 02_デザインの版 | 03_ClaudeDesign書き出し |
| 02/00_デザインシステム | 05_デザインシステム（＋案件直下の実体と .zip） |
| 03_デザイン側への指示文 | 06_デザイン側への指示文 |
| 04_画像素材 | 04_写真・イラスト素材 |
| 05_公開と計測 | （無し。公開手順は memory とビビの報告にある） |
| 07_先方とのやり取り | 01_団体への確認リスト |
| 08_集客と広告 | 02_Google広告 |

**★こどもSのフォルダは今回★改名していない。** 理由は2つ、どちらも実測した事実。
①`05/02_Google広告` 等のパスが memory に**7か所**書かれている（うち Ad Grants は 10/7 に使う）。
②サイト本体の作業が進行中（v46・リンク修正を依頼中）。
**★改名するなら、記録のパスを同時に書き換えるのが条件**（10/6 にかわちばなしで、番号を変えた後に古いパスへ書き続けて空フォルダが増えた事故を踏んでいる＝上の節）。
→ 揃えるかどうかは有璽氏の判断。Current_Focus にタスク行を1本出した。

**How to apply:** Webサイトの案件フォルダを新設するとき、または既存案件に新しいフォルダを足すときは、
上の番号と名前を使う。**★最初に作るのは `00_はじめに読む_案件の地図.md` 1枚**（これが無いと、
次に開いた人・次のセッションが「いまどこまで出来ているか」を探し直すことになる）。
