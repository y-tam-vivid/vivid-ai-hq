**承認を求めすぎるな。有璽氏はこれを何度も指摘している。**

> 「承認ダイアログっていうの、頻繁に出てくるやん。それないと進まへんやろ。
>   もう無視して進んだらええと思うけど、よっぽどのことがなければ。
>   数多すぎるねん。自動で進めていいよって言ってねんやん」（2026-08-20）
> 「このやりとりも何回もしてる。承認が多すぎるっていうのも、さっきから何回も言ってる。
>   **なんでそれが共有されてないねん**」（同日）

> 「**止まらずに進めろ**」（2026-08-20・Slack DM）

**Why:** 承認待ちは「安全」ではなく**停止**。判断を人へ押し返しているだけ。
規範（fukuchi-core）は既に「★既定は自分で進める。可逆な操作は承認を待たずに実行する」
「★確認は溜めて1回にする。一手ごとに承認を求めない」と定めている。
にもかかわらず、**設定（`~/.claude/settings.json`）が「基本ぜんぶ聞く」のままだった**。
規範と設定がずれていて、規範の側だけ直しても止まらない。

**How to apply:**

```
承認が要るのは6つだけ（規範）
   外へ出る（送信・公開）／お金（課金・契約・発注）／正本の削除
   規範の変更／人に配るもの／大きな分岐
これ以外は バックアップを取ってから 自分で進める。聞かない
```

- **設定で担保する。** 規律ではなく `permissions` で。2026-08-20 に
  `defaultMode: "dontAsk"` ＋ allow 58件 ／ ask 11件（送信・削除系だけ）／ deny 6件 にした
- **止まったらSlackへ知らせる。** `PermissionRequest` フックが
  `~/.vivid-relay/hook_permission_slack.py` を呼び、何を承認しようとしているかをDMへ出す。
  **止まっているのに本人が知らないなら、それは止まっているのではなく消えている**
- **同じ指摘を2度させない。** 指摘を受けたらその場で memory に書く。
  「一度踏んだ地雷は手順書に落として再発を止める」は規範にあるのに、
  2026-08-20 は1日で同じ型の指摘を5種類受けて、どれも記録していなかった

**★「検査待ち」も停止である**（2026-08-20 有璽氏「止まらずに進めろ」）

> 承認を減らしても、**検査の返事を待って手が止まれば結果は同じ**。
> つる（data-auditor）の検査は必須だが、**待っているあいだに他の残件を進める。**

```
つるへ投げる  →  待たない  →  別の残件を進める  →  返ってきたら合流して書く
```

- 検査は **並行**で回す（Agent は背景で走る）。直列に並べると1件ごとに数分止まる
- 報告は溜めて1回。「投げました」「返りました」を都度出さない
- 止まってよいのは規範の6項目に当たるときだけ。**それ以外で止まったら理由を書く**

**★「バックアップ→提示→承認→実行」を宣言したら、着手可否は別途聞かない**（2026-08-23）

正本（受付シート）の値を機械が書き換える件で、こちらから
「これは当方でやりますか？ その流れで進めます」と確認した。返答は
**「そちらでやってください。その流れで進めてください」**。

- **4段フローの宣言そのものが安全装置。** 宣言したうえで「やっていいですか」を重ねるのは、
  同じ承認を2回取っているだけ。**承認を取るのは③の1回（変更内容の提示）に寄せる**
- 有璽氏に投げてよいのは **③のdiff** であって、**①着手の可否ではない**
- 規範6項目（外へ出る／お金／正本の削除／規範変更／人に配る／大きな分岐）に
  当たらない限り、**値の書き換えは着手可否を聞かずに①②まで進める**

**★「判断待ち」に積むと、こちらの停滞が人の判断のせいに見える**（2026-08-23 実測）

申告倒れ7件について「人が要るのは1件だけ。**残り6件はこちらで進められる**」と自分で出しながら、
着手しなかった。有璽氏に「**ゼロのやつは全部やってくれた?**」と聞かれるまで、
6件は判断待ちの欄に積まれたままだった。

```
実態     こちらが手を止めていた
見え方   有璽氏の判断待ちで止まっている  ← ★停滞が人のせいに転嫁される
```

- **★進めてよいものを判断待ちに混ぜない。** 「人が要る」と「こちらで進める」を
  同じ表に並べた時点で、読む側からは全部が自分待ちに見える。**表を分ける**
- **★判断が要るのは「止めるか動かすか」だけ。** 動かす準備（調査・下書き・バックアップ・
  ドライラン）は判断を待たずに進め、**判断が来た瞬間に反映できる状態**まで作っておく
- 報告に「有璽氏の判断待ち」と書くときは、**その1件以外は全部こちらで動かし終えてから書く**。
  そうでなければ、待っているのは人ではなくこちらである
- 同じ形 → [[feedback_find_holes_without_being_told]]（指摘される前に探す）

**★止めるなら「案件ごと」でなく「操作ごと」に止める**（2026-08-24 実証）

2026-08-18、ビビ朝ブリーフィングへの Slack 通知の設計を作り、差分まで用意して
「この差分で update をかけてよければ実行する」で止めた。**6日間、誰も拾わなかった。**
8/24 に有璽氏から出たのは「これ、Viviからの重要な通知って今止まってるよね。
**どうやったらいいやったっけ**」── 内容が本人の記憶からも落ちていた。

```
承認が要ったのは       Slack へ投稿する（外へ出る）── これ1点だけ
承認が要らなかったのは  routines/ にプロンプト正本を新設する（可逆）
                       差分を書いて用意しておく（可逆）
                       締切2DBの集約を足す（Notionに書くだけ・可逆）
実際にやったこと        全部止めた ← 誤り
```

- **1点のために案件ごと止めない。** 承認が要る操作だけを最後に残し、
  手前の可逆な部分は全部やり切ってから「ここだけ押してください」を出す。
- **★止めたものは `WORKING.md` に置く。** このときどこにも書かなかったので、
  会話が終わった時点で消えた。**保留は「意図的な保留」として可視化する**のが規範
  （fukuchi-core「意図的な保留を可視化して持つ。着手トリガーを併記する」）。
  会話にしか無い保留は、保留ではなく消失。
