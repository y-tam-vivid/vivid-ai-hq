# 人が選んだ答えを、書き込み先で実物を見て確かめる

**11/6 の実例**：議事録カードで有璽氏が「区分=社内／共有=する」を送った3件（#71f409・#5d31ea・#b4e8a9）が、全社へ共有=false のまま残っていた。
作りが「社内・個人なら共有を付けない」という分岐で、答えはメモ欄に出るだけで捨てられていた。送信は成功と表示され、誰も気づかなかった。
有璽氏の答えを書き込み先（write_log）で見て初めて分かった。

**Why:** 送信の成功表示・カードの「回答済み」表示は、答えが台帳に入った証拠ではない。
分岐の既定値（「無ければ付けない」など）は、人の答えより優先されて黙って効く。

**How to apply:**
- 人の答えを受けて書き込む仕組みを作ったら、答えの種類ごとに **書き込み先の実物** を1件ずつ読む（送信画面・ログでなく台帳）。
- 「答えが無い時の既定」と「答えがある時の扱い」を別々に書く。答えがあるのに既定の分岐へ落ちる経路を残さない。
- 既に送られた答えは、作り直した後に **さかのぼって** 当てはまるものを拾う（11/6 は #b4e8a9 だけ付け直し、機微の列を見て他は付けなかった＝判定の正は列）。
