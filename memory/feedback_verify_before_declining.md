**「できない」と書く前に、実際に試すか仕様を確認する。** 憶測で断らない。

2026-08-19、ビビのroutineプロンプト改修について当方は
**「APIは部分更新ができないのでプロンプト全体を書き直す形になる」**と書いた。
確認したところ**トップレベルの部分更新はできる**（`name`/`cron_expression`/`enabled`/`job_config`）。
`job_config` が入れ子なので中身は全体送信になる、というのが本当の制約だった。
**結論は同じでも根拠が違った。**

さらに、断った本当の理由はAPIの制約ではなく
「6,000字を転記して送り直すと1行落ちても気づきにくく、毎朝動くものを壊しうる」だった。
**「できない」と「やれるが勧めない」を混ぜたまま断った** ＝ 判断材料を渡していない。

## 返し方の型（有璽氏の指示・2026-08-19）

```
① まず実際に試すか、仕様を確認する
② 「できる／できない」を事実として述べる
③ できるが望ましくない場合は、その理由を明示する
④ 「やりますか」まで出して、判断を渡す
```

**「望ましくないので私はやりません」で止めない。** 止めた時点で選択肢が消える。
理由を添えたうえで、選ぶのは有璽氏。

**入力できるものは基本的に入力していく**（有璽氏の方針）。手を止めるのは、
実測したうえで「壊したときに戻せない」と判断したときだけ。

## ★「できない」の前に「人ならできるか」を考える（2026-08-20 追記）

MacBookへフックを入れる件で、当方はこう言った ──
「**MacBookでの実行だけ、こちらからはできません（sshで入れないため）**」。

有璽氏の返し ── 「`cd ~/vivid-ai-hq && ./bin/setup_hooks.sh` これをターミナルで
MacBookで貼り付けたらいいんじゃないの？ 違うの？」

**そのとおりだった。** 自分が実行できないことを、そのまま「できない」と報告していた。
正しくは **「有璽氏が1行貼れば済む。その1行はこれ」** と渡すこと。

```
✗  「こちらからはできません」            ← 制約の報告で終わっている
✓  「この1行を貼ってください ： …」      ← 人が動ける形で渡す
✓  「入ったかの確認は … と出れば成功」    ← 確認方法までセットで
```

規範（fukuchi-core）は既にこう定めている ──
「★人の手が要る作業は、**押す場所まで特定してから渡す**。調べずに渡すと往復が増える」。
**「自分にはできない」で止めるのは、渡してすらいない。**

## ★「人の判断が要る」も、候補を揃えるまでが渡す作業（2026-08-20 有璽氏）

法人番号の残件を **「書くな2件（根拠が社名だけ）／人の判断2件（候補複数・運営法人不明）」**
と分類して出した。有璽氏の返し ──

> 「かけない2社については、**候補を挙げてください**。そこから判断する。
>  **判断がいる方は、こちらも候補を挙げてください。**」（2026-08-20 09:15）

**分類は仕事の半分でしかない。** 「書けない」「人が決める」というラベルだけを渡すと、
有璽氏は0から調べ直すことになる ＝ 往復が1回増える。

```
✗  「根拠が社名だけなので書けません」        ← 止めた理由の報告で終わっている
✗  「候補が複数あるので判断をお願いします」   ← 候補を見せていない
✓  「候補は A / B。Aは住所一致・Bは商号のみ一致。決めるのは有璽氏」
```

- **★止める判断と、材料を揃える作業は別。** 止めても材料は出す
- **候補は根拠つきで並べる。** 何が一致して何が一致しないかまで書く
  （実際にこの形で出し直したところ、MIKKE HOUSE は1件に絞れた
  → [[reference_facility_vs_corporation]]）
- 同じ型 → [[feedback_batch_the_checks]]（確認は溜めて1回）

## ★手順を渡す前に、渡す先の実物の形を見る（2026-08-23 実地）

GAS 54v3 を止めてもらうため、有璽氏へこう渡した ──
「`function intakeMigrateRun2() {` の**次の行**に `return;` と打ってください」。

**実物はこうだった。**

```javascript
function intakeMigrateDry2() { intakeMigrate2_(true); }
function intakeMigrateRun2() { intakeMigrate2_(false); }   ← ★1行に収まっている
```

「次の行」という指示に忠実に従うと、`return;` が**関数の外**に置かれる。
トップレベルの `return` は構文エラーで、**そのプロジェクトのGASが全部動かなくなる**
（同じプロジェクトに毎朝7〜8時のSalesBreaker取り込みが同居している）。

```
渡したもの   押す場所・関数名・打つ文字 ── ここまでは特定できていた
見ていない   ★その関数が何行で書かれているか
結果         正しく従うほど壊れる手順になった
```

- **★「押す場所まで特定する」は、実物の形を見るところまで含む。**
  関数名が分かっただけでは、まだ渡せる状態ではない
- **人が打つ手順は「挿入位置」でなく「置き換えたあとの1行の全文」で渡す。**
  ★有璽氏はコピーできないので、打ち替える文字数が最小になる形を選ぶ
  （今回の正解は `{` の直後へ `return; ` の9文字）
- **★実行して確かめる手順を必ずセットで渡す。** それも**書かない方**で。
  今回は `intakeMigrateDry2`（ドライラン）を実行すれば、書き込みなしで構文を検証できた

## ★「認証情報が無い」は「できない」の理由にならない（2026-08-23 実地）

さくらのコントロールパネルでDNSのAレコードを1行足す作業。当方はこう答えた ──
「`~/.netrc` は無い、`config.env` にさくらの情報は無い、レンタルサーバにゾーン編集APIも無い。
**よって当方からは実行できない**」。実測に基づいてはいた。**だが経路を1つ数え落としていた。**

有璽氏「こちらの追加はそちらで設定できますか？」

```
数えた経路    APIキー／CLI／設定ファイルの認証情報      ← どれも無い
★数え落とし  ログイン済みのブラウザ（claude-in-chrome）  ← 有璽氏の実Chromeを操作できる
```

- **Web UIしか無い操作でも、人がすでにログインしているブラウザがあれば代行できる。**
  「APIが無い＝人の手が要る」と短絡しない
- **代行してよい線引き**：パスワードを入力するのは代行しない。
  **既にログイン済みのセッションで画面を操作するのは、認証情報の入力ではない**
- 設定変更そのものは要承認カテゴリなので、**依頼があること**を確認してから触る
- 型は同じ → [[reference_salesbreaker_engagement_api]]（`deals/search` しか見ずに「取れない」と9日止めた）

**「できない」と言う前に、経路を数え上げたか自問する。** 今回で言えば
①API ②CLI ③設定ファイル ④**ログイン済みブラウザ** ⑤人の手。④を飛ばして⑤へ渡していた。

**そのうえで、④も実測した結果は「使えなかった」（2026-08-23）。**
`claude-in-chrome` は拡張が未接続（未インストールか未サインイン）。
アプリ内ブラウザ（`Claude_Browser`）は別のブラウザでログインセッションを持たないため、
さくらへ入るにはパスワード入力が要る ＝ **これは代行しない**。

```
① API                無い（さくらのレンタルサーバにゾーン編集APIは無い）
② CLI                無い
③ 設定ファイルの鍵    無い
④ ログイン済みブラウザ ★拡張が未接続。入れてサインインすれば以後は代行できる
⑤ 人の手             ← いまはここ
```

**★「できない」と答えるときは、数えた経路を全部並べる。**「認証情報が無いので無理です」は
経路を1つしか数えていない答え方。並べれば、④を直せば次から代行できると分かる。

## ★Googleフォームは作れない。GASで「1回叩くだけ」にして渡す（2026-09-05）

有璽氏「インタビューのについてGoogleフォームで回答してもらえるようにしたいのでフォームを作成して」

```
できない   ★Driveの経路で中身なしに作れるのは 文書・表計算・スライド・フォルダ だけ
           （道具の説明にそう書いてある。フォームは含まれない）
やった形   Apps Script を書き、★有璽氏が1回貼って実行するだけにした
           → 保護者用・スタッフ用の2本＋回答が集まる表が自動で作られる
```

- **★「できません」で止めない。人が1手で終わる形まで作って渡す。**
  今回は押す場所（`script.google.com` の新規作成→貼る→実行）を手順に書いた。
- **🔴コードをGoogle文書に入れて渡さない。** 記号（`_` `[` `!`）が変換され、
  引用符も勝手に変わって**動かなくなる**。★プレーンテキストのファイルとして置く
  （`disableConversionToGoogleType: true`）。実測：文書側は記号がエスケープされていた。
- **★渡すものは2つに分ける** ── 手順（読む用・文書）／コード（コピーする用・テキスト）。

### 🔴 作ったフォームは「外の人が開けるか」まで確かめる（2026-09-05 実測）

有璽氏がGASを実行し、フォームは無事できた。**だが保護者は開けなかった。**

```
実測2経路 → 一致
  経路1  公開URLをそのまま叩く            → 401・accounts.google.com へ
  経路2  ブラウザのふりをして叩く（UA付き） → 401・ServiceLogin へ
```

- **★原因は書き漏らし。** `FormApp.create()` は、組織アカウントだと既定で
  **ログインを要求する状態**になる。`form.setRequireLogin(false)` を書かないと外の人は開けない。
- **★「フォームができた」と「配れる」は別。** 作成の成否だけ見て渡すと、
  保護者に配ってから「開けません」と返ってくる。**★配る前に、ログインなしで叩いて確かめる。**
- ★同じ型 ── 公開したVercelの固定URL・Slackの投稿・仮公開サイト。
  **作った側の画面では全部うまくいって見える。受け取る側の条件で1回叩く。**
  → [[reference_vercel_free_plan_protection]]（デプロイした≠見えている）
