**枠を先に出しておく設計は、中身が1件のときの見え方まで決めて初めて完成する。**

2026-09-24、JFBI調査研究サイトで有璽氏の指摘 ──
> 「協力団体のところ、このメンバーとかと**同じような形で**2団体掲載できるようにしていきたい。
>  2か3かかな。ので、そういう形にしてほしいです。レイアウトを調整して。」

**★「増やせるようにして」ではなく「同じ形にして」と言われている。**
実装側は「団体が増えれば自然に横へ並ぶ」と思っていた。**実際に増えれば並んだ。**
だが**いま画面に出ているのは1件**で、その1件が全幅に伸び、すぐ上のメンバー2枚と
形が違って見えていた。**将来は正しいが、いま見えている絵が違う。**

## 機械の側の理由（同じ書き方をすれば毎回起きる）

```css
grid-template-columns: repeat(auto-fit,  minmax(min(100%,400px),1fr))   ← 1件だと★全幅へ伸びる
grid-template-columns: repeat(auto-fill, minmax(min(100%,400px),1fr))   ← 1件でも★1列分に収まる
```

**auto-fit は空になった列を畳む。** 畳んだぶんの幅が残った1件へ回るので、
**件数によってカードの幅が変わる。** auto-fill は列を畳まないので幅が一定。

実測（2026-09-24・JFBI・コンテナ1120px／gap24px）

```
            1件         2件              3件
auto-fit    全幅1096    548 + 548        （2件目以降は同じ）
auto-fill   ★548       548 + 548        548 + 548 ／ 2行目の左に548
メンバー枠   548 + 548  ← ★揃えたい相手はこれ
```

折り返す幅も一致させること。**同じ 400px を指定すれば、1列へ落ちる幅も同じになる**
（実測：824px で両方とも1列。823px でも一致）。ここがずれると、
ある幅だけ「片方は2列・片方は1列」になり、また形が違って見える。

## 型として持っておくこと

- **★「あとで増える枠」を先に出すときは、0件・1件・2件・3件の4通りを実際に描いて見る。**
  こちらは2件以上しか想定していなかった。**人が見るのは、いま入っている件数の絵。**
- **★隣に並んでいるブロック（ここではメンバー）を基準にする。**
  「揃える」の相手は仕様書ではなく**同じ画面で隣に見えているもの**
  → [[feedback_uniform_unless_reason]]
- 高さが違うカードは、末尾のリンクに `margin-top:auto` を当てて下端を揃える
  （`.card` が `display:flex; flex-direction:column` である前提）。
- 枠を先に出す判断そのものは正しい（先方へ「ここに載ります」と実物を指して依頼できた）
  → [[project_jfbi_research_site]]。**直すのは出し方であって、出したこと自体ではない。**
