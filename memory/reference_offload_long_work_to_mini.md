**MacBook がスリープすると、走っているサブエージェントは全部同時に止まる。**
2026-09-04 に5体が「10分無応答」で落ち、うち1体が明示的に返した ──
`API Error: Your computer went to sleep mid-response.`

**★「1体に大量に渡すと落ちる」と誤診し、分割で対処しようとして無駄にした。**
分割しても3体とも落ちた。**真因は件数でも担当でもなく、マシンの電源状態だった。**

## 有璽氏の制約（2026-09-05）

> 「MacBookをスリープにする。**持ち運ぶときにスリープになってしまう**んだけど、これは致し方ない。
> なんかその中でも動いてもらう方法はないかな。**指示はここで出している。（…）
> 裏側ではMac miniで実際は作業させているみたいなことってできないですかね。
> ★今のこのセッションの延長で**ってことです。」

**★スリープを我慢してもらう方向で直さない。**仕組みの問題を人に吸収させない。

## できること・できないこと（★実測に基づく）

```
✕ サブエージェント（LLM）を mini へ移す
   → エージェントは MacBook のプロセス。★移せない。スリープで必ず止まる

◎ ★スクリプトを mini へ切り離して走らせる
   → ssh + nohup で投げれば即座に返り、★mini 側で走り続ける
   → ★MacBook がスリープしても関係ない。結果はファイルに残る
   → ★セッションは MacBook のまま。新しいセッションを立てる必要は無い
```

```bash
# 投げる（即座に返る）
ssh mini 'nohup python3 ~/.vivid-relay/<script>.py > ~/.vivid-relay/<name>.log 2>&1 &'

# あとで結果を見る（別のターンでよい）
ssh mini 'tail -30 ~/.vivid-relay/<name>.log'
ssh mini 'ls -l ~/.vivid-relay/<出力ファイル>'
```

- **★`ssh mini 'python3 …'` を前面で待たない。**待つと ssh 接続がスリープで切れる。
  `nohup … &` で切り離す。**「投げる」と「結果を見る」を別のターンに分ける。**
- ★mini には Google の認証（`sheets_client.py` / サービスアカウント）が在る。
  **MacBook には無い。**Drive・スプレッドシートを触る処理は元々 mini 側でしか動かない。
- ★`~/.vivid-relay/` は git 管理外。**両機で自動同期されない。**置いたら実測で確認する。

## ★どこまでを「スクリプト」にするか

**LLMに1件ずつ判定させる作業は、たいてい機械で書ける。**

```
機械で書ける   対応表の完全一致／既知パターンの検出／コード表の引き当て／
              日付や金額の正規化／残ったものを「未判定」にする
LLMが要る      ★新しい摘要をどう分類するか＝全体のごく一部
```

**★LLMに回す件数を減らすほど、落ちにくく・速く・毎回同じ結果になる。**
→ fukuchi-core「繰り返す作業はスキル化し、どの端末でも同じ結果が出る状態にする」。
