**MacBook がスリープすると、走っているサブエージェントは全部同時に止まる。**
2026-09-04 に5体が「10分無応答」で落ち、うち1体が明示的に返した ──
`API Error: Your computer went to sleep mid-response.`

**★「1体に大量に渡すと落ちる」と誤診し、分割で対処しようとして無駄にした。**
分割しても3体とも落ちた。**真因は件数でも担当でもなく、マシンの電源状態だった。**

## 有璽氏の制約（2026-09-05）

> 「MacBookをスリープにする。**持ち運ぶときにスリープになってしまう**んだけど、これは致し方ない。
> なんかその中でも動いてもらう方法はないかな。**指示はここで出している。（…）
> 裏側ではMac miniで実際は作業させているみたいなことってできないですかね。
> ★今のこのセッションの延長で**ってことです。」

**★スリープを我慢してもらう方向で直さない。**仕組みの問題を人に吸収させない。

## ★★2026-09-05 実測 ── **AIごと mini へ投げられる。「移せない」は誤りだった**

有璽氏の指摘 ──「**AIはミニ側にはないんだっけ？なんでないんだったっけ？**
GitHub側にあるような状態にできるから、それは関係ないんじゃないの？」
**★指摘が正しく、ビビの説明が不正確だった。**

```
実測1  mini に claude CLI が在る            ~/.npm-global/bin/claude  2.1.261
実測2  ★非対話 `claude -p` が動く。認証も通っている
実測3  ★nohup で切り離せる。投げた瞬間に返る（rc=0）。45秒後にログへ答えが書かれていた
実測4  ★mini 側の AI も fukuchi-core の規範を読み、Stopフックまで効いている
```

**★「サブエージェントは MacBook のプロセスだから移せない」は、範囲が狭すぎる説明だった。**
移せないのは**このセッションのサブエージェント**であって、**mini で AI を走らせること自体はできる。**

## ★★恒久の運用（2026-09-05 有璽氏が承認）── **これを既定の形にする**

> 「構造的には良いと思います。**基本MacBook側ではViviと私がディスカッションし、Viviから
> SSHミニを活用して各AIやエージェントに投げてもらう。**
> **Viviとそのmini側とのやり取りも、このMacBook側にも出してもらってもいい**と思います。
> その方が**進捗がわかる**ので。**整理はしてもらえた方がありがたい**のは確かですが。
> なので**私自身がMacBookから指示をし、ただMacBookがスリープしても、
> Mac mini側のエージェントたちは動いているという状態を作りたい。**」

```
MacBook   ★有璽氏 ⇄ ビビ の議論の場。ここだけを人が見る
mini      ★実作業の場。ナミ・つる・ピタゴラス等をここで走らせる
ビビ      ★橋渡し。ssh で投げ、★結果を「整理して」MacBook側へ出す
```

- **★mini とのやり取りも MacBook 側に出す。**進捗が見えないと待たされている感覚になる。
  **★ただし生ログを貼らない。「整理して」出す**（有璽氏の明示）。
  → [[feedback_one_session_split_by_owner]]（有璽氏へは1本にまとめて出す）と同じ構え。
- **★人が見る場所と、機械が働く場所を分ける。**これが今回の構造の核心。
- **★「役割」も mini 側で再現できる。**指示文の冒頭に
  「あなたはナミ（CFO）です。`~/.claude/agents/cfo.md` を読んで従ってください」と書く。
  ★agents 定義は git で両機へ配られているので読める（実測で規範が効いていることを確認済み）。

## ★恒久の運用 ── 有璽氏は mini のターミナルを一度も触らない

> 有璽氏「他のものも**コピペの関係でMacBook側でやりたい**。sshでMac miniを呼び出すのもやっているが、
> **コピーが使えなくて手間**。**MacBook版のClaude Codeでやり取りしている延長で、
> mini側に指示を出していくオペレーションが組めたら**」

```
有璽氏 → ★ここ（MacBookのClaude Code）で日本語で指示するだけ
   ↓
ビビ  → ssh mini で claude -p を ★nohup で投げる
   ↓
mini  → AIが走る（★MacBookがスリープしても・持ち運んでも止まらない）
   ↓
ビビ  → ★後のターンでログを読み、ここに日本語で報告
   ↓
有璽氏 → ★mini のターミナルを一度も触らない ＝ コピペの問題が起きない
```

→ [[feedback_cannot_copy_from_terminal]]（mini のターミナルからはコピーできない）を、
**そもそも触らせないことで回避する。**

```bash
# 投げる（★即座に返る）
ssh mini 'cd ~ && nohup ~/.npm-global/bin/claude -p "<指示文>" > ~/.vivid-relay/<name>.log 2>&1 &'
# 後のターンで読む
ssh mini 'cat ~/.vivid-relay/<name>.log'
```

- **★mini 側は別セッション。この会話の文脈を持たない。**指示文に必要な前提を全部書く。
  ★規範・記憶（`vivid-ai-hq`）は git で両機に配られているので**そちらは読める。**
- **★ログにはフック等の応答も混ざる。**答えは**別ファイルへ書かせる**と拾いやすい
  （例：「結果を `~/.vivid-relay/<name>_result.md` に書いて」と指示に入れる）。
- ★`ssh mini 'claude -p …'` を**前面で待たない。**待つとスリープで ssh が切れる。

## できること・できないこと（★実測に基づく）

```
✕ ★このセッションのサブエージェントを mini のプロセスにする
   → 仕組みが無い。MacBook で動くので、スリープで止まる

◎ ★スクリプトを mini へ切り離して走らせる（ssh + nohup）
◎ ★AI（claude -p）ごと mini へ切り離して走らせる  ← ★2026-09-05 実測で確認
   → どちらも★MacBook がスリープしても走り続ける。結果はファイルに残る
   → ★セッションは MacBook のまま。新しいセッションを立てる必要は無い
```

```bash
# 投げる（即座に返る）
ssh mini 'nohup python3 ~/.vivid-relay/<script>.py > ~/.vivid-relay/<name>.log 2>&1 &'

# あとで結果を見る（別のターンでよい）
ssh mini 'tail -30 ~/.vivid-relay/<name>.log'
ssh mini 'ls -l ~/.vivid-relay/<出力ファイル>'
```

- **★`ssh mini 'python3 …'` を前面で待たない。**待つと ssh 接続がスリープで切れる。
  `nohup … &` で切り離す。**「投げる」と「結果を見る」を別のターンに分ける。**
- ★mini には Google の認証（`sheets_client.py` / サービスアカウント）が在る。
  **MacBook には無い。**Drive・スプレッドシートを触る処理は元々 mini 側でしか動かない。
- ★`~/.vivid-relay/` は git 管理外。**両機で自動同期されない。**置いたら実測で確認する。

## ★どこまでを「スクリプト」にするか

**LLMに1件ずつ判定させる作業は、たいてい機械で書ける。**

```
機械で書ける   対応表の完全一致／既知パターンの検出／コード表の引き当て／
              日付や金額の正規化／残ったものを「未判定」にする
LLMが要る      ★新しい摘要をどう分類するか＝全体のごく一部
```

**★LLMに回す件数を減らすほど、落ちにくく・速く・毎回同じ結果になる。**
→ fukuchi-core「繰り返す作業はスキル化し、どの端末でも同じ結果が出る状態にする」。
