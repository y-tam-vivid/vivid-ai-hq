**★読む人が知らない名前を、その人が読む文書に出さない。**

2026-08-23、営業へ渡す `94_営業の使い方` の21行目に
`intake_register.py` / `GAS 54v3` / `Apps Script` がそのまま書かれていた。
営業はこれを読んでも何のことか分からない。

**Why:** 書いたのが実装した側だから。**自分には自明な名前を、そのまま置く。**
起きるのは誤読ではなく**離脱**である。

```
読む側の反応   「自分には関係ない部分だ」と判断して、その節ごと飛ばす
★事故         飛ばされた節に、営業がやるべきことが書いてあっても届かない
```

内部名が出た文書は、間違っているのではなく**宛先が違う**。
届かない文書は、無い文書と同じ → [[reference_delivered_but_unread]]

**How to apply:**

```
悪い   intake_register.py が毎朝07:20に受付シートを台帳と4キーで突合します
良い   毎朝7時すぎに、機械が受付シートと台帳を照合します
       あなたがやるのは、★が付いた行に ○ か × を入れることだけです
```

- **★何が起きるかで書き、どう実装されているかは書かない。**
  実装は変わるが、起きることは変わらない。実装名を書くと、実装を変えた日に文書が嘘になる
- **★実装名が出てきたら、それは書き手が自分向けに書いた合図。**
  1語見つけたら、その文書全体を宛先の目で読み直す（1語だけ直しても、たいてい他にもある）
- **人が何をするかを必ず1文入れる。** 「機械が動きます」で終わる節は、
  読む側にとって行動が無い＝飛ばしてよい節に見える
- 出す前に**その人になったつもりで通読する**。判定者は書き手ではなく読み手
  → fukuchi-core「★『完璧』は自己評価ではなく、外部の判定者が決める」

**同じ型で起きること** ── 社員向けの案内・広報の原稿・議事録の要約・Slackの通知文。
営業ワークブックに限らない。**人に配るものすべて**が対象。

## ★★「反映した」と書くな。どこに書いたかを、相手が見られる場所で言う（2026-09-03）

### ★言い換えたうえで原文を残し、どこを言い換えたかを言う（2026-09-03・定型）

人へ送る文面で、**原文をそのまま貼る**のと**読む人の言葉に直す**のは、しばしば衝突する。
担当が両立させた形が良かったので、**定型にする。**

```
原文    「ledger_report」          ← ★道具の名前。読む人には意味を持たない
書いた  「営業の台帳で6日続けて出ている指摘について、どうしますか」
★同時に  「機械が持っている文面（原文のまま）」として★件名・選択肢・日時を並記
★さらに  「ここが唯一の私の作文です」と★申告した
```

**★3つそろって初めて安全。**
```
① 読む人の言葉に直す        → 伝わる
② ★原文を並記する           → 読む人が「どれのことか」を原文で確かめられる
③ ★どこを言い換えたか言う    → 受け取る側（窓口）が、作文の混入を検査できる
```
**言い換えだけだと、元が何だったか誰も分からなくなる。**
**原文だけだと伝わらない。** ②③が無い言い換えは、**善意の改ざんと区別がつかない。**

★あわせて**値を手で打たない形**にしたのが根本の対処 ──
文面を作るスクリプトの中で実物を `open()` し、**変数のまま流し込む。**
**「気をつける」ではなく「打てない」形。**
→ [[feedback_never_write_an_unmeasured_number]]（実物を読んだ、と、実物から書いた、は別）

## ★同じ内容でも、渡す相手が変われば書き直す（2026-09-04）

**有璽氏「この2点引っかかったものを、これをそのままClaude Designに返した方がいいかしらね？？」**

こちらが書いた文面は**有璽氏に向けて**書いたもの。そのまま作り手へ渡すと通じない。

```
有璽氏へ書いた文       「保護者の目に触れる」「前より寂しくなる」
                       ＝ ★なぜ困るかを、事業の言葉で書いてある
作り手へ渡す文         「一覧のカードに写真の枠を足す」「写真の並びを2列固定でなく
                       2列と3列を選べるようにする」
                       ＝ ★何をどう変えるかを、作る手が動く形で書く
```

- **★「そのまま転送」は、窓口が仕事をしていない状態。** 束ねる役の仕事は、
  **受け取った側がそのまま動ける形に書き直すこと。**
- **★人に転送させない。**「これを貼ってください」の形まで作って渡す。
  相手先が別のAIでも同じ ── **相手が判断に使う材料を、相手の言葉で並べる。**
- **★根拠になる実測値は落とさない。** 「1記事に写真のまとまりが11〜28回」のような数字は、
  作り手が仕様を決めるのに要る。**理由は書き換えても、数字はそのまま渡す。**
