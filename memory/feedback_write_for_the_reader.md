**★読む人が知らない名前を、その人が読む文書に出さない。**

2026-08-23、営業へ渡す `94_営業の使い方` の21行目に
`intake_register.py` / `GAS 54v3` / `Apps Script` がそのまま書かれていた。
営業はこれを読んでも何のことか分からない。

**Why:** 書いたのが実装した側だから。**自分には自明な名前を、そのまま置く。**
起きるのは誤読ではなく**離脱**である。

```
読む側の反応   「自分には関係ない部分だ」と判断して、その節ごと飛ばす
★事故         飛ばされた節に、営業がやるべきことが書いてあっても届かない
```

内部名が出た文書は、間違っているのではなく**宛先が違う**。
届かない文書は、無い文書と同じ → [[reference_delivered_but_unread]]

**How to apply:**

```
悪い   intake_register.py が毎朝07:20に受付シートを台帳と4キーで突合します
良い   毎朝7時すぎに、機械が受付シートと台帳を照合します
       あなたがやるのは、★が付いた行に ○ か × を入れることだけです
```

- **★何が起きるかで書き、どう実装されているかは書かない。**
  実装は変わるが、起きることは変わらない。実装名を書くと、実装を変えた日に文書が嘘になる
- **★実装名が出てきたら、それは書き手が自分向けに書いた合図。**
  1語見つけたら、その文書全体を宛先の目で読み直す（1語だけ直しても、たいてい他にもある）
- **人が何をするかを必ず1文入れる。** 「機械が動きます」で終わる節は、
  読む側にとって行動が無い＝飛ばしてよい節に見える
- 出す前に**その人になったつもりで通読する**。判定者は書き手ではなく読み手
  → fukuchi-core「★『完璧』は自己評価ではなく、外部の判定者が決める」

**同じ型で起きること** ── 社員向けの案内・広報の原稿・議事録の要約・Slackの通知文。
営業ワークブックに限らない。**人に配るものすべて**が対象。

## ★公開する文書に個人名を書かない ── 権限構造まで晒す（2026-08-24 実測）

営業の手順書を Notion の**公開ページ**（リンクを知っていれば誰でも読める）に置くと決めた。
草稿に **「田村」という実名が4箇所**入っていた。

```
書いた     「あなたか、田村のどちらか早い方が押してください」
           「あとで田村が見ます」
何が漏れるか  ① 社内の個人名そのもの
             ② ★**誰が最終承認者かという権限構造**
                 誰に頼めば通るか、誰が詰まりどころかが外から分かる
直し       「管理側」へ置換。★営業には意味が通り、外からは構造が見えない
```

- **役割名で書けば、営業には伝わり、外には構造が見えない。**
  「田村」を知っているのは社内の人だけ ── 逆に言えば、**社外の人には情報にならない**
- **★公開ページに人名が要る場面は、ほぼ無い。** 要ると感じたら役割名に置き換わるか試す

### ★`<details>` は「本文と分けた」ことにならない

付録を折りたたみにしても、**同じ公開ページの一部**。区分ではない。
**「あとでうっかり追記される受け皿」**になりやすい（誰が担当か、どの顧客で詰まったか）。

```
入れた予防策  ページ冒頭に編集者向けの注記を置く
              「このページは公開です。お客さまの名前・金額・個人名を書き込まないでください」
残る課題      ★運用の詳細は、公開ページの外（社内限定ページ）へ切り出す方が安全
              公開ページからは内部リンクだけ残す
```

- **★公開と社内向けを同じページに並べない。** 折りたたんでも同じページ

### ★仕組みの名前で聞くと、答えようがない（2026-08-26 実地）

有璽氏へ4件の判断を並べたうち、1件がこう返った ── **「4番の意味はわからんな」**。

```
こちらが書いた   check.sh 項目7の扱い ── scratchpad を検査対象から外すか（規範の変更＝要承認）
実際に聞きたかった  契約書の版が2つ並んでいると自前の検査が赤になる。
                    赤を放置するか、検査の側を直すか
```

- **★判断を仰ぐときに、こちらの実装名（ファイル名・項目番号・ディレクトリ名）を主語にしない。**
  有璽氏が判断できるのは「何が困っていて、どちらを選ぶと何が起きるか」であって、
  `check.sh` の項目番号ではない。**名前で聞かれると、判断以前に「それは何か」から始まる。**
- **★他の3件が通って1件だけ返ってきたときは、内容が難しいのではなく書き方が違っている。**
  同じ場面で並べた「対象期間の起点」「第14条第2項の削除」「ドラフトの中身」は即答されている。
  難易度の差ではなく、**その1件だけ社内の道具の名前で書いていた**のが原因。
- **対策**：判断を並べる前に1件ずつ読み返し、**主語が社内の道具になっている行を書き直す**。
  「◯◯（仕組みの名前）をどうするか」ではなく「**何が起きていて、どちらを選ぶか**」で書く。
## ★自分で書いた禁止事項を、自分で破っていた（2026-08-27 センゴクの指摘）

営業へ配る手順書の冒頭に、当方はこう書いた ──
**「このページは公開です。お客さまの名前・金額・個人名を書き込まないでください」**

**その同じ文書の本文で、実在の顧客名と実在の社内IDを例に使っていた。**

```
1章  「上妻」だけ → 台帳の「上妻央育」さんと結びつきにくい   ★実在の顧客
3章  例1  C-0049                                            ★実在のID
```

- **★禁止事項を書いた本人が、いちばん先に破る。**
  ルールを書くことと、そのルールで自分の文章を点検することは別の作業
- **★公開文書の下書きは、最初から架空データで書く。**
  実データで書いて後から置換すると、必ず取りこぼす
  （今回は検査役が見つけた。自分では気づかなかった）
- 代替は説明を壊さない ── 「田中」「田中一郎」「C-0000」で骨格はそのまま成立した

              社内手順書に書くこと自体を禁じない）

## ★文書管理の情報を冒頭に置くと、読む人が離脱する（2026-08-31 フランキー）

```
やってしまった形   正本宣言の直後に「種別／派生元／最終更新／次回棚卸／責任AI」を置いた
                   ＝ ★営業が最初に見る1画面が「自分に関係ない話」になる
                   実装名を書いて節ごと飛ばされたのと★同じ構造の事故
直し               ★末尾の折りたたみへ移す。消さない（Notion運用ルールで必要な情報のため）
```

**★最初の1画面は「読む」ではなく「押す」にする。**

```
悪い形   正本宣言 → 文書管理メタ → 流れ図 → 1章…（リンクが出るのは下の方）
良い形   # いまやること
         📥 受付フォームを開く（★クリックできるリンク）
         接点ができたら、その日のうちに1回だけ入れてください
         ↓ その後に流れ図・説明
         ＝ ★先に押せる状態を作ってから、仕組みを見せる
```

## ★同じ話を3回書かない

7章のうち2〜4章が、**冒頭の流れ図が既に言っていることを散文で3回追体験させていた**。
→ 1章に統合し、**7章 → 5章**へ。図で言えていることを、文で繰り返さない。

## ★飛べない文書は、迷った人に届かない

「困ったとき」の節があっても、**そこへジャンプする手段が無ければ、迷った人は上から順に読むしかない。**
→ Notion純正の目次ブロックを冒頭に置く（★カスタムのリンク集にしない。見出しから自動生成でメンテ不要）。
