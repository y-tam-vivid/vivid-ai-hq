**機微が入っている場所ほど、共有設定を見る習慣が無い。** 中身の設計（分類・命名・自動化）は
何度も見直すのに、「誰が読めるか」は最初に決めたきり誰も確認しない。

2026-08-18実測。議事録ルート `[01]事業部門別 議事録フォルダ` が
**「リンクを知っている全員／閲覧者」**のままだった。

```
継承の範囲   ルート1か所 → 配下の全フォルダ・全ファイル（議事録751件）
中身         給与・条件面談 ／ 採用面接 ／ 役員報酬契約 ／ 1on1 ／
             閉会後20分の私的会話（録音の切り忘れ）
到達経路     リンクはSlack承認カード・Notionの元ファイルリンク・カレンダー添付に載っている
             ＝それらが見える範囲が、そのまま読める範囲だった
```

**直したら7か所すべてが一斉に閉じた。** 個別に付いていたのではなく全部が継承。
1か所直せば済む構造だったが、裏返せば**1か所間違えると全部開く構造**でもある。

## `0A` 始まりは共有ドライブとは限らない

**マイドライブのルートIDも `0A` で始まる**（`0AGuOo8KWuKrTUk9PVA` = マイドライブ）。
[[reference_shared_drive_form_upload]] の「親ルートが `0A` 始まり＝共有ドライブ」は
文脈限定の判別法であって、一般則ではない。当方はこれで一度誤診した。

**確実な見分け方** ── 共有ダイアログに「オーナー」が出ればマイドライブ。
共有ドライブのアイテムは個人がオーナーにならない。`get_file_metadata` の
`owner` フィールドの有無でも判断できる。

**この違いは設計を変える。** マイドライブならフォルダ単位で権限を絞れる
（＝受付だけ開けて処理後は閉じる、が作れる）。共有ドライブは配下に継承されて
個別に狭められない → [[reference_shared_drive_permission_floor]]。

## 何をいつ確認するか

```
新しく人を入れる前        置き場の「一般的なアクセス」を見る
機微が入る場所を作った時   作った直後に見る。後回しにすると誰も見ない
自動化で移動先を足した時   移動先が親の設定を継ぐ。新しい年月フォルダも同じ
```
