**有璽氏の要望（2026-08-24・原文の要点）**

1. **定例タスクを管理したい。** 日々やるもの／週／月／年 ―― 周期がそれぞれある
2. **メモ書きの癖がある。** 「どうしても癖で入れてしまう」。**やめるのではなく、拾って寄せたい**
3. ビビがそのメモを拾って、Notionのタスクへ反映してほしい

**★2の読み方を間違えないこと。** 「メモを書くのをやめて Notion に直接入れてください」は答えではない。
**癖は変えない前提で設計する。**入口を変えろと言うと運用が死ぬ。

## ★実測②（2026-08-25）── 置き場が確定した。**Chatwork。ただし1箇所ではない**

有璽氏の申告を API で裏取りした（読み取りのみ）。**入口は3層に割れている。これが「二重管理」の実体。**

```
① 【個人】タスク管理  room 441066768   189件・7/23〜8/25   ★タスクの本命
② マイチャット        room  36235980  12,165件・ほぼ毎日   ★メモ全般。①と用途が重なる
③ 【個人】〜 の他25部屋               計約1,600件          ★分類がそのまま部屋になっている
④ Chatwork タスク機能 /my/tasks        13件・期限2023〜2025-10  ＝ 死んでいる。ここではない
```

**★「【個人】〜」が26部屋ある**（法人管理3社分／SNS／営業／補助金／健康／価値観／プロンプト集…）。
有璽氏の頭の中の分類が部屋の形で外に出ている。**畳む対象は2つではなく26+1。**

### ★deleted の意味 ── 「完了で消している」ではない（2026-08-25 有璽氏が訂正）

当初「終わったら消している」と推測したが**誤り**。実際は次の運用。

```
1つの投稿を手で編集し続けている
  日付ブロック（2026/08/19 ＊… ＊…）  ＝ ★その日に「完了した」ものを日付の下へ手で移した記録
  末尾の日付なしリスト                  ＝ ★まだ終わっていないもの（これから）

完了したら 末尾 → 日付ブロックへ 手で移す。投稿を書き直すので古い投稿が [deleted] になる
```

- **★`[deleted]` は編集の痕跡であって完了の合図ではない。**差分で完了を検知する設計にしない。
- **★「＊」が付いた行は未完了ではなく完了ログ。**取り違えると、済んだ仕事が大量に起票される。
  **日付ブロックの中にあるか外にあるかで意味が180度変わる。**
- **★件数の根拠に message_num を使わない。**deleted を含んだ数字になる。

### 書き方の型は2つ混在

```
まとめ型   日付 ＋ ＊箇条書き    完了ログ。1投稿を編集し続ける
単発型     8/25 09:54  15字     「眉毛エステへ行く ⏎ 接骨院へ行く」  ＝思いついた時に1件ずつ
```

- **「＊」は項目の印であってタスクの印ではない。**マイチャット側でも資料メモの見出しに使われている
  （「＊GameBull デモアカウント」）。**＊ をタスク判定のキーにしない。**
- **私用と仕事が同じ部屋に混ざる**（眉毛エステ／119番の名刺）。オーナー区分での仕分けが要る。

**★中身はタスクだけではない。ここが設計の核心。** 直近30件の実測で4種が混在していた。

| 種類 | 実例（8月） | 割合の体感 |
|---|---|---|
| タスク | 「吉川さんへBPO資料の共有」「STAND UP研修動画の分類分けを検討」 | 2〜3割 |
| 商談・会議のメモ | 「人材・採用：中規模で20万／一人入社で50万」「MIKKEHOUSE 当日に契約を行う」 | 最多 |
| **認証情報（機微）** | **GameBull デモアカウントの URL・ID・パスワードが平文** | 数件 |
| リンク・電話番号・下書き文面 | Drive URL、PR TIMES 用の電話番号、送信前のメール文 | 常時 |

- **★「メモを全部 Notion タスクへ流す」は誤り。**タスクは少数派。全部流すと台帳が汚れる。
- **★機微が混ざっている。**認証情報をそのまま Notion へ写すと、平文の複製が1つ増える
  → [[reference_plaintext_credentials_handling]]。**回収の設計には除外の口が要る。**
- `[deleted]` が多数ある（削除済みメッセージ）。件数の根拠に使わない。

## 周期タスクの扱い（設計メモ・未着手）

Notion に「繰り返しタスク」のネイティブ機能は無い（テンプレートの定期作成はあるが Status を戻さない）。
取りうる形は3つ ―― ①Notion のテンプレート定期作成 ②mini の cron から冪等に起票
③周期マスタDB＋次回予定日を持つ。**★どれも「完了したら次を作る」の1点で壊れる。**
決める前に、有璽氏が実際に回している定例が何件あるかを数える。

## ★★真の目的は「タスク管理」ではない ── 移譲（2026-08-25 有璽氏）

> 「前提としては、**私以外でもできるようにしていきたい**。私がやっている定期でやっているものを、
> 私以外ができるように。私自身が**定期タスクを洗い出し、それぞれどれぐらいの所要時間が
> あるのかを洗い出していくことを優先したい**。」

**★ここを取り違えない。**求められているのは「有璽氏がタスクを消化しやすくなる仕組み」ではなく
**「有璽氏の手から離すために、何にどれだけ時間が掛かっているかを可視化すること」**。
所要時間は管理指標ではなく**移譲コストの見積り**として要る。優先は 洗い出し ＞ 回収の自動化。

## 既にある棚卸し ── `~/Downloads/routine_master.xlsx`（2026-08-21・★器に入っていない）

列は **No./カテゴリ/タスク名/頻度/想定所要時間(分)/期日/担当区分/対象法人/現状/ソース/備考**。
担当区分は5値（自分で実行・確認と指示出し・現場任せ・外部委託(社労士)・外部委託(税理士)）。
**この5値が移譲設計の骨格。新しく分類を作らず、これを使う。**

| シート | 件数 | 内訳 |
|---|---|---|
| 事業ルーティン | **82件** | 実施中37 / 未実施（追加提案）45 |
| 個人ルーティン | **35件** | 実施中25 / 未実施10 |
| 凡例・サマリー | ― | 担当区分の定義＋「次のステップ」5項目 |

**実測の集計（2026-08-25・ビビが xlsx を読んで算出）**

```
事業  実施中 × 自分で実行   35件   227時間/年（週4.4h）  ★未換算9件を含まない＝下限値
      未実施 × 自分で実行   18件   140時間/年            ＝やると決めたら増える分
      未実施 × 他へ渡す形   27件                        ＝提案どまりで着手していない
個人  35件                        1,546時間/年（日次12件が大半・最低回数で換算）
```

- **★「都度」24件は年間換算できない。**しかも重いものがそこに居る（施設現場支援240分／
  施設送迎60分／実地指導対応480分）。**227時間は必ず下振れしている。**総量を語るときは
  「未換算24件を除いた下限値」と必ず断る → [[feedback_one_route_is_not_verification]]
- 未実施45件は**「まだやっていない提案」**。移譲以前に「やるのか」の判断が先。混ぜない。
- xlsx の「次のステップ」に有璽氏の意図が既にある ── ①追加提案の要否 ②担当区分の確定
  ③所要時間を実態へ修正 ④頻度・期日の確定 ⑤日→週→月→年へ落とす。
