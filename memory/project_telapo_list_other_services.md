## 見本の補助タブ4枚（新リストに要るか）

| タブ | 中身（実測） | 所見 |
|---|---|---|
| 活動FB | 日別の稼働実績12行。稼働日/コール数/通電数/通電率/受付ブロック/アポ獲得/所感 | **要る。**ただしリストごとに増やさず1枚に集約すべき |
| 記載参考 | 2024年の実架電ログ114件（放デイ・大阪）＋見出し1行 | **不要。**過去の実データで、新リストに写すと二重管理になる。見本側に残す |
| テレアポトーク | 架電スクリプト43行。★本文が放デイ／児発／就労継続の文言で書かれている | **要るが書き換えが要る。**種別ごとに切り出すか判断が要る |
| 仮メモ欄 | KPI試算・単価・人員配分の下書き36行 | **不要。**作業層 |

- **★入力規則・条件付き書式・シート保護は3タブとも0件**（API の conditionalFormats /
  dataValidation / protectedRanges を取得し、大阪絞りは別範囲でもう一度取り直して2経路で確認）。
  再現すべき仕掛けは無く、**列を並べて値を入れるだけで見本と同じ器になる**。
  法人単位・事業所単位に basicFilter が1つずつ付いているのみ。

**Why:** 「既存の形式に合わせて作り変えて」と言われた作業の本体が、実際には**もう終わっていた**
（列が完全一致）。そのまま着手すると、揃っているものを作り直しにいく。壊れるのは
**「見本と同じ形にする」という依頼文そのものの前提**で、実物を突き合わせるまで誰も気づけない。

**How to apply:**

- 着手前に**見出しを1行ずつ突き合わせる。** 同じなら、仕事は絞り込みとタブ分けだけになる。
- 「対象サービスN種」と言われたら、**抽出元にその種別が実在するか数える。**
  今回は5種のうち1種（放デイ）だけソースが別ファイルだった。
- 種別・区分が**複数値で入る列**は、タブ分けの前に重複の扱いを人へ確認する。機械が決めない。
- **既存の絞り込み済みタブを「同じ基準で」と言われたら、その基準を先に再現して検算する。**
  今回は条件は再現できたが、9市の除外だけ意図が説明できなかった。
