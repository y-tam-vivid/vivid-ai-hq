**もらった素材には、先方が出すつもりのないものが混ざる。**

2026-09-24、JFBI の協力団体から「**掲載用写真**」というフォルダで18枚が届いた。
全部見たところ、そのうち1枚に**先方の社内の数字が焼き込まれていた**。

```
IMG_9163  「フールセックギフトM　グレ　20-2672 ／ 数量100 ／ 単価135（4月より値上がり）」
          ＝ギフト箱（資材）の型番・仕入れ数量・単価・値上がりの注記
```

**先方に落ち度は無い。** 商品の写真を撮るときに、作業用のメモを書き込んだ1枚が
同じフォルダに入っていただけ。**「掲載用」という名前は、中身を見た人がいる保証ではない。**

## 開いて数えるもの（4つ）

```
① 写り込んだ文字   価格・数量・型番・住所・電話・氏名・日付
                   ★拡大して読む。縮小表示では「文字がある」ことしか分からない
② 第三者           他社の店名・商標・価格／自社と関係の無い人や建物
③ 重複             sha256 で数える（今回 IMG_9157 と IMG_9160 が同一ファイル）
④ 画面で読めるか   チラシ・資料の撮影は、載せる大きさでは文字が読めないことが多い
```

**★人の顔**は毎回数える（今回は0件だった）。写っていたら、掲載の同意を確かめるまで載せない。

## 今回どうしたか

```
届いた   写真18枚＋ロゴ2枚
載せた   10枚
外した   ①仕入れの数字1枚 ②他社の店舗が主役の1枚（a’s の要素が写っていない）
         ③重複1枚 ④チラシ2枚（文字が読めない）
         ロゴ2枚は既に掲載中のものと同一ファイル（バイト数一致）＝差し替え不要
```

**外した理由は、実装の中と引き継ぎ書の両方へ書いた。**次に素材が届いたとき、
同じ写真を「まだ載せていないもの」として拾い直さないため。

**原本は消さず、公開されない場所へ控える**（JFBI では `_source/`＝`.vercelignore` 対象。
本番で404になることを実測した）。**判断が変われば載せられる。**

関連 → [[reference_grid_collapses_when_only_one]]（枠へ入れたあと、切られ方を測る）
／ [[feedback_confidential_two_layer_rule]] ／ [[project_jfbi_research_site]]

## ★2026-09-24 「サイトに載っている」と「提供された」は別（JFBI・2団体目）

有璽氏「WEBサイトから写真なども転載してくれる？」。**転載できる写真は1枚も無かった。**

```
サイトの写真 7枚（uploads配下・ロゴ除く）
  人が写る 5枚   スタッフの顔・演奏の様子 ＝ ★肖像権。別サイトへ移す同意は別に要る
  人が写らない 2枚 ノートとお茶／テーブルの手 ＝ ★素材サイトで買った写真の疑い
★Exif は7枚とも空   WordPress が画像処理で落とす。撮影者も著作権表示も残らない
                    ＝ ★自前の撮影か購入素材かは、写真そのものからは判定できない
```

**★購入素材は「そのサイトで使う」までしか許諾が無いことが多い。** 別ドメインへ移すと
契約違反になりうる。**自社グループの関連先であっても、素材の権利までは持っていない。**

- **★「載っている」は「配ってよい」ではない。** 先方サイトの写真は、先方がそのサイトで
  使う許諾しか取っていないかもしれない。**提供された写真（＝掲載前提で渡されたもの）とは
  権利の範囲が違う。**
- **★出どころが分からないものは、出どころを聞く。**推測で「たぶん自前だろう」で載せない。
- 有璽氏の判断も **B＝先方から出してもらう**（2026-09-24）。依頼一式は
  `~/Downloads/JFBI_リライフ_写真の掲載依頼_20260924/`（文面・候補一覧・掲載イメージ）。
- **★候補一覧は「○を付けて返すだけ」の形にする。** 7枚を並べて □はい □いいえ を置き、
  確認したいこと（本人の了承／素材の出どころ／クレジット表記）を3行で添えた。
  → [[feedback_ui_must_be_self_explanatory]]（相手が読む物も、説明でなく物自体で伝える）

## ★縮小した一覧は「候補を絞る」ためのもの。載せてよいかは原寸で決める（2026-10-03・3例目）

こどもまつりのリリースで、Drive 62枚をコンタクトシート（1枚240px）にして選び、15枚を採った。
**組み終えてから原寸で見直したところ、2枚で来場者とこどもの顔が判別できた。**
縮小表示では「顔は小さい」に見えていた。落として13枚にした。

```
縮小一覧で分かる   構図・主題・明るさ・似た絵の重複     ← ここまで
原寸でしか分からない 顔が判別できるか・文字が読めるか・写り込み  ← ★載せる判定はこちら
```

**★リリースの画像は記事にそのまま転載され、一度出ると回収できない。** SNSより厳しく見る。
顔が写るものは、同意が確認できるまで載せない。**同意の確認自体をタスク行に出す**（人の手が要る）。

## ★「記念写真」は素材写真に見える。活動が写っているものを選ぶ（2026-10-03 有璽氏）

告知バナーに**正面でピースをした2人の笑顔**を採ったところ、有璽氏の反応はこうだった ──
**「これって素材写真なんかな、ちゃうんかな。でもいいですよ」**

```
★選んだ基準   明るい・光が入っている・笑顔・にぎわいが背景にある
★足りなかった 「その催しで何が起きているか」が写っていない
              正面・カメラ目線・ポーズ ＝ どこの行事でも撮れる絵＝★ストックフォトに見える
```

**★人が写っていればよいのではない。「その人が何をしているか」が写っていること。**
店番をしている・商品を差し出している・値札を書いている・お金を数えている ──
**手と物が写っている写真は、ストックフォトには無い。**

**★明るさ・光は必要条件であって十分条件ではない。** 数値で絞ったあと、
**「これは素材写真に見えないか」をもう一度 目で通す。**

## ★2026-10-12 先方サイトの画像は「写真」とは限らない ── バナーは貼れない

JFBI の協力団体3件目（プラスワン・エステティックラボ）で、有璽氏から
**「写真ってホームページ側じゃなかったでしたっけ？先方の」**と聞かれた。
サイトには確かに画像があった。**だが3枚とも写真ではなくバナーだった。**

```
取った3枚   2560x1440（16:9）
中身        左半分だけが写真。★右半分はオレンジの帯で、
            「施術 / Treatment」「研修 / Training」「動画 / Movie」が★焼き込み
そのまま貼ると  こちらの見出し（SERVICE 学びの内容）の横に、先方の見出しがもう1つ出る
```

**★「先方のサイトに画像がある」＝「使える素材がある」ではない。**
サイトの画像は、そのサイトのデザイン部品として作られている。見出し・帯・ロゴ・
テロップが焼き込まれていれば、別のサイトへは持ち込めない。**縮小一覧では帯に気づく。
だが「帯に文字が入っているか」は開かないと分からない。**

中身の判定も同時に出た（型は上の節と同じ）：

```
①②  素材写真の作り（手元と背中・顔は写っていない）
     → ★ストックフォトのライセンスは「そのサイトでの使用」に限られるのが通常。
       先方が買っていても、こちらのサイトへは及ばない
③    ★代表本人の顔が正面から写る＋左下に先方名のテロップ＝動画のキャプチャ
Exif  3枚とも空（a's 18枚・リライフ7枚と同じ。WordPress が落とす）
```

→ **確認なしで載せられる画像は0枚**。リライフ（2026-09-24）と同じ結論に、同じ道で着いた。
**協力団体を足すときは、写真の扱いを最初の提示に含める**（有璽氏は毎回ここを聞く）。
