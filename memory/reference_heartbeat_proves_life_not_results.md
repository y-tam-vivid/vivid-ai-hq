**★心拍は生存確認であって、成果の確認ではない。** 2026-08-29 有璽氏
──「心拍とか作ってもなんかあんま意味ない気がつくんだけど。ほんまに」。**正しい。**

## 実際に起きたこと（2026-08-29 実測）

`build_landmine_index.py` は毎朝08:25に走り、**心拍を「成功」で打ち続けていた**。
その裏で起きていたこと：

```
memory 188本を走査 → 常設枠に載ったのは 19本（10%）
                     100本を上限で静かに落としていた
出す側は重い順の上位2本に固定 → 残り186本は一度も出ていない
さらに import time の抜けで NameError → ★それでも exit=0 → 心拍「成功」
```

**動いていた。成功と申告していた。効いていなかった。**
そして**こちらは気づかず、有璽氏の指摘で初めて分かった。**

## なぜ心拍では捕まらないか

```
心拍が見ているもの     プロセスが最後まで走ったか（生死）
心拍が見ていないもの   何件効いたか（成果の量）
                       その量が妥当か（期待値）
```

**中身が0件でも、空振りでも、心拍は緑になる。** だから
「毎朝ちゃんと動いています」という報告は、**何の保証にもならない**。

## 二度と起こさない形 ── 3点セットで持つ

心拍を捨てるのではなく、**心拍に数字を持たせ、数字に期待値を持たせる**。

| | 何を持つ | 例（地雷インデックス） |
|---|---|---|
| ① 生死 | 走ったか | 心拍「成功」 |
| ② 成果 | **何件効いたか（数字）** | 走査188本 / 載った59本 |
| ③ 期待 | **その数字が満たすべき条件** | 載った率 ≧ 50%／未提示の記憶 = 0本 |

**★③が無いと、①②が揃っても人が見て気づくしかない。**
「見れるものがない」のではなく、**見ても正常か異常か判定できない**のが問題。
条件を機械に持たせて初めて、人の指摘なしに🔴が立つ。

- 数字は**別々に数えない**。`dashboard_data.json` に集約し `facts.py` から読む
  （[[feedback_never_write_an_unmeasured_number]] の設計をそのまま使う）
- **★期待値を人の記憶や文章に置かない。データとして持つ**
  （fukuchi-core「稼働確認は最後にいつ動いたかと次はいつ動くはずかをセットで持つ」の
  成果版。間隔だけでなく**量**にも同じことが要る）

## ★申告と実物のズレは、作った本人の報告には出ない

「改善しました」と言った後に止まっている、が繰り返される理由は
**過剰修正・空振りが本人には成功に見えるから**。だから
[[feedback_never_write_an_unmeasured_number]] と同じく **別主体が数字で読む**しかない。
自己申告を検知の経路にしない。


## ★検査を作った本人が、同じ壊れ方を検査に入れた（2026-08-29・ドーベルマン指摘）

対策として `dashboard_data.py` に `build_effectiveness()`（4項目の不変条件）を入れた。
**その実装が、今日の事故と同じ形で壊れていた。**

```
① 全チェックが例外で落ちると out=[] → ng_count=0 → 「🟢 全部効いている」を返す
   ＝ 何も数えていないのに緑。build_landmine_index が exit=0 を返したのと同じ型
   ★_errors に理由は残るが、health の判定には一切効いていなかった

② 閾値を、実測値を見てから決めた
   実測 55% を見て「50%以上なら🟢」とした ＝ 必ず緑になる基準
   本来向き合うべき事実は「memory 189本のうち45%が候補にすら載っていない」

③ カバレッジが memory・フック系だけ。intake_register や notion_backfill など
   金と時間が絡む業務側の停滞をゼロカバー ＝ 本丸を見ていない

④ 検査自体に専用の心拍が無い。この検査が丸ごと止まっても🔴が立たない
```

- **★「判定不能」を「正常」に倒さない。** 数えられなかったものは緑ではなく**灰**にし、
  ng に数える。エラーを別枠へ逃がすと、全滅したときにいちばん静かになる。
- **★基準は測る前に決める。** 実測を見てから閾値を置くと、必ず自分に甘い数字になる
  （[[feedback_never_write_an_unmeasured_number]] の変種。数字を捏造しなくても、
  基準を後から合わせれば同じことが起きる）。
- **★検査を作った本人は、自分が想定した壊し方しか思いつかない。** 別主体を通す
  （[[feedback_use_the_team_not_alone]]）。今回は実際に、通して初めて4つ出た。
