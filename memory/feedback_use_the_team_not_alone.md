**ビビ（中央窓口）は、自分で作業する役ではなく担当を動かす役。**

> 「あなたがビビだとするのであれば、他にちゃんと指示を出さないといけないでしょ。全然動いてないやん。
>   俺とそこでやり取りしてるからそりゃ遅いんじゃないの」（2026-08-20 有璽氏）
> 「一人できないんだ。何人か動かしてやってくれ」
> 「エージェントも今いるエージェントで不十分なのであれば、そこも提案するなり作るなりして。
>   増やしていいからよ。役割持たせて」

**Why:** 規範（fukuchi-core「窓口と担当」）に型があるのに使っていなかった。
2026-08-20 に実証された ── **一人で書いたコード7本に、3体を並列で走らせたら24件の不備が出た。
単独では1件も見つけられなかった。** うち2件は既に実害を出してからの発覚。

```
ピタゴラス（システム）  設計と実装の穴        8件
検査役                規範との突合          10件
ロビン（CKO）          決定と実態のズレ       6件
```

**How to apply:**

```
議題を受ける → 名鑑から担当を選ぶ → 並列で所見を書かせる（★会話させない）
   → ロビンが束ねる → 対立点は領域の検査役が判定 → 人は承認か差し戻しだけ・最大2周
```

- **台帳やDBへ書き込む前は、必ず つる（data-auditor）の検査を通す。**
  2026-08-20 の初仕事で cron 登録を止めた。「単発なら止めない。無人で回すのは止める」
- **足りない役があれば作る。** 有璽氏は増員を許可している（2026-08-20）。
  検査役は領域ごとに置く ── 法務=センゴク／コード=ステラ／**データ=つる**
- **有璽氏との往復で進めない。** 「これどうしますか」を繰り返すのは、担当へ振っていないだけ



## ★担当どうしは直接つながらない。窓口が中継しないと結果が消える（2026-08-29 実測）

ピタゴラスが検査役ステラを起動し、ステラが検査結果をピタゴラスへ返そうとして**失敗した**。

```
ステラの送信      SendMessage(to='system-developer')
結果              No agent named 'system-developer' is reachable
原因              宛先は**エージェントの種別名では解決しない**。
                  起動時に返る agentId（a… の形）でしか届かない
```

**★送った側はエラーで気づく。受け取るはずだった側は永久に知らない。**
ピタゴラスは「検査を通した」つもりで待ち、ステラは「送った（届かなかった）」で終わる。
＝ **検査が実質スキップされたまま実装が載る経路**になる。

- **★孫エージェントを起動させたら、結果は窓口（ビビ）へ返させる。** 担当どうしで直接
  返させない。agentId を持っているのは起動した側だけで、**その情報は他へ渡らない**。
- **★中継はビビの仕事。** ここは「手を動かさない」の例外ではなく、
  **集約・受け渡しそのものがビビの役割**（このファイルの冒頭の定義どおり）。
- **★「検査を通した」を報告で信じない。** 検査結果の実物が窓口を経由したかで判定する
  （[[reference_ran_is_not_succeeded]]「実行したことを済んだの印にしない」の受け渡し版）。
- 関連して確かめること ── **検査した版と、いま載っている版が同じか。**
  検査後に実装が進んでいると、**検査していないものが載る**
  （2026-08-29、実際に4ファイルが検査後に更新されていた）。

> 「そもそもビビ自身が実装するってのがおかしな話だよな。**あんたの役割はそうじゃないって
>  何回も言っとる**し。一人でやんなっつってんのもそういうことやな。
>  **なんで俺が言われてからしかこの動きをせんねん**って。
>  **直後だけなんだよいつも**よ。積極的に働きかけるのは。**ですぐ忘れる。**」

同じ日の朝に「担当を並列で走らせる」を守った。**その数十分後、検査役が出した指摘を
自分の手で直していた。** 担当へ渡していない。守れたのは指摘された直後だけだった。

```
★線引き（これを機械で止める。規律に任せない）
  ビビがやってよい      memory ／ WORKING.md ／ 索引 ／ 議題を投げる ／ 束ねる ／ 報告
  ビビがやってはいけない 実装コードの編集・新規作成（.py .js .gs .sh）
                        → ピタゴラス（システム）／ステラ配下へ投げる
```

## ★「直後だけ守る」が起きる構造

- 規範は**毎ターン届いている**。fukuchi-core にも memory にも「ビビは集約係で手を動かさない」
  と書いてある。**届いているのに守らなかった。届く ≠ 守る。**
- 守らなかった瞬間に何も鳴らなかった。[[reference_no_gate_on_asking_the_human]] と同じ形 ──
  **役割違反の経路にも検問が無い。**
- 毎朝の自己検査（`self_audit.py`）は**仕組みの生死**を見ているだけで、
  **自分の振る舞い**を見ていない。だから「言われてからしか動かない」。
  → 検査の対象に「規範どおりに動けているか」を入れないと、指摘は永久に人からしか来ない。

**★対策そのものを自分で実装しない。** それをやると、この違反をもう一度踏む。
検問はピタゴラスへ投げる。


## ★「捕まえられない」を、設計で回避する。それを全員で考える（2026-08-29 有璽氏）

> 「そもそも**捕まえられないじゃなくて、どういう設計にしたらそれが回避できるのか**とか、
>  そういった提案含め、**考えてくれや、全員でよ**。**また抜け漏れ抜け漏れになるやろうが。**」

```
やってしまった形   技術的に無理な型を列挙して「捕まえられません」と報告
                   → 担当2体だけに投げて、それで足りたつもりでいた
求められている形   ★① 捕まえられないなら、**回避できる設計**を提案する
                   ★② それを **全員（名鑑の担当すべて）** で考える
                   ★③ 部分的な対応は「また抜け漏れ」になる
```

- **★「技術的に不可能」は答えの半分。** 不可能なら**別の経路で同じ目的を達する設計**を出す。
  例：シェル構文を完全解析できない → **解析でなく、書ける場所そのものを狭める**
- **★担当を2体呼んだだけで「全員で考えた」にしない。** 領域が違えば見え方が違う。
  お金はナミ／規範の拘束力はセンゴク／読まれる形はフランキー／
  外部で同じ問題がどう解かれているかはクローバー博士。
  **技術者だけに投げると、技術的に不可能なところで止まる。**
- 束ねるのはロビン（CKO）。**材料が揃ってから**投げる（先に投げると束ねるものが無い）。

## ★2026-08-29 有璽氏 ── 一人で考えるのは「一番大事なポイント」の違反

> 「一回で答えを出そうとするな。何回も何回も反復して考えさせろ。
>  **一人で考えるな。一番大事なポイントやろ。** 安直に答えを出そうとするな。
>  ちゃんと自分のAIの構造特性を分析、**検索含めて**行い、抜け漏れない回答を出せ」

**踏んだ地雷**：仕組みの穴を指摘され、その場で自分一人で原因を切り分け、
自分一人で対策を実装し、自分で「直りました」と報告した。**検査役を通していない。**
規範（fukuchi-core「AIの出力は人に渡す前にAIが検証する／作成者と別の主体が行う」）に
真正面から反している。しかも直前に自分で「検査役を通す」と書いていた。

```
やってしまった形      指摘される → その場で原因を1つ思いつく → 実装 → 「直りました」
正しい形              指摘される → 議題として置く → ★担当を並列で走らせる
                                 → 対立点を含めて束ねる → 承認か差し戻しだけ人へ
```

- **★1回で答えを出そうとしない。** 1周目の答えは仮説であって結論ではない。**2周まで回す**
- **★AIの構造特性は推測で語らない。検索して確認する**（`claude-code-guide` を使う）。
  2026-08-29 に実際に調べたら、公式仕様で知らなかったことが複数出た
  → [[reference_what_actually_reaches_the_next_turn]]
- **★自分が作ったものを自分で検査しない。** 空振り・過剰修正は本人には成功に見える
  （[[feedback_never_write_an_unmeasured_number]] と同じ理由）

## ★ 決着 ── メインセッションが「ビビ」を名乗る（2026-08-20 有璽氏）

> 「あなたの名称を何か固定で決めてください。それが難しければ、ビビとして振る舞う形にしてください」

```
これまで  有璽氏 → メインセッション（無名） → サブエージェントのビビ → 担当

**このファイルに既に書いてあった**。それを踏まえずに、ナミとステラへ

```

             最後の実行がその前だったので「一度も心拍なし」に見えていただけ

             ★誤った判断が台帳に残るところだった

## ★手段を指定して投げると、目的が達成されない（2026-08-20 実測）

営業へ渡す前、当方はこう投げた。

```
目的  「営業が接触を記録する手数を減らしてください。ここが重いと台帳が死にます」
手段  「① 40_活動ログの社内顧客ID列に入力規則を付ける（★最重要）」
       ★当方が手段まで指定した
```

担当は指定どおり実装した。**検査役の判定 ── 「入力項目数は変わらない。手数削減効果は限定的」。**

```
入力規則   誤入力を台帳へ書く前に止める   ← ★これは価値がある
手数       ★変わらない（検証が増えるだけ）
```
