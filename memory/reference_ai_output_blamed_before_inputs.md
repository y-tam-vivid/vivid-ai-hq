**「AIの判定が当てにならない」と見えたとき、まずプロンプトの選択肢と、出力の書き込み先を読む。**

2026-08-14実測（議事録GASのタスク抽出）。担当者がまともに付かない、参加者でない人が担当者になる
――という症状の原因は、AIの読解力ではなく次の2つだった。

```
① プロンプトが担当者を6名に限定  「…のいずれか。不明なら田村」
     → 選択肢に無い人（下村・Shun）は全員「田村」へ倒れる
     → 担当者マスターには27名。ベタ書きの選択肢が腐っていた（[[reference_hardcoded_option_lists]] と同型）
② 書き込み側が assignee をそもそも書いていない
     → AIに判定させた結果を捨てていた。列自体が無かった
```

**「不明なら◯◯」というフォールバックは、誤りを正解の顔で量産する。** 不明は null にする。

**当方はこのとき原因を誤診していた。**「入力がAIの要約だから担当者が落ちる」と説明したが、
コードを読むと入力は最初から元Docの本文だった。**症状から原因を推定して語る前に、
入力・処理・出力の3点を実際に読む。** 推定を説明に混ぜると、直す場所を間違える。

**検証は答えを先に決めてから走らせる。** 元Docに `@田村さん×4 / @下村さん×3 / @Shun×1 / @全員×1`
と書かれていることを読んでから実行し、結果が一致するかで判定した。
「それらしい出力が出た」では検証にならない。

## ★フォールバックは1箇所直しても終わらない。工程ごとに散らばっている（2026-08-23 実測）

「不明なら田村」を1本直したので片づいたと思っていた。**議事録の入口から昇格までの
全工程で「機械が誰にも聞かずに決めていること」を数えたら7個あった。**

```
入口   counterpart が特定できない      → ★強制で「未登録」
       folderIndex が範囲外            → ★強制で先頭の部門
       contentType の確信度 < 0.6      → ★自動で「🔒個人どまり」
                                          承認フローを通らず誰にも見えなくなる
抽出   assignee 不明                   → ★「田村」（08-13版。本体への反映は未確認）
紐付   相手が固定リストに一致          → ★対象外（447件・★見込み客が混ざっていた）
       部門・担当者の relation 不一致  → 空欄のまま ＝ ★これは正しい設計
```

**★「静かに既定値へ倒れる」型と「空欄のまま残す」型は、実害がまるで違う。**
空欄は後から見つかる。既定値へ倒れたものは**正解の顔をして残る**ので、二度と見つからない。

- **★フォールバックは工程ごとに数える。** 1本直したことを「型を潰した」と取り違えない
- **★確信度で自動分岐する箇所は全部洗う。** 閾値の下側は「判断を放棄した」ではなく
  「機械が勝手に決めた」。人へ聞く口が要る
- **★直したはずのものが本体へ反映されているかは別問題。**
  GAS（Apps Script）は Drive 上で中身が読めない → [[reference_drive_gs_file_not_previewable]]
  手元のバックアップだけを見て「直っている」と言わない
