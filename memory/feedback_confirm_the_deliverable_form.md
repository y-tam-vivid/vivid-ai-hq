**作るものの「形式」と「本数」を、着手する前に自分の言葉で復唱して確定する。**

**Why:** 2026-08-20 実地。有璽氏の依頼文にあった「報告のPR動画を作成したい」の1語を根拠に、
**動画の構成案・素材要件・肖像権の確認事項まで作り込んだ**。実際に必要だったのは
**PR TIMES用のプレスリリース2本**であり、動画は不要だった。有璽氏に
「誤認しているようですが、動画の作成は今回は不要です」と訂正させた＝1往復まるごと無駄にした。

依頼文には別の手がかりが揃っていた ── PR TIMESの契約の話、リリース原稿案の全文添付、
「以前のようにURLで」という納品形式の指定。**手がかりは複数あったのに、単語1つに引きずられた。**

**How to apply:**

```
着手前に必ず復唱する3つ
  形式   文章／リリース／スライド／動画／HTML（URL納品）／コード
  本数   1本か複数か。複数なら「何と何か」を列挙する
  出口   どこへ出すのか（PR TIMES／SNS／社内／顧客）＝ここで制約が変わる
```

- **依頼文の1語と、他の手がかりが食い違ったら、他の手がかりを優先して確認する。**
  「誤記では」と決めつけないのと同じで、単語を額面どおりに拡張して作り込まない
  → [[feedback_dont_call_it_a_typo]]
- 復唱は1〜2行でよい。「◯◯を△本、□□向けに、××形式で作ります」と書いてから手を動かす。
  骨組みを先に見せる原則と同じ運用 → [[feedback_show_the_skeleton_first]]
- **範囲が広がった／変わった合図が出たら、セッション途中でも復唱し直す。**

## ★「どこまで保証するか」を先に決める（2026-09-03・画面幅で実地）

スマホ幅の横あふれを潰していて、**直す範囲に底が無くなった。**

```
390px  ★有璽氏が指摘した幅。3本とも合格になった
360px  20px残る。犯人＝172px固定のカード2枚が折り返していない  ← 意匠を壊さず直せる
320px  60px残る。犯人＝★意匠として意図的に枠外へ出している装飾バッジ（left=-8 / right=376）
       → 一律に潰すと意匠が壊れる
```

**★「はみ出しをゼロにする」を目標にすると、意匠を壊してまで直し続けることになる。**
目標は「横スクロールを出さない」であって「全ての幅で0px」ではない。

```
決めたこと   ★保証するのは 360px 以上（Androidの標準的な幅を含む）
            320px は意匠を優先し、横あふれが残ることを承知で触らない
            ★決めたことを書く。「まだ直していない」と「直さないと決めた」を区別する
```

- **★底が無い作業に入る前に、どこで止めるかを決める。** 決めずに始めると、
  止める根拠が「疲れたから」になり、次の人には「未完」に見える。
- **★担当が「意匠に触るのであなたの判断を待つ」と止めたのは正しい。**
  実装の都合で意匠を削る判断を、実装側に押し付けない。
- ★同じ形 → fukuchi-core「どこまで作り込むか ── 領域とフェーズで変える」
  （正解がある領域＝完璧を求める／探索領域＝出しながら精度を上げる）

## ★有璽氏へ渡す文書は `.md` で渡さない（2026-09-04）

**有璽氏「これMDじゃなくてPDFとかでもらいたいです。」**

```
✕ .md    ★AI同士の受け渡しの形。人が開くとタグや記号がそのまま出る
◎ PDF    ★人が読む形。スマホでも開ける・そのまま人に回せる・印刷できる
```

- **★道具は既にある。** `python3 ~/vivid-ai-hq/bin/md2pdf.py <file.md>` で同じ場所へ出る
  （日本語フォント埋め込み済み。実測：7ページ・HeiseiKakuGo-W5/HeiseiMin-W3 が入る）。
  Word が要るなら `bin/md2docx.py`、スライドなら `bin/md2pptx.py`。
  **★「無いから作る」禁止** → [[feedback_use_the_team_not_alone]]。
- **★中で書くのは .md でよい。渡すときに変換する。** 正本を増やさない。
- **★これは規範の「読む人の言葉で書く」の形式版。** 中身を平易にしても、
  **開けない形式で渡した時点で届いていない** → [[feedback_write_for_the_reader]]。
- **★出したPDFは開いて確かめる。** このMacには `pdftoppm` が無く画像化できないので、
  **ページ数と埋め込みフォントの2つで確かめた**（文字化けは埋め込みが無いときに起きる）。

### ⛔訂正（2026-09-05 ロビン・mini で独立に再現）── 上の「日本語フォント埋め込み済み」は誤り

**`bin/md2pdf.py` の PDF は、日本語フォントを埋め込んでいない。**
reportlab の**標準CJKフォントを名前で参照している**だけなので、
**表示は正常なのに、テキスト抽出すると日本語が読めない。**

```
実測2経路 → 一致
  経路1  9/4 担当（MacBook）が抽出して判読不能 → 画像化して表示は正常と確認
  経路2  9/5 ロビンが mini で新しくPDFを1本作って中身を数え直した
         ★/FontFile 0件（＝埋め込みの実体が無い）・/ToUnicode 0件（＝文字コードの対応表が無い）
         BaseFont = HeiseiKakuGo-W5 / HeiseiMin-W3 / Helvetica
```

- **★次に「PDFが壊れている」と誤解しないこと。** 抽出できないのはこのツールの既知の性質。
  **人が読む・印刷する・スマホで開く分には問題ない。**
- **★ただし「あとで機械に読ませる」用途には向かない**（検索・引用・別AIへの受け渡し）。
  その用途があるなら **.md か .docx を併せて渡す**。
- **★「埋め込みフォントで確かめた」は検査として成立していなかった。**
  フォント名が入っていることを、埋め込まれている証拠として読んでいた
  → [[feedback_one_route_is_not_verification]]。**名前の存在は実体の存在ではない。**
