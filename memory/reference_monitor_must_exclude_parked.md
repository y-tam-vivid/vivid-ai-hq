**「警告が出ている」と「異常がある」は別。** 止めてあるもの・対応保留のものまで
警告に数えると、毎週同じ行が鳴り続け、**新しく増えた本物のズレが見分けられなくなる。**

2026-08-20 実測 ── `~/.vivid-relay/automation_inventory_check.py`（⚙️自動処理レジスタと
cron/launchd の突合・毎週月曜09:20）が「ズレ 4件」を出していた。中身を開くと：

```
本物の申告倒れ    2件   有効=True なのに cron に無い（notion_backfill / notion_customer_upsert）
止めてあるだけ    1件   有効=False（受付シート→台帳の登録。破壊的バグ修正中で意図的にOFF）
既に解消済み      1件   inbox_runner の登録漏れ（検査中に別経路で登録された）
```

**判定コードが `有効` も `既知（対応保留）` も読んでいなかった。** レジスタ側にはフラグが
あるのに、突合側が無視していた。＝**台帳に状態を持たせても、読む側が見なければ意味がない。**

## 監視は3つに分ける

```
① 本物のズレ      有効=True かつ 既知=False なのに実体が無い     → 警告に数える・Slackへ
② 止めてある      有効=False                                    → 参考表示のみ・数えない
③ 対応保留        既知（対応保留）=True                          → 参考表示のみ・数えない
```

②③を消さずに「参考」として出すのが要点。**消すと「そんな行があったこと」ごと忘れる。**

## ★④ 古い失敗 ── ログを走査する検知は「いつの失敗か」を見ていない（2026-08-21 実測）

2026-08-21朝の材料に「ログに出た失敗・警告」として
`watch_external.log ： 取得失敗 ビビ 朝ブリーフィング: <HTTPError 404>` が3件×2回、
計6行並んでいた。**前日の失敗ではなかった。**

```
実測（ログを行番号つきで読んだ）
   2〜10行目   404が3件×2回 ＝ ★このログの最初の2回の実行（2026-08-13頃・共有前）
   11〜35行目  以降7回はすべて「代理心拍 4件」＝正常
   今日トークンでGET   3ページとも 200（last_edited は 08-20 深夜）
→ ★404は8日前に解消済み。いまは1件も失敗していない
```

**真因は検知側。** `~/.vivid-relay/self_audit.py`（毎朝08:40）は各 `*.log` を
`tail -25` して `Traceback` `Error` `★失敗` `エラー` を含む行を数えるだけで、
**日付を一切見ていない**（66〜77行目）。ログは追記のみでローテートされないので、
**一度出た失敗は、直したあとも毎朝「今日の失敗」として報告され続ける。**

同じ走査で `inbox.log ： 【★本実行】📮 AI指示箱` のような**ただの見出し行**も
「失敗・警告」として並ぶ。★を含む行を拾っているため。

- **★ログから失敗を数えるなら、必ず「その行がいつのものか」で絞る。**
  時刻を持たない行しか無いログは、そもそも失敗の件数源にできない
- **★「N件失敗」を受け取ったら、ログを行番号つきで開いて位置を見る。**
  先頭に固まっていれば、それは初期不良の残骸であって現在の障害ではない
- 解消済みの失敗を数え続けると、②③と同じく**本物が埋もれる**
- **★2026-08-23 の朝も、同じ404が3件そのまま並んだ。**`self_audit.py` は未修正のまま
  （実体は `~/.vivid-relay/` ＝ git外なので放置すると両機で腐り続ける →
  [[reference_fix_where_git_reaches]]）。**毎朝この3行を調べ直す時間が繰り返し消えている**

## ★⑤ 期待間隔を実体のスケジュールから逆算していない（2026-08-22 実測）

⚙️レジスタ「有璽氏への進捗報告（progress_report.py）」は **期待間隔=8時間**で登録されていた。
実体は `daily_jobs.conf` の **12:00 と 18:00 の1日2回**。18:00→翌12:00 は **18時間**空く。

```
毎朝 08:40 の自己監査から見ると    経過14.7h > 8h ＝ 必ず🟡遅延
→ 正常に動いた翌朝ほど確実に鳴る。★異常の日と1文字も違わない見た目で
```

**1日N回の処理は「回数」ではなく「いちばん長い空き」で間隔を決める。**
`24 ÷ 回数` で入れると、実行が等間隔でない限り必ず慢性的な黄色になる。
2026-08-22 に 8 → **20**（18h＋余裕）へ是正した。

- **★レジスタに行を足すときは、実体の起動時刻を並べて最大の空きを数えてから間隔を書く。**
- 逆に**1件の遅れで間隔を緩めない**。同日、成果物ベースの外形監視
  （議事録の自動整理・35.5h）も🟡だったが、これは会議が無かっただけ ―― 履歴7日分を
  見てから判断し、**緩めなかった**（[[feedback_one_route_is_not_verification]]）。

## 型として

- **フラグを足したら、そのフラグを読む側を必ず同時に直す。** 片方だけでは効かない
- **警告の件数を見たら、必ず中身を開く。** 4件のうち本物は2件だった
- **★「止めてある」「対応保留」「もう直った」は、どれも異常ではない。**
  監視が見るべきは「いま・有効なのに・動いていない」だけ
