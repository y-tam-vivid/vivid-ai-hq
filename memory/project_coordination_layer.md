## なぜ作ったか

有璽氏の同じ指摘が3回来た（8/20・8/29・8/31「有機的に動かせてない」「俺がめっちゃ入らなあかん」）。
**原因は team_run.py が 8/20 の作成から 8/31 まで一度も呼ばれていなかったこと**（被参照0件を2経路で実測）。
旧規範は「AI同士を会話させない」と禁じただけで代わりの受け渡し形式を決めず、
**間を有璽氏が毎回チャットで運ぶ構造**になっていた。設計の欠落であって運用の問題ではない。

## 検査の重さは成熟度で変える（2026-08-31 有璽氏）

```
新しいもの・型が変わったもの   実測(full)  全数を検査役へ通す
   ↓ 3回連続で差し戻しなし
```

**★危険度の下限（A案・承認済み）** ── 次の6つは何回通っても spec へ降ろさない。
台帳へ書く／外へ出る／規範の変更／自動処理へ載せる／削除／お金。理由は「戻せないから」。

**★B案（担当・ファイル単位の実績）は未実装。** 同じ危険度の中では kind（7分類）の粗さが残る。
