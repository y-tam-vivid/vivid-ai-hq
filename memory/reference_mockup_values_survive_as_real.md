# 見本として置いた値は、実データの顔をして残る

**★2026-09-13 有璽氏**
> 「今、席にいる担当ってなっているんだけど、これの時間、もうなんか走り出したの16時54分で
>   22分経過とかなってるけど、**これ絶対ちゃうやん。全然動いて、絶対動いてないやん。**
>   だからこう、**全部動いているの？**って思っている。終わるまでの実績とかね、書いてるやつもそうだよね。」

## 何が起きていたか

画面の作り方が「①まず見本の値を書いたHTMLを作る → ②JSで実データに差し替える」で、
**②で差し替え忘れた場所が、見本のまま実データの隣に並んでいた。**

```
JSが書き換えていた   .now .nm（人数と担当名）／.now .task（経過とPID）  ← 本物
JSが触っていなかった 走り出した 16:54 ／ 経過 22分 ／ 終わる見込み 17:22ごろ
                     最後に動いた 40秒前 ／ 次の見張り 16:45 ／ 次の報告 17:00
                     中央値28分・最短4分・最長69分 ／ 過去6件すべて
                     担当14人 ／ 今日8席 ／ 次に動くもの5行（16:45〜明朝07:20）
                                                                        ← 全部 作り物
```

**★いちばん悪かったのは、その画面が自分でこう書いていたこと。**

> 「この画面の数字・時刻・ジョブ名はすべて実測です（**手で書いた値はありません**）。」

嘘の隣に「嘘はありません」と書いてあった。**見る側は数えようがない。**

## なぜ気づけなかったか

- 見本の値は**それらしい**（16:54・22分・中央値28分）。0や999なら一目で分かる。
- 「誰かが走り出したら、ここにこう出ます」という見出しが付いていたが、
  **本当に誰かが走り出しても、その見出しごと残った。**
- 走行中が常に0件だった時期（`ps -eo etimes` の件）は、見本しか出ないので誰も比べられなかった。

## ★機械で数える（次からこれをやる）

```
① JSが触るidとセレクタを全部拾う   getElementById / querySelector を正規表現で
② 本文（<script>の外）から数字・時刻を全部拾う
③ ①に載っていない場所の数字は★全部「固定値の疑い」として並べる
```

2026-09-13 に実際にこれで8か所を一度に見つけた。**目で読んでも見つからない。**

## ★規範に足すこと

- **画面に「すべて実測です」と書いてよいのは、上の①〜③で0件を出せるときだけ。**
- **見本の値を置くなら、ありえない値にする**（`99:99` `―` `＿＿`）。それらしい値を置かない。
- **データが無い項目は数字を作らず「―」と出す。**推測で埋めるより空白のほうが正しい。

## ★「ちゃんとそれを見といてや」── 人の目でなく機械に見させる

1回直しても再発する型なので、**毎日数える検問**を作った。

```
~/.vivid-relay/office_fake_check.py        cron 毎日08:50・心拍つき
  ① 公開版 office.html の <script> から、JSが書き換える id を全部拾う
  ② <script>の外で★値を出す場所（.v .t .w .cnt .val / est-row / next-row）の数字を拾う
  ③ ②のうち①に無いものを「作り物の疑い」として並べる ── 0件でなければ🔴
  ★JSが innerHTML ごと差し替える箱の中は「器」なので数えない（誤爆を出さない）
  ★画面が「すべて実測です」と書いているのに疑いが残っていれば、それも🔴として出す
  失敗したら findings_tracker へ積む＝3日続けば既存の経路でSlackへ上がる
```

**★作った直後、この検問が自分でさらに6件見つけた**（実績バーの「リリス｜スタッフ追記 21分」等）。
JSが差し替える場所なので普段は見えないが、**JSが落ちた瞬間に作り物が見える。**

**★壊して確かめた**（`est-start` の id を外して `16:54` を埋める → 1件検出・rc=1）。
正常しか出せない検査ではない。

## ★この型の総まとめ

```
作り物を置く      → 実データの顔で残る          （午前に踏んだ）
作り物を消す      → 空っぽになって同じく読めない （同日午後に踏んだ）
★正しいのは       → 実データ／無いなら「無い理由と直近の事実」／
                     そして★混入していないかを毎日機械が数える
```


## ★見本を外すときは「出す値」と「受け取る側の名前」を両方数える

★今回、ダミーを実データへ替えた瞬間に**別の崩れが出る手前まで行った**（出す前に気づいた）。

```
実データが返す区分   important（お知らせ）／ activity（活動）／ event（イベント）
                     ＝ functions.php の lsu_flow_cats()
CSS に在った色        .news-cat.notice ／ .news-cat.event ／ .news-cat.report
                     ＝ ★名前が2つ食い違う → お知らせ・活動が★白いバッジで崩れる
```

**★ダミーは「値」と「その値に合わせた見た目」がセットで作られている。**
値だけ差し替えると、見た目の側が置き去りになる。**替える前に、受け取る側の名前を数える。**

★直し方は写像を足す（`important`＝旧 notice の青／`activity`＝旧 report の黄）。
**旧クラスは消さない**（他で使われていても壊れない）。

## ★1件も無いときに原本のダミーへ戻さない

実装では `if ( $q->have_posts() )` で囲み、**0件なら何も出さない**形にした。
★「空だと寂しいから見本を出す」は、この型の入口そのもの。
