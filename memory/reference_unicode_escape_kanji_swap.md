**日本語を `\u` エスケープで書かない。literal のまま書く。**

2026-08-13、Notion ③決定・論点ログへ3件登録した際、`\u` エスケープで書いた日本語が
**別の実在する漢字にすり替わっていた。**

```
書いたつもり      実際に入った        原因
有璽（U+74BD）  → 有璞（U+749E）     エスケープの取り違え
曜（U+66DC）    → ٣（U+0663）        アラビア数字に化けた
溜（U+6E9C）    → 溢（U+6EA2）        別字だが意味が通ってしまう
㉓（U+3252）    → ⑓（U+2453）        丸数字の別ブロック
```

**壊れ方が静か。**
- 例外は出ない。書き込みは成功する
- **化けた先が実在する文字なので、見た目が自然**。「溢れすぎる」は日本語として読める
- 人名が特に危険。`有璽` → `有璞` は一見して気づけない

## How to apply

- **日本語は literal で書く。** ツール引数でも同じ。エスケープに変換しない
- 固有名詞（人名・社名・シート名・DB名）を含む書き込みは、**書いたあと必ず fetch して読み返す**
- 突合するのは「意味が通るか」ではなく **1文字ずつ一致するか**。意味は通ってしまう
- 同じ理由で、**大容量ファイルを逐語再生成してDriveへ上げ直すのも危険**
  （→ [[project_meishi_to_kintone_pipeline]] の「法人番号/電話番号が破損する」）

**関連する既知の型** ── kintone CSV の cp932 化け、手転記の漢字化け。
いずれも「書けてしまうが中身が違う」。**作成後の突合検証を省かない。**
→ [[project_kintone_csv_to_notion_mirror]]

関連: [[project_kintone_csv_to_notion_mirror]] [[project_meishi_to_kintone_pipeline]]

## ★漢字だけではない。記号も化ける（2026-08-20 実測）

Notion のページを書いた担当が、**自分で3回化けさせた**と自己申告した。

```
★  →  ☦ ／ ♦     ★2回。**見出しの目印に使っている記号が別物になる**
閾値 → 閘値       1回。既知の型（実在する漢字にすり替わるので目視で気づけない）
```

**大半は自分で検出して直したが、1箇所（⛔廃止セクション直下の見出し）に `☦` が残った。**

- **`★` `⛔` `🔴` のような目印の記号も対象。** 漢字だけを見ていると見逃す
- **書いたあと、自分が使った記号で grep して数える。** 目視では拾えない
- **★自己申告できたのは良い形。** 化けたこと自体より、
  「大半は直したが1箇所残っている」と場所まで書けることのほうが価値がある

## ★3度目の再発（2026-08-26・ビビ）── 旧字体と全角数字も混ざる

Notion「🗓 週の型（第1段階）」を `notion-create-pages` で作った際、**4種類**が同時に出た。

```
書いたつもり      実際に入った        字の性質
週（U+9031）    → 周（U+5468）        ★タイトルに出た。「周の型」
就寝（U+5BDD）  → 就寢（U+5BE2）      ★旧字体。3箇所。日本語として読めてしまう
隙間（U+9699）  → 隑間（U+9691）      稀な字だが実在する
3日 / 2〜3行    → ３日 / ２〜３行      ★全角数字の混入。他は半角なので不統一になる
```

- **★旧字体（寝→寢）が最も危険。**意味も読みも同じで、日本語として完全に自然。
  人名の `有璽→有璞` と同じ壊れ方。**目視の流し読みでは絶対に拾えない。**
- **★全角/半角の混入は「化け」に見えないので見逃す。**が、表記が不統一になる。
- **★MCPツールへの入力でも同じことが起きる。**ファイル書き込みだけの話ではない。
  `notion-create-pages` の `content` も同じ経路。
- **★全部拾えたのは「作成直後に fetch で全文を読み返した」から。**
  タイトルだけ見て終わっていたら、本文の3箇所は残っていた。
  **書く → 読み返す → 突合 までで1作業**。分けない。

**★同じセッションの2回目の書き込みでも再発した**（同日・同ページの更新時）。

```
暫定（U+66AB）  → 暗定（U+6697）    ★また旧字体でない同音の別字。日本語として読めない語だが見落とす
21件 / 1件      → ２１件 / １件      全角数字。2度目
```

**★1回直したから安全、にはならない。書き込みのたびに読み返す。**
`update_content` の差分だけを確認しても足りない ── **毎回 全文を fetch して突合する。**

### ★★5度目 ── 「直した先」がまた別の字に化けた（同日・同ページ）

```
暫定 → 暗定（U+6697）      4度目。これを直しに行って…
暗定 → 暂（U+6682）定      ★5度目。今度は簡体字。正しい「暫」は U+66AB
```

**★修正そのものが新しい事故になる。**エスケープを打ち直すたびに賭けをしている。

**★対策は「正確に打つ」ではない。使う語を変える。**

```
✕ 暫定 を正しく打とうとする   → 暗定・暂定 と2回外した
◎ ★平易な語へ言い換える       「暫定の目安」→「いまの目安」
                              ひらがな＋常用漢字なら化けようがない
```

- **★化けやすいのは「熟語の難しい方の漢字」。**暫・寢・隑・璽 …
  同義の平易な語がある場合は必ずそちらを使う。**文章の質は落ちない。**
- **固有名詞（人名・社名）は言い換えられない。**そこは必ず fetch して1文字ずつ突合する。

### ★おまけ：`update_content` の old_str は fetch の表示と一致しないことがある

同日、コードブロック内の複数行を old_str に指定して `No matches found` になった。
**fetch が返す整形済みテキストと、Notion 内部の実体は空白が違う。**

- **★長い複数行を old_str にしない。**短く一意な断片（1行・数語）で置換する
- 表の1セルなら `<td>…</td>` 単位で指定すると通る

## ★6度目 ── 常用漢字でも化けた。「化けやすいのは難しい漢字」は前提が崩れた（2026-08-31）

Notion の投稿アーカイブDBへ地名を書いたところ、**同じ字が2回とも別の字に化けた。**

```
入れたい字   桂（イオンモール京都桂川）
1回目        桅   ← create-pages で作成した直後
2回目        桜   ← update-page で直したのに、また別の字
```

- **★「桂」は常用漢字。** このファイルは5度目まで「化けやすいのは熟語の難しい方の漢字
  （暫・寢・隑・璽）」と書いていたが、**その前提は成り立たない。** 普通の地名で起きた
- **★直しても直らない。**2回目の修正でも化けた。同じ経路で入れ直しても意味がない
- **★対処＝その字を使わずに書く。**タイトルとタグから会場名を外し、
  「※この経路で正しく入らないため外した。実物を見て手で補ってほしい」と注記へ逃がした
- **★書いた直後に読み返す。**書けたことは正しく入った証拠にならない。
  Notion なら `query-data-sources` で該当行だけ SELECT して目で見る

## ★6度目 ── 「璽」→「琪」。**化けた字を機械の突合キーにしていた**（2026-09-03）

予実の口座一覧ページを作った際、帰属列へ入れた **`個人（田村有璽）` が `個人（田村有琪）` になった**
（璽 U+74BD → 琪 U+742A）。ナミが書いた直後に読み返して気づき、その場で修正・再確認した。

**★これまでの5件と違う点＝化けた字が「表示だけの問題」で済まない。**

```
これまで   タイトル・タグ・本文     → 見た目が変。人が読めば気づく
今回       ★予実管理DBの select 値と突き合わせるキー
           → 化けても画面は普通に見える。**突合だけが静かに落ちる**
```

- **★人名の難字を、機械が突き合わせるキーに使わない。**「個人（田村有璽）」ではなく
  「個人」で足りるなら、そちらにする。**化けようのない文字列を選ぶのがいちばん強い対処。**
- **★突合の確認は目視でなくコードポイントで。** ナミは U+74BD / U+742A を並べて確かめた。
  **見た目が似ている字ほど、目視は通ってしまう。**
- ★今回は「書いた直後に読み返す」が機能した唯一の防波堤だった。**この規律を外さない。**

→ [[project_cfo_agent]]（法人 select を「個人」へ短縮＝**有璽氏の承認あり**。
★有璽氏ご本人ですら「田村雄二」と打っており、**本人も毎回この字を正しく打たない**）

## ★同じ日に3回目 ── 今度は漢字ではなく **`\n` がそのまま文字列で入った**（2026-09-03）

Notionページの本文を更新するとき、**改行を `\n` というエスケープ表記のまま渡した**結果、
改行にならず**文字としての n** が本文に入り、**テーブルの構造ごと壊れた**。

```
漢字の化け   璽→琪 ／ 末尾→末對     ★見た目が似ていて目視をすり抜ける
今回        \n が文字として入る      ★構造そのものが壊れるので、読み返せば必ず分かる
```

- **★対処＝実際の改行文字を使う。**エスケープ表記を渡さない。
- **★共通する唯一の防波堤は「書いた直後に読み返す」。**今日3回とも、これだけで拾えた。
  **書けたことは、正しく入った証拠にならない。**
- ★1日に3回起きている。**人の注意力ではなく、書き込みのたびに読み返す手順で守る。**

## ★★また出た（2026-09-03）── 記録はあったのに、対処が「気をつける」止まりだった

Notion台帳へ書いた「**有璽氏**」が「**有璟氏**」になった（璽=璽／璟=璟）。
書き込み後の読み返しで気づき、同じ2行を上書きして解消。**実測で2行とも「有璽氏」を確認。**

**★このファイルに事例は3件あったが、「どうすれば起きないか」が書かれていなかった。**
だから読んでも止まらない。**事例だけの記録は、次に同じ人が同じ手順を踏む。**

### ★根本の対処 ── エスケープを使わない

```
起きる条件   ★人（AI）が \uXXXX を手で組み立てる工程があること
             1文字違いで別の漢字になり、しかも★見た目で気づけない
対処         ★日本語はエスケープせず、生の文字列のまま渡す
             組み立てる工程が無ければ、そこで間違えようがない
```
**★「注意して書く」は対処ではない。** 注意が要る工程を無くす。
→ [[reference_hooks_enforce_what_discipline_cannot]]（規律に依存する対策は、切れた回に効かない）

### ★それでも通すなら、読み返しを工程に入れる

今回**気づけたのは、書いた後に必ず読み返す手順を踏んだから**。
```
書く → ★書いたものをSQL/APIで読み返す → 意図した文字列と突き合わせる
★「書けた」は「意図どおり書けた」ではない
```
→ [[reference_ran_is_not_succeeded]]

## ★良い形 ──「当たった」と「踏み込まなかった」を区別した（同日・同じ担当）

119番の状態を「稼働」に変えず保留し、**結果として台帳が汚れなかった。**
担当の自己評価：
> 「正しく判定したのではない。**判定を保留した**だけで、当てにいっていない。
>   これは正確さの成果ではなく、**踏み込まなかったことの成果**だ」

**★結果が良かったことを、判断が良かったことにしない。**
「フォロワーがいるから稼働だろう」と1歩踏み込んでいたら、同じ日に3度目の
[[feedback_one_route_is_not_verification]]「説明がついた≠答えが出た」になっていた。
**保留は、当てられないときの正しい出力。**

## ★エスケープしなくても混入する ── 別言語の単語が紛れる（2026-09-04）

日本語の依頼文を担当へ送ったところ、**ロシア語が1語混ざっていた。**

```
送った文  「особенно Yoast 18.5.1 と Jetpack 10.8.2 は2022年版です。」
意図      「★特に Yoast 18.5.1 と…」
＝ 「特に」の位置に、同じ意味のロシア語がそのまま出た
```

- **★このファイルの主題（\uエスケープ）とは別の原因。** エスケープを避けても起きる。
  **生成の途中で、同じ意味の別言語が出てくる。**
- **★エラーにならない。** 文として成立しているので、機械も検問も止めない。
  読んだ相手が「意味がわからない」と言うまで気づけない。
- **★対処は読み返し。** 人・担当・外部へ出す文は、**送る前に自分で1回読む。**
  特に**長い依頼文**（今回は50行超）は、書いた端から確認しないまま送りやすい。
- **★見つけたら即座に訂正を送る。** 依頼文なら、相手が動き出す前に届く可能性が高い。
  今回は混入に気づいた直後に訂正を送った。
- ★機械で止めるなら ── **日本語の文書に、日本語・英数字・記号以外の文字種が混ざったら警告**
  （キリル文字・ハングル・タイ文字など）。★いまは作っていない。
