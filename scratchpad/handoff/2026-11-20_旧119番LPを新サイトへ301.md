# 旧119番LP（さくら）を新サイトへ301で転送する ── Mac mini セッションへの依頼

作成 2026-11-20（クラウドセッション）。渡すのは有璽氏の手（セッション間に自動の橋は無い）。

## やりたいこと
旧LP `https://fukushi119.vivid-global.com/` に来た人と検索エンジンを、新サイト `https://119.fuku-chi.com/` へ恒久転送（301）する。

## 理由
- 2026-11-20 有璽氏の決定：新サイト 119.fuku-chi.com を検索に載せた（noindex 解除済み・本番で実測済み）。
- 旧LPは `<meta name="robots" content="index,follow">` で検索に載っている＝同じ「福祉施設の119番」のページ同士で順位を食い合う。
- 有璽氏の回答「旧119番LPも転送する（推奨）」を選択済み（11/20）。

## 現在地（11/20 クラウドから実測）
- 旧LP：HTTP 200・meta robots＝index,follow・robots.txt／sitemap.xml は 404。
- 置き場：さくら(vivid) `/home/vivid/www/fukushi119/`（`bin/web_tracking/sites.json` の記録より。★書く前に実物で確かめる）。
- 新サイト：200・canonical・sitemap（8URL）・構造化データあり。旧医療LP iryo.vivid-global.com は全パス→ /iryo へ 308 済み。

## 手順（★①控え → ②実行 → ③実物で照合）
1. ★さくらは会員IDログインでサーバーが替わる。書く前に初期ドメイン（vivid）のサーバーであることを確かめる（`memory/feedback_sakura_cp_switches_server.md`）。
2. `ls -la /home/vivid/www/fukushi119/` で中身を一覧にする。**index.html 以外のファイル（PDF・画像など）が外から直接リンクされていないか**を確かめ、結果をこのファイルの末尾に書く。
3. 控え：`cp -p .htaccess .htaccess.bak_20261120`（無ければ「無かった」と記録）と `index.html` の控え。
4. `.htaccess` に次を足す（既存の行は消さない）：
   ```apache
   # 2026-11-20 旧119番LP → 新サイトへ恒久転送（有璽氏の決定）
   RewriteEngine On
   RewriteCond %{HTTP_HOST} ^fukushi119\.vivid-global\.com$ [NC]
   RewriteRule ^ https://119.fuku-chi.com/ [R=301,L]
   ```
   - パスは引き継がない（旧LPは1枚もの・新サイトに同じパスが無い）。クエリ（utm など）は Apache の既定で引き継がれる。
   - 手順2で直接リンクされているファイルが見つかったら、そのファイルだけ転送から外すか、有璽氏に聞く。
5. 照合（2経路）：
   - `curl -sI https://fukushi119.vivid-global.com/` → `301` と `location: https://119.fuku-chi.com/`
   - `curl -sI "https://fukushi119.vivid-global.com/?utm_source=x"` → location にクエリが付く
   - `curl -s -o /dev/null -w "%{http_code}" -L https://fukushi119.vivid-global.com/` → 200
6. `bin/web_tracking/sites.json` の旧LPの行の status に、実施日時と結果を書く。

## してはいけないこと
- 旧LPのファイルを消さない（戻せるように残す。.htaccess の追記を外せば戻る）。
- さくらの他のサイト（WordPress など）の .htaccess・DNS には触らない。

## 次にやること（任意・有璽氏の判断）
- Search Console に 119.fuku-chi.com を登録してサイトマップ `https://119.fuku-chi.com/sitemap.xml` を送る。ドメインプロパティ（sc-domain:fuku-chi.com）があればそこで送るだけでよい。旧ドメイン側のプロパティで「アドレス変更」は、サブドメイン間では使えないため不要。
