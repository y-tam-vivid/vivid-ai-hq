# 仕分けカード③の設計（2026-10-30 名鑑の設計担当 → MacBook / mini の実装担当）

> 前提は `2026-10-30_議事録GASの変更と名鑑側で引き取ること.md`（main）。GAS は触らない。
> 実装＝ピタゴラス（mini）／検査＝ステラ。判断の出口は規範どおり `ask_hub`。

## 0. このカードで決めること・決めないこと

| 決める | 決めない（別の道で決まる） |
|---|---|
| 区分（社外／社内／個人） | 顧客の基本情報そのもの（スプレッドシートが正本） |
| 相手はどの顧客か（既存の候補／新規） | 社内顧客IDの発番（§6 の答え次第） |
| 初めて会う相手か | 関係の段階（名鑑で人が選ぶ） |
| 出会った場所・紹介者（初めての時だけ） | 議事録の中身の要約 |
| 全社へ共有するか（共有する／個人どまり／機微あり） | |

## 1. 全体の流れ

```
GAS（変更なし） ── 🔒個人議事録DBに新しい行
                         │
mini  meeting_sort.py（15分ごと・新設）
   ① 新しい行を拾う   条件：仕分け＝空 かつ 作成が稼働開始より後
   ② 見立てを作る     区分・相手の候補3つ・初めてか・共有（§2）
   ③ 振り分け
        社内／個人で確信が高い ──▶ カードは出さず自動で記録。夕方に1通 tell()（返信不要の一覧）
        それ以外              ──▶ ask_hub でカードを1枚（§3）
   ④ 押されたら書く     §4 の書き先へ。結果は必ずカードに返す
```

- **カードを出さない自動処理の条件**：相手・会社が「社内」で始まる、または参加者が全員👤担当者マスターの在籍者。10/29 の実測で、直近6か月の未紐付け238件のうち104件が「社内」。これを全部カードにすると、毎日カードが社内の定例で埋まる。
- 自動で決めたものも「仕分け＝自動」と残し、夕方の一覧から「違う」を押せば直せるようにする（一覧は tell() ではなく、1件ずつ [違う] ボタンを付けたいなら ask_hub をまとめて1通にする。§7 の判断に入れた）。

## 2. 見立ての作り方

| 項目 | 材料 | 作り方 |
|---|---|---|
| 区分 | 相手・会社、参加者、種別 | 上の自動条件で社内を拾う。種別＝私用は個人。残りは社外 |
| 相手の候補 | 相手・会社、参加者、Name（題）、本文の冒頭2,000字 | ①機械で顧客DB（506件）の会社名・代表者・先方担当から文字の近さで上位20件に絞る → ②Haiku に「どれが相手か、上位3つと理由1行」を選ばせる。★候補に無ければ「新規」を1番に出す |
| 初めてか | 選ばれた候補に紐付く過去の議事録の件数 | 0件なら「初めて」。★相手を直したら数え直す |
| 共有 | 種別、本文 | 既定は「個人どまり」。機微の語（金額・健康・家族・個人の連絡先）があれば「機微あり」を見立てにする |

- 表記ゆれの実例（テストに使う）：小野紙工／有限会社小野紙器（B-0031）、クヴァシルワークス／Kvasir Works株式会社、相手欄に「田村」と入っている諸橋さんの回（→ 諸橋薫 B-0438）、スマートコンテンツ辻様（SparkNow経由）→ 株式会社SparkNow（B-0294）、中島 拓己 / 株式会社CLOUD WIN（顧客DBの CLOUD WIN の行に「名刺担当は中島拓己」）。
- モデルは規範どおり Haiku（定型の仕分け）。迷いが大きいときは候補を3つ並べるだけにし、AIに決めさせない。

## 3. カードの形

`ask_hub.ask()` は選択肢4つまで・1問。なので **「見立てをそのまま確定」を1押しにし、直すときはモーダル**にする（モーダルは「その他」で既に通っている経路）。

```
【議事録の仕分け】2026-10-29【商談】スマートコンテンツ辻様（SparkNow経由）_福祉・介護分野での業務連携…
AIの見立て
  区分        社外
  相手        株式会社SparkNow（B-0294）   ほかの候補：スマートコンテンツ（未登録）
  初めてか    はい（この相手の議事録は0件）
  出会った場所 紹介（SparkNow経由）
  全社へ共有   個人どまり
[この内容で確定]  [直す]  [相手は新規（受付へ）]  [✍️ その他]
```

- **[直す]** を押すとモーダルが開く。中身：区分（ラジオ）／相手（候補3つ＋「別の会社を探す」＝顧客DBから検索できる選択）／初めてか（ラジオ）／出会った場所（流入経路の選択＋具体名の入力）・紹介者（任意）／全社へ共有（ラジオ）。初期値は見立て。
- **[相手は新規（受付へ）]**：受付シートに1行足す（会社名・人名・流入経路・議事録のリンク）。以降は既存の「受付→照合→人の○×→発番」に乗る。Notion で顧客を作らない。
- 押したら、元のカードを「✅ 確定：株式会社SparkNow／個人どまり（10/30 10:12 有璽氏）」に書き換え、ボタンを消す。失敗したら「⚠️ 書き込めませんでした（理由）。Notion の行で直接直してください＋行のリンク」を返す。
- 1日に出すカードの上限を置く（初期値 10枚）。溢れた分は翌日に回し、夕方の tell() に「残り◯件」を出す。

## 4. 書き先

| 押した結果 | 🔒個人議事録DB | ほか |
|---|---|---|
| 相手（既存） | 顧客 relation | — |
| 相手（新規） | 顧客は空のまま・仕分け＝受付待ち | 受付シートに1行 |
| 区分＝社内 | 種別＝社内 | — |
| 区分＝個人 | 種別＝私用 | — |
| 共有する | 全社へ共有 ✅（昇格は既存の promote_minutes.py） | — |
| 個人どまり | 昇格状態＝🔒個人どまり | — |
| 機微あり | 昇格状態＝🔒個人どまり・機微の疑い に理由 | — |
| 初めてか・出会った場所・紹介者 | （名鑑の「人」DBができるまでは）メモ欄の末尾に1行 | 名鑑の人DBができたらそちらへ |

- **新しく足す列（個人議事録DB）**：`仕分け`（select：未／自動／確定／受付待ち／保留）、`仕分けの受付番号`（text）。★列の追加は非破壊だが、足す前に有璽氏へ1回出す。
- 書く前に、その行の 顧客 が空であることを確かめる（人が先に手で付けていたら上書きしない）。
- 1件ずつ「行ID・押した内容・前の値・新しい値」をログに残す（戻せるように）。

## 5. 段階

```
段階1  有璽氏の議事録だけ（オーナー区分＝有璽氏個人）。新しく入る分だけ。1週間回して、見立ての当たり率を数える
       （確定のうち「直す」を押さずに通った割合。★測っていない率を書かない）
段階2  過去分（§6 の範囲）を同じカードで流す。1日10枚
段階3  社員の議事録へ広げる（★10/29 実測でオーナー区分＝社員は0件。社員の議事録の入口がまだ無い＝別に決める）
```

## 6. 有璽氏の答えが要るもの（名鑑の設計担当から聞き直し済み・答えが来たらここを書き換える）

1. **社内顧客IDの発番**（スプレッドシートのまま／Notion へ移す）── 推奨はスプレッドシートのまま。カードの「新規」は受付シートへ流すだけで済み、kintone の週次同期も今のまま動く。
2. **過去分をどこまで遡るか**（全件／直近6か月）── 推奨は直近6か月（社内を除くと約95件＋自動の104件）。
3. **全社員に見せる要約の材料**（個人議事録から機微を落とす／全社昇格分だけ）── カードの「全社へ共有」で昇格が回り始めれば、昇格分だけでも名鑑の要約が埋まっていく。

## 7. 実装担当が決めてよいこと・聞くこと

- 決めてよい：拾う間隔（15分）、上位20件への絞り方、ログの形、1日の上限の初期値
- 有璽氏へ ask_hub で聞く：個人議事録DBへの列の追加（§4）、自動で記録した社内分の一覧を tell() にするか [違う] ボタン付きにするか
- ★cron に載せる前にドーベルマンの点検を通す。★「動いた」と「書けた」を分ける（心拍は書けたときだけ）。

## 8. 確かめ方（段階1の合格）

- 新しい議事録1件でカードが出て、[この内容で確定] で個人議事録DBの 顧客 が付き、カードが ✅ に変わる
- [直す] で相手を変えると、変えた相手で書かれる
- [相手は新規] で受付シートに1行入る
- 社内の定例はカードが出ずに 種別＝社内 で記録され、夕方の一覧に出る
- わざと失敗させた（Notion の権限を外したテスト行）ときに ⚠️ と逃げ道が返る
