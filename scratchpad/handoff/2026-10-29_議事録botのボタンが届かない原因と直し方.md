# 議事録botのボタンが届かない原因と直し方（2026-10-29 クラウドセッション → MacBook / mini のセッションへ）

> 渡すのは有璽氏の手。このファイルを MacBook のセッションで開いて「この手順で進めて」と頼む。
> クラウドからは mini の `~/.vivid-relay/` に届かないため、ここでは診断と手順までにしている。

## 起きていること（Slack の実物で確認）

- `#09_事務-議事録管理bot` に「⚠️ 受け取れませんでした（ボタンの中身が読めませんでした）。お手数ですが受付シートで直接ご記入ください」が並んでいる。
  チャンネルの直近40件（10/13 12:08〜10/29 14:08）のうち36件がこれ。残り4件は週次レポート2件と重複通知2件。
- 週次レポート（10/19・10/26）はどちらも **承認済み0件・承認待ち15件／19件**。＝議事録の承認ボタンが1件も通っていない。

## 原因（ほぼ確定。最後の1点は mini で実測して確かめる）

```
議事録整理Bot（App A0ASVGXNXQF）
  ├ GAS の議事録整理 v4 ……… 承認カードを出す。ボタンの value は承認ID（裸のUUID）
  └ mini の slack_socket.py …… 2026-08-25 に Socket Mode で同じアプリに接続（受付シートの照合ボタン用）

Socket Mode を入れたアプリは、すべてのボタン押下が websocket（slack_socket.py）に流れ、
GAS の Request URL（doPost）には届かなくなる。
slack_socket.py は value を JSON 前提で読むので、UUID は弾き、受付シート向けの文言で失敗を返す。
```

- 文言「受付シートで直接ご記入ください」は受付シート用の `fail_reply()`（`slack_socket.py:530` 付近）。議事録のbotの文言ではない。
- `memory/reference_slack_tokens_and_socket_mode.md` に 8/25〜9/3 の「value が裸のUUID」33件の記録があり、送信元は「GAS の議事録bot 等」と推測で止まっていた。今回の週次レポート（承認0件）で辻褄が合う。
- 毎時08分前後に失敗がまとまって出ている。人が押した時刻にしては規則的で、何が押下を再送しているかは未確認。

### GAS側の裏付け（Drive のバックアップ `議事録自動整理_GAS_v4.js`・6/16版で確認）

- 承認カードのボタン：`action_id: 'approve' / 'reject'`、`value: params.pendingId`
- `pendingId = Utilities.getUuid()`（226行目）＝**裸のUUID**。mini のログに残っていた値の形と一致する
- `doPost(e)`：`JSON.parse(decodeURIComponent(e.postData.contents).replace('payload=', ''))` で読む。**署名の検証はしていない**＝mini から転送しても受けられる
- ★6/16版は古い（8/15 にフォルダ選択を外している）。転送前に、今の GAS の doPost が同じ読み方かを Apps Script の画面で1回見る

### mini で確かめる1点
`slack_socket.log` の `★valueがJSONとして読めない` の行の時刻と、`#09_事務-議事録管理bot` の「受け取れませんでした」の時刻が一致するか。一致すれば確定。

## 直し方の案

| 案 | やること | よい点 | 弱い点 |
|---|---|---|---|
| A 転送（推奨・当座） | `slack_socket.py` の `handle_block_actions` で、value が JSON でなく UUID 形式のときは、payload をそのまま GAS の Web アプリURL（doPost）へ `payload=<JSON>` で POST し、受付シート向けの fail_reply は返さない | GAS 側を触らずに、溜まっている承認待ちがすぐ流れる | 2つの仕組みが1つのアプリに同居したまま |
| B アプリを分ける | 受付シート用に別の Slack アプリを作り、Socket Mode はそちらだけで使う | 混線が二度と起きない | Slack の管理画面での作業（有璽氏の手）と、トークンの差し替えが要る |

- A を入れる前に、GAS の Web アプリURL と doPost が今も生きているか（デプロイが残っているか）を確かめる。
  URL は Slack アプリ（A0ASVGXNXQF）の「Interactivity & Shortcuts」の Request URL に残っているはず。無ければ Apps Script の「デプロイを管理」で `/exec` のURLを見る。

### A の差し込み（`slack_socket.py`・Python 3.9・標準ライブラリのみ）

★先に `slack_socket.py` の控えを取る（`cp slack_socket.py _backups/slack_socket.py.bak_YYYYMMDD-HHMM`）。

```python
import re, urllib.parse, urllib.request

GIJI_GAS_URL = cfg.get("GIJI_GAS_WEBAPP_URL")      # config.env に1行足す（.../exec）
_GIJI_ACTIONS = {"approve", "reject", "change_folder"}
_UUID = re.compile(r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$")

def forward_to_gas(payload):
    body = "payload=" + urllib.parse.quote(json.dumps(payload, ensure_ascii=False))
    req = urllib.request.Request(GIJI_GAS_URL, data=body.encode("utf-8"),
                                 headers={"Content-Type": "application/x-www-form-urlencoded"})
    with urllib.request.urlopen(req, timeout=30) as r:   # /exec は302を返すが doPost は先に実行済み
        return r.status
```

`handle_block_actions` の、value を JSON として読む**手前**に入れる：

```python
act = (payload.get("actions") or [{}])[0]
if act.get("action_id") in _GIJI_ACTIONS or _UUID.match(str(act.get("value", ""))):
    log(f"議事録のボタンをGASへ転送: action={act.get('action_id')} "
        f"app={payload.get('api_app_id')} ch={(payload.get('channel') or {}).get('id')}")
    try:
        log(f"GAS応答 {forward_to_gas(payload)}")
    except Exception as e:
        log(f"★GASへの転送に失敗: {e!r}")
        fail_reply(payload.get("response_url"),
                   "議事録の承認を受け取れませんでした（GASへの転送に失敗）。少し待ってもう一度押してください")
    return
```

- `cfg` / `log` / `fail_reply` は既存のものの名前に合わせる（実物を見てから）。
- 受付シートのボタン（JSON の value）はこれまでどおり通る。
- 確かめ方：①転送を入れたら、溜まっている承認待ちのカードを1枚だけ押す ②`slack_socket.log` に「GAS応答」 ③Slack のカードが承認済みに変わる ④🔒個人議事録DBに行が入り、Drive のファイルが移っている、の4つを実物で見る。1つでも欠けたら残りは押さない。
- 通ったら、残りの承認待ち（10/26 の週次で19件）を押す。量が多いときは、7/13 にまとめて却下して87件を取りこぼした件を思い出す（`memory/project_giji_automation_gas.md`）。却下は押さない。
- A のあと、承認待ちの19件が実際に Notion に入り Drive に移ったかを実物で見る（「動いた」と「成功した」を分ける）。
- 担当：コード変更＝ピタゴラス、検査＝ステラ。`~/.vivid-relay/` は git の外なので両機へ手で配る。

## このあとの形（有璽氏 10/29 の希望）

議事録が Notta／Google Meet から自動で入ったら、Slack に1枚のカードを出して、そこで選べるようにする。Notion では操作しない。

```
【商談】2026-10-29 スマートコンテンツ辻様（SparkNow経由）
相手はどれですか     [株式会社SparkNow B-0294] [別の会社] [該当なし（新規登録へ）]
全社へ共有しますか   [全社へ共有] [個人どまり] [機微あり]
```

- 相手の候補は、相手・会社の欄だけでなく参加者と本文も使ってAIが上位を出す（表記ゆれ：小野紙工／小野紙器、クヴァシルワークス／Kvasir Works、相手欄に「田村」が入る諸橋さんの回など）。
- 判断のボタンは規範どおり mini の `ask_hub.ask()` から出す。押したら必ず結果を返す（`memory/reference_silent_failure_kills_adoption.md`）。
- まず有璽氏の議事録で回し、同じ形を社員の議事録へ広げる。
- 過去分の紐付けも同じカードで流す（直近6か月の、社内・未登録・自社を除いた分から）。
