# 119番 解決パートナー：実際の掲載に必要な情報と、社内名鑑との分け方

作成 2026-10-31（クラウド・ビビ）／取扱：社内限定

## 1. 2つのサイトの役目（有璽氏 10/31）

```
スプレッドシート（顧客の正本・社内顧客IDを発番）
        │
        ▼
社内パートナー名鑑（社内だけ・全件）  ← 商談前・商談中に開いて提案に使う
        │   載せる条件：3つすべて満たすものだけ
        │   ① 福祉施設の119番に関わる（お悩み分類のどれかに当てはまる）
        │   ② 公開レベル＝外部公開可
        │   ③ 本人の掲載の承諾と、原稿の確認が済んでいる
        ▼
119番 解決パートナー（社外へ公開）  ← 名鑑の一部を、外向けの文章で載せる
```

- **名鑑が全件、ポータルはその一部。** ポータルにだけ載っている人・会社はつくらない。
- 2つをつなぐのは **社内顧客ID（スプレッドシートの番号。例 B-0438）**。ポータルの各掲載の `_meta.meikan_id` に入れる。
- **外向けの文章と写真はポータル側だけが持つ。** 名鑑のメモや議事録の要約をそのまま外へ出さない。本人が確認した文面だけを載せる。
- 名鑑の写真（Drive `30_顧客写真`）は「名鑑の中だけで使う」と決まっている（10/29）。**ポータルの写真は、本人から掲載用にもらったものだけを使う。**

## 2. 掲載に要る情報

★印は必須。それ以外は任意（空なら、その欄は画面に出さない）。

| 項目 | 例・目安 |
|---|---|

## 3. 写真

| 使う場所 | 向き・大きさ | 中身 |
|---|---|---|
| パートナーの記事の上 | 横長 16:9、横 1600px 以上 | 人物か、仕事の様子 |
| 経営者の声 | 横長 16:9 か 4:3 | 経営者ご本人（施設の中で） |
| 顔写真（あれば） | 正方形 | 肩から上 |

- ★本人から「サイトに載せてよい写真」として受け取る。スマホの写真でよい。
- ★子ども・利用者の顔が分かる写真は使わない（写るなら後ろ姿かぼかし）。
- 写真がない掲載は、いまのダミー写真か色の面で出す。
- 置き場は `scratchpad/f119-portal/photos/<掲載のid>.jpg`（元の写真は Drive の119番フォルダに残す）。

## 4. 承諾として残すもの

`_meta.consent` に「いつ・誰が・何に」を1行で書く（例 `2026-11-05 諸橋薫さん LINEで原稿と写真を確認・掲載OK`）。
**空のまま `kind: real` にすると、組み立てのスクリプトが止まる**（`render_data.py`）。

## 5. 情報のもらい方（有璽氏 → こちら）

1. 相手ごとに、上の表の分かる範囲を会話へ貼る（箇条書きでよい）。議事録・資料・LINEのやり取りでもよい。
2. こちらで外向けの原稿に整え、`data/*.json` へ「下書き（show: false）」で入れる。
3. 原稿を相手に確認してもらう（送るのは有璽氏）。
4. 承諾が出たら `kind: real`・`consent`・`show: true` にして公開する。架空の見本は、実在の掲載が増えたら順に外す。

## 6. 仕組み（作業する人向け）

- 掲載の正本は `data/partners.json`・`data/voices.json`・`data/facilities.json`。
- `render_data.py` が `index.html` の `/*DATA:BEGIN*/〜/*DATA:END*/` を書き直す（画面に渡すのは見本かどうかだけで、社内IDや承諾の記録は出さない）。
- `build_public.py` が公開版を組み立てる（最初に render_data を呼ぶ）。見本と実在が混ざると、帯の文言と各掲載の「（架空）」が自動で切り替わる。
- 将来、名鑑の人DB（Notion）ができたら、`meikan_id` で突き合わせ、名鑑の側に「ポータル掲載中」を表示する（名鑑の担当へ渡す話）。
