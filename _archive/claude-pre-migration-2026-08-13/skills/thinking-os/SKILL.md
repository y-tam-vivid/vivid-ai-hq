# 思考OS ― 判断構造を借りる指示骨格（モデル非依存）

## これは何か
メール要約や下書きのような「雑用」ではなく、**重い判断**（事業の前提を壊す・顧客が本当に欲しい変化・捨てる作業・一点突破・実行計画化）をClaudeに任せるための**再利用可能な指示構造**。

出典は NewsPicks 記事「Claude Fable 5 指示10選」（KAWAI/川合卓也, 2026-07-04）だが、**この構造の本体はモデルに依存しない**。Fable専用の裏技ではなく、Sonnet/Opus/Fableのどのモデル・どのセッションからでも同じ骨格で使える。だから記事の"Fable限定"の枠組みは外し、汎用の判断OSとして運用する。

## 3つの大原則（厳守）
1. **借りるのは人格ではなく判断構造**。「イーロンっぽく」「ジョブズ風に」は禁止。口調模倣は仕事を進めない。「本人ではないが、〇〇に象徴される思考法を私の案件に適用する」という形にする。
2. **強い指示には必ず6要素**（下記骨格）。弱い指示＝「いい感じにして」は普通の回答しか返らない。性能差より前提差が効く。
3. **成果物は"読んで気持ちいい文章"ではなく"次の行動が決まること"**。会話ログで満足しない。最後に5点セットを残す。

## 6要素の指示骨格（すべての土台）
どのレンズを使うときも、この6要素を埋めてから渡す。

```
あなたは本人ではありません。ただし {人物/レンズ} に象徴される思考法を、私の案件に適用してください。

目的:          {何を前に進めたいか。1文で}
制約:          {時間・予算・使える素材・実績の有無など}
顧客:          {誰の、どんな変化のためか}
成果物:        {何を出力してほしいか。形式まで指定}
やってほしい判断: {下してほしい意思決定}
やってほしくないこと: {精神論・名言風・網羅・全部入りなどの禁止事項}
```

弱い/強いの差の実例:
- 弱: 「Claudeの使い方を教えて」
- 強: 「2日間で法人向けAI研修の提案導線を作りたい。対象は研修担当者。制約は実績資料が少なく予算をかけずnote/Xで集客。成果物はnote構成/X3本/CTA/提案骨子。まず顧客の不安と購買理由を整理し、最小コストで成約に近づく順番を提案して」

## 標準の実行順（散らからせない）
思考を散らかさないため、単発で使うより次の順で回す：

**広げる → 顧客に戻す → 削る → 資産化 → 実行計画**

- 分解/選択フェーズ: ① マスク(前提を壊す) → ③ ベゾス(顧客逆算) → ⑦ バフェット(やらない決定)
- 設計/出力フェーズ: ④ ジョブズ(1メッセージへ削る) → ⑤ アルトマン(資産化) → ⑩ 自分専用CEO(実行計画)

迷ったら最初の3つ：**① マスク / ③ ベゾス / ⑩ 自分専用CEO**。これだけで十分価値が出る。

## 最後に残す5点セット（出力の定型）
セッションの締めに、必ずこの5点に集約する：
1. 1枚の戦略メモ
2. やらないことリスト
3. 顧客FAQ
4. 発信テーマ1つ
5. 実行計画（次の行動）

## 機密の扱い（必須ゲート）
- 会社資料・顧客情報・未公開数字は**匿名化/要約/仮名化してから**渡す。生データを貼らない。
- 御社ルール準拠: 記録時は公開レベル（内部限定/メンバー共有可/外部公開可）を付与。戦略内容・数値目標・人物情報は対外発信側に含めない。
- サイバー攻撃・生物・化学・モデル蒸留に関わる依頼は扱わない（安全分類でフォールバックする領域）。判断・事業・文章・資料・業務設計に振る。

## モデル運用（進言）
- この骨格は**モデル非依存**。日常の判断整理は Sonnet で十分。
- 案件が重い（契約級の意思決定・大規模設計・精度が結果を左右）ときだけ Opus 昇格を提案。
- Fable は「一発勝負・大規模移行・長時間自律」でユーザー指名時のみ（コスト約2倍）。

## 使い終わったら（ナレッジ還流）
重い判断を回したセッションは、実務の区切りとして ⑥ディスカッションログDB へ短く記録（都度確認なし・機密は公開可否で判定）。再利用価値のある新レンズ/改良骨格が出たら ④プロンプト・スキルDB を更新。
