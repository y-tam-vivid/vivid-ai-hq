[[project-kids-event-apps]]の開発は**量産モード**で回す(2026-07-04ふくち合意)。

**自律度**: コンセプト選定もステラに一任。ステラが企画→エジソンに発注→検証→バッチ報告、を連続で回す。ふくちは基本ノータッチ。途中の口出し不要。

**Why**: 共通キット([[project-kids-event-apps]])で量産の型が完成済み。とにかくアプリの数を増やしたい、というのがふくちの狙い。

**How to apply**:
- 毎アプリ必ず自動チェック: tsc + eslint + next build パス / Playwright通しプレイでエラー0 / 既存アプリを壊さない / キオスク要件(大ボタン・ふりがな・自動リセット・端末内完結)。
- 同一Nextプロジェクト(fukuchi-kids-apps)内は**順番に**着手(page.txと共有buildの競合回避)。1本完成→次を自動着手。
- 報告はバッチ/完成ごと、スクショ付き。
- **これら5つだけは着手/実行前にふくちへ確認(=致命的ライン)**:
  1. 公開(デプロイ) — ふくちのVercelログイン操作が必要
  2. コストが発生する変更(本番Claude API接続など)
  3. プライバシー設計(カメラ・写真アップロード等。子ども対象で特に慎重)
  4. 公開済みアプリを壊す/消す変更
  5. 方向性が大きく分岐して手戻りが大きい判断
- 上記以外は自律で作って量産。カメラ/写真系アプリ(どうぶつへんしんカメラ/おえかき魔法等)は#3該当なので着手前に一声。クイズ/診断系は端末内完結の大きめ問題バンクで作りコスト回避(#2回避)。
