案B＝✅ビビッドタスク管理DB（全社）の `Company` `Department` `Project` を、select/multi_select から🏢組織マスター4DBへの**双方向Relation**に付け替える作業。2026-07-21に **Step 1〜5＋双方向化まで完了**。

https://app.notion.com/p/3a47b1568b5781d783a4d9b52d13fe34

**完了したこと**
- ②法人マスターに2行追加（`40 NPO法人南河内こどもステーション` `50 株式会社ふくち。`＝句点は社名の一部）
- ④プロジェクトマスターに4行追加（`就労施設Figma受託`＝コード11-302・稼働・部署はデザイン制作部11-300＋オレンジワークス藤井寺15-400／他3件は状態=廃止）
- タスクDBに `法人` `部署` `プロジェクト` のDUAL Relation列を新設。マスター側の逆方向プロパティ名は3DBとも `関連タスク`
- 旧select列は**削除せず並走**（非破壊）

**確定した判断**
- 「グループ横断」は**複数法人へのマルチRelation**で表現（ダミー法人行は作らない）。集計は法人別＝各法人に計上／全社合計＝行数
- `30SWELL` → `リアンライフ株式会社(30)`（マスター備考に「旧SWELLSOCIETY」と明記あり）
- `11-100 総合開発部` → マスター `事業開発部`（同一部署の旧称）
- 「担当」のRelation化は**スコープ外**（別タスク）
- 「芽育プロジェクト」の分割寄せ先は**未確定**（投入時に判断）

**重要な発見**：タスクDBの実レコードは**3件のみ**で組織分類はほぼ全null。引き継ぎ資料の「Department 21件」等はスキーマのoptions定義であって実データではなかった。移行対象が実質ゼロだったため突合リスクなく付替えできた。

**Step 6・7 も完了（2026-07-21）**
- 旧3列を `【非推奨】Company` `【非推奨】Department` `【非推奨】Project` にリネームして降格。**物理削除なし**（v1.1 9章準拠）。値消失なし
- **知見**：`RENAME COLUMN` は `ALTER COLUMN ... SET RELATION(..., DUAL ...)` とは別操作で**値は消えない**。Notion DDLは操作ごとに破壊性が違うので操作単位で警戒度を判断する
- **ビュー8種は存在しない可能性が非常に高い**。3手段で一貫してDefault view 1件のみ検出（他DBでは正常にビューを返す）。引き継ぎページ4章「影響範囲」の前提が崩れた。張り替え対象なし
- 📆締切ダッシュボードは旧列名を一切参照していないことを確認済み
