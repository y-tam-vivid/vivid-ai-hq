**kintoneのルックアップは「取得した時点のコピー」であって、コピー元への参照ではない。** 設計上は単一の出所に見えるが、コピー元を更新しても参照側は古い値を持ち続ける。

2026-08-12の実例：案件管理アプリ（15レコード）の `流入経路` は `顧客情報ルックアップ` グループ内のルックアップ項目。顧客管理側で流入経路を16値へ再分類したが、案件管理側は取得時の値のままで、**15件中9件がずれていた**（食い違い4件＋参照側が空5件）。食い違い4件はすべて顧客管理側を再分類した会社。

- **マスタ項目を更新したら、ルックアップを持つ全アプリで取り直すところまでが1つの作業。** 週次ルーティンに組み込む
- 取り直しは、レコードを編集モードで開いて「取得」を押す。件数が少なければ画面が確実。CSV取り込みでキー項目を含めても再取得は走るが、**キーの指定を誤ると別レコードを引く**
- ルックアップ項目は文字列としてコピーを持つので、**参照側アプリには選択肢（ドロップダウンの値）が存在しない**。「両アプリの選択肢を揃える」という作業自体が発生しない。設定を見ずに作業計画を書くとここを間違える
- 取り直しはグループ全体に効く。流入経路だけでなく住所・代表者名・法人番号なども最新化される
- コピー側だけで値が壊れることがある（実例：法人番号が `4120101064498<TAB×6>4120101064498<TAB×6>` と二重化。コピー元は単一値だったので取り直しで解消）。**法人番号は結合キーなので、この形だと突合で外れる**
