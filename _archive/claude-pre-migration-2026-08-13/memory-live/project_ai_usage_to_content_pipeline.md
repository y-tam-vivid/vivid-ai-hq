Claude Code等でのAI活用を、Notionの「AI活用 発信ネタDB」へ投稿ネタとして自動的に溜める仕組み。収集(ローカル)とネタ化(クラウド自動)の二段構え。関連: [[project_pr_agent]] / [[reference_notion_knowledge_hub]] / [[project_fable_style_improvement_loop]]

# 制約(なぜ二段構えか)
- クラウドのroutineは**ローカルのClaude Code履歴を読めない**。→ 収集はローカルがNotionへ push。ネタ化はNotion内で完結するのでクラウド自動化可。

# パイプライン
1. **収集(ローカル・実務の区切りごとの習慣＝規範化済)**: ローカルClaudeは実務が一段落するたびに、**都度の確認を取らず自動で**記録する(2026-07-11 ユーザー方針)。「残す価値がある」と判断したものは聞かずに残し、モルガンズへ渡る前提で書く。機微の扱い(公開可否判定)だけは厳格に。この自動記録ルールは**全エージェント定義(agents/*.md「作業ログの自動記録」節)＋Fable Style(fable-mode.md)に埋め込み済み=全AI共通認識**。
   - (a) **⑥ディスカッションログDB**(`collection://01061f08-2b49-432d-8ff9-40eb24993376`)に短く記録。継続は同一ページに📅セッション追記、新規は新ページ。**＝モルガンズ週次巡回の主ネタ源(ここを厚くするのが自動供給の核)**。
   - (b) 対外発信になり得る事例なら、**学習ログDB(案A・AI活用の単一入り口)** `data_source 16936917-fd98-42e7-962b-f13820600d22` にも記録し `発信候補`=✓/`発信ステータス`=ネタ(素材)/`公開可否` を付与(＝📣発信ネタボード `view 3997b156-8b57-813c-aa2d-000c09d45651` に乗る)。
   - **区切りでの"提案"(2026-07-17 ユーザー方針・UX)**: 実装作業の自動記録に加え、**対話的な区切りのタイミングでは「今までのやり取りをログに残しませんか？」とユーザーに一声提案**し、迷わせない設計にする(ユーザーが能動的に「記録して」と頼むのも可)。社内向けの使い方は社内ガイド `3a07b156-8b57-81ab-af6e-d827d703d5bf`(親=ビビッド業務管理)に明文化。
   - 規範反映先: Fable Style([[feedback_language_japanese]]と同ディレクトリ fable-mode.md「作業ログの記録」節) / 本メモリ / MEMORY.md索引。
   - ★[[project_ai_log_db_consolidation]](案A)整合。**Phase2(モルガンズ参照を学習ログ発信ボードへ付替)は保留**＝勢いで実行しない。当面モルガンズは⑥を読む。両方登録は実害なし。
2. **ネタ化(クラウド自動)**: routine `trig_01GtVoVWQzEKPwbDSeNRQYwL`「モルガンズ(PR)週次 AI活用発信ネタ化」、cron `0 2 * * 6`(土11:00 JST)。⑥/③を巡回→発信ネタDBに素材を起票(最大5件/週、重複回避、ステータス=ネタ(素材)、公開可否は要判定)。**自動公開しない**。
3. **公開判断**: 人間。素材→構成中→下書き→公開済 は手動で進める。
