# Report Structure

実施報告書の章立てと、各章の書き方。Step 1 で読む。

---

## 標準の章立て（固定）

**この構成は案件ごとに変えない。** 揃っているから比較できる。
デザインだけを提出先に合わせて切り替える。

| # | 章 | 内容 |
|---|---|---|
| 1 | 実施概要 | イベント名・開催日時・会場・主催者・対象者・開催目的 |
| 2 | 実施内容 | 当日のプログラムと進行。各プログラムが目的とどう結びついたか |
| 3 | 成果（KPI） | 目標値・実績値・達成率。未達は要因分析を添える |
| 4 | 参加者の反応 | アンケート結果、印象的な声（許諾を得たもの） |
| 5 | 広報実績 | 媒体別のリーチ、メディア掲載、SNS実績 |
| 6 | 収支実績 | 収入・支出・収支、1来場者あたりコスト |
| 7 | 課題・改善点 | 段階別の棚卸しと、対になる具体的改善策 |
| 8 | 総括 | 数値と事実に基づく結論。次回の方針 |
| 9 | 添付 | 写真（肖像権処理済）、アンケート集計、配布物 |

会場は建物名だけでなく**建物内の場所まで書く**。次回の会場選定で参考になる。

---

## KPIの分類

指標は企画書で決めたものをそのまま引き継ぐ。分類の目安は以下。

| 分類 | 指標の例 |
|---|---|
| 集客・認知 | 来場者数、新規来場者比率、メディア掲載数、SNSインプレッション、ハッシュタグ利用数 |
| 事業成果 | 相談件数、リード獲得数、商談化数、契約数、売上 |
| 満足・関与 | アンケート回答率、満足度スコア、再来意向、平均滞在時間 |
| 運営品質 | 受付待ち時間、配布物回収率、タイムテーブル遵守率 |
| コスト効率 | 1来場者あたりコスト、1件あたり獲得単価 |

達成率はパーセンテージで示し、グラフや数表にすると読み手が把握しやすい。
**未達でも隠さない。** 要因を分析して残すことが次回の資産になる。

## 書き方の原則

### 主観ではなく数値と事実で書く

| 悪い例 | よい例 |
|---|---|
| 多くの来場者が集まり、成功だった | 来場者は目標200名に対し243名（達成率122%）。事前のSNS告知が寄与したとみられる |
| アンケートの評判は良かった | 回答62件、満足度平均4.3/5.0。自由記述では体験時間の延長を求める声が7件 |
| 課題も見つかった | 受付の待機列が最大15分発生。次回は受付を2列化し、事前申込者レーンを分ける |

「成功」「盛況」といった評価語は、数値を伴わない限り使わない。
`validate_report.py` がこれを検出する。

### 次に読む人を想定する

報告書の読み手は、次回の企画者・決裁者・協力先・行政。
「これを読めば次回が組める」水準を目指す。

具体的には、会場の使い勝手、当日の想定外、有効だった集客経路、
避けるべき時間帯といった**再現に必要な情報**を残す。

### 参加者の声は許諾を得たものだけ

アンケートの自由記述をそのまま載せる場合、個人が特定されない形にする。
氏名・所属・年齢は載せない。

## 提出先ごとの調整

内容は変えず、**強調する章を変える**。

| 提出先 | 厚くする章 |
|---|---|
| 社内決裁者 | 成果（KPI）、収支実績、課題・改善点 |
| 協賛・協力先 | 広報実績、参加者の反応、写真 |
| 行政・補助金 | 実施概要、実施内容、収支実績、添付資料 |
| 一般公開（Web） | 実施内容、参加者の反応、写真 |

一般公開版では収支や社内課題を落とす。ただし**同じ元データから派生させる**こと。
別々に書き起こすと数値が食い違う。
