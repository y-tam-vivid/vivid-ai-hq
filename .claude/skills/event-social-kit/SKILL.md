# Event Social Kit

イベント現場の写真を、そのまま投稿できるSNS素材とキャプションに変換するためのスキル。

このスキルの前提は「イベントは毎回違う」こと。内容も会場も時間もターゲットも投稿先アカウントも変わる。
そこで**変わる情報をイベントプロファイルに外部化し、加工処理と文章設計はその設定を読んで動く**構造にしている。
最初にプロファイルを固めれば、以降の工程はイベントが何であっても同じ手順で流せる。

---

## 全体の流れ

```
0. イベントプロファイル確定  ← 汎用性の核。ここを飛ばさない
1. 素材受け取り・肖像権チェック
2. 画像／動画生成（scripts/snspipe.py）
3. アカウント別キャプション生成
4. 配信計画（単発 or 反復運用）
```

---

## Step 0: イベントプロファイルを確定する

**この工程を飛ばすと、会場名や参加条件を推測で書いてしまい、事実誤認のまま公開される。**
実際に起きやすい事故なので、必ず先に埋める。

`assets/event-profile-template.md` を読み込み、以下を確定する。
すでにプロファイルが会話中・プロジェクト内にある場合はそれを再利用し、差分だけ確認する。

| 項目 | 用途 | 不明時の扱い |
|---|---|---|
| イベント名／正式表記 | 全文面・ハッシュタグ | 確認する |
| 会場名（正式表記・階層まで） | 告知テキスト | **推測せず確認**。写真から読み取れても要裏取り |
| 開催日・時間 | 告知・カウントダウン | 確認する |
| 参加条件（無料／有料・予約要否・出入り自由か） | 告知の信頼性に直結 | **推測せず確認** |
| ターゲット層 | 文体・語彙・訴求点 | 写真から推定し提示して確認 |
| 投稿先アカウント（複数可）とそれぞれの性格 | トーン設計 | 確認する |
| ブランドカラー（背景／アクセント） | 画像のテキスト帯 | 既定値で進めて後から調整可 |
| 主催／共催／出展 のどの立場か | 一人称・動詞（「開催しました」／「行ってきました」） | **推測せず確認**。誤ると関係先に失礼になる |
| 使用可否が不明な要素（他社ロゴ・IP・出演者） | 掲載判断 | 確認する |

確定できない項目は空欄のまま進め、生成物を渡すときに「ここは仮です」と明示する。
埋めた内容はプロファイルとして保存し、同じイベントの2回目以降は再質問しない。

## Step 1: 素材を受け取り、肖像権を確認する

イベント写真には必ず第三者が写る。ここが最も判断を要する工程であり、
**自動処理に任せきりにしてはいけない**。

1. 全カットを実際に目で見る。`view` で開いて確認する。
2. 特定可能な顔（正面・準正面・近景）を洗い出す。子どもは特に慎重に扱う。
3. 判断は次の順で行う。

| 状況 | 対応 |
|---|---|
| 後ろ姿・手元・画面のみ | 加工不要 |
| 背景に小さく写る来場者 | 自動顔ぼかしで足りる |
| 中景〜近景に特定可能な顔が複数 | 帯状のソフトぼかし（被写界深度風）で面ごと処理 |
| 主要被写体が第三者の顔 | そのカットは使わない、またはトリミングで外す |
| 撮影許諾が取れている関係者 | ぼかさない。プロファイルに記録する |

四角いモザイクは検閲的で印象が悪い。**羽根付きのソフトぼかしを使い、被写界深度に見せる**。
ぼかし面積が広くなる場合、そのカット自体を採用しない判断も検討する。

詳しい判断基準とNG例は `references/privacy-checklist.md` を読む。

## Step 2: 画像・動画を生成する

`scripts/snspipe.py` を使う。EXIF回転補正・顔自動検出・ソフトぼかし・色補正・トリミング・
テキスト合成・動画書き出しを一括で行う。

```bash
# 手動ぼかし領域を決めたいとき（%座標グリッドを出力）
python3 scripts/snspipe.py --in <入力> --mode grid --prefix G --out <出力先>

# ストーリー（9:16・テキスト帯付き）
python3 scripts/snspipe.py --in <入力> --mode story \
  --badge "OPEN 10:00" --headline "本日も\n開催中です。" \
  --sub "10:00 - 17:00" --note "<会場名>" \
  --bg "#0A1630" --accent "#FF8A00" --prefix s1000 --out <出力先>

# カルーセル（4:5）
python3 scripts/snspipe.py --in <入力> --mode carousel --prefix c1000 --out <出力先>

# リール（9:16 MP4・複数枚をKen Burnsで連結）
python3 scripts/snspipe.py --in <入力> --mode reel \
  --headline "<エンドカード見出し>" --sub "<補足>" --note "@account" \
  --sec 3.0 --prefix r1700 --out <出力先>
```

主要オプション

- `--band x0,y0,x1,y1` … 手動ぼかし領域を%指定（複数回指定可）。grid モードの出力を見て決める
- `--noblur` … 自動顔ぼかしを無効化（関係者のみ・許諾済みのとき）
- `--focus x,y` … トリミング中心（既定 `0.5,0.45`）。主役が下寄りなら y を上げる
- `--zoom` … 1.0未満で寄る
- `--bg` / `--accent` … ブランドカラー。プロファイルの値を渡す
- `--sec` … リール1枚あたりの秒数（既定3.0秒。10〜20秒に収まる枚数を選ぶ）

**生成後は必ず出力を `view` で目視確認する。**
自動顔検出は正面顔に強い一方、横顔・小さい顔・帽子やマスクで隠れた顔を取りこぼす。
漏れがあれば `--band` を足して再実行する。この確認を省くと肖像権事故になる。

リールに音声は入れない。BGMは投稿アプリ内の音源ライブラリから付けてもらう。
権利面が安全で、かつプラットフォーム側の推奨挙動としてリーチも伸びやすい。

## Step 3: アカウント別キャプションを生成する

投稿先が複数ある場合、**同じ文章を使い回さない**。同一内容の重複投稿はリーチを損ない、
両方フォローしている人の体験も悪くする。

プロファイルの「アカウントの性格」に応じて軸をずらす。代表的な型は次の通り。

| アカウント種別 | 軸 | 一人称・文体 | 冒頭に置くもの |
|---|---|---|---|
| 個人（経営者・専門家） | 気づき・思想・現場で感じたこと | 一人称あり／丁寧語 | 情景や発見 |
| 主催・公式 | 開催情報・参加方法・来場促進 | 主語は主催者／明るい丁寧語 | 開催情報（日時・場所） |
| 事業者・法人 | 取り組みの意義・実績 | 主語は法人／落ち着いた丁寧語 | 何をしたか |
| 施設・店舗 | 現場の空気・スタッフ視点 | 一人称あり／親しみやすい | 呼びかけ |

構成・文字数・ハッシュタグ設計・NG表現は `references/caption-playbook.md` を読む。

事実に関する記述（来場者数・「大盛況」などの評価語・共催者名）は、
プロファイルまたはユーザーの発言に根拠があるものだけを書く。写真からの推測で書かない。

## Step 4: 配信計画を立てる

### 頻度設計の原則

**ストーリーは高頻度、フィードは低頻度。** これを混同すると成果が落ちる。

フィード投稿を1日に何本も流すと、同一アカウントの連続投稿は分散して配信されるため、
1本あたりのリーチが目減りし、エンゲージメントも分散する。翌日以降の表示にも響く。

推奨は次の配分。

| 媒体 | 頻度 | 役割 |
|---|---|---|
| ストーリー | 1〜2時間ごと | 速報性・現場感・リアルタイム情報 |
| フィード | 1日1〜2本 | 記録性・検索流入・資産化 |
| リール | 会期終了後に1本 | 総集編・拡散 |

### 当日のタイムライン設計

開催時間をプロファイルから読み、次の役割を時間帯に割り当てる。
時刻は固定ではなく、開催時間に応じて按分する。

1. **開場前** … 告知。カウントダウンスタンプを開場時刻にセットすると、投稿時と開場時の二度、通知が飛ぶ
2. **開場直後** … オープンの瞬間、行列や賑わい
3. **前半** … 参加者の手元・制作中の様子（顔を避けやすく、内容が伝わる）
4. **中盤** … **混雑状況の実況**。「いま空いています」は来場判断に最も効く
5. **後半** … 成果物・ビフォーアフター
6. **終了1〜2時間前** … ラストコール。緊急性を出す
7. **終了後** … 御礼とハイライト保存

反復運用の具体的な回し方、スタンプ活用、複数アカウントの相互送客は
`references/story-cadence.md` を読む。

## 反復運用モード（開催中に写真が届き続ける場合）

「2時間ごとに投稿したい」のように継続依頼を受けたら、次の形に切り替える。

- 毎回ユーザーに求める情報を3点に固定する ── **写真／撮影時刻／一言メモ**
  （「子どもが自分の作品を親に見せていた」程度の断片で十分。そこから文章を起こす）
- どのアカウント向けか、どの媒体（ストーリー／フィード／リール）かを毎回確認する
- 同じ切り口を繰り返さない。前回どの角度で書いたかを踏まえ、毎回ずらす
- 生成は1〜2分で返す。現場は待てないので、完璧さより速度を優先する
- 会期を通じて撮り溜めた素材は、終了後にリール1本へまとめる

作業環境がセッションをまたいで初期化される場合があるため、
イベントプロファイルは早い段階でファイル化してユーザーに渡し、再開時に読み込ませる。

---

## 引き渡し時に必ず伝えること

生成物を渡すときは、次の2点を添える。省くと事故につながる。

1. **仮置きした情報** ── プロファイルで確定しなかった項目（会場表記・参加条件など）を明示し、
   確認後に差し替える旨を伝える
2. **ぼかし処理の範囲** ── どのカットのどこを処理したか。ユーザー自身が最終判断できるようにする

## バンドルされているファイル

- `scripts/snspipe.py` … 画像・動画生成パイプライン。`--help` で全オプションを確認できる
- `assets/event-profile-template.md` … Step 0 で埋めるテンプレート
- `references/caption-playbook.md` … キャプション構成・トーン設計・ハッシュタグ・NG表現
- `references/story-cadence.md` … ストーリー運用の詳細設計
- `references/privacy-checklist.md` … 肖像権・写り込みの判断基準

## 動作要件

Python 3（Pillow, OpenCV, NumPy）と ffmpeg、日本語フォント（Noto Sans CJK）。
不足時は `pip install pillow opencv-python numpy --break-system-packages` で補う。
