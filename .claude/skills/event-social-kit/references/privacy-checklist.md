# Privacy Checklist

イベント写真の肖像権・写り込み対応。Step 1 で読む。

このスキルで最も判断を要する工程。生成物の見栄えより優先する。

---

## 1. 基本の考え方

イベント会場は不特定多数が行き交う空間であり、撮影された写真には必ず第三者が写る。
公開の場での撮影自体が直ちに問題になるわけではないが、**特定の個人が識別できる形で
SNSに公開すること**は別の話になる。企業アカウントであればなおさら、指摘を受けたときの
コストが大きい。

判断の軸は「その人が自分だと分かるか」「その人が公開を望まない可能性があるか」の2点。
迷ったら処理する。処理しすぎて怒られることはない。

法的な線引きの詳細は状況により異なるため、重要な案件では主催者や法務の確認を取ること。
このチェックリストは実務上の安全側の運用指針であり、法的助言ではない。

---

## 2. 判断表

| 状況 | 対応 | 補足 |
|---|---|---|
| 後ろ姿・手元・作品・画面のみ | 加工不要 | 最も安全。積極的にこの構図を選ぶ |
| 遠景に小さく写る来場者 | 自動顔ぼかし | 顔が数十ピクセルなら元々識別困難 |
| 中景に複数の顔 | 帯状のソフトぼかし | 面で処理して被写界深度に見せる |
| 近景に特定可能な顔 | 個別にぼかす、またはトリミングで外す | |
| 主要被写体が第三者の顔 | そのカットを使わない | 加工しても構図が成立しない |
| 子どもが識別可能 | 原則ぼかす。保護者の許諾があれば例外 | 最も慎重に扱う |
| 撮影許諾済みの関係者・出演者 | ぼかさない | プロファイルに記録し、次回以降も参照 |
| 自社スタッフ | 社内ルールに従う | 本人の同意を前提に |

---

## 3. 処理の作法

**四角いモザイクやピクセル化は使わない。** 検閲的で印象が悪く、投稿全体の質を下げる。

代わりに羽根付きのソフトぼかしを用い、被写界深度が浅いレンズで撮ったように見せる。
`snspipe.py` の `soft_blur` はこの処理を行い、領域の輪郭をぼかしてから合成するため
境界が目立たない。

面積が広くなる場合は帯状に処理する。人物が横に並ぶ群衆写真では、
個別に囲うより横帯で一括処理したほうが自然に見える。

ぼかし面積が画面の4割を超えるようなら、そのカット自体の採用を見直す。
何を見せたい写真なのかが曖昧になっている可能性が高い。

---

## 4. 自動検出の限界

`snspipe.py` の自動顔検出は Haar カスケードを用いており、以下を取りこぼす。

- 横顔・後頭部寄りの角度
- 小さく写った顔
- 帽子・マスク・手で部分的に隠れた顔
- 逆光や強い影の中の顔
- 走っている・かがんでいるなど非定型の姿勢

逆に、模様や影を顔と誤検出することもある。

**したがって、生成後に必ず出力を目視確認する。**
`--mode grid` で%座標グリッド付きの画像を出し、漏れた領域を `--band x0,y0,x1,y1` で
指定して再実行する。この確認を省略した時点で、このスキルの安全性は担保されなくなる。

---

## 5. 人物以外の写り込み

顔以外にも公開前に確認すべきものがある。

| 対象 | リスク | 対応 |
|---|---|---|
| 他社ロゴ・ブランド看板 | 無断利用と受け取られうる | 主要被写体でなければ通常可。前面に大きく出る場合は要確認 |
| キャラクター・IP | 権利侵害 | 権利者の許諾がなければ避ける |
| 個人名の入った掲示物・名札 | 個人情報 | ぼかす |
| 参加者リスト・申込書 | 個人情報 | 写さない。写っていれば使わない |
| PC画面の業務情報・メール | 情報漏洩 | ぼかす |
| 会場の非公開エリア | 会場ルール違反 | 使わない |
| 車のナンバープレート | 個人特定 | ぼかす |

会場によっては撮影・SNS投稿のルールが定められている。
商業施設や公共施設での催事では特に、プロファイルの「会場側の撮影・投稿ルール」を確認する。

---

## 6. 引き渡し時の説明

生成物を渡すときは、**どのカットのどこを処理したか**を必ず伝える。

ユーザーは現場を見ており、写っている人が誰かを知っている。
「3枚目の背景の群衆を帯でぼかしました」と伝えれば、
「あの人は許諾済みだからぼかさなくていい」といった補正が返ってくる。
最終判断はユーザーに委ねられるべきで、そのための材料を渡すのが役割。

処理漏れを見つけた場合も、指摘を待たずに自分から報告する。
