# Notion Structure

イベントDBのプロパティ設計と、Notion MCP経由で書き込む際の落とし穴。Step 2・Step 5 で読む。

---

## 1. イベントDB のプロパティ

既存DBがある場合はその構造に合わせる。ない場合は以下を提案する。

| プロパティ名 | 型 | 用途 |
|---|---|---|
| イベント名 | タイトル | 正式表記 |
| 通称 | テキスト | ハッシュタグ用の短縮表記 |
| ステータス | ステータス | 企画中 / 開催決定 / 告知中 / 開催中 / 終了 / 振り返り済 |
| 開催初日 | 日付 | 広報カレンダー逆算の起点 |
| 最終日 | 日付 | 単日なら初日と同じ |
| 開催時間 | テキスト | `10:00-17:00` 形式で統一 |
| 会場 | テキスト | 正式表記・階層・区画まで |
| 所在地 | テキスト | 市区町村 |
| 自社の立場 | セレクト | 主催 / 共催 / 出展 / 協力 / 後援 / 視察 |
| 主催者・共催者 | テキスト | 併記が必要な名称 |
| 参加費 | セレクト | 無料 / 有料 / 一部有料 / 未定 |
| 予約 | セレクト | 不要 / 要予約 / 一部要予約 / 未定 |
| ターゲット | マルチセレクト | 親子 / 事業者 / 学生 / 支援者 など |
| 投稿先アカウント | マルチセレクト | 運用するアカウント |
| プレス配信 | チェックボックス | PR TIMESを使うか |
| メディア招致 | チェックボックス | 記者を招くか |
| ブランドカラー | テキスト | `#背景 / #アクセント` |
| 掲載NG事項 | テキスト | 他社IP・撮影禁止エリアなど |
| 配信タスク | リレーション | 配信タスクDBへ |
| 来場実績 | 数値 | 確定後に入力 |
| メディア掲載 | テキスト | 掲載媒体と本数 |
| 振り返り | テキスト | 次回に活かす気づき |

## 2. 配信タスクDB（子DB）

`event-comms-orchestrator` の `build_schedule.py` が出力するCSVと1対1で対応する。

| プロパティ名 | 型 | CSVの列 |
|---|---|---|
| タスク | タイトル | タスク |
| 実施日 | 日付 | 日付 |
| 時刻 | テキスト | 時刻 |
| フェーズ | セレクト | フェーズ |
| 媒体 | セレクト | 媒体 |
| 担当アカウント | テキスト | 担当アカウント |
| 状態 | ステータス | 状態 |
| イベント | リレーション | 親DBへ |

CSVは `utf-8-sig` で出力されるため、Notionのインポートで文字化けしない。

## 3. MCP書き込みの落とし穴

以下は同一組織の既存スキル（`standup-event-notion-importer`）の運用で確認された事象。
MCPの版により変わる可能性があるため、初回書き込み時は1件で試してから一括投入する。

- **親の指定は `data_source_id`**。`page_id` ではない
- **日付は分解して渡す**。`date:実施日:start` / `date:実施日:end` / `date:実施日:is_datetime`
- **リレーション値はページURLのJSON配列文字列**。例 `"[\"https://app.notion.com/p/<32桁hex>\"]"`
- **マルチセレクトもJSON配列文字列**。数値は素の number
- **ページ削除・ゴミ箱移動はできない**。重複を見つけても削除せず、タイトルに `【重複・削除予定】` を
  付けてユーザーに手動削除を依頼する
- **固有名詞の文字化けに注意**。人名・地名の漢字が変換で崩れることがある。
  崩れたら最後にまとめて修正する

---

## 4. 一括投入の作法

- **必ず1件で試す**。プロパティ名や型が想定と違うと全件やり直しになる
- 10件を超える投入は分割する。途中で失敗したとき、どこまで入ったか追える
- 投入後は件数を数えて照合する。投入したつもりで入っていないことがある
- 失敗したレコードは飛ばさず記録する。あとでまとめて再投入する
