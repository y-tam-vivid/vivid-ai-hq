# 【ビビッド】SNS投稿文生成スキル

ビビッドグループ用に、プロジェクト内のナレッジと外部データソース（Notion等）を情報源としてSNS投稿文を生成するスキル。

## 責務範囲

このスキルは**投稿文（テキスト）の生成のみ**を担当する。画像プロンプト生成・QA判定は別スキルの責務。

## 入力ソース

### プロジェクトナレッジ内ファイル

| ファイル名 | 用途 | 必須/任意 |
|---|---|---|
| `brand_info.md` | ブランド・発信者情報、トーン定義 | 必須 |
| `content_themes.md` | コンテンツテーマ、カテゴリ、訴求軸 | 必須 |
| `platform_spec.md` | 文字数上限、ハッシュタグ運用、絵文字方針等 | 必須 |
| `data_sources.md` | 外部データソースのURL定義 | 必須 |

### 外部データソース（data_sources.md経由で取得）

data_sources.mdに記載されたURLをfetchして過去投稿を取得する。URLの種類（Notion、Google Drive等）は問わない。スキルは「URLからデータを取得する」という汎用的な動作のみ行う。

## 実行手順

### Step 1: プロジェクトファイル読込

上記4ファイルを読み込む。いずれか1つでも欠けている場合は不足を明示してユーザーに確認する。

### Step 2: 外部データソースから過去投稿を取得

1. `data_sources.md`を読み、「過去投稿アーカイブ」のURLを取得
2. 該当URLに対して適切なfetch手段を実行（Notion URLならnotion-fetch、その他ならweb_fetch等）
3. **直近30投稿**のみを参照対象とする
4. 各投稿のテキスト本文・画像（取得可能であれば）を取得

### Step 3: 過去投稿のスタイル分析

取得した過去投稿から以下を分析し、新規投稿のスタイル基準とする：

- **文体**：敬体/常体、語尾パターン、一人称
- **構成パターン**：導入→本文→締めの典型的な流れ
- **段落の長さ・改行頻度**
- **絵文字の使い方**：種類、頻度、配置パターン
- **ハッシュタグの傾向**：数、ジャンル、定番タグ
- **フック（1行目）のパターン**：疑問形/断定形/数字使用等
- **CTA（行動喚起）のパターン**
- **全体のトーン・温度感**

### Step 4: テーマの確認

ユーザーがテーマを指定していない場合：
- `content_themes.md`から3〜5件を提案（直近30件と重複するテーマは回避）
- ユーザーに選択を促す

ユーザーがテーマを指定している場合：
- そのテーマで進行（重複度が高い場合は差別化アングルを提案）

### Step 5: 投稿文生成

生成の核心原則：**過去の投稿一覧に新しい投稿を混ぜたとき、読者が「いつもと同じ人が書いている」と自然に感じるスタイルで書くこと。**

- **文体の統一**：過去投稿の語尾パターン・表現の癖を踏襲
- **構成の踏襲**：過去投稿の典型的な構成パターンに倣う
- **トーンの維持**：`brand_info.md`のトーン定義＋過去投稿の実際の温度感を反映
- **文字数**：`platform_spec.md`の推奨範囲内
- **NGワード厳守**：`brand_info.md`のNGワードは絶対に使わない
- **重複回避**：直近30投稿と切り口が酷似しないようにする
- **スタイル優先順位**：過去投稿の実際のスタイル > brand_info.mdのルール定義（読者にとっての一貫性が最重要）

### Step 6: 出力

```markdown
## 投稿文（[プラットフォーム名]）

### テーマ
[選択したテーマ]

### 本文
[投稿本文]

### ハッシュタグ
[ハッシュタグ群]

### 補足情報
- 文字数: [現在数] / [上限]
- 差別化ポイント: [直近投稿との違い]
- スタイル踏襲メモ: [過去投稿のどのパターンを参考にしたか簡潔に]
```

## 重要な原則

- **事実誤認回避**：ビビッドグループの事業に関わる数値・実績は、ナレッジに記載のないものは創作しない
- **法的表現の注意**：補助金・助成金・融資・金融に関わる表現は、断定的・誇大表現を避ける

## エラー時の対応

- data_sources.mdのURL未記載 → ユーザーに記載を依頼
- fetch失敗 → エラー内容を明示し、共有設定の確認を依頼
- 投稿が0件 → スタイル分析をスキップし、brand_info.md＋platform_spec.mdのルールのみで生成（ユーザーに通知）
- 必須ファイル不足 → 生成を中断し、不足ファイルを明示
