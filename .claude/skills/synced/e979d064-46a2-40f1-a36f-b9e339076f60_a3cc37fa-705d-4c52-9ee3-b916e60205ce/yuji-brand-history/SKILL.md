# 田村有璽 ブランドヒストリー

このスキルは、田村有璽および「ふくち。」グループの**人物・事業に関する事実ナレッジ**を正確に保持し、用途と公開レベルに応じて一貫した記述を生成するためのものである。

## 最重要: 最終更新日と鮮度チェック

**最終更新日: 2026-06-06**
**推奨更新サイクル: 6か月**

このスキルを使う**最初のステップ**として、必ず鮮度チェックを実行する。経歴・肩書き・施設数・法人設立状況は時間とともに変化するため、古い情報のまま出力すると事実誤認につながる。

```bash
python3 scripts/check_freshness.py
```

このスクリプトは最終更新日からの経過月数を計算し、6か月を超えていれば警告メッセージを返す。**警告が返ってきた場合は、応答の冒頭で田村氏（ユーザー）に対し、以下の項目に変更がないか確認を促す一文を必ず添えること**: 肩書き・役職、グループ内の法人数と設立状況（特に非営利法人）、運営施設数、共同研究・倫理審査の進捗、対外公開可となった情報の範囲。

スクリプトが実行できない環境の場合は、SKILL.md冒頭の「最終更新日: 2026-06-06」と現在日付を目視で比較し、6か月を超えていれば同様に確認を促す。

## 公開レベルの三区分（厳守）

田村氏に関する情報は、以下の三段階で扱う。**社外非公開情報を対外用途のテキストに混入させることは重大な誤りである。** 用途が対外（書籍・Web・登壇・SNS・取材など第三者の目に触れるもの）か、社内（戦略検討・内部資料）かをまず判断し、レベルに応じて使い分ける。

- **【公開可】** 対外資料・公開資料で自由に使用してよい情報。
- **【条件付き】** 文脈・媒体・本人の最終判断を確認した上で使用する情報。機微な個人情報や、相手・時期によって出し方を調整すべき情報を含む。
- **【非公開】** 社外非公開。対外用途のテキストには決して含めない。社内向け・戦略検討用途でのみ扱う。

各事実がどのレベルに属するかは、参照ファイル内に `【公開可】`／`【条件付き】`／`【非公開】` のタグで明示している。**対外用途のテキストを生成する際は、【非公開】タグの情報を一切使わないこと。【条件付き】の情報は、使用してよいか確認するか、確認済みの範囲に留めること。**

迷った場合の原則: **対外用途では、明示的に【公開可】とされた情報のみを使う。** 判断がつかない情報は使わず、必要ならユーザーに確認する。

## 参照ファイルの構成

事実ナレッジは4つの参照ファイルに分割している。**依頼内容に応じて関連するファイルを読んでから**テキストを生成すること。プロフィールや経歴紹介など複数領域にまたがる依頼では、複数ファイルを読む。

- `references/biography.md` — 経歴・基本プロフィール（生年・学歴・資格・職歴・現在の肩書き・連絡先情報）
- `references/origin_story.md` — 原体験（NPO親子二代／発達障害当事者性の二つの原体験、診断の経緯、お金にまつわる原体験）
- `references/philosophy.md` — 思想・価値観（「理解→応援→活きる」、MVV、ポジショニング表現、執行草舟の哲学、「大衆になるな、民衆であれ」）
- `references/business_evolution.md` — 事業変遷（NPO起点から各社設立、グループ構造、現在の事業、将来構想のフェーズ展開）

各ファイルの冒頭に内容の目次を置いている。

## テキスト生成の基本方針

田村氏の確立した好みとして、以下を踏襲する（既存の制作実績に基づく）。

- **文体ルール**: 三人称紹介文では、地の文は三人称・である調、会話・引用文は一人称・ですます調を基本とする。一人称の自己紹介文ではこの限りではないが、その場合も品位ある丁寧な文体を保つ。
- **構成**: 物語性を持たせる場合、「現在（今手がけていること）→過去（原体験と変遷）→未来（目指す姿）」の時間構成が田村氏の物語と相性が良い。
- **力点**: 「福祉とお金」という事業ビジョンの新規性と、それを支える二つの原体験（事業者目線・当事者目線）を軸に据えると一貫性が出る。
- **文字数管理**: プロフィールは用途により幅がある（書籍掲載で250〜350字、簡易紹介で100〜170字など）。指定文字数がある場合は厳守し、生成後に文字数を確認する。

## 研究・学術連携に関する記述の鉄則

田村氏は大学教授との共同研究を進めているが、**学会発表前の研究結果を、確定・完了した知見として対外テキストに記載してはならない**（研究倫理上のリスク）。研究については「問い・目的・姿勢・進行中であること」を語るに留め、「こういう結果が出た」「こういうことが分かった」という成果の先取りは絶対にしない。詳細は `references/business_evolution.md` および `references/origin_story.md` の研究関連セクションを参照。

## 使用後の確認

対外用途のテキストを生成したら、出力前に以下を自己点検する。

1. 【非公開】情報が混入していないか
2. 事実（年・法人名・数値）が参照ファイルと一致しているか
3. 研究結果を先取りしていないか
4. 指定文字数・文体ルールを満たしているか
