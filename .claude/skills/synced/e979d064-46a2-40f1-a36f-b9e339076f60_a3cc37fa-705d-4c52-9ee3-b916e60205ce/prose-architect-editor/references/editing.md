## 1. 校閲チェックリスト

原稿を仕上げる際、以下を順に点検する。

- [ ] 推敲の痕跡（旧表現と新表現の二重残し）がないか
- [ ] 同じ内容を二度言っていないか（重複・冗長）
- [ ] 文体が混在していないか（地の文と会話文、敬体と常体）
- [ ] 助詞の重複・脱字・崩れた文がないか
- [ ] 指定文字数を満たしているか（機械的に計測）
- [ ] 機密情報・研究結果の先取りがないか（safeguards.md 参照）
- [ ] 表記ゆれがないか（同義語の不統一。例「福祉とお金」と「福祉×お金」）

## 2. 推敲の二重表現・重複の検出

改稿を重ねた原稿には、旧表現を消し忘れて新表現と並存させる崩れが生じやすい。実例（今回の制作で発生）:
- 「幅広く手がけている。事業を手がけている。」（旧文と新文の併存）
- 「制度を知りながら活用しきれないジレンマを抱えながら、経営を続けてきたのだ。」が、直前の総括文と重複
- 「築く構想する」（推敲途中の語が残存）

検出のコツ:
- 同じ語・言い回しが近接して二度出ていないか走査する
- 段落の冒頭と末尾で同じ主張を繰り返していないか確認する
- 「AだったがAではない」のような、論理が一周して戻る箇所を探す

また、**同じ認識を地の文で二度提示していないか**にも注意する（実例: 当事者の発言で「私だけのものではない」と語った直後に、地の文で「強い問題意識があった」と再提示すると重複になる）。一方が問題提起なら、もう一方はその根拠説明や次の展開に役割を変える。

## 3. 文体の混在チェック

style_rules.md で定めた文体ルールが原稿全体で一貫しているか確認する。よくある混在:
- 地の文の途中で一人称・敬体が紛れ込む（例: 「〜こなしながら、周りに合わせて生きてきました」が地の文に出現）
- 会話文が常体になっている
- 一文の中で視点（三人称/一人称）が切り替わる

混在を見つけたら、その箇所がどちらの文体であるべきかを判断して統一する。一人称の語り口を活かしたい場合は、その部分を会話文（カギ括弧）として切り出す手もある。

## 4. 助詞重複・脱字の検出

改稿時のタイプミスで生じる崩れ。実例:
- 「そして田村自身も、が、プレイングマネージャーとして」（助詞「も」「が」の重複）
- 「事業を行いたい起業したい」（語の重複）
- 「不十分であると感じておりを用意できていない」（文の崩れ・脱字）

音読するように一文ずつ追い、主語・述語・助詞のつながりが自然かを確認する。

## 5. 文字数の機械的計測

**目視で字数を見積もらない。** 必ずコマンドやスクリプトで数える。空白・記号の扱い（カウント基準）は媒体により異なるため、最終入稿前に媒体の定義を確認する。

本文テキストをファイルに保存し、以下で計測:

```bash
# 空白・改行を除いた文字数（日本語原稿の概算に有効）
python3 -c "import sys,re; t=open('draft.txt',encoding='utf-8').read(); print('文字数（空白改行除く）:', len(re.sub(r'\s','',t)))"
```

複数ブロックに分かれている場合は、各ブロックを結合してから数える。見出しを含めるか否かも媒体基準に合わせる。

## 6. 文字数調整の進め方

字数オーバー時は、力点（composition.md 参照）を基準に「何を削るか」を判断する。

- 主軸でない具体例の列挙、機能の細部説明は圧縮しやすい
- 重複・冗長の解消だけで収まることも多い（まず2の検出を済ませる）
- 削減候補は複数提示し、どこを削るかユーザーに選ばせる

字数に余裕がある場合は、力点に沿って厚みを足す（主軸の原体験・論点の深掘り）。どこに字数を配分するかもユーザーに確認する。

## 7. ライターに戻す場合の運用

第三者（ライター・編集者）に原稿を戻す前提のとき、今回有効だった運用:
- 文書冒頭やコメント機能で、**版数・前版からの変更点サマリー・確認事項**を明示する
- 確認事項（未確定の固有名詞・数値・公開可否など）は赤字や注記で目立たせる
- これにより差し戻し回数が減り、相手の校正作業がスムーズになる
