# 構成設計（composition.md）

フェーズ1の詳細手順。原稿を書き始める前に、方向性・力点・骨格を固める。

## 目次
1. なぜ構成設計を先行させるか
2. ステップ1: 現状の方向性を言語化する
3. ステップ2: 力点を決める
4. ステップ3: 構成骨格を設計する
5. 構成パターンの選択肢
6. 確認の進め方

---

## 1. なぜ構成設計を先行させるか

長文原稿で最も手戻りが大きいのは、書き上げた後に「方向性が違った」と判明すること。先に骨格を言語化して合意を取れば、執筆後の大規模な書き直しを防げる。**いきなり本文を書き始めない**のが鉄則。

## 2. ステップ1: 現状の方向性を言語化する

既存の原稿・ドラフト・初稿がある場合、まずその構成と力点を自分の言葉で整理し、ユーザーに提示して認識を揃える。

- どんなブロック（段落のまとまり）で構成されているか
- どこに力点（重心）が置かれているか
- 全体のテーマや到達点は何か

この「現状認識の共有」を挟むと、「どこを変えたいか」の議論が具体的かつ速くなる。ユーザーは現状への違和感を起点に修正方針を語りやすくなる。

ドラフトがない新規原稿の場合は、このステップを飛ばし、ステップ2から始める。

## 3. ステップ2: 力点を決める

原稿の重心をどこに置くかを確定する。同じ素材でも力点で印象が大きく変わる。例として:

- 人物紹介なら: 原体験・人柄を主軸にするか、実績・専門性を主軸にするか
- 事業紹介なら: ビジョンの新規性を主軸にするか、課題解決の実用性を主軸にするか
- 主張・提案なら: 論理的妥当性を主軸にするか、共感・物語性を主軸にするか

力点が決まると、各ブロックの順序・分量・トーンが自ずと定まる。力点は「何を捨てるか」の判断基準にもなる（字数制約下では特に重要）。

## 4. ステップ3: 構成骨格を設計する

力点に沿って、ブロックの並びを設計する。設計した骨格は**箇条書きの流れとして言語化し、ユーザーに提示して合意を取る**。本文を書くのはその後。

骨格提示の例（インタビュー記事の場合）:
「導入（現在の活動を一望→問いを立てる）→ 理由①（原体験A）→ その帰結としての事業 → 理由②（原体験B）→ 深掘り → ビジョンで締め」

## 5. 構成パターンの選択肢

案件に応じて選ぶ。推奨を添えるが、ユーザーに選ばせる。

### 時間構成
- **現在→過去→未来**: 「今こうしている → なぜなら（原体験・変遷）→ どこへ向かうか」。人物・事業の物語に適し、読者の関心を引きやすい。インタビュー記事の定番。
- **過去→現在→未来（編年体）**: 生い立ちから時系列で追う。経歴の正確な理解が目的の場合に。
- **未来→現在→過去**: ビジョンを先に掲げ、その根拠を遡る。理念先行の訴求に。

### 論理構成
- **問い→答え→根拠**: 冒頭で問いを立て、答えを示し、根拠を展開。説得・提案に強い。
- **全体像→個別→統合**: 活動の全体を一望させてから各論に入り、最後に束ねる。「幅広い活動の共通項は何か」を示す導入に有効。
- **PREP（結論→理由→具体例→結論）**: ビジネス文書・提案書の標準。

### 物語構成
- **二項対比型**: 「事業者目線」と「当事者目線」のように二つの軸を立てて交互・並列に描く。複数の原体験や視点を整理して見せたいときに。
- **転機ドリブン**: 転機（気づき・出会い・挫折）を物語の節目に置く。

## 6. 確認の進め方

- 構成の分岐点や未確定事項は、**着手前にまとめて提示**してよい（着手後に小出しにすると手戻りが増える）。
- 大きな構成変更は別途検討し、合意できた骨格を「確定版の流れ」として明文化してから執筆に移る。
- ステップを踏むこと自体をユーザーに見せる（「まず力点を確認させてください」等）と、認識合わせが進めやすい。
