# 利用者負担上限額管理結果表 自動分割スキル ― 運用マニュアル

このスキルは、毎月ダウンロードされる「利用者負担上限額管理結果表」PDFを、施設ごとに自動で分割・結合・リネームするための Cowork スキルです。

---

## 1. このスキルでできること

入力：1ヶ月分の「利用者負担上限額管理結果表」PDF（複数ページ、複数利用者・複数施設が含まれる）

出力：施設ごとに分割・結合され、ファイル名が整理されたPDF

具体例：
- 入力：`お試し①.pdf`（15ページ、令和08年04月分、13施設が登場）
- 出力：`2026-04/` フォルダ内に13個のPDF
  - `2026_04_LIFE STAND UP_利用者負担上限額管理結果表.pdf`（15ページ）
  - `2026_04_放課後等デイサービス ライフスタディ_利用者負担上限額管理結果表.pdf`（6ページ）
  - …他11件

各施設に対し、その施設に関係するページだけを束ねたPDFが生成されるため、そのまま各施設へ送付できます。

## 2. 初期セットアップ（1回だけ）

### 2.1. Cowork のインストール

Cowork デスクトップアプリがインストールされていることを確認してください（Claude.ai と同じアカウントでログインしている前提です）。

### 2.2. スキルのアップロード

本スキルは Claude.ai 経由でアップロードします。Claude.ai にアップロードしたスキルは、同一アカウントで利用している Cowork でも自動的に有効になります。

手順：

1. 納品物として受領した ZIP ファイル `riyousha-futan-pdf-splitter.zip` を準備
2. ブラウザで [https://claude.ai](https://claude.ai) を開きログイン
3. 左下のアカウント名 → 「設定」または「Claudeをカスタマイズ」を選択
4. 「スキル」または「Skills」のタブを開く
5. 「スキルを追加」「アップロード」等のボタンから、上記の ZIP ファイルをアップロード
6. アップロード後、スキル一覧に `riyousha-futan-pdf-splitter` が表示されることを確認

※ Claude.ai 側のUIは更新される可能性があります。画面表記が異なる場合は「スキル管理」「カスタムスキル追加」等の表記を探してください。

### 2.3. 作業フォルダの準備

デスクトップなど任意の場所に **`利用者負担上限額管理結果表`** という名前のフォルダを作成してください。毎月のPDFはこのフォルダに格納します。

## 3. 毎月の使い方（基本3ステップ）

### Step 1: PDFを所定フォルダに置く

「成長療育支援システム」等からダウンロードした当月分のPDFを、`利用者負担上限額管理結果表` フォルダに入れてください。

### Step 2: Cowork を起動し、フォルダを選択

Cowork を起動して、上記の `利用者負担上限額管理結果表` フォルダを作業フォルダとして選択してください。

### Step 3: Claude に処理を依頼

以下のいずれかの方法で依頼してください。

**方法A：自然言語で依頼（推奨）**

Claude に以下のように依頼します。

> 今月の利用者負担上限額管理結果表を処理して

または単に「処理して」「分けて」でも、フォルダ内にPDFが入っていれば自動的に本スキルが起動します。

**方法B：スラッシュコマンドでスキルを明示指定**

チャット入力欄で `/` を入力するとスキル一覧が表示されます。`riyousha-futan-pdf-splitter` を選択して実行してください。

Claude は以下を順に行います：

1. フォルダ内のPDFを発見し、対象を確認
2. PDFの内容を読んで、年月と各ページの事業所一覧を抽出
3. 抽出結果をテーブルで提示し、内容に間違いがないか確認
4. 承認後、施設ごとに分割・結合・リネームを実行
5. 生成されたファイルへのリンクを報告

---

## 4. 注意点

### 4.1. 同じ月を再処理する場合

既に `YYYY-MM/` フォルダが存在する状態で再実行すると、Claude は「上書きしてよろしいですか？」と確認します。修正版PDFで再処理したい場合は「上書きでOK」と答えてください。

### 4.2. 複数PDFが同一フォルダにある場合

誤って先月分が残っていたり、複数のPDFをまとめて入れていた場合、Claude は「どれを処理しますか？」と必ず確認します。勝手にどれかを処理することはありません。

### 4.3. 事業所名の表記揺れ

「LIFE STAND UP」と「LIFE　STAND UP」（全角スペース）のような表記揺れは、自動的に同一施設として扱います。

別の事業所として扱うべきケース（=施設名そのものが異なる場合）は、当然ながら別ファイルとして出力されます。

### 4.4. 処理時間

通常、15〜30ページのPDFで 1〜2分程度です（Claudeの読み取り時間を含む）。

## 5. 出力フォルダの構成

処理後、`利用者負担上限額管理結果表` フォルダは以下のような構成になります。

```
利用者負担上限額管理結果表/
├── お試し①.pdf                          ← 元の入力PDF（残ります）
└── 2026-04/                             ← 処理結果フォルダ（自動生成）
    ├── 2026_04_LIFE STAND UP_利用者負担上限額管理結果表.pdf
    ├── 2026_04_Snuggle UP_利用者負担上限額管理結果表.pdf
    ├── 2026_04_あすてっぷ八尾南_利用者負担上限額管理結果表.pdf
    └── …他10件
```

入力PDFは削除されません。年月別にフォルダが分かれるので、過去分の管理も容易です。

## 6. うまく動かないとき

| 症状 | 対処 |
|---|---|
| 「フォルダにPDFが見つかりません」と言われる | 作業フォルダを正しく選択しているか、PDFがフォルダ直下にあるかを確認 |
| 事業所名が抜けている | Claude の読み取りミスの可能性。「もう一度確認して」と依頼。それでも繰り返す場合は弊社までご連絡ください |
| 同名のPDFが既に存在する旨の警告 | 上書きで進めて問題ないか判断。前回分を保存しておきたい場合は、`2026-04/` フォルダを別名にリネームしてから再実行 |
| スキルが起動しない | Cowork で「利用者負担上限額管理結果表 スキルを起動して」と明示的に依頼 |

## 7. 別書類への流用方法（応用編）

本スキルと同じロジック（複数ページPDF→項目別に分割・結合・リネーム）を **別の書類** に適用したい場合は、本スキルフォルダを丸ごとコピーして書き換えてください。

### 7.1. 流用の手順

1. **スキルフォルダを ZIP から展開**：受領した ZIP を展開し、フォルダごと別名（例：`<新書類名>-pdf-splitter/`）でコピー
2. **`SKILL.md` を書き換え**：以下の項目をカスタマイズ
   - `name`：新スキル名
   - `description`：新書類名・トリガー条件
   - 「3. 処理フロー」の Step 2「PDFの内容を読み取る」：抽出すべき項目（事業所名→新書類の項目に変更）
   - 入力フォルダ名（必要に応じて）
3. **`process_pdf.py` を書き換え**：スクリプト内に `===== カスタマイズポイント =====` というコメントで3箇所をマーキングしています
   - **(A) ファイル名フォーマット**：`process()` 関数内の `filename = f"..."`
   - **(B) 出力サブフォルダ名**：`process()` 関数内の `out_dir = ...`
   - **(C) 禁止文字ルール**：`safe_filename()` 関数
4. **`README.md` を書き換え**：クライアント向け説明文を新書類用に修正
5. **新スキルフォルダを ZIP 化**して、Claude.ai の「カスタマイズ → スキル」から再度アップロード（既存スキルとは別名で）

### 7.2. 流用時の注意

- スキル名は **重複させない**（Cowork内で一意である必要があります）
- `description` のトリガー条件は **既存スキルと明確に異なるキーワード** にしてください（例：「△△管理表」など書類名そのものを含める）。誤発火を防ぐためです
- スキル切り替えはユーザー側の操作不要。作業フォルダに対応するPDFを入れて「処理して」と依頼すれば、Claudeが該当スキルを自動で選択して実行します

### 7.3. 流用が向く書類

- 月次でフォーマットが固定されている帳票
- 複数の関係者（施設・部署・取引先など）が1つのPDFに混在しており、関係者ごとに分けて配布する必要がある書類

### 7.4. 流用が向かない書類

- レイアウトが毎回変わる書類（Claudeの読み取りが不安定になる可能性）
- 1つの書類に1つの関係者しか登場しない場合（そもそも分割不要）
- 100ページを大きく超える書類（処理時間が長くなる）
