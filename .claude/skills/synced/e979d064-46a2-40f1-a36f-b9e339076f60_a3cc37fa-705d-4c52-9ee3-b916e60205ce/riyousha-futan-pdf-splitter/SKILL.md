# 利用者負担上限額管理結果表 自動分割・施設別結合スキル

## 1. スキルの目的

毎月クライアント側で「成長療育支援システム」等からダウンロードされる「利用者負担上限額管理結果票」PDF（複数ページ）を、施設ごとに分割・結合した個別PDFに自動で再編成する。

クライアントは各施設に対し、その施設に関係するページだけを束ねたPDFを送付する必要があるため、本スキルが施設別の束ね直しを担当する。

## 2. 前提条件

- ユーザーが Cowork で `利用者負担上限額管理結果表` フォルダ（またはそれに準じる名称のフォルダ）を選択している
- そのフォルダ内に、処理対象のPDF（複数ページ）が配置されている
- PDFは「Microsoft Print To PDF」で出力されたベクター描画形式である可能性が高く、テキスト抽出は不可。Claudeはビジョン機能でPDFを直接読み取って情報を抽出する

## 3. 処理フロー（厳守）

### Step 1: 入力PDFの特定（ユーザー確認必須）

1. ワークスペースフォルダ直下の `*.pdf` ファイル一覧を取得する（サブフォルダは対象外）
2. **PDFが0件の場合**：ユーザーに「フォルダにPDFが見つかりません」と通知し、終了
3. **PDFが1件の場合**：そのPDFを処理対象として確定し、ユーザーに「次のPDFを処理します：◯◯.pdf。よろしいですか？」と確認
4. **PDFが2件以上ある場合**：必ずユーザーに「複数のPDFが見つかりました。どれを処理しますか？」と AskUserQuestion で確認する。**勝手に最新ファイルを選んだり全件処理したりしない**
5. ユーザーの承認を得たPDFのみを処理対象とする

### Step 2: PDFの内容を読み取る

1. 確定したPDFを Read ツールで開く
2. **年月の特定**：PDFの右上「令和○○年○○月分」を読み取り、西暦に変換
   - 変換式：西暦 = 2018 + 令和年
   - 例：令和08年04月分 → 2026年4月
3. **各ページの事業所名抽出**：
   - 「利用者負担額集計・調整欄」の表内、「事業所名称」行に記載されている事業所名を、**上段表・下段表の両方から**全て抽出する
   - 1ページに複数の事業所が記載されている場合は全て列挙
   - 「合計」列は事業所ではないので無視
   - 「事業所及びその事業所の名称」欄（管理事業者）は、それ自体は1施設として扱う必要があるが、各ページの利用者負担額集計欄に必ず登場しているはずなのでそこから取得すれば良い

### Step 3: マッピングJSON の作成

抽出した情報を以下のフォーマットで一時ファイルに保存する。

```json
{
  "year": 2026,
  "month": 4,
  "pages": {
    "1": ["LIFE STAND UP", "スバル・トータルプランニング(株)ぱすてる"],
    "2": ["LIFE STAND UP"],
    ...
  }
}
```

保存先：`<outputs>/mapping.json`（一時ファイル、ワークスペース外）

### Step 4: 抽出結果のユーザー確認

スクリプト実行前に、抽出結果をテーブル形式でユーザーに提示し、間違いがないか確認する。

提示する内容：
- 対象月（YYYY-MM）
- 検出されたユニーク施設一覧と、それぞれが該当するページ番号
- ページ数の合計内訳

ユーザーが「OK」「進めて」等で承認した時点で次へ進む。修正指示があれば mapping を修正して再提示。

### Step 5: スクリプト実行

```bash
python3 <skill_dir>/process_pdf.py \
  "<workspace>/対象PDF.pdf" \
  "<outputs>/mapping.json" \
  --out-base "<workspace>"
```

- `<skill_dir>` は本スキルが配置されているディレクトリ
- `<workspace>` はユーザーが選択しているワークスペースフォルダ
- 初回実行時に `pypdf` が無ければ `pip install pypdf --break-system-packages --quiet` で導入

### Step 6: 結果報告

スクリプトの実行が成功したら、ユーザーに以下を報告する：

- 出力先フォルダ（例：`利用者負担上限額管理結果表/2026-04/`）への computer:// リンク（フォルダ直接ではなくPDFへのリンクが望ましいが、件数が多い場合はサンプル数件＋総件数の報告でも可）
- 出力件数（施設数）
- 各PDFのページ数サマリー

## 4. エラーハンドリング・例外時の挙動

- **ワークスペースフォルダが未選択**：「Coworkで `利用者負担上限額管理結果表` フォルダを選択してから再度依頼してください」と案内
- **同じ年月の出力フォルダが既に存在**：「`YYYY-MM/` フォルダが既に存在します。中身を上書きしてよろしいですか？」と AskUserQuestion で確認する
- **事業所名の正規化判定で迷う**：表記揺れ（半角/全角スペースの違い等）は同一施設として扱うが、判断に迷う場合はユーザーに確認する
- **マッピング作成中にClaudeが事業所名を読み取れなかったページがある**：そのページの該当箇所を画像で確認させて、ユーザーに正解を尋ねる

## 5. やってはいけないこと

- ユーザー確認を飛ばして勝手にスクリプトを実行する
- 複数PDFがある状態で勝手にどれかを選んで処理する
- 事業所名を推測で補完する（曖昧な場合は必ずユーザーに確認）
- 出力先フォルダを書き換える（必ず `<workspace>/YYYY-MM/` の形）

## 6. 参考：別書類への流用について

本スキルと同じロジック（複数ページPDF→項目別に分割・結合・リネーム）を別の書類に適用する場合は、本スキルフォルダを丸ごとコピーして、以下の箇所を書き換えてください。詳細は同梱の `README.md` の「7. 別書類への流用方法」を参照。

- 本ファイル（SKILL.md）の `name`, `description`, トリガー条件
- 本ファイル（SKILL.md）の Step 2「PDFの内容を読み取る」の項目定義
- `process_pdf.py` の `safe_filename()` のルール（必要に応じて）
- ファイル名フォーマット（必要に応じて process_pdf.py 内のf-stringを修正）
