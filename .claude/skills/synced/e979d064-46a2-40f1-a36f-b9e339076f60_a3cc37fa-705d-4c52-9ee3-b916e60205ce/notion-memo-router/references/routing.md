## 1. 共通：Notion書き込みの記法
`notion-create-pages` / `notion-update-data-source` 等で値を入れる際の型ルール：
- **select**：選択肢名の文字列をそのまま渡す（例 `"Status": "Inbox"`）。
- **multi_select**：JSON配列の文字列（例 `"Assignee": "[\"Yuji\"]"`）。
- **date**：展開記法で渡す。`"date:<項目>:start"`（ISO日付）、必要に応じ `"date:<項目>:end"`、`"date:<項目>:is_datetime"`（0=日付のみ / 1=時刻あり）。
- **checkbox**：`"__YES__"` / `"__NO__"`。
- **title / text / url**：文字列。
- `id` や `url` という名前の項目は `userDefined:` を前置（例 `"userDefined:ID"`, `"userDefined:URL"`）。
- 既存データの検索は `notion-search` に `data_source_url`（`collection://…`）を指定して行う。重複チェック・upsert判定はこれを使う。

## 4. アカウント情報 → アカウント管理DB（upsert）
- データソース: `collection://2f17b156-8b57-819f-8367-000b8e94d6eb`
- DBページ: https://app.notion.com/p/2f17b1568b578197bc3bd325e659c2ab

### 項目
| 項目 | 型 | 投入規則 |
|---|---|---|
| `Name` | title | サービス名 |
| `userDefined:ID` | text | ログインID／メールアドレス |
| `Password` | text | パスワード |
| `userDefined:URL` | url | ログインURL |
| `Note` | text | 2FA有無・備考・更新理由など |
| `Date` | created_time | 登録日（自動・編集不可） |
| `最終更新日` | last_edited_time | 自動・編集不可。更新のたびに変わる |

### upsert 手順（必ず守る）
1. `notion-search` に `data_source_url="collection://2f17b156-8b57-819f-8367-000b8e94d6eb"` を指定し、サービス名／IDで既存ページを検索。
2. 一致あり → そのページを更新（Password / Note / URL を上書き）。`最終更新日` は自動更新される。プレビューで「既存更新」と明示。
3. 一致なし → 新規作成。プレビューで「新規」と明示。
4. 表記ゆれ等で一致が曖昧なときは、プレビューで「更新／新規どちらにするか」を確認してから書き込む。

`Date`・`最終更新日` は自動項目なので**値を書き込まない**。

## 5. シークレット（#key）の内容判定と扱い
`#key` は内容で2分岐する。タグだけで「値を残さない」と決めない。

**(A) パスワード・ログインID・アカウント認証情報**（WordPress等のPW、メール共通PW、各サービスのログインID／メール）
→ 実質 `#acct`。セクション4のアカウント管理DBへ upsert で保存する。プレビューで「`#key`だが内容はアカウント情報のためアカウント管理DBへ」と明示し確認。パスワードはアカウント管理DBに集約する方針のため。

**(B) APIキー・トークン・シークレットの値**（Claude/LINE等のAPIキー、アクセストークン、クライアントシークレット等）
→ **値は Notion に書かない**。残すのは参照情報のみ：どのサービスのキーか／管理場所（.env・シークレット管理ページ）／用途。メモDB（種別=その他メモ）に短く残すか報告で提示する。
  - 既存の管理先：「環境変数管理の設計（.env設定・シークレット管理）」ページ（LINE/Claude APIキー等）。値はそちらで管理する前提。
  - 値をNotionに置く明示指示があれば、リスク（共有・履歴・AI経路への露出）を一言伝え、閲覧権限を絞った専用DB前提であることを確認してから本人の選択に従う。

判定に迷う場合は (B) 寄り（安全側）に倒し、プレビューで確認する。
