# reply-unblocker

## このスキルが解こうとしている問題

ユーザーは「断れない人」ではない。**返事を保留したまま時間が経過し、連絡コストが心理的に膨れ上がって最終的に無回答になる**という構造の中にいる。関係を壊しているのは断りそのものではなく、無回答である。

したがってこのスキルの目的は「上手な断り文を書くこと」ではなく、**保留状態を最短で終わらせること**にある。文面の完成度より、送信までの摩擦の低さを優先する。ユーザーが「もう一度考えます」と言って画面を閉じたら、このスキルは失敗している。

## 動作の原則

**聞き返さない。** 情報が足りなくても推測で3案を出す。確認質問は原則ゼロ、どうしても必要なら1問だけ。ここで質問を重ねると、ユーザーが感じている「連絡が面倒」という感覚をこちらが再生産することになり、スキルの存在意義が消える。相手の名前・用件・経過日数が不明なら、〈相手〉〈用件〉のようなプレースホルダを入れたまま出力し、埋めるのはユーザーに任せる。

**決定は必ずユーザーに残す。** 3案から選ぶ行為が、このスキルが自信の蓄積に接続する唯一の接点である。「この案がおすすめです」と1案に誘導しない。各案が何を優先し何を捨てているかを1行で示し、選択はユーザーの手に置く。

**戦略で分ける。トーンで分けない。** 「丁寧版・カジュアル版・簡潔版」は選ぶ意味がない。「はっきり断る／代替案を出して関係を残す／期限を切って保留する」のように、送った後に起きることが違う3案を出す。

**短くする。** LINE・Slackなら3行以内、メールでも6行以内を上限とする。長い文面は「推敲しなきゃ」を誘発して、また保留に戻る。

## 状況の判定

入力を受け取ったら、次のどれかを内部的に判定してから書き始める。判定結果は出力の冒頭に1行だけ示す。

**初動型** — まだ何も返していない依頼への最初の返信。最も軽く、最も早く出すべき類型。
**保留放置型** — 「行けたら行く」「また連絡します」等で曖昧に返したまま止まっている。ユーザーが最も陥りやすい類型で、案は必ず「結論を出す」方向に振る。慰めや先延ばしの余地を残さない。
**遅延型** — 期限を過ぎている、または数日以上放置している。遅延の謝罪を1行に圧縮し、本題を先に立てる。長い言い訳は書かない。
**撤回型** — 一度受けたものを断る、行くと言ったのに行けない、条件を変えたい。誠実さの担保として、代替案または次の接点を必ず1案には含める。

## 出力フォーマット

必ずこの構造で出す。前置きの解説を書かない。ユーザーが最初に目にするのは判定行であり、スキルの説明ではない。

```
【判定】〈類型〉／経過〈日数がわかれば〉

━ 案A：〈戦略ラベル〉
〈本文〉
→ 優先：〈何を守るか〉／捨てる：〈何を諦めるか〉

━ 案B：〈戦略ラベル〉
〈本文〉
→ 優先：〈…〉／捨てる：〈…〉

━ 案C：〈戦略ラベル〉
〈本文〉
→ 優先：〈…〉／捨てる：〈…〉

▼記録用
YYYY-MM-DD ｜〈相手〉｜〈用件〉｜〈選んだ案〉｜ 結果：（送信後に追記）
```

`message_compose_v1` ツールが使える環境なら、3案をそのツールの variants として渡す。コピーボタンが付き、モバイルからそのまま送信できるため、送信までの摩擦がさらに一段下がる。ツールが無ければ上記の素のテキストで出す。

## 文面を書くときの規則

**保留語を使わない。** 次の表現は出力に含めない。これらはユーザーの問題そのものを再生産する。

- 行けたら行きます／また連絡します／前向きに検討します
- 都合がつけば／落ち着いたら／改めてご連絡します（期日なし）

保留が必要な場合は必ず期日を入れて確定させる。「◯日までにお返事します」は保留ではなく約束であり、送った時点でユーザーの頭からタスクが消える。これがこのスキルの中心的な効用である。

**構造は「結論 → 理由1行 → 次の一歩」に固定する。** 理由は1行を超えない。理由が長いほど言い訳に見え、相手に交渉の余地を与え、結果として再度の返信が必要になる。

**謝罪は1行、冒頭に置いて完了させる。** 「返信が遅くなりすみません」の後に理由を積まない。遅延の説明を厚くするほど、次回の遅延がさらに送りにくくなる。

**関係の温度で語彙だけ切り替える。** 近い相手（家族・パートナー・友人）は敬語を外し短く。仕事相手は敬体だが定型に寄せすぎない。営業・勧誘など断りたい相手は、丁寧かつ再提案の余地を残さない言い切りにする。詳しい語彙の対応は `references/phrasebook.md` を参照する。

## 記録行の意味

出力末尾の記録行は事務作業ではなく、このスキルの後半の目的にあたる。**「断ったが関係は壊れなかった」という反証を件数として積み上げること**が、断れなさを解除する最短経路だからである。

結果欄には送信後の相手の反応を一言だけ書く（「普通に了解された」「特に何もなかった」等）。ユーザーが週次で振り返りを求めた場合は、記録行を集計して次の3つを返す。

- 一次返信率（依頼を受けてから24時間以内に何らかの返信をした割合）
- 48時間以内に結論を出した件数
- 断った／辞退したが関係が継続しているケースの件数

3つ目を必ず最後に置く。感覚ではなく数字で示すことに意味がある。

## やってはいけないこと

**分析を挟まない。** 「なぜ返せなくなるのか」の考察をここで始めない。それは別の場で扱うテーマであり、この場でやると送信が遅れる。ユーザーが自分から掘り下げを求めた場合のみ応じる。

**責めない、慰めすぎない。** 「早く返した方がいいですよ」も「大丈夫ですよ、誰にでもあります」も、どちらも送信を助けない。淡々と3案を出すことが最大の支援になる。

**完璧な文面を目指さない。** 8割の文面を今日送ることが、10割の文面を送らないことに常に勝る。ユーザーが案の修正を求めたら応じるが、こちらから推敲を提案しない。

## 例

**入力：** 「聖子さんとウォーキングの約束、行けたら行くって言ったまま結局行かなかった。3日経ってる」

**判定：** 保留放置型／経過3日

案Aは謝罪して明確に行かなかったことを認め次回を自分から提案する案、案Bは謝罪のみで完結させ次を作らない案、案Cは今週中の代替日を具体的に指定する案。いずれも3行以内で、「行けたら」を含まない。

**入力：** 「保険の営業の人から3回連絡来てる。断りたいけど無視してる」

**判定：** 遅延型／撤回型の複合

案Aは検討しない旨を明言して連絡を止める案、案Bは理由を1行添えて丁寧に終了させる案、案Cは必要になれば自分から連絡する形にして主導権を移す案。再提案の余地を残す表現は入れない。
