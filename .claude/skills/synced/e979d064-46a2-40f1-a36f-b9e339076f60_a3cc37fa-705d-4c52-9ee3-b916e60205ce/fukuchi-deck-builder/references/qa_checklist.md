# 視覚QAチェックリスト

生成したスライドは必ず目視確認する。pptxgenjs の初回生成はほぼ必ず1〜2件の実害（文字切れ・
はみ出し・重なり）が出る。それを直して止める。座標の微調整を延々と繰り返さない。

## 変換コマンド

```bash
python /mnt/skills/public/pptx/scripts/office/soffice.py --headless --convert-to pdf OUT.pptx >/dev/null 2>&1
rm -f slide-*.jpg
pdftoppm -jpeg -r 110 OUT.pdf slide
ls -1 "$PWD"/slide-*.jpg
```

修正後は4コマンドを再実行（PDFを作り直さないと画像に反映されない）。

## 重点チェック項目（この順で見る）

1. **文字のはみ出し・切れ**（最頻出・最重要）
   - 循環図: 右ノードがスライド右端を超えていないか／中央コアとノードが重なっていないか
   - カード: ヘッダ文字がカード幅で折り返して2行になり溢れていないか
   - 組織図: 部門数が多い時にラベルがボックス幅を超えていないか
   - 表: セル文字がはみ出していないか（長文は要約するか rowH を上げる）

2. **要素どうしの重なり**
   - 循環図と左の説明テキスト（cycleDiagram の cx を右に寄せる／lead の幅を詰める）
   - 最下段の本文とフッター（onDark の濃色ページで起きやすい。フッターを省くか本文を上げる）

3. **余白**
   - スライド端から 0.5インチ以上の余白があるか
   - ブロック間が詰まりすぎ／空きすぎでないか

4. **ブランド整合**
   - 配色が BRAND 定数のみか（浮いた色が無いか）
   - 会社の役割記述が鉄則どおりか（ビビッド＝金融、ILIFE＝現場 等）
   - 制作メモ・プレースホルダ（"確認用" "TODO" "[insert" 等）が残っていないか

```bash
# 残存プレースホルダの機械チェック
python /mnt/skills/public/pptx/scripts/office/extract-text OUT.pptx 2>/dev/null | \
  grep -iE "確認用|TODO|\[insert|lorem|ipsum|負教育" && echo "→ 要修正" || echo "→ OK"
```

## 修正の止めどき

ユーザーに見える欠陥（重なり・はみ出し・欠落）が無くなったら止める。サブピクセルの位置や
わずかな色味は調整しない。1回の修正サイクルで新たな実害が出なければ完了とする。
