# Downloads 週次スイープ（Stage 1）

Downloads の散在ファイルを、法人マイドライブ `Downloads書類アーカイブ/`（17分類）へ**整理してから格納**する。
設計の全体像は `Downloads書類アーカイブ/_整理ログ/_設計_2段分類フロー_2026-07-07.md` を参照。
これは **Stage 1（機械化してよい工程）**。事業部門/個人への振り分け（Stage 2）はここでは扱わない。

## 大原則（厳守）
- **移動のみ・削除なし**（junkも「隔離」まで。削除は人の最終確認後）。
- **提案 → 承認 → 実行** の順。承認なしに移動しない。
- **原本名を必ずログに残す**（完全可逆）。
- **迷ったら動かさない**（承認欄を空のままにする＝保留）。
- **Googleネイティブ形式(.gdoc/.gsheet 等)はローカル改名しない**（Drive側で改名）。

## 手順

### 1. 提案CSVを生成
```
python3 ~/.claude/skills/downloads-weekly-sweep/scan.py
```
→ `Downloads書類アーカイブ/_整理ログ/週次整理_提案_YYYY-MM-DD.csv` が出力される。
列：`id, 種別, 現在名, 元パス, サイズMB, 判定, 提案カテゴリ, 新名案, ネイティブ, 根拠, 承認(y/n)`
- 判定 = 格納A（自動確定・承認yで出力済）/ 格納B（要レビュー・承認空欄）/ 隔離C（junk）。

### 2. 格納B をレビューして埋める（ここが人＋AIの仕事）
CSVを読み、`判定=格納B` の行について**中身の手がかりから**：
- **提案カテゴリ**（17分類のどれか）を確定する。
- **新名案** を全社統合規則（Notionナレッジホーム設計§10, 2026-07-07確定）に沿って提案する：
  `YYYY-MM-DD_[事業体]_[内容]_v1.0.拡張子`（日付はハイフン先頭、版は末尾 `_v1.0`）。
  - **禁止語**：「最新」「コピー」「修正版」等は使わない（版番号で表す）。
  - 事業体略号：**ビビッド(本体) / ILIFE(=施設 LIFE STAND UP, 略LSU) / SWELL(=オレンジワークス, 略OW) / リアン(リアンライフ・後継) / ふくち(持株) / PRIVATE(個人)**。※「STAND UP」は法人でなく施設名なので主体に使わない。
  - 日付・事業体が不明なら無理に埋めない（省略可）。
  - **ネイティブ=yes の行は新名案を空のまま**（Drive側で改名する旨を残す）。
  - 注：`NN_部門`/`[Vnn]案件`/`[Ynn]個人開発` 等の**正本記法はStage 2（部門振り分け時）で付与**する。アーカイブ段階では上記の日付＋事業体＋内容で十分。
  - **特例（2026-07-07決定）**：`07_議事録・面談・商談` は議事録自動化の既存規則 `[案件番号]_[組織名]_[種別]_v[版数]_[YYYYMMDD]` を**そのまま維持**する（§10へは寄せない）。他カテゴリのみ§10統合案を適用。
- 確信が持てない行は**承認を空**のまま（保留）。
- 問題なければ `承認(y/n)` 列に `y` を入れる。格納A/隔離Cの既定yも最終確認する。

必要なら中身を確認：`head`/` file`/PDFやdocxのテキスト抽出等で判断材料を得る。

### 3. ドライラン（任意・推奨）
```
python3 ~/.claude/skills/downloads-weekly-sweep/apply.py "<提案CSVのパス>" --dry-run
```
→ 実際には動かさず、どこへ何が移動するかを `週次整理_実行_YYYY-MM-DD_dryrun.csv` で確認。

### 4. 実行
```
python3 ~/.claude/skills/downloads-weekly-sweep/apply.py "<提案CSVのパス>"
```
→ 承認y行のみを移動（格納 or 隔離）。`週次整理_実行_YYYY-MM-DD.csv` に原本名・元/先パスを記録。

### 5. 報告
処理件数・保留件数・隔離件数と、ログCSVの場所を田村さんへ報告。junk隔離分の削除可否は別途確認。

## ルールの育て方（併用方針）
初期はこのSkillで運用し、`scan.py` の `STRONG_RULES`（強キーワード→カテゴリ）を実データに合わせて追記・調整する。
分類が安定し「格納A」で確実に決まるパターンが固まったら、その部分だけ launchd 定期実行スクリプトに移し無人化する（設計書§2-3 併用案）。

## やってはいけないこと
- 承認欄が空/nの行を動かす。
- 削除（隔離までに留める）。
- 事業部門（共有ドライブ）へ直接振り分ける（＝Stage 2。誤配防止のため別工程・別承認）。
- ネイティブ形式のローカル改名。
