# 何を検査するか

## 1. 3つの状態を混ぜない

```
① 本物の異常     動くはずなのに動いていない・申告と実体が食い違う
② 止めてある     有璽氏またはレジスタの判断で意図的に無効化されている
③ 対応保留(既知) 穴は分かっている・直す判断はまだ人待ち
```

★警告が出ている ≠ 異常がある。2026-08-20、台帳と実体の突合で「ズレ4件」と出したが、実際に対応が要ったのは2件だった(残り2件は①止めてある②対応保留)。**この3つを分けずに出すと、本物の異常が埋もれる。**

## 2. 「心拍が無い」を「動いていない」と読み替えない

先に成果物(Drive・Notion・シートの実際の更新日時)を見る。**心拍は「打つ実装が入っているものだけ」に付いている。** 心拍が無い=未検証の可能性と、心拍を打つ実装自体が無いだけの可能性を分けて報告する。

## 3. 新設の3点セット(★必ずこの順)

```
① 実測で1回通す      ドライラン → 本実行 → 成果物を実物で照合
② レジスタに行を作る  ⚙️自動処理レジスタへ新規登録。行が無ければ心拍が来ても誰も気づけない
③ 心拍の着弾を確認    本実行後、レジスタ側に実際に届いたかを見る
```

**心拍を打つコードを書いたら、同じ作業でレジスタの行を作るまでが1作業。** ②を飛ばすと「動いているのに誰も知らない」自動処理が生まれる(2026-08-20実例)。

## 4. 月次監査 ── 「有効=YES だが最終実行=null」の抽出(★この役が持つ)

`~/.vivid-relay/automation_inventory_check.py`(既存・毎週月曜09:20の「台帳と実体の突合」)の管轄を拡張し、**月次でレジスタの「有効=YES」行のうち最終実行が空のものだけを抽出する監査をここへ足す**。self_audit.py(汎用オーケストレータ)側には足さない ── ドメイン固有の判定基準を2箇所で育てると二重管理になる。★実装はまだしていない。着手時は必ず data-auditor(つる)の検査を通す。

## 5. 直してよいもの／直さないものを分ける

```
直してよい(可逆)    cron登録・daily_jobs.conf・レジスタの行・ログ・心拍の接続・
                    routineのプロンプト(★変更前を必ず退避してから。ただし置く手は
                    ビビ ── 上の「自分の手足の範囲」を参照)
直さない            台帳・顧客DB・kintone のデータ本体
                    規範(fukuchi-core・Notion運用ルール)の変更は提案のみ・要承認
```

## 6. ★自分が作ったもの・直したものを自分で検査しない

修正した後、「直った」と自分で判定して終わらせない。**data-auditor(つる)へ回す。** 判定は3択で聞く(2択は不可へ倒れて収束しない):

```
① 載せてよい
② 載せてよい(★条件つき・条件を明記)
③ ★不可
```

## 7. 踏んではいけない地雷(全部、実際に踏まれたもの)

- cron から `git pull --ff-only` を直呼びしない(作業中は必ず失敗。153回連続を実測)
- cron→launchd に移すとファイルアクセス権が消える(TCCは起動元で判定する)
- 周期より長い自動処理はロックを取る(5分周期×15分で3本同時に走った実例)
- **成功したときだけ完了の印を書く**(失敗しても `.done` が書かれ、一時的な503で丸1日分が黙って飛んだ実例)
- **「諦めた」を「済んだ」と同じ印にしない**
- **人が手で書くプロパティを機械の判定条件に使わない**(書き忘れると静かに対象から消える)
- **自分の書き込みを、自動処理が動いた証拠にしない**
- 世代管理を本数で切らない(頻度が高い時期ほど保護され、希少な版から消える) ── 残す単位は「日ごとに最新1本」
- 日本語は literal で書く(`\u`エスケープは別の漢字に化ける)
- 鍵・トークンの実値をログや報告に出さない
- 未検証のものを cron・daily_jobs.conf・routine に載せない

## ★逆申告倒れ（2026-08-20 初仕事で実測）

申告倒れ＝レジスタが「有効・成功」なのに実体が無い、の**逆型**を実測した。
実体（daily_jobs.conf の実行行）は動いているのに、レジスタが有効=NO／未検証と申告していた
（intake_register・notion_customer_upsert）。

原因は「**新しい判断（人の指示・検査役の通過）が、レジスタへの反映だけ漏れた**」こと。

```
① 登録漏れ      実体があるのに台帳に行が無い
② 申告倒れ      台帳は「有効・成功」だが実体が無い
③ ★逆申告倒れ  台帳が「無効/未検証」と言うが実体は動いている
                → **監視されていない。止まっても🔴が立たない**
```

**②だけ見ると③を見逃す。**

★実体と台帳が食い違ったら、**どちらが新しい判断かを日付・経緯で確認してから直す。**
実行行を止める方向にだけ倒さない。
